# Technical Debt Register (`TD-NN`)

Methodology item 44 (root README §10): *Technical Debt* — everything in this analysis or its downstream artifacts that is **declared but not delivered, stale, contradictory, or missing**, and that will cost time or correctness later.

**Series:** `TD-NN` (two digits, starting `TD-01`). This file is the **single allocator** — no other document mints `TD-*` IDs; citations elsewhere must already exist here (mirrors the `RISK-*` rule in `17-risk-management/risk-review-process.md` §9). IDs are never reused, and numbering gaps are prohibited; the next free ID after this revision is `TD-11`.

**Status values:** `OPEN` (default) → `IN PROGRESS` → `PAID` → `ACCEPTED` (explicitly carried forward with rationale). Every row started `OPEN` at authoring — nothing in the product has been implemented; the first pay-down (`TD-10`, same-day domain authoring) is documentation debt, not product delivery.

**Review rule:** this register is checked at **every gate** in `21-completion/quality-gates.md` (documentation check D-2): each open `TD-NN` must have an owner and a disposition — paid down, scheduled, or explicitly accepted — or the gate records a finding.

**Priority scale:** `CRITICAL · HIGH · MEDIUM · LOW` (same vocabulary as finding severity, so gate reports read uniformly).

## 2. Register Rules

1. **Single allocator.** New debt = next free sequential `TD-NN` issued only in this file (`TD-11`, `TD-12`, …). No gaps, no renumbering, no reuse.
2. **Origin is mandatory.** Every row names the file where the debt originates — an unlocatable debt cannot be paid down.
3. **Evidence tag discipline.** Rows TD-01…TD-07, TD-09, TD-10 are `VERIFIED` (each was checked against the cited files while authoring this register). TD-08 is `INFERENCE` (a design gap, not a directly observed defect). Corrections to any row are version bumps here, with a Change History row (root README §9).
4. **Debt is never silently dropped.** A paid row moves to `PAID` with the change set that paid it; an accepted row keeps its rationale. Deleting a row is prohibited (mirrors `risk-review-process.md` §5 rule 6).
5. **Gates review this register** (D-2 in `21-completion/quality-gates.md`) at Gate 0, Gate 1, Gate 2, and Gate 3.
6. **Relationship to risk:** debt that threatens an objective also gets screened into `17-risk-management/risk-register.md` (finding/gap screening logic in `risk-review-process.md` §6); a `TD-NN` is not a risk and never replaces one.
7. **Root README §10 item 44** is satisfied by this file; it pairs with `21-completion/recommendations.md` (item 46) — every `TD-NN` here has a corresponding pay-down `REC-NN` there.
