# TC-114 — Admin surface is deny-by-default: low-privilege tokens are refused server-side, failures are audited, nothing persists

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that privileged admin endpoints called directly over the API with low-privilege tokens (Moderator on settings/roles/returns, Admin on roles, Customer/Vendor/Courier on the admin surface) are denied server-side with the documented error codes, that each authenticated denial is recorded with `outcome = DENIED`, and that no denied call mutates state — while Moderator's granted moderation read still succeeds. | security | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Tokens: `MODERATOR`, `ADMIN`, `SUPER_ADMIN`, `CUSTOMER`, `VENDOR`, `COURIER`; one anonymous request (no `Authorization` header). |
| 2 | Fixtures: wallet `791100008` `ACTIVE`; top-up `TOPUP-3301` `PENDING_VERIFICATION`; return `RET-8847` admin-decidable; `commission.defaultRate` version `v0 = 3`; user `771234567` roles unchanged. |
| 3 | `t0` recorded; baseline role list of `771234567`, version of the setting, and status of the wallet/top-up/return captured. `GET /readyz` → `200`. |

## Test Data

| Field | Value |
|---|---|
| 1 settings write | `MODERATOR` `PUT /admin/settings/commission.defaultRate {"value":15,"expectedVersion":3}` |
| 2 role grant | `ADMIN` `POST /admin/users/771234567/role {"role":"MODERATOR","reason":"TC-114 probe"}` |
| 3 role grant | `MODERATOR` `POST /admin/users/771234567/role {"role":"MODERATOR","reason":"TC-114 probe"}` |
| 4 wallet freeze | `CUSTOMER` `POST /admin/wallets/791100008/freeze {"reason":"TC-114 probe"}` |
| 5 top-up verify | `VENDOR` `POST /admin/topups/TOPUP-3301/verify {}` |
| 6 directory read | `COURIER` `GET /admin/users?page=1&pageSize=10` |
| 7 return decision | `MODERATOR` `POST /admin/returns/RET-8847/approve {"reason":"TC-114 probe"}` |
| 8 no token | `GET /admin/users?page=1&pageSize=10` without `Authorization` |
| 9 control read | `MODERATOR` `GET /admin/moderation?page=1&pageSize=10` |

## Steps
1. Execute calls 1–7 as raw HTTP requests (bypassing any UI guard); capture status and error envelope per call.
2. Call 8 without a token; capture status/code.
3. SQL by each captured `correlation_id`: count `b13.audit_log` rows with `outcome = 'DENIED'` created in `[t0, now]`.
4. Re-read the fixtures: setting version, `771234567` roles, wallet `791100008` status, top-up `TOPUP-3301` status, return `RET-8847` state.
5. Call 9 (the granted moderation read) as `MODERATOR`.

## Expected Result
- Steps 1 → exactly as coded, all `403` except noted: (1) `403 FORBIDDEN` — settings writes are Super Admin only (`API-ADM-023`, `rbac.md` row 24); (2) and (3) `403 ROLE_ASSIGNMENT_FORBIDDEN` — role management is the sole Super Admin capability (`API-ADM-025`, `rbac.md` row 23, `UC-037`); (4) `403 FORBIDDEN` — Customer denied wallet freeze (`rbac.md` row 13); (5) `403 FORBIDDEN` — Vendor denied top-up verification (`rbac.md` row 14); (6) `403 FORBIDDEN` — Courier denied the admin directory (`rbac.md` §5); (7) `403 FORBIDDEN` — Moderator is read-only on return decisions (`TC-077`, `rbac.md` row 12). Every body is the error envelope only — no resource payload is disclosed (`SEC-REQ-004` R1/P7, `AC-SR004-03`: raw HTTP hits the same server-side decision as the UI would).
- Step 2 → `401 AUTH_INVALID` (`error-model.md` 401) — a request with no role context fails closed, never open (`AC-SR004-04`, `SEC-REQ-004` R1).
- Step 3 → exactly **7** rows with `outcome = 'DENIED'`, one per authenticated denied call, each carrying the call's `correlation_id`, its `actor_role`, `action` and non-null `ip`/`created_at` — failed authorization attempts are recorded too (`audit_log.md` outcome enum, `SEC-REQ-004`); the unauthenticated call writes **no** row (no actor context).
- Step 4 → all baselines unchanged: setting version still `3` (value `10`), roles of `771234567` unchanged, wallet still `ACTIVE`, top-up still `PENDING_VERIFICATION`, return still admin-decidable — **nothing persisted** by any denied step (`SEC-REQ-004` R1).
- Step 5 → `200 { items, page, total }` — the matrix discriminates rather than blanket-denying: Moderator keeps its granted moderation read (`API-ADM-027`, `rbac.md` row 20).
