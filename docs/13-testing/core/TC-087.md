# TC-087 — Templates follow the user locale (Arabic default) and deep links stay server-generated

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that every notification type ships an Arabic and an English template, that rendering follows the user's locale with Arabic as the default, and that every in-app/push payload carries the documented server-generated `deepLink` contract (relative route, whitelisted entity/action, matching locale). | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Buyer `771234567` has locale `ar` (explicit); buyer `771234570` has locale `en`; customer `771234571` has **no** locale set (default path). |
| 2 | Equivalent `ORDER` events (`ORD-7F3A21` → `PLACED` style) are seeded for all three users; one `SECURITY` event (login) seeded for `771234567`. |
| 3 | Template registry is exported for the locale-pair inventory scan; push devices registered for each user. |

## Test Data

| Field | Value |
|---|---|
| users | `771234567` (ar), `771234570` (en), `771234571` (unset) |
| expected deepLink | `surface: "CUSTOMER"`, `route: "/orders/{orderId}"`, `entity.type: "ORDER"`, `action: "VIEW"`, `locale` = user locale |
| security deepLink | `action: "VIEW"`, route under the account/security area (e.g. `/account/sessions`) |

## Steps
1. Template inventory scan: for every notification type in the registry, list missing `ar` or `en` variants.
2. Trigger the seeded `ORDER` events for the three users; `GET /notifications?category=ORDER&limit=5` as each user.
3. Inspect `title`, `body`, `deepLink.locale` per user; inspect the push payload shape for one of them.
4. Trigger the `SECURITY` login event for `771234567` → inspect its `deepLink`.

## Expected Result
- Step 1 → zero missing pairs — every template exists in both Arabic and English (`BR-NTF-04`, `AC-FR017-04`, `C-24`).
- Step 2 → each user receives exactly one `ORDER` notification.
- Step 3 → `771234567` gets Arabic `title`/`body`; `771234570` gets English; `771234571` (locale unset) gets **Arabic** — Arabic is the default (`BR-NTF-04`, `C-24`); `deepLink` per item is `{ surface: "CUSTOMER", route: "/orders/ORD-7F3A21", entity: { type: "ORDER", id: "ORD-7F3A21" }, action: "VIEW", locale }` matching the rendered locale — route is app-relative, never an absolute URL, never client-supplied (`notifications.md` §2); push payload is `{ notification: { title, body }, data: { …deepLink, category, severity } }` with the body already localized.
- Step 4 → security notice `deepLink.action = "VIEW"` with a server-generated account/security route — never an external URL (`notifications.md` §2 security rule, `BR-NTF-02`).
