# TC-003 — Wrong-OTP attempts, expiry, resend cooldown and resend limit

| Field | Value |
|---|---|
| Objective | Verify the full OTP failure envelope: two wrong codes report remaining attempts, the third invalidates the OTP, an expired OTP is rejected, a resend inside 60 seconds is throttled and a fourth resend inside 10 minutes is refused. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Phone `771234567` is registered and `UNVERIFIED` with a fresh OTP (`attemptsAllowed` 3).
- No OTP resend has been made for this phone in the last 10 minutes.
- OTP rate limit buckets for the test IP are reset.

## Test Data

| Field | Value |
|---|---|
| Phone | `771234567` |
| Correct code | `481902` |
| Wrong code 1 | `000001` |
| Wrong code 2 | `000002` |
| Wrong code 3 (fatal) | `000003` |
| Resend cooldown | 60 seconds |
| Resend window limit | 3 resends per 10 minutes |

## Steps
1. `POST /auth/otp/verify` with `{"phone":"771234567","code":"000001","context":"REGISTER"}`.
2. Repeat with code `000002` and record `error.details`.
3. Repeat with code `000003`.
4. After step 3, `POST /auth/otp/verify` with the correct code `481902`.
5. Backdate the stored OTP expiry to 6 minutes ago, then verify with `481902`.
6. Request a new OTP and immediately call `POST /auth/otp/request` again within 60 seconds.
7. Call `POST /auth/otp/request` four more times inside a 10-minute window.

## Expected Result
- Step 1 returns `422 OTP_VERIFICATION_FAILED` with `details[0].issue = ATTEMPTS_REMAINING` and value 2; step 2 reports 1 remaining.
- Step 3 returns `422 OTP_MAX_ATTEMPTS`, `retryable:false`; the stored OTP is invalidated and the correct code is now useless.
- Step 4 returns `422 OTP_MAX_ATTEMPTS` (or `OTP_VERIFICATION_FAILED`) — no token pair is ever issued for a code that exhausted attempts.
- Step 5 returns `422 OTP_EXPIRED` with `retryable:true`; a fresh OTP must be requested.
- Step 6 returns `422 OTP_RESEND_COOLDOWN` carrying `retryAfterSeconds` between 1 and 60.
- Step 7's fourth resend returns `422 OTP_RESEND_LIMIT`; earlier resends returned `200 OTP_SENT`.
- No step creates an account session or marks the phone VERIFIED.
