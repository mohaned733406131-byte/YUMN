# TC-102 — Coupon disable flow and store-coupon scoping behave as documented

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that admin disabling a coupon requires a reason, takes effect immediately on validation, is audited, and that store-coupon reads/writes are scoped to the owning store (foreign coupons 404, other stores never listed, Moderator read-only). | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `ADMIN` token; `VENDOR` Owner tokens for `tech-store` (`779876543`) and store B; `MODERATOR` token. |
| 2 | Active coupons: platform `RAMADAN25`, store `TECH10` (owned by `tech-store`, 1 redemption), store B coupon `BSTORE15`. |
| 3 | Buyer cart `C-100` exists for the post-disable validation probe. |

## Test Data

| Field | Value |
|---|---|
| disable | `POST /admin/coupons/{ramadan-id}/disable {}` → expect `422 REASON_REQUIRED` |
| disable with reason | `POST /admin/coupons/{ramadan-id}/disable {"reason":"Budget exhausted"}` |
| validate after | `POST /coupons/validate {"code":"RAMADAN25","cartSnapshot":"C-100"}` |
| scoping | `GET /store/coupons` as each vendor; `PUT /store/coupons/{bstech-id}` from `tech-store` owner |

## Steps
1. As `ADMIN`, disable `RAMADAN25` without a body; then with `{"reason":"Budget exhausted"}`; repeat the second call.
2. As buyer, validate `RAMADAN25`; as `ADMIN`, `GET /admin/coupons?status=DISABLED` and `GET /admin/audit-log?targetId={ramadan-id}`.
3. As `MODERATOR`, `GET /admin/coupons`; then attempt the disable on `TECH10`.
4. As `tech-store` owner, `GET /store/coupons`; attempt `PUT /store/coupons/{bstech-id}` (store B's coupon) with `{"status":"DISABLED"}`; as `tech-store` owner disable own `TECH10` via `PUT … {"status":"DISABLED"}`.
5. As store B owner, `GET /store/coupons`.

## Expected Result
- Step 1 → no reason → `422 REASON_REQUIRED`; with reason → `200 { status: "DISABLED", disabledAt }`; repeat → `409 STATE_CONFLICT` (already disabled, `API-CNT-017`).
- Step 2 → validate → `422 COUPON_INVALID` (`details[].issue = "NOT_FOUND"` or disabled issue) — in-flight carts are hit on the very next validate (`API-CNT-017`, `BR-PRM-03`); list shows `status: "DISABLED"`; audit entry records `coupon.disable`, actor `ADMIN`, reason and timestamp (`SEC-REQ-010`, `AC-FR020-01`).
- Step 3 → Moderator list → `200` (read-only rows); Moderator disable → `403 FORBIDDEN` (`SEC-REQ-004`).
- Step 4 → `tech-store` list contains only `TECH10` — `BSTORE15` never appears (own-store scoping, `API-CNT-018`, `BR-VND-07`); foreign `PUT` → `404 NOT_FOUND` (foreign coupons 404, never 403-leak, `API-CNT-020`); own disable → `200 { …coupon }` with `status: "DISABLED"` — vendors may disable but not discount-edit (`BR-PRM-01`); every item carries `redemptionCount` (`API-CNT-018`).
- Step 5 → store B lists only `BSTORE15`; suspended store calling the same endpoint → `403 STORE_SUSPENDED` (`API-CNT-018`, `BR-VND-03`); admin may also disable store-scoped coupons (platform override, `BR-PRM-03`).
