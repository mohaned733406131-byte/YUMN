# TC-034 — VAT math: 15 % on (subtotal − discount), shipping untaxed, half-up rounding and master sum

| Field | Value |
|---|---|
| Objective | Verify the authoritative money math: VAT = 15 % × (subtotal − coupon discount) computed on integers, shipping excluded from the VAT base, half-up rounding to whole YER per sub-order, and master total = Σ sub-order totals. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (exact-figures assertions; math unit tests referenced from PLAN-10) |

## Preconditions
- Buyer `771234567` wallet funded with 200,000 YER; address `adr-771` resolves to zone `sanaa-center`.
- Coupons seeded: `482913` = 10 % platform coupon, active, usage remaining; cart fixtures `V-1` (40,000 YER), `V-2` (33,333 YER), `V-3` (two stores, no coupon).
- Rounding account exists for posting sub-YER differences (`BR-FIN-05`).

## Test Data

| Field | Value |
|---|---|
| `V-1` | subtotal `40000`, coupon `482913` → discount `4000`, VAT `5400`, shipping `700` → total `42100` |
| `V-2` | subtotal `33333`, no coupon → raw VAT `4999.95` → `5000` half-up, shipping `500` → total `38833` |
| `V-3` | store A `25000+3750+500 = 29250`; store B `4500+675+300 = 5475`; master `34725` |

## Steps
1. Load cart `V-1`, then `POST /checkout/session` with `Idempotency-Key: chk-034-01`, body `{"addressId":"adr-771","shippingMethod":"STANDARD","paymentMethod":"wallet","couponCode":"482913"}`.
2. Recompute independently: `40000 − 4000 = 36000`; `0.15 × 36000 = 5400`; `36000 + 5400 + 700 = 42100`; compare with `totals`.
3. `POST /orders` with `Idempotency-Key: ord-034-01` and assert the stored totals equal the session totals.
4. Load cart `V-2` and repeat session + confirm; assert `vat = 5000` and `grandTotal = 38833`.
5. Check the rounding-account posting for the `4999.95 → 5000` difference (`BR-FIN-05`).
6. Load cart `V-3` (two stores), `POST /checkout/session` (`chk-034-03`), then `POST /orders` (`ord-034-03`) and assert master/sub arithmetic.

## Expected Result
- Step 2 → session returns `{"subtotal":40000,"discount":4000,"vat":5400,"shippingFee":700,"grandTotal":42100}`; `vat = 0.15 × (subtotal − discount)` exactly, shipping contributes `0` to the VAT base (`BR-FIN-01`).
- Step 3 → `201`; `GET /orders/{id}` shows the identical breakdown — no client-supplied total is ever trusted (`BR-CRT-04`).
- Step 4 → `201` with `vat 5000` (half-up from `4999.95`), `grandTotal 38833`, all values integer YER (`BR-FIN-05`, `BR-PAY-10`).
- Step 5 → a single rounding-account entry equals the rounding difference; wallet and escrow amounts stay whole YER.
- Step 6 → `201` with `byStore` totals `29250` and `5475`, `totals.grandTotal 34725 = 29250 + 5475` (`BR-FIN-02`, `AC-FR011-04`).
- Rejected coupon (`POST /coupons/validate` with an expired code) returns `422 COUPON_INVALID` and creates no discount, no session totals and no order (`BR-PRM-06`).
