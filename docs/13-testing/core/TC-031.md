# TC-031 — Wallet checkout happy path: debit, escrow funding and PLACED order with visible VAT math

| Field | Value |
|---|---|
| Objective | Verify that a funded-wallet checkout atomically debits the buyer exactly once, funds escrow, creates the master and sub-orders in PLACED and posts a balanced HOLD ledger pair, with the VAT breakdown (15 % of subtotal, shipping untaxed) visible on every response. |
| Level | integration |
| Priority | P0 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Customer `771234567` holds an `ACTIVE` wallet with 50,000 YER credited by a verified m-Floos callback (`BR-PAY-03`).
- Vendor `779876543` store `tech-store` is KYC `APPROVED`, active, selling `هاتف سامسونج` (`PRD-P1`) at 12,500 YER with stock 10; address `adr-771` sits in zone `sanaa-center` (STANDARD = 500 YER).
- API base `/api/v1` returns 200 on `/readyz`; locale `ar` (default); no other open checkout session exists for this buyer.

## Test Data

| Field | Value |
|---|---|
| Buyer / keys | `771234567`; `chk-031-01`, `ord-031-01` |
| Cart | `PRD-P1` × 1 @ `12500` YER, shipping STANDARD `500` YER |
| Totals | subtotal `12500` + VAT `1875` + shipping `500` = grand total `14875` YER |
| Balances | before `50000` → after `35125` YER |

## Steps
1. `GET /wallet` and record `balance`, `status` and `limits` (`topUpMin/topUpMax/orderMin/orderMax`).
2. `POST /checkout/session` with `Idempotency-Key: chk-031-01`, body `{"addressId":"adr-771","shippingMethod":"STANDARD","paymentMethod":"wallet"}`.
3. `POST /orders` with `Idempotency-Key: ord-031-01`, body `{"checkoutSessionId":"cs-031","confirmTotals":true}`.
4. Repeat step 3 byte-identically (same key, same body).
5. `GET /orders/{orderId}` and `GET /orders/{orderId}/timeline`.
6. `GET /wallet`, `GET /wallet/transactions?type=ORDER_PAYMENT`, `GET /wallet/escrow?orderId={orderId}`.
7. SQL: read the capture postings, the escrow row and `order_status_history` for this order.

## Expected Result
- Step 2 → `201` with `totals {"subtotal":12500,"discount":0,"vat":1875,"shippingFee":500,"grandTotal":14875}`, `wallet.balance 50000`, `wallet.shortfall 0`.
- Step 3 → `201` `{orderId:"ORD-031A", masterState:"PLACED", subOrders:[{id:"SUB-031A", total:14875, state:"PLACED"}], payment:{amount:14875, ledgerReference}}`.
- Step 4 → the **original** order and the original status code; exactly one wallet debit (`BR-ORD-06`, `BR-PAY-08`).
- Steps 6–7 → balance `35125`; one `ORDER_PAYMENT` debit of `14875` with `balanceAfter 35125`; escrow position `amountHeld 14875`, `releaseEligibleAt` absent (clock starts only at `DELIVERED`, `BR-ESC-01`).
- Ledger holds a balanced debit + credit pair inside one ACID transaction, `SUM(amount) = 0` (`BR-PAY-06`); exactly one history row `→ PLACED` carrying actor and timestamp (`BR-ORD-03`).
- VAT equals 15 % × 12,500 = 1,875 and the 500 YER shipping fee is excluded from the VAT base (`BR-FIN-01`); every response is `Cache-Control: no-store`.
