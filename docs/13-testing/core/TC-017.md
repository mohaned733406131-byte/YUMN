# TC-017 — Category structure preserves unique names within a parent

| Field | Value |
|---|---|
| Objective | Verify that `POST /admin/categories` enforces the 5-level depth limit (`422 CATEGORY_DEPTH_EXCEEDED`) and slug uniqueness per level (`409 SLUG_TAKEN`), with no row persisted on rejection. |
| Level | integration |
| Priority | P2 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Super Admin token is available for `/admin/categories`.
- Existing tree seeded to depth 4: `electronics` (L1) → `phones` (L2) → `smartphones` (L3) → `android` (L4).
- A level-5 node `midrange` exists under `android`; no category uses slug `phones-x`.

## Test Data

| Field | Value |
|---|---|
| Root | `electronics` (`إلكترونيات`, level 1) |
| Existing chain | `phones` (L2) → `smartphones` (L3) → `android` (L4) → `midrange` (L5) |
| Valid new sibling | `nameAr: حواسيب`, `slug: computers`, parent `electronics` |
| Duplicate slug | `slug: phones`, parent `electronics` (same level as `phones`) |
| Depth violation | `nameAr: منخفض`, `slug: low-end`, parent `midrange` (would be level 6) |

## Steps
1. `POST /admin/categories` with the valid `computers` node (parent `electronics`).
2. `POST /admin/categories` with `{"parentId":"<electronics>","name":{"ar":"هواتف","en":"phones-x"},"slug":{"ar":"phones","en":"phones-x"}}`.
3. `POST /admin/categories` with `{"parentId":"<midrange>","name":{"ar":"منخفض"},"slug":{"ar":"low-end"}}` (would create level 6).
4. `PUT /admin/categories/{smartphones}` moving `smartphones` under `midrange` (would re-evaluate depth on move).
5. `DELETE /admin/categories/phones` while its products still exist.
6. `GET /categories?locale=ar` as an anonymous visitor and `GET /admin/categories` for the admin tree.

## Expected Result
- Step 1 returns `201` with `level: 2`; the node appears under `electronics` in both reads.
- Step 2 returns `409 SLUG_TAKEN` — slugs are unique per level/parent scope (`BR-CAT-03`, DB partial indexes `uq_category_parent_slug`).
- Step 3 returns `422 CATEGORY_DEPTH_EXCEEDED` — the tree may not exceed 5 levels; no row with `level = 6` exists.
- Step 4 returns `422 CATEGORY_DEPTH_EXCEEDED` — move revalidates depth, exactly like create (`API-ADM-016`).
- Step 5 returns `409 STATE_CONFLICT` — a category with children or products must be emptied first.
- Step 6: after every rejection the tree is byte-identical to the pre-test snapshot; no orphan or deep row persists (`AC-FR004-05`: specific error + nothing saved).
- `GET /categories` still returns the full tree within one cached response (depth ≤5, `API-CAT-001`).
