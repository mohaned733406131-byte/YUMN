# TC-046 — Cancellation attempts at/after READY_FOR_PICKUP are refused with 409 CANCEL_WINDOW_CLOSED

| Field | Value |
|---|---|
| Objective | Verify that once a sub-order reaches `READY_FOR_PICKUP` the customer and vendor cancellation windows are closed: every cancel attempt is refused with `409 CANCEL_WINDOW_CLOSED` (or `409 STATE_CONFLICT` for admin force-moves outside the canonical table) with state, history, escrow and wallet untouched. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Orders seeded in `READY_FOR_PICKUP` (`ORD-046-R`) and `ASSIGNED` (`ORD-046-A`), each funded and escrow-held.
- Buyer `771234567`, vendor `779876543`, admin `775550010` all hold valid tokens.

## Test Data

| Field | Value |
|---|---|
| Orders | `ORD-046-R` state `READY_FOR_PICKUP`; `ORD-046-A` state `ASSIGNED` |
| Reasons | `"أريد الإلغاء"` (customer), `"المتجر مغلق مؤقتاً"` (vendor/admin) |
| Snapshot | `version`, history row count, escrow `amountHeld`, wallet balance before each attempt |

## Steps
1. Buyer `POST /orders/{ORD-046-R}/cancel` `{"reason":"أريد الإلغاء"}`.
2. Vendor `POST /store/orders/{ORD-046-R}/cancel` `{"reason":"المتجر مغلق مؤقتاً"}`.
3. Admin `POST /admin/orders/{ORD-046-R}/transition` `{"subOrderId":"SUB-046R","toState":"CANCELLED","reason":"ops override"}`.
4. Buyer `POST /orders/{ORD-046-A}/cancel` `{"reason":"أريد الإلغاء"}`.
5. Re-read both orders (`GET /orders/{id}`), their timelines, refund receipts, escrow and wallet balances.
6. Contrast: move a `PLACED` order (`ORD-046-P`) through a successful customer cancel to confirm the window logic is state-based, not blanket.

## Expected Result
- Step 1 → `409` `error.code = CANCEL_WINDOW_CLOSED`, `retryable:false` (`AC-FR012-03`); customer may cancel only while `PLACED`/`CONFIRMED` (`BR-ORD-04`).
- Step 2 → `409 CANCEL_WINDOW_CLOSED` — the vendor window also ends at `READY_FOR_PICKUP` (`API-ORD-010`: last cancellable state).
- Step 3 → `409 STATE_CONFLICT` — `READY_FOR_PICKUP → CANCELLED` has no row in the canonical transition table (`C-09`, `API-ORD-014`); no audit entry is written for a refused move.
- Step 4 → `409 CANCEL_WINDOW_CLOSED` at `ASSIGNED` as well.
- Step 5 → both orders remain in their original states with unchanged `version`, unchanged history row counts, escrow still held for the exact amounts, **0** refund rows, wallet balances unchanged.
- Step 6 → the `PLACED` cancel returns `200`, proving refusal is caused by the closed window, not by the endpoint.
- Every refusal carries `messageKey errors.CANCEL_WINDOW_CLOSED`, localized `message` and `correlationId`.
