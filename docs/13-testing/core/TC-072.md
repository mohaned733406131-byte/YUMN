# TC-072 — Three courier-recorded failed attempts escalate to admin review

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that courier-recorded failed delivery attempts (`POST /deliveries/{id}/failed-attempt`) count separately from wrong-code entries: attempts 1–2 return the delivery to `IN_TRANSIT` with `remainingBeforeEscalation`, the 3rd escalates the sub-order to admin review (`DELIVERY_ESCALATION` flag), further attempts are refused with `409 DELIVERY_ATTEMPTS_EXCEEDED` until an admin intervenes, and the code attempt budget stays untouched. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `DLV-4471` is `OUT_FOR_DELIVERY`, code `482913` issued, `code.attemptsUsed = 0`; sub-order `SUB-9C1104` is `OUT_FOR_DELIVERY`; no escalation flag yet. |
| 2 | Courier `790000011` is the assignee with an active token; an `ADMIN` token and a `MODERATOR` token are seeded. |
| 3 | `GET /admin/orders?escalated=true` does not contain `ORD-7F3A21` before the run. |

## Test Data

| Field | Value |
|---|---|
| delivery / order / sub-order | `DLV-4471` / `ORD-7F3A21` / `SUB-9C1104` |
| attempt reasons | 1: `CUSTOMER_ABSENT` (`note: "no answer at door"`), 2: `ADDRESS_UNREACHABLE`, 3: `CUSTOMER_REFUSED` |
| correct code | `482913` (untouched until step 7) |

## Steps
1. As courier `790000011`, `POST /deliveries/DLV-4471/failed-attempt {"reasonCode":"CUSTOMER_ABSENT","note":"no answer at door"}`.
2. `GET /deliveries/DLV-4471` → inspect `state`, `code.attemptsUsed`.
3. `POST /deliveries/DLV-4471/out-for-delivery`, then repeat step 1 with `{"reasonCode":"ADDRESS_UNREACHABLE"}`.
4. `POST /deliveries/DLV-4471/out-for-delivery`, then repeat step 1 with `{"reasonCode":"CUSTOMER_REFUSED"}` (3rd failed attempt).
5. As `ADMIN`, `GET /admin/orders?escalated=true&sort=slaAge_desc`; repeat the failed-attempt call (4th).
6. As `MODERATOR`, `GET /admin/orders?escalated=true` (read-only check), then as `ADMIN`, `POST /admin/orders/ORD-7F3A21/transition {"subOrderId":"SUB-9C1104","toState":"OUT_FOR_DELIVERY","reason":"escalation reviewed — retry delivery"}`.
7. Courier `POST /deliveries/DLV-4471/failed-attempt {"reasonCode":"CUSTOMER_ABSENT"}` (resumed), then `POST /deliveries/DLV-4471/code {"code":"482913"}`.

## Expected Result
- Step 1 → `200 { state: "IN_TRANSIT", attemptNumber: 1, remainingBeforeEscalation: 2 }` — failed attempt ≠ wrong code (`delivery.md` §2, `BR-SHP-06`).
- Step 2 → `state: "IN_TRANSIT"`, `code.attemptsUsed = 0` — the two counters are independent; `REASON_REQUIRED` is returned if `reasonCode` is omitted (`API-SHP-011`).
- Step 3 → `200 { state: "IN_TRANSIT", attemptNumber: 2, remainingBeforeEscalation: 1 }`.
- Step 4 → `200 { state: "IN_TRANSIT", attemptNumber: 3, remainingBeforeEscalation: 0 }`; the 3rd failed attempt escalates the sub-order to admin review with the full timeline (`BR-SHP-06`) — escalation is a review flag, never an 18th state (`C-09`).
- Step 5 → the admin queue lists `ORD-7F3A21` with `flags` containing `DELIVERY_ESCALATION` (`API-ORD-013`); the 4th failed attempt returns `409 DELIVERY_ATTEMPTS_EXCEEDED` until an admin intervenes; the `MODERATOR` read succeeds (read-only subset, `SEC-REQ-004`) but any moderator transition attempt is `403 FORBIDDEN`.
- Step 6 → forced transition `200 { subOrderId, state: "OUT_FOR_DELIVERY", version, historyEntry, auditId }` — inside the canonical 17-state table, audited append-only (`API-ORD-014`, `BR-PLT-06`, `SEC-REQ-010`, `C-09`).
- Step 7 → the failed attempt is accepted again (`attemptNumber` continues, escalation cleared by the intervention), and the correct code returns `200 { state: "DELIVERED", … }` — `code.attemptsUsed` was never consumed by the failed-attempt records (`delivery.md` §2).
