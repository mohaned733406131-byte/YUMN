# TC-097 — Content admin APIs enforce Moderator read-only and Admin-only writes

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that every `API-CNT` admin write refuses `MODERATOR` (read-only rows), that unauthenticated and non-admin callers are denied, and that each successful publish/disable writes an append-only audit entry. | security | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Tokens seeded: `ADMIN`, `MODERATOR`, `CUSTOMER`, unauthenticated (no `Authorization` header). |
| 2 | Existing draft page, active banner `BNR-EID-01`, and active seeded coupon `RAMADAN25` for the write probes. |
| 3 | `GET /admin/audit-log` is append-only (`SEC-REQ-010`) and readable by `ADMIN` and `MODERATOR` (`API-ADM-024`); no write method exists for it. |

## Test Data

| Field | Value |
|---|---|
| read probes | `GET /admin/pages`, `GET /admin/pages/{id}`, `GET /admin/banners`, `GET /admin/coupons` |
| write probes | `POST /admin/pages`, `POST /admin/pages/{id}/publish`, `POST /admin/banners`, `POST /admin/coupons`, `POST /admin/coupons/{id}/disable` |
| cross-check | `CUSTOMER` token and no token against one read and one write probe |

## Steps
1. As `MODERATOR`, call all four read probes.
2. As `MODERATOR`, call all five write probes (skip one of each when a precondition would return `STATE_CONFLICT`/`NOT_FOUND` — use valid targets so `403` is the deciding status).
3. As `CUSTOMER` and with no token, repeat `GET /admin/pages` and `POST /admin/coupons`.
4. As `ADMIN`, publish the draft page and disable `RAMADAN25`; then as `ADMIN`, read `GET /admin/audit-log?targetId=…` for both entities; as `MODERATOR`, read the same log.

## Expected Result
- Step 1 → four `200` responses including draft rows — `MODERATOR` legitimately reads content lists (`API-CNT-005/007/011/015`, `SEC-REQ-004`).
- Step 2 → every write → `403 FORBIDDEN` (content admin writes are `ADMIN`-only, `API-CNT-006/009/012/016/017`, `SEC-REQ-004`; `content.md` §2 further promises scope details in `details`); no draft/page/banner/coupon mutation occurred (entity re-read unchanged).
- Step 3 → `CUSTOMER` → `403 FORBIDDEN`; no token → `401 AUTH_INVALID` (`AUTH-01`, deny-by-default `FR-002`) — guest reads are limited to `API-CNT-001…003`.
- Step 4 → `ADMIN` operations succeed (`200 { …, auditId }` for publish per `API-CNT-009`) and produce `page.publish` / `coupon.disable` audit entries with `actorRole: "ADMIN"`, before/after values and timestamp (`SEC-REQ-010`, `AC-FR020-01`); `MODERATOR` audit read → `200` with the same entries (audit listing allows `ADMIN` and `MODERATOR`, `API-ADM-024`) while remaining unable to write; any write attempt against the audit log → `405 AUDIT_LOG_IMMUTABLE` (`error-model.md` 405) — the trail is append-only for every role.
