# TC-027 — Arabic search normalization matches variant forms and never returns inactive products

| Field | Value |
|---|---|
| Objective | Verify that `GET /search/products` finds products through alef/ya/ta-marbuta variants and diacritics, and that inactive, soft-deleted or suspended-store products never appear in results. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (ES index fixtures with Arabic variants from DOC-TST-005) |

## Preconditions
- Index contains `هاتف سامسونج جالكسي` (ACTIVE, store `STORE-A`) and `آيفون ١٥ برو` (ACTIVE, store `STORE-B`).
- Product `PRD-OLD` (`هاتف قديم`) is ACTIVE and indexed, then soft-deleted; product `PRD-DRAFT` is `DRAFT`.
- Store `STORE-B` gets suspended (admin action) after indexing.
- `GET /categories/{slug}` is available as the browse fallback.

## Test Data

| Field | Value |
|---|---|
| Query A (plain) | `هاتف` |
| Query B (diacritics) | `هَاتِف` |
| Query C (alef variants) | `ايفون` / `أيفون` / `آيفون` |
| Query D (ta-marbuta) | `جماليه` vs `جمالية` |
| Soft-deleted product | `PRD-OLD` (`هاتف قديم`) |
| Suspended store | `STORE-B` |

## Steps
1. `GET /search/products?q=هاتف` and record items and `meta`.
2. Repeat step 1 with `q=هَاتِف` (same meaning, fully vocalized).
3. `GET /search/products?q=ايفون`, then `q=أيفون`, then `q=آيفون` — compare the three result sets.
4. Search a ta-marbuta/ta spelling pair (`جماليه` / `جمالية`).
5. Soft-delete `PRD-OLD`, backdate the index job, then search `q=قديم` immediately and after the reindex job runs.
6. Set `PRD-DRAFT` name to contain `هاتف` and search `q=هاتف`.
7. Suspend `STORE-B` (admin) and repeat step 3 (`آيفون` belongs to it).
8. Search `q=ه` (too short) and an unknown nonsense string `q=زززززز`.

## Expected Result
- Step 1: `200` with `items` containing `هاتف سامسونج جالكسي`, `facets` populated, `meta.degraded: false`.
- Step 2: identical results to step 1 — the Arabic analyzer strips diacritics before matching (`C-24`, `AC-FR009-01`).
- Steps 3: all three alef spellings return the same `آيفون` product — normalization is server-side; clients send the query verbatim.
- Step 4: both spellings return the same product (ta/ta-marbuta normalization).
- Step 5: the soft-deleted product disappears from results (re-checked at query time, belt-and-braces with index time, `AC-FR009-02`); no `5xx` occurs while the index catches up.
- Step 6: `DRAFT` products never appear — only `ACTIVE`, non-deleted products (`BR-CAT-06`).
- Step 7: `STORE-B` products vanish from results after suspension (`BR-VND-04`).
- Step 8: too-short query → `422 QUERY_TOO_SHORT`; nonsense query → `200` with empty `items`, `facets`, `meta.didYouMean`/`meta.popularCategories` — zero results are never an error status.
