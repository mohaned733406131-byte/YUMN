# TC-009 — Password reset via OTP revokes all sessions and forbids reuse

| Field | Value |
|---|---|
| Objective | Verify the full reset chain `reset/start → reset/verify → PUT /auth/password` returns the same generic response for existing and missing accounts, issues a 10-minute single-use reset token, and revokes every session on success. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Account `771234567` exists with 2 active sessions (`sess_A`, `sess_B`).
- Phone `776660002` has no account (anti-enumeration control).
- OTP counters are reset for both phones.

## Test Data

| Field | Value |
|---|---|
| Existing phone | `771234567` |
| Non-existing phone | `776660002` |
| Reset OTP (sandbox) | `330451` |
| New password | `Reset#2026z` |
| Reset-token lifetime | 600 seconds |

## Steps
1. `POST /auth/password/reset/start` for `771234567`, then for `776660002`; compare the two bodies.
2. `POST /auth/password/reset/verify` with `{"phone":"771234567","code":"330451"}` and capture `resetToken`.
3. Wait past 10 minutes (or backdate the token) and call `PUT /auth/password` with the stale `resetToken`.
4. `PUT /auth/password` with `{"newPassword":"Reset#2026z","resetToken":"<fresh>"}`.
5. Replay the same `resetToken` in a second `PUT /auth/password` call.
6. `POST /auth/refresh` with `sess_A`'s and `sess_B`'s refresh tokens.
7. `POST /auth/login` with the old password, then with `Reset#2026z`.

## Expected Result
- Step 1: both phones return `200 {"status":"OTP_SENT","expiresAt":…,"resendAfterSeconds":60}` — byte-identical shapes, so account existence cannot be enumerated.
- Step 2 returns `200 {"resetToken":"…","expiresIn":600}`; consuming the OTP does not change the password yet.
- Step 3 returns `401 TOKEN_INVALID` or `400 VALIDATION_ERROR` with `retryable:false` — the reset token is expired and single-use.
- Step 4 returns `204`; the new password is stored with bcrypt cost 12 and must differ from the old hash.
- Step 5 returns `401 TOKEN_INVALID` — reset tokens cannot be replayed.
- Step 6: both sessions fail with `401 SESSION_NOT_FOUND` — **all** sessions were invalidated by the reset.
- Step 7: old password rejected (`401 INVALID_CREDENTIALS`), new password accepted (`200`).
- A mandatory security notification for the password change is sent (cannot be disabled).
