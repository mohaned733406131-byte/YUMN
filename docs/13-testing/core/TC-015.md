# TC-015 — Publishing a product requires an Arabic name and complete catalog data

| Field | Value |
|---|---|
| Objective | Verify that `POST /store/products` enforces the publishable-product rule — Arabic name, YER price, category, ≥1 image, stock ≥ 0 and a store — and that publish fails when any element is missing. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- KYC-approved vendor `774440001` (store `STORE-A`) with `EDITOR` rights.
- Category `electronics` exists (depth 2); no product with slug `samsung-galaxy-a15` exists yet.
- Stock counters are clean for this store.

## Test Data

| Field | Value |
|---|---|
| Arabic name (valid) | `هاتف سامسونج جالكسي` |
| English name (optional) | `Samsung Galaxy A15` |
| Category slug | `electronics` |
| Price | `12500` YER |
| Stock | `20` |
| Missing-Arabic payload | same body with `nameAr` absent |

## Steps
1. `POST /store/products` with the full valid body (`nameAr`, `categorySlug`, `price:12500`, `stock:20`).
2. `POST /store/products` with the same body minus `nameAr`.
3. `POST /store/products` with `price:0`, then with `salePrice:13000` (≥ `price`).
4. `POST /store/products` with `nameAr` but no `categorySlug`.
5. `POST /store/products/{id}/publish` for the product created in step 2 (no image uploaded yet).
6. `GET /products/{slug}` as an anonymous visitor for the draft created in step 1.
7. `POST /store/products/PRD-A1/variants` with 6 dimensions (`color`, `storage`, `ram`, `sim`, `warranty`, `bundle`) and with 51 combinations.
8. `POST /store/products` with `sku: SKU-A1` while another product in `STORE-A` already uses that SKU.

## Expected Result
- Step 1 returns `201` with `status: "DRAFT"` — a draft may exist without an image, but it is not publicly visible.
- Step 2 returns `400 VALIDATION_ERROR` with `details[0].field = "nameAr"`; no row is created (`AC-FR004-01`).
- Step 3 returns `422 PRICE_INVALID` for both attempts (price ≤ 0; sale price not below original).
- Step 4 returns `400 VALIDATION_ERROR` with `details[0].field = "categorySlug"`.
- Step 5 returns `422 PRODUCT_NOT_PUBLISHABLE` listing the missing elements (Arabic name/image); the product stays `DRAFT` and never reaches `ACTIVE`.
- Step 6 returns `404 NOT_FOUND` — drafts are excluded from the public storefront (`BR-CAT-06`).
- Step 7 returns `422 VARIANT_LIMIT_EXCEEDED` for 6 dimensions and for >50 combinations — the saved variant set never exceeds `≤5 dimensions / ≤50 combinations` (`AC-FR004-02`).
- Step 8 returns `409 DUPLICATE_RESOURCE` (duplicate SKU within the store, `BR-CAT-02`); a SKU repeated in a *different* store is accepted.
- All rejection messages are localized (Ar default) and the store's product list shows no row for steps 2–4, 7–8 (`AC-FR004-05`: specific error, nothing persisted).
