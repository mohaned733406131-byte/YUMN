# TC-012 — Vendor A cannot read or mutate vendor B's product or sub-order

| Field | Value |
|---|---|
| Objective | Verify that `store_id` scoping at the service layer denies every cross-store read and write with `404 NOT_FOUND`, while identical calls on the caller's own store succeed. |
| Level | integration |
| Priority | P0 (merge-blocking, also runs under SEC-P-05) |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Vendor A (`774440001`, store `STORE-A`, product `PRD-A1`) and vendor B (`774440002`, store `STORE-B`, product `PRD-B1`) are KYC-approved.
- Vendor A's staff user holds an `EDITOR` role on `STORE-A` only.
- Sub-order `SUB-B1` of `STORE-B` exists in state `PLACED`.

## Test Data

| Field | Value |
|---|---|
| Attacker | Vendor A staff (`EDITOR` on `STORE-A`) |
| Foreign product | `PRD-B1` (store `STORE-B`) |
| Own product | `PRD-A1` (store `STORE-A`) |
| Foreign sub-order | `SUB-B1` |

## Steps
1. `GET /store/products/PRD-B1` with A's token.
2. `PUT /store/products/PRD-B1` with A's token and body `{"price":1,"nameAr":"هاتف مخفّض"}`.
3. `DELETE /store/products/PRD-B1` with A's token.
4. `POST /store/products/PRD-B1/publish` with A's token.
5. `GET /store/orders/SUB-B1` and `POST /store/orders/SUB-B1/confirm` with A's token.
6. `GET /store/products/PRD-A1` and `PATCH /store/inventory/SKU-A1` with A's token (positive control).
7. Query the database for `PRD-B1` fields and `SUB-B1.state` after the run.

## Expected Result
- Steps 1–5 each return `404 NOT_FOUND` — a foreign `store_id` row is indistinguishable from a non-existent one; no payload, price or customer name is disclosed.
- Step 2 does not change `PRD-B1`'s price; step 3 does not soft-delete it; step 5 does not move `SUB-B1` out of `PLACED`.
- Step 6 returns `200` — legitimate same-store access still works, proving the denial is scope-based, not a blanket failure.
- The database snapshot after step 7 matches the pre-test snapshot for all `STORE-B` rows (`version` unchanged).
- Every denied request is logged with correlation ID, but no cross-store data appears in the log.
- The same denial applies to `GET /store`, `GET /store/inventory`, `GET /store/reviews` when called with B's identifiers.
