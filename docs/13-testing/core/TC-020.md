# TC-020 — Concurrent checkout never oversells the last unit of a product

| Field | Value |
|---|---|
| Objective | Verify that N parallel checkouts against a product with 1 unit of stock result in exactly one winner and `409/422` for the rest, with invariants intact at the end. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (Promise.all over 8 requests) |

## Preconditions
- `SKU-LAST` has `stock: 1`, `reservedQuantity: 0`.
- 8 authenticated customers each hold 1 unit of `SKU-LAST` in their cart (carts pre-validated).
- DB constraint `stock >= 0` and `stock >= reservedQuantity` are active.

## Test Data

| Field | Value |
|---|---|
| SKU | `SKU-LAST` |
| Initial stock | `1` |
| Parallel actors | `8` customers, 1 unit each |
| Allowed outcome | exactly `1` success |

## Steps
1. Fire 8 concurrent `POST /checkout/session` + `POST /orders` flows for `SKU-LAST` with `Promise.all` and capture every status/body.
2. Tally successes and failures by status code and `errorCode`.
3. Read `GET /store/inventory/SKU-LAST` and count the `reserve` ledger rows.
4. Verify each successful order's `subOrders[0].state = PLACED` and reserved quantity matches.
5. Verify every failed request produced no order row, no ledger entry and no wallet debit.

## Expected Result
- Exactly 1 of 8 returns `201`; the other 7 fail with `409 STOCK_CONFLICT` (or `422 INSUFFICIENT_STOCK`) carrying `details.available = 0`.
- Final row: `stock: 0`, `reservedQuantity: 1`, `stock - reserved = 0` — no negative value, no double reservation (invariant `C-11` holds).
- Exactly one `RESERVE` ledger row exists for `SKU-LAST`; the DB count of reserve rows equals the number of winners.
- Each of the 7 losers leaves zero side effects: no `orders` row, no `ledger` row, no wallet hold (`BR-INV-01` atomicity).
- The winner's cart shows the item removed and the loser carts are untouched (they can retry with a different SKU).
- Retrying a loser after a reservation is released (TTL, TC-018) succeeds with `201`.
- No request returns `500` — contention surfaces as a typed conflict, never as an unhandled exception.
