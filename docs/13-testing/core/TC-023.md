# TC-023 — Vendor application creates one PENDING_KYC store and publishing stays blocked until approval

| Field | Value |
|---|---|
| Objective | Verify that `POST /vendor/application` creates exactly one store draft in `PENDING_KYC` with a 48-hour SLA, that KYC documents obey the upload limits, and that product publishing is denied while `kycStatus ≠ APPROVED`. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (KYC fixtures masked per MASK-03) |

## Preconditions
- Fresh verified account `774440010` with role `VENDOR` and no store yet (`GET /vendor/onboarding/status` → `step: "NONE"`).
- A KYC-**approved** vendor `774440001` exists as positive control.
- Upload scanner enabled; the platform's required `docType` set is configured.

## Test Data

| Field | Value |
|---|---|
| New vendor phone | `774440010` |
| Trade name | `متجر اليمن للتجارة` |
| Legal name | `مؤسسة اليمن للتجارة` |
| Category | `electronics` |
| Address | `governorate: SANA'A`, `district: Al-Sabeen`, `line1: شارع الزبيري 12` |
| Valid KYC document | `cr-moj.pdf`, 2.4 MB |
| Oversized document | `cr-huge.pdf`, 12 MB |
| Disallowed type | `id-scan.svg`, 90 KB |
| SLA | 48 hours (`BR-VND-03`) |

## Steps
1. `GET /vendor/onboarding/status` for `774440010`.
2. `POST /vendor/application` with the full valid body.
3. `POST /vendor/application` again (second store attempt).
4. `POST /vendor/kyc/documents` with `cr-moj.pdf` (`docType: "CR"`), then with `cr-huge.pdf`, then with `id-scan.svg`.
5. `GET /vendor/kyc` and `GET /vendor/onboarding/status` after the uploads.
6. As vendor `774440001`-style product draft exists for `774440010` — `POST /store/products` then `POST /store/products/{id}/publish` **before** any approval.
7. `GET /admin/kyc?status=PENDING` as `ADMIN` and inspect `slaDueAt`.
8. As `MODERATOR`, `POST /admin/kyc/{id}/approve` (Moderator tries to decide).

## Expected Result
- Step 1 returns `200 {"step":"NONE"}`.
- Step 2 returns `201 {"applicationId":"…","storeId":"…","status":"PENDING_KYC"}` — one store draft created (`BR-VND-02`).
- Step 3 returns `409 ONE_STORE_PER_VENDOR`; no second store row exists.
- Step 4: valid PDF → `201 {"documentId":"…","status":"UPLOADED"}`; 12 MB → `413 PAYLOAD_TOO_LARGE`; SVG → `415 UNSUPPORTED_MEDIA_TYPE`; a malware-flagged file → `422 FILE_SCAN_FAILED` (all per `SEC-REQ-011`, no SVG ever accepted).
- Step 5: `GET /vendor/kyc` returns `status: PENDING/IN_REVIEW`, `documents[]` with the uploaded set, `slaDueAt = submittedAt + 48h`; `onboarding/status.step = "PENDING_KYC"` with `resubmissionAllowed`.
- Step 6: `POST /store/products/{id}/publish` returns `403 KYC_NOT_APPROVED` (`BR-VND-01`) — the product never reaches `ACTIVE` (`AC-FR007-02`), while the identical call with an approved vendor succeeds.
- Step 7: the case appears in the admin queue with `slaDueAt` and `overdue: false`.
- Step 8 returns `403 FORBIDDEN` — Moderators read the queue but only `ADMIN` decides (`API-ADM-007/008`).
