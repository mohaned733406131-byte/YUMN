# TC-019 — Inventory mutations validate stock and reject writes below reservations

| Field | Value |
|---|---|
| Objective | Verify that `PATCH /store/inventory/{sku}` rejects negative or fractional stock with `422 INVALID_STOCK`, and refuses reductions that would fall below `reservedQuantity` with `409 STOCK_BELOW_RESERVATIONS`. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Vendor `774440001` owns `SKU-A1` with `stock: 10`, `reservedQuantity: 4` (live customer reservations).
- No other inventory writes are in flight for this SKU.

## Test Data

| Field | Value |
|---|---|
| SKU | `SKU-A1` |
| Current stock | `10` |
| Reserved | `4` (floor for valid stock) |
| Invalid value A | `-1` |
| Invalid value B | `2.5` |
| Too-low value | `3` (below reserved 4) |

## Steps
1. `PATCH /store/inventory/SKU-A1` with `{"stock":-1,"reason":"negative"}`.
2. `PATCH /store/inventory/SKU-A1` with `{"stock":2.5,"reason":"fraction"}`.
3. `PATCH /store/inventory/SKU-A1` with `{"stock":3,"reason":"flash sale"}` (below reservations).
4. `PATCH /store/inventory/SKU-A1` with `{"stock":4,"reason":"match reserved"}` (boundary).
5. `PATCH /store/inventory/SKU-A1` with `{"stock":25,"reason":"restock"}` (normal raise).
6. Read `GET /store/inventory/SKU-A1` and the stock ledger after all attempts.

## Expected Result
- Step 1 returns `422 INVALID_STOCK` with `details[0].field = "stock"` (`≥ 0` required).
- Step 2 returns `422 INVALID_STOCK` — stock must be an integer.
- Step 3 returns `409 STOCK_BELOW_RESERVATIONS` with `details: {requested:3, reserved:4}` — live reservations are protected (`BR-INV-03`).
- Step 4 returns `200` with `stock: 4` — the boundary (stock == reserved) is allowed.
- Step 5 returns `200` with `stock: 25`, `updatedAt` bumped, and a `RECEIPT`/`ADJUST` ledger row carrying actor (vendor user), `reason`, delta `+21`, timestamp (append-only, `BR-INV-05`).
- After steps 1–3 the DB row is unchanged (`stock` still `10`/`4` after rejections — no partial writes).
- The same patch on a foreign `SKU-B1` returns `404 NOT_FOUND` (tenant scope, see TC-012).
