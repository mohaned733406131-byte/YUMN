# TC-024 — KYC decisions: reject with reason, resubmit restarts the 48-hour SLA, approval unlocks publishing

| Field | Value |
|---|---|
| Objective | Verify the admin decision cycle — rejection requires a reason, resubmission restarts the 48-hour SLA, late decisions surface as `KYC_DECISION_LATE`, and approval immediately unlocks publishing with an audit trail. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (injectable clock for the 48-hour boundary) |

## Preconditions
- The `PENDING_KYC` case from TC-023 (vendor `774440010`, `submittedAt = T0`) is in the admin queue.
- `ADMIN` token available; `MODERATOR` token available for the deny check.
- Clock injection works for SLA arithmetic; audit log is queryable.

## Test Data

| Field | Value |
|---|---|
| Case | KYC submission from TC-023 |
| Rejection reason | `مستند صورة غير واضحة` |
| Resubmitted document | `cr-clear.pdf`, 1.8 MB |
| SLA window | 48 h from `submittedAt` |

## Steps
1. `POST /admin/kyc/{id}/reject` **without** `reason` as `ADMIN`.
2. `POST /admin/kyc/{id}/reject` with `{"reason":"مستند صورة غير واضحة"}`.
3. `GET /vendor/kyc` as the vendor — inspect `decision` and `resubmissionAllowed`.
4. While a decision is pending/in review: attempt `PUT /vendor/application` (double submission guard) on a *fresh* `IN_REVIEW` case.
5. `PUT /vendor/application` with corrected body after the rejection (resubmission) and capture `slaDueAt`.
6. Backdate `submittedAt` to 49 hours ago; read `GET /admin/kyc?status=PENDING` (overdue case) and then `POST /admin/kyc/{id}/approve`.
7. After an in-time approval (fresh case, within SLA): `POST /admin/kyc/{id}/approve`, then retry TC-023 step 6 (`POST /store/products/{id}/publish`).
8. Read `GET /admin/audit-log?action=KYC_*` for steps 2 and 7.

## Expected Result
- Step 1 returns `422 REASON_REQUIRED` — no decision recorded.
- Step 2 returns `200 {"status":"REJECTED","reason":"…","decidedAt":…,"auditId":"…"}`.
- Step 3 shows `decision.outcome = REJECTED` with reason and `decidedAt`; `resubmissionAllowed: true`.
- Step 4 returns `409 KYC_IN_REVIEW` — no parallel submission while under review (`BR-VND-03`).
- Step 5 returns `200 {"status":"PENDING_KYC","slaDueAt":"<resubmittedAt + 48h>"}` — the SLA **restarts** from resubmission, unlimited resubmissions allowed (`AC-FR007-04`).
- Step 6: the queue flags `overdue: true` after 48 h; the escalation alert exists; the late `approve` returns `409 KYC_DECISION_LATE` (`retryable: true`) because auto-escalation already moved the case (`BR-VND-03`).
- Step 7 (in-time approve): `200 {"status":"APPROVED","decidedAt":…,"by":"ADMIN","auditId":"…"}`; the subsequent publish returns `200` with `status: "ACTIVE"` — approval unlocks publishing (`BR-VND-01`), the mirror image of `AC-FR007-02`.
- Step 8: append-only audit rows exist for reject and approve with actor, reason, timestamp; no update/delete rows (`SEC-REQ-010`).
- A `MODERATOR` token on steps 2/7 returns `403 FORBIDDEN`.
