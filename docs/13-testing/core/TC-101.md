# TC-101 — Coupon creation enforces bounds, uniqueness, idempotency and immutability

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that admin and store coupon creation reject `discountPercent > 90` and validity windows `> 90` days with `COUPON_BOUNDS_EXCEEDED`, reject duplicate codes with `DUPLICATE_RESOURCE`, that store creation is idempotent, and that an issued coupon's `code` and `discountPercent` are immutable afterwards. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Tokens: `ADMIN`; `VENDOR` Owner `779876543` on `tech-store` with `Idempotency-Key` support; store not suspended. |
| 2 | No coupon with the codes under test exists (fresh codes `YUMN90`, `SNEAKY95`, `TECH10`). |

## Test Data

| Field | Value |
|---|---|
| valid admin coupon | `POST /admin/coupons {"code":"YUMN90","scope":"PLATFORM","discountPercent":90,"startsAt":"2026-09-26T00:00:00+03:00","endsAt":"2026-12-24T23:59:59+03:00"}` (90 days inclusive) |
| 91-day window | same but `endsAt: "2026-12-25T23:59:59+03:00"` → expect `422 COUPON_BOUNDS_EXCEEDED` |
| 95 % discount | `{"code":"SNEAKY95",…,"discountPercent":95,…}` → expect `422 COUPON_BOUNDS_EXCEEDED` |
| duplicate | second create with `code:"YUMN90"` → expect `409 DUPLICATE_RESOURCE` |
| store create | `POST /store/coupons {"code":"TECH10","discountPercent":10,…}` with `Idempotency-Key: idem-tech10` |
| immutability probes on `TECH10` | `PUT /store/coupons/{id} {"discountPercent":50}`, `{"code":"HIJACKED"}`, `{"endsAt":"2026-11-30T23:59:59+03:00"}` |

## Steps
1. As `ADMIN`, create `YUMN90`; then create the 91-day variant, the 95 % variant, and a duplicate `YUMN90`.
2. As `VENDOR`, create `TECH10` with `Idempotency-Key: idem-tech10`; repeat the same create with the same key and body; repeat with the same key but a different body; repeat without any key.
3. On the created `TECH10` coupon, `PUT` a changed `discountPercent`, then a changed `code`, then a valid `endsAt` edit.
4. As `VENDOR`, attempt `POST /admin/coupons`; as `CUSTOMER`, attempt the same.

## Expected Result
- Step 1 → `YUMN90` → `201 { …coupon, status: "ACTIVE" }` (90-day window, 90 % discount are the inclusive limits, `BR-PRM-01`); 91-day → `422 COUPON_BOUNDS_EXCEEDED`; 95 % → `422 COUPON_BOUNDS_EXCEEDED` (`API-CNT-016`, `AC-FR019-01`); duplicate → `409 DUPLICATE_RESOURCE` — code unique within scope (`error-model.md` 409).
- Step 2 → first create → `201 { scope: "STORE", storeId, status: "ACTIVE" }`; same key + same body → `201` replay of the original coupon (idempotent, no second row, `BR-PLT-03`); same key + different body → `409 IDEMPOTENCY_CONFLICT`; missing key → `400 IDEMPOTENCY_KEY_REQUIRED` (`API-CNT-019`).
- Step 3 → `discountPercent` and `code` changes → `400 VALIDATION_ERROR` (fields are not accepted by `API-CNT-020` — code and discount are immutable after issuance, `content.md` §2); `endsAt` edit → `200 { …coupon }` with the new schedule; re-read shows unchanged `code`/`discountPercent` (`BR-PRM-01`, `BR-PRM-04`).
- Step 4 → `403 FORBIDDEN` for both — coupon creation is `ADMIN` (platform) / `VENDOR` Owner (own store) scoped (`SEC-REQ-004`, `BR-PRM-03`).
