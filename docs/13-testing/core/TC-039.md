# TC-039 — Coupon math at checkout plus stacking, expiry, over-usage and under-minimum rejections

| Field | Value |
|---|---|
| Objective | Verify that a valid coupon discounts the server-computed totals exactly once, that a second coupon is refused with `COUPON_STACKING_NOT_ALLOWED`, and that expired / fully-used / under-minimum coupons are refused with `COUPON_INVALID` and never create an order row. |
| Level | integration |
| Priority | P2 |
| Automation | Yes — Jest + Supertest (coupon fixtures `482913`, `RAMADAN25`, `USEDUP25`, `MIN9000` from DOC-TST-005) |

## Preconditions
- Buyer `771234567` wallet funded with 100,000 YER; cart `V-1` totals 40,000 YER before discount.
- Coupons seeded: `482913` 10 % active with usage left; `RAMADAN25` expired; `USEDUP25` global usage exhausted; `MIN9000` with `min_order_amount 9000`; `EXTRA5` 5 % active.
- No order exists for this buyer before the run.

## Test Data

| Field | Value |
|---|---|
| Valid case | subtotal `40000`, discount `4000`, VAT `5400`, shipping `700`, total `42100` YER |
| Rejections | `RAMADAN25` (`EXPIRED`), `USEDUP25` (`USAGE_LIMIT_REACHED`), `MIN9000` on a 3,200 YER cart (`MIN_NOT_MET`) |
| Stacking | `482913` already applied, then `EXTRA5` |

## Steps
1. `POST /coupons/validate` body `{"code":"482913","cartSnapshot":"V-1"}`.
2. `POST /checkout/session` with `Idempotency-Key: chk-039-01`, body `{"addressId":"adr-771","shippingMethod":"STANDARD","paymentMethod":"wallet","couponCode":"482913"}` → record `totals`.
3. While coupon `482913` is active on the cart, `POST /coupons/validate` with `{"code":"EXTRA5"}`; then start a session that carries `EXTRA5`.
4. `POST /coupons/validate` for `RAMADAN25`, `USEDUP25`; load a 3,200 YER cart and validate `MIN9000`.
5. For each rejected coupon run `POST /checkout/session` with that `couponCode` and `Idempotency-Key` `chk-039-<code>`.
6. `POST /orders` with `Idempotency-Key: ord-039-01` for the valid session; count `orders` rows for the rejected attempts.

## Expected Result
- Step 1 → `200 {"valid":true,"code":"482913","discountAmount":4000}` (half-up per store, `API-CNT-004`).
- Step 2 → `201` with `{"subtotal":40000,"discount":4000,"vat":5400,"shippingFee":700,"grandTotal":42100}` — VAT computed on `40000 − 4000` (`BR-FIN-01`).
- Step 3 → `422 COUPON_STACKING_NOT_ALLOWED` for both calls — exactly one coupon per order (`BR-PRM-02`); no discount from `EXTRA5` ever appears.
- Step 4 → `422 COUPON_INVALID` with `details[].issue` = `EXPIRED`, `USAGE_LIMIT_REACHED`, `MIN_NOT_MET` respectively (`BR-PRM-04`).
- Step 5 → each session creation fails with `422 COUPON_INVALID`; **0** order rows, **0** ledger rows, no discount applied (`BR-PRM-06`).
- Step 6 → `201` with the discounted total `42100`; the coupon's redemption count increments by exactly 1; wallet debited `42100` once.
- Every rejection carries `messageKey errors.<CODE>`, localized `message` and `correlationId`.
