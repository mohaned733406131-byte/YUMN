# TC-075 — Return request rejections: elapsed window, non-returnable, wrong state, open dispute, duplicate

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that every ineligible return request is refused with its distinct error code — `WINDOW_EXPIRED`, `NOT_RETURNABLE`, `STATE_CONFLICT`, `DISPUTE_ALREADY_OPEN` — and that no return row is ever created for a rejected request. | integration | P0 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `ORD-LATE1` / `SUB-LATE1` delivered `2026-09-19T14:30:00+03:00`, `returnPeriodDays: 7` (deadline `2026-09-26T14:30:00+03:00`); clock will run at `2026-09-27T14:31:00+03:00` (day 8). |
| 2 | `ORD-NORET` / `SUB-NORET` delivered `2026-09-25T10:00:00+03:00` but product `isReturnable: false`. |
| 3 | `ORD-PLC1` is `PLACED` (never delivered); `ORD-DSP1` / `SUB-DSP1` (its only sub-order) has an open dispute (`DISPUTED`); `ORD-DUP1` / `SUB-DUP1` (its only sub-order) already has open return `RET-8851` (`RETURN_REQUESTED`). |
| 4 | Buyer `771234567` owns all seeds; baseline `GET /returns?limit=50` item count captured before the run. |

## Test Data

| Field | Value |
|---|---|
| request body (all probes) | `{"items":[{"orderItemId":"…","quantity":1,"reasonCode":"CHANGED_MIND"}],"reasonCode":"CHANGED_MIND"}` |
| expected codes | `WINDOW_EXPIRED` (422), `NOT_RETURNABLE` (422), `STATE_CONFLICT` (409), `DISPUTE_ALREADY_OPEN` (409) |
| duplicate case | `ORD-DUP1` with existing `RET-8851` |

## Steps
1. Clock `2026-09-27T14:31:00+03:00`; `POST /orders/ORD-LATE1/returns` with the standard body.
2. `POST /orders/ORD-NORET/returns` with the standard body.
3. `POST /orders/ORD-PLC1/returns` with the standard body.
4. `POST /orders/ORD-DSP1/returns` with the standard body (its only sub-order is `SUB-DSP1`).
5. `POST /orders/ORD-DUP1/returns` with the standard body (its only sub-order already holds `RET-8851`).
6. `GET /returns?limit=50` — recount; `GET /store/returns` as vendor; clock back to `2026-09-26T12:00:00+03:00` and repeat step 1 against `ORD-LATE1` (control).

## Expected Result
- Step 1 → `422 WINDOW_EXPIRED` — the window elapsed at day 8 (`BR-RET-01`, `C-11`, `AC-FR016-01`).
- Step 2 → `422 NOT_RETURNABLE` — distinct from the elapsed-window rejection; policy flag blocks it even inside the date range (`BR-RET-01`, `returns.md` §2).
- Step 3 → `409 STATE_CONFLICT` — a return may only open from `DELIVERED`/`COMPLETED` (`C-09`, `BR-ORD-01`).
- Step 4 → `409 DISPUTE_ALREADY_OPEN` — a sub-order in an open dispute cannot also enter the return flow (`API-RET-001`, `BR-ORD-05`).
- Step 5 → `409 STATE_CONFLICT` — the sub-order is already `RETURN_REQUESTED`; the state machine never re-enters it (`C-09`, `BR-RET-02`).
- Step 6 → total count unchanged and the vendor queue shows no new item — a rejected request persists nothing; the control request (inside the window, no dispute) still returns `201`, proving the rejections are caused by their own conditions and not by the harness.
