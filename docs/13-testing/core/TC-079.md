# TC-079 — Uninspected return auto-approves after 72 hours and a late inspection is refused

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that a `RETURN_RECEIVED` return with no vendor inspection after 72 hours is transitioned by `SYSTEM` to `REFUNDED` with `inspection.autoApproved: true`, that a vendor inspection arriving after the window is refused with `422 INSPECTION_WINDOW_PASSED`, and that both parties are notified of the automatic decision. | integration | P0 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `RET-8850` (order `ORD-7F3A26`, `SUB-9C1110`) is `RETURN_RECEIVED` since `2026-09-23T09:30:00+03:00` ⇒ inspection deadline `2026-09-26T09:30:00+03:00`; no inspection recorded; controllable clock starts at `2026-09-26T09:00:00+03:00` (T+71.5 h). |
| 2 | Scheduler (BullMQ `SYSTEM` jobs) is running and observable in tests; tokens: vendor `779876543`, buyer `771234567`. |
| 3 | Wallet/escrow seeded for `SUB-9C1110` with `frozenBy: "NONE"`; notification outboxes empty for this return. |

## Test Data

| Field | Value |
|---|---|
| return | `RET-8850`, receivedAt `2026-09-23T09:30:00+03:00`, deadline `2026-09-26T09:30:00+03:00` |
| clock probes | `2026-09-26T09:29:00+03:00` (before), `2026-09-26T09:31:00+03:00` (after) |
| late inspection | `POST /store/returns/RET-8850/inspection {"outcome":"PASS","notes":"late look"}` |

## Steps
1. Clock `2026-09-26T09:29:00+03:00`; `GET /returns/RET-8850` (vendor view `GET /store/returns/RET-8850`).
2. Advance the clock to `2026-09-26T09:31:00+03:00` and run the scheduler tick; `GET /returns/RET-8850` again.
3. As vendor, `POST /store/returns/RET-8850/inspection {"outcome":"PASS","notes":"late look"}`.
4. `GET /returns/RET-8850` → timeline; `GET /orders/ORD-7F3A26/refund` as buyer; read notification outbox for buyer and vendor.

## Expected Result
- Step 1 → `200 { state: "RETURN_RECEIVED", inspection: absent }` — still inside the window (`BR-RET-05`).
- Step 2 → `200 { state: "REFUNDED", inspection: { autoApproved: true, at: "2026-09-26T09:30:00+03:00", by: "SYSTEM" }, refund: { status: "PENDING", expectedCreditBy } }` — the 72-hour SLA expiry auto-approves (`BR-RET-05`, `AC-FR016-03`, `C-09`); the sub-order is `REFUNDED` (`BR-RET-02`).
- Step 3 → `422 INSPECTION_WINDOW_PASSED` — a late vendor inspection cannot override the automatic approval (`API-RET-009`, `returns.md` §2).
- Step 4 → timeline contains the SYSTEM auto-approval entry, append-only (`BR-ORD-03`); refund status `PENDING` with `expectedCreditBy` (credit ≤3 business days, `BR-RET-04`); buyer and vendor each receive one notification of the automatic decision in their locale (`BR-NTF-04`) — the case is never left pending.
