# TC-089 — In-app inbox pagination, read-state idempotency, owner scoping and device tokens

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify the notification center contract: cursor pagination (default 20), unread counts, idempotent mark-read/read-all, delete that never unsends channel deliveries, strict owner scoping (foreign items ⇒ 404), and device-token management (register/detach/list/cap/invalid token). | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Buyer `771234567` has **25** unread in-app notifications (mixed `ORDER`/`DELIVERY`/`PROMOTION`); customer `771234568` has 3 of their own. |
| 2 | Buyer has one registered device `pushtest-buyer-1` (`ANDROID`, `deviceName: "Galaxy A54"`); session/device cap = 5 (`BR-AUTH-06`). |
| 3 | SMS/WhatsApp delivery logs for at least one of the buyer's notifications contain `SENT` rows (needed for the delete-does-not-unsend check). |

## Test Data

| Field | Value |
|---|---|
| inbox | 25 unread items for `771234567`, 3 for `771234568` |
| pagination | `GET /notifications?limit=20` → page 1 (20) + cursor → page 2 (5) |
| new device | `POST /devices {"token":"pushtest-buyer-2","platform":"ANDROID","deviceName":"Redmi Note 12"}` |
| invalid token | `{"token":"","platform":"ANDROID"}` → expect `422 DEVICE_TOKEN_INVALID` |

## Steps
1. `GET /notifications?limit=20` then follow `page.next` cursor; `GET /notifications/unread-count`; `GET /notifications?unreadOnly=true&limit=20`.
2. `POST /notifications/{idA}/read` twice; re-read unread-count; `POST /notifications/read-all?category=ORDER` → re-read counts.
3. As `771234568`, `POST /notifications/{idA}/read` and `DELETE /notifications/{idA}`; as owner, `DELETE /notifications/{idA}` → re-read inbox and the SMS delivery log for that notification.
4. `POST /devices` with the new token; `GET /devices`; register `pushtest-buyer-2` again as user `771234568`; `POST /devices` with the empty token; `DELETE /devices/pushtest-buyer-2` twice; as `771234568`, `DELETE /devices/pushtest-buyer-1`.

## Expected Result
- Step 1 → page 1 returns 20 items with a cursor, page 2 returns 5 (cursor pagination, default 20 max 50, `API-NTF-001`, `pagination.md` §1); `200 { total: 25, byCategory: {…} }`; `unreadOnly=true` returns only items without `readAt`.
- Step 2 → first mark-read `200 { id, readAt }`, second call idempotent with the same `readAt` (`API-NTF-003`); unread total drops by exactly 1; `read-all?category=ORDER` returns `{ marked: n }` counting only `ORDER` items and the `DELIVERY`/`PROMOTION` counts stay unchanged (`API-NTF-004`).
- Step 3 → foreign read and delete both `404 NOT_FOUND` — the inbox is owner-scoped (`DATA-REQ-008`, `BR-ORD-09`-style scoping); owner delete → `204`, the item disappears from `GET /notifications` and unread-count decrements, but the SMS/WhatsApp `SENT` delivery rows remain logged — deleting never unsends (`API-NTF-005`, `notifications.md` §3).
- Step 4 → new device `201 { deviceId, token, registeredAt }`; `GET /devices` lists ≤5 entries with `registeredAt`/`lastPushAt`; re-registering the same token as another user succeeds and the token detaches from `771234567`'s list (single active owner per token, `API-NTF-008`); empty token → `422 DEVICE_TOKEN_INVALID`; own `DELETE` → `204` twice (idempotent), foreign token → `404` (`API-NTF-009`, `DEVICE_NOT_FOUND`/`NOT_FOUND`).
