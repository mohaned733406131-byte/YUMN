# TC-002 — Correct OTP verification activates the account and issues a session

| Field | Value |
|---|---|
| Objective | Verify that `POST /auth/otp/verify` with the correct code within 5 minutes marks the phone VERIFIED, activates the account and issues the 15-minute access / 7-day refresh token pair. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Registration for `771234567` was completed (TC-001) and the account is `UNVERIFIED` with a live OTP.
- The same endpoint also serves `context=LOGIN` and `context=PASSWORD_RESET`; only `REGISTER` is exercised here.
- Redis OTP keys exist with `attempts = 3` remaining.

## Test Data

| Field | Value |
|---|---|
| Phone | `771234567` |
| Correct code | `481902` |
| Context | `REGISTER` |
| Access token lifetime | 900 seconds |

## Steps
1. `POST /auth/otp/verify` with `{"phone":"771234567","code":"481902","context":"REGISTER"}`.
2. Capture `accessToken`, `refreshToken`, `expiresIn`, `sessionId` from the response.
3. Call `GET /users/me` with `Authorization: Bearer <accessToken>`.
4. Call `POST /auth/otp/verify` again with the same code `481902`.
5. Decode the JWT header/payload of `accessToken` without verifying the signature and inspect `exp`, `sid`, `roles`.
6. Call `POST /auth/otp/verify` with `{"phone":"771234567","code":"481902","context":"REGISTER"}` after backdating the stored OTP expiry to 6 minutes ago.

## Expected Result
- Step 1 returns `200` with `{"verified":true,"accessToken":"…","refreshToken":"…","expiresIn":900,"sessionId":"sess_…"}`.
- Step 3 returns `200` and `users/me` reports `phoneVerified: true`, `status: ACTIVE`, role `CUSTOMER`.
- The OTP Redis key is deleted after success — step 4 returns `422 OTP_VERIFICATION_FAILED` (code already consumed), not a second session.
- Step 5 shows `exp − iat = 900`, a `sid` claim, and exactly the roles granted at registration — no `ADMIN` claim.
- Step 6 returns `422 OTP_EXPIRED` with `retryable` set to allow a resend; the account stays unverified only if no earlier success occurred.
- Refresh token lifetime is 7 days and it is single-use (asserted in TC-006).
