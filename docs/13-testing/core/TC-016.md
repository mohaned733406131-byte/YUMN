# TC-016 — Image upload security limits and the publish/unpublish lifecycle

| Field | Value |
|---|---|
| Objective | Verify that `POST /store/products/{id}/images` enforces type/size/count rules with EXIF stripping, and that publish → unpublish moves the product through `ACTIVE`/`INACTIVE` correctly. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- KYC-approved vendor `774440001` owns a complete draft product `PRD-A1` (Arabic name, price, category, stock) with zero images.
- Malware scanner is enabled in the staging environment.
- Public product feed `GET /products` is queryable anonymously.

## Test Data

| Field | Value |
|---|---|
| Valid JPEG | `phone-front.jpg`, 1.2 MB, with EXIF GPS tag |
| Oversized JPEG | `phone-huge.jpg`, 12 MB |
| Disallowed type | `logo.svg`, 40 KB |
| 11th image | `extra-11.jpg`, 0.9 MB |
| Image cap | 10 per product (`BR-CAT-08`) |

## Steps
1. Upload `phone-front.jpg` via `POST /store/products/PRD-A1/images` (`multipart file`, `position:1`).
2. Upload `phone-huge.jpg`.
3. Upload `logo.svg`.
4. Upload 9 more valid images (total 10), then attempt the 11th.
5. Download the stored image from step 1 and inspect its EXIF/metadata.
6. `POST /store/products/PRD-A1/publish`, then `GET /products/PRD-A1-slug` anonymously.
7. `POST /store/products/PRD-A1/unpublish`, then repeat the anonymous read.
8. `DELETE /store/products/PRD-A1` (soft delete), then re-run the anonymous storefront read and `GET /search/products?q=…` for the same product.

## Expected Result
- Step 1 returns `201 {"imageId":"img_…","url":"…","position":1}` and the response URL is publicly fetchable.
- Step 2 returns `413 PAYLOAD_TOO_LARGE`; step 3 returns `415 UNSUPPORTED_MEDIA_TYPE` (SVG is never executed or served inline).
- Step 4: images 2–10 return `201`; the 11th returns `422 IMAGE_LIMIT_EXCEEDED` with the cap in `details`.
- Step 5: the stored JPEG has **no** EXIF block (stripped on upload) and passed the malware scan; a scan-rejected file returns `422 FILE_SCAN_FAILED`.
- Step 6: publish returns `200` with `status:"ACTIVE"`; the anonymous read returns `200` with all 10 image URLs.
- Step 7: unpublish returns `200` with `status:"INACTIVE"`; the anonymous read then returns `404 NOT_FOUND`, while `GET /store/products` still lists it for the vendor.
- Step 8: soft delete returns `204` (row kept for history — never a physical delete); the storefront read returns `404 NOT_FOUND` and `GET /search/products` never returns the product — even for a query that matched it minutes earlier (`AC-FR004-04`, `BR-CAT-06`).
- Deleting the last image of an `ACTIVE` product is refused (`400 VALIDATION_ERROR`, minimum 1 image).
