# TC-047 — Invalid transitions (PLACED → DELIVERED and other forbidden moves) return 409 STATE_CONFLICT

| Field | Value |
|---|---|
| Objective | Verify that any transition outside the canonical 17-state table — including the flagship `PLACED → DELIVERED`, backward moves from `DELIVERED`, and stale-version writes — is refused with `409 STATE_CONFLICT` while the order state, `version` and history remain byte-identical. |
| Level | integration |
| Priority | P0 |
| Automation | Yes — Jest + Supertest (forbidden-move matrix over `DOC-SA-010` §2) |

## Preconditions
- Orders in `PLACED` (`ORD-047-P`) and `DELIVERED` (`ORD-047-D`) exist with known `version` and history checksums.
- Admin `775550010`, vendor `779876543` and buyer `771234567` hold valid tokens; delivery code for `ORD-047-D` already verified.

## Test Data

| Field | Value |
|---|---|
| Forbidden moves | `PLACED→DELIVERED`, `PLACED→COMPLETED`, `DELIVERED→PROCESSING`, `CANCELLED→CONFIRMED`, `REFUNDED→PLACED` |
| Stale version | `expectedVersion = version − 1` on a legal move |
| Endpoints | `POST /admin/orders/{id}/transition`, `POST /store/orders/{id}/ready` |

## Steps
1. Snapshot `ORD-047-P`: `state`, `version`, history row count + checksum; repeat for `ORD-047-D`.
2. Admin `POST /admin/orders/{ORD-047-P}/transition` `{"subOrderId":"SUB-047P","toState":"DELIVERED","reason":"force deliver"}`.
3. Vendor `POST /store/orders/{ORD-047-P}/ready` (skip `CONFIRMED`/`PROCESSING`) with `{"weightKg":1}`.
4. Exercise the remaining forbidden moves from the matrix (admin transition endpoint) against `ORD-047-P` and `ORD-047-D`.
5. Perform a **legal** move (`PLACED→CONFIRMED`) while sending a stale `version`.
6. Re-read both orders and their timelines; check escrow, ledger and delivery notifications.

## Expected Result
- Step 2 → `409` `error.code = STATE_CONFLICT`, `retryable:false`, with `messageKey errors.STATE_CONFLICT` (`AC-FR012-02`).
- Step 3 → `409 STATE_CONFLICT` — a vendor endpoint can never skip states (`BR-ORD-01`, `DOC-SA-010` §2).
- Step 4 → `409 STATE_CONFLICT` for every entry in the matrix, including returns from `DELIVERED` to pre-delivery states and any revival of `REFUNDED`.
- Step 5 → `409 STATE_CONFLICT` — optimistic lock on `version` failed; no partial write.
- Step 6 → both orders show identical `state`, `version`, history count and checksum as in step 1; **0** new ledger rows, escrow positions unchanged, no delivery-code or completion notification emitted (history is unchanged, `AC-FR012-02`).
- Rejections carry `correlationId`; `409` guidance tells clients to refetch (`error-model.md` §3).
- The move matrix feeds `TST-CON-09` (17/17 states, ≥1 test per table row).
