# TC-060 — Commission tier change applies to the next escrow release only

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that the commission rate is set only by Super Admin through the settings API with optimistic locking and the 5–20% band, that vendors cannot write it, and that the rate in force at release time (not at order time) is applied. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `SUPER_ADMIN` (`770000002`), plain `ADMIN` (`770000001`) and vendor `779876543` tokens are available; store `tech-store` has `commission.source = "PLATFORM_DEFAULT"` (inherits the platform default). |
| 2 | Escrow `SUB-9C1104` is `RELEASED` from TC-058 with `commission_amount_yer = 1250` (10% of 12,500) — the retroactivity control. |
| 3 | A fresh sub-order with the same totals (subtotal 12,500, total 14,875 YER) sits `OUT_FOR_DELIVERY`, ready for TC-057-style delivery and release. |

## Test Data

| Field | Value |
|---|---|
| setting key | `commission.defaultRate` (group `COMMISSION`) |
| before | value `10`, `version = 3` |
| after | value `20`, `version = 4` |
| out-of-band values | `25` (above 20), `4` (below 5) |
| release fixture | base 12,500 YER, total 14,875 YER, tier 20% → commission **2,500 YER** |
| payable after release | 14,875 − 2,500 = **12,375 YER** |

## Steps
1. `GET /admin/settings?group=COMMISSION` with the `SUPER_ADMIN` token → record `commission.defaultRate`, `value = 10`, `version = 3`.
2. `PUT /admin/settings/commission.defaultRate` with the plain `ADMIN` token, body `{"value":20,"expectedVersion":3}`.
3. `SUPER_ADMIN` `PUT` with body `{"value":25,"expectedVersion":3}`, then with `{"value":4,"expectedVersion":3}`.
4. `SUPER_ADMIN` `PUT` with a stale version, body `{"value":20,"expectedVersion":1}`.
5. `SUPER_ADMIN` `PUT` with body `{"value":20,"expectedVersion":3}`.
6. Read `GET /admin/stores/st-tech-01`, vendor `GET /store`, vendor `GET /store/finance/overview`.
7. Vendor `PUT /store` with body `{"nameAr":"tech-store","commission":{"tierPercent":5}}`.
8. Deliver the fresh sub-order with code `482913`, advance the clock 7 days, run `b07.escrow.release`; then `GET /wallet/escrow?orderId=ORD-7F3A21`.
9. `GET /admin/audit-log?action=settings.update&targetId=commission.defaultRate`, then revert with `{"value":10,"expectedVersion":4}`.

## Expected Result
- Step 2 → `403 FORBIDDEN`; the value stays `10` — only `SUPER_ADMIN` writes settings (`API-ADM-023`, `SEC-REQ-004`).
- Step 3 → both calls `400 VALIDATION_ERROR` with `details[]` naming the 5–20 band (`BR-ESC-03`); `value` still `10`, `version` still `3`.
- Step 4 → `409 SETTINGS_VERSION_CONFLICT` (`retryable: true`); nothing written — no lost update.
- Step 5 → `200 { key, value: 20, version: 4, auditId }`; the audit row records actor, before `10` / after `20`, IP and timestamp (`BR-PLT-06`, `AC-FR020-01`).
- Step 6 → `tierPercent = 20` on `GET /admin/stores/st-tech-01` and on vendor `GET /store` (still `min: 5, max: 20`); `commissionRatePercent = 20` and `payoutThreshold: 1000` in the finance overview.
- Step 7 → `200` but the commission block is unchanged at `20` — the tier is never vendor-writable (`stores.md`, `BR-ESC-03`).
- Step 8 → escrow `RELEASED`, `commission_rate_bps = 2000`, `commission_base_yer = 12500`, `commission_amount_yer = 2500`, payable credit 12,375 YER; the TC-058 escrow keeps `commission_amount_yer = 1250` (commission is booked once, at release — no retroactive restatement).
- Step 9 → both settings writes appear in the audit log; after the revert a subsequent release again books 10%.
- Ledger stays balanced end to end: `SUM(amount_yer) = 0` (`BR-PAY-06`).
