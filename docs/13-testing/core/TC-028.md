# TC-028 — Filter/sort results stay consistent with facet counts, and search degradation falls back to category browse

| Field | Value |
|---|---|
| Objective | Verify that a filter+sort combination returns deterministic ordering with facet counts equal to returned totals (`AC-FR009-04`), and that Elasticsearch outage degrades gracefully to `meta.degraded` or `503 SEARCH_UNAVAILABLE` with working category browse (`AC-FR009-03`). |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (fault injection against the ES dependency) |

## Preconditions
- Index holds ≥ 60 products in `electronics` across 3 price bands and 2 stores, with ratings 3–5.
- The ES connection can be cut per test (network partition / process stop) and restored.
- `GET /categories/electronics` (API-CAT-002) works from DB/cache without ES.

## Test Data

| Field | Value |
|---|---|
| Filters | `category=electronics`, `priceMin=10000`, `priceMax=90000`, `inStock=true` |
| Sort | `price_asc` (run once, then repeat) |
| Cache cold/warm | Redis aggregations flushed before the first run |
| ES states | healthy → degraded (cache replay) → down (no cache) |

## Steps
1. `GET /search/products?q=هاتف&category=electronics&priceMin=10000&priceMax=90000&inStock=true&sort=price_asc&limit=24`.
2. Immediately repeat step 1 (warm cache) and compare item order and ids.
3. `GET /search/facets` with the identical query/filters and compare each facet bucket count with the full unpaginated result set of step 1 (walk cursors).
4. `GET /search/products` with `sort=bogus` and with `ratingMin=6` (`FACET_INVALID` probe).
5. Cut the ES connection with the Redis aggregation cache **warm**; repeat step 1.
6. Cut ES and flush the cache; repeat step 1; then `GET /search/suggest`.
7. While ES is down: `GET /categories/electronics?limit=24` as a guest.
8. Restore ES and repeat step 1.

## Expected Result
- Step 1: `200` with items sorted ascending by price; every item satisfies all four filters; `meta.degraded: false`.
- Step 2: identical ordering and identical ids across runs — deterministic ordering for the same filter+sort (`AC-FR009-04`).
- Step 3: for every facet bucket, `count` equals the number of matching items returned by walking the cursor — facet totals and result totals agree in the same filter context (`API-SRC-002`).
- Step 4: invalid sort → `400 VALIDATION_ERROR`; invalid facet value → `422 FACET_INVALID` (no silent widening of the filter — a dropped filter would leak data).
- Step 5: request succeeds from cached aggregation with `meta.degraded: true` (`NFR-007` fallback).
- Step 6: with no cache the search and suggest endpoints return `503 SEARCH_UNAVAILABLE` with a `correlationId` and no stack trace; status is never `200` with fabricated results.
- Step 7: category browse returns `200` with correct products from DB/cache — browsing never depends on ES (`AC-FR009-03`).
- Step 8: after restore, search returns `200`, `meta.degraded: false` — automatic recovery, no manual index rebuild required.
