# TC-053 — Admin force-cancel at PROCESSING writes an append-only audit entry; Moderator is refused

| Field | Value |
|---|---|
| Objective | Verify that an `ADMIN` forcing `PROCESSING → CANCELLED` through the canonical transition endpoint succeeds with an immutable audit entry (actor, reason, `ipHash`, `correlationId`), that a `MODERATOR` is refused, and that the master is re-evaluated with the refund path started. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (audit assertions via `GET /admin/audit-log`) |

## Preconditions
- Order `ORD-053` (single vendor, total 14,875 YER) is `PROCESSING`; admin `775550010`, moderator `775550020` hold valid tokens.
- Audit log is cursor-paginated and writable by no API route (`API-ADM-024`).

## Test Data

| Field | Value |
|---|---|
| Force body | `{"subOrderId":"SUB-053A","toState":"CANCELLED","reason":"تحقيق في احتيال البائع"}` |
| Invalid variants | missing `reason`; `toState:"ARCHIVED"`; caller = Moderator |
| Balance | before refund `35125` → after `50000` YER |

## Steps
1. Admin `POST /admin/orders/{id}/transition` with the force body above → record `version`, `historyEntry`, `auditId`.
2. `GET /admin/audit-log?targetId={orderId}&action=ORDER_TRANSITION` and `GET /orders/{id}/timeline`.
3. Admin repeats the same call with the identical body (idempotence probe); then sends the three invalid variants.
4. Moderator `POST /admin/orders/{id}/transition` with a valid body.
5. `PATCH /admin/audit-log/{auditId}` and `DELETE /admin/audit-log/{auditId}`.
6. Run the refund job; read `GET /orders/{id}`, `GET /orders/{id}/refund` and the wallet.

## Expected Result
- Step 1 → `200 {subOrderId, state:"CANCELLED", version, historyEntry, auditId}` — the move exists in the canonical table (`C-09`) and the master is re-evaluated (`BR-ORD-07`).
- Step 2 → exactly one audit entry `{actorId, actorRole:"ADMIN", action, targetType, targetId, reason, ipHash, correlationId}` appended; timeline gains `PROCESSING→CANCELLED` with `actorRole ADMIN` and the reason (`BR-ORD-03`, `SEC-REQ-010`).
- Step 3 → identical repeat returns the original outcome without a second history row (`BR-PAY-08`-style idempotence for money-adjacent actions); missing reason → `422 REASON_REQUIRED`; `toState:"ARCHIVED"` → `409 STATE_CONFLICT` (invented state refused); a non-canonical move never creates an audit success entry.
- Step 4 → `403 FORBIDDEN` — Moderator is read-only on this endpoint (`API-ORD-014`).
- Step 5 → `405 AUDIT_LOG_IMMUTABLE` for both verbs; the entry is unchanged (`DATA-REQ-007`).
- Step 6 → refund `PENDING → CREDITED`, wallet `50000`, one refund credit pair, `SUM(ledger) = 0`; master settles as `CANCELLED` for the single sub-order.
