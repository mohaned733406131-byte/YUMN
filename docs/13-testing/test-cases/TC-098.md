# TC-098 — Banners honour targeting, schedule windows and the home surface

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that banners created with `visibleTo` role lists and optional `startsAt`/`endsAt` windows are filtered correctly in `GET /home` for each surface, that editing the schedule changes visibility atomically, and that delete is idempotent and removes the banner from home. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Tokens: `ADMIN`, `CUSTOMER` (`771234567`), guest (no token); images pre-uploaded via the shared upload endpoint (valid `imageUrl`s). |
| 2 | No existing banner matches the seeded labels (clean probe set). |
| 3 | `GET /home` is cacheable (`Cache-Control: max-age=60, stale-while-revalidate=300`) — responses read after each mutation reflect the mutation (cache bypassed with `Cache-Control: no-cache` for assertions). |

## Test Data

| Field | Value |
|---|---|
| create | `POST /admin/banners {"label":"Eid Mega Sale","imageUrl":"https://cdn.yumn.ye/banners/eid.jpg","surface":"CUSTOMER","visibleTo":["CUSTOMER"],"startsAt":"2026-09-26T00:00:00+03:00","endsAt":"2026-09-28T23:59:59+03:00"}` |
| future banner | same body, `label:"Winter Sale"`, `startsAt:"2026-12-01T00:00:00+03:00"` |
| vendor-only banner | `visibleTo:["VENDOR"]`, window open now |
| schedule edit | `PUT /admin/banners/{id} {"endsAt":"2026-09-26T23:59:59+03:00"}` |

## Steps
1. As `ADMIN`, create the three banners; capture their ids and `active` flags.
2. As guest, `GET /home?surface=GUEST`; as `CUSTOMER`, `GET /home?surface=CUSTOMER`; grep each response for the three labels.
3. As `ADMIN`, `PUT /admin/banners/{eid-id}` moving `endsAt` to the end of 2026-09-26; re-request both home surfaces after the edited window has closed (clock advanced past `endsAt` in test control).
4. As `ADMIN`, `DELETE /admin/banners/{eid-id}` twice; re-request home; `GET /admin/banners?active=true`.

## Expected Result
- Step 1 → three `201 { …banner, active }` responses (`API-CNT-012`); past/absent schedule fields leave `active` as computed from the window.
- Step 2 → `CUSTOMER` surface contains `Eid Mega Sale` (in window, role targeted) and `Winter Sale` is absent (window not started — `AC-FR019-04` scheduling windows); `VENDOR`-targeted banner is absent for both guest and customer (`visibleTo` gate, `API-CNT-011`); the guest `surface=GUEST` response never contains `visibleTo:["CUSTOMER"]` banners (`API-CNT-002` role-aware hydration); no `VALIDATION_ERROR` for well-formed bodies.
- Step 3 → after `endsAt` passes, `Eid Mega Sale` disappears from `GET /home` for every surface — the schedule is authoritative and edits take effect without re-publishing (`API-CNT-013`, `AC-FR019-04`); `PUT` → `200 { …banner }`.
- Step 4 → first `DELETE` → `204`, second `DELETE` → `204` (idempotent, `API-CNT-014`, `SEC-REQ-010`); banner absent from home and from `GET /admin/banners?active=true`; each successful `PUT`/`DELETE` leaves an audit entry (`AC-FR020-01`); invalid body (`surface:"DESKTOP"`) → `400 VALIDATION_ERROR`, oversize image at upload step → `413 PAYLOAD_TOO_LARGE` (`API-CNT-012`, `SEC-REQ-011`).
