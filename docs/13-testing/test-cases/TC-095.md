# TC-095 — Admin report families and daily reconciliation expose mismatches to admins only

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that admin reports cover the seven documented families with annotated totals that reconcile to the ledger, that `GET /admin/reconciliation` surfaces MATCHED/MISMATCH rows for the previous day (available the next morning), and that reconciliation and heavy reports are `ADMIN`-only — moderators and vendors are refused. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Admin report seeds for `2026-09-01…2026-09-30`: `gmv` rows summing to **451,250 YER** after the nightly job (`relation: "exact"`); `groupBy=day` supported on `gmv`. |
| 2 | Reconciliation for `date=2026-09-25` (previous day) exists at run time `2026-09-26T01:30:00+03:00`: one `INTERNAL` row `MATCHED` (`deltaYER: 0`) and one `BANK` row `MISMATCH` (`ledgerTotal: 500000`, `providerTotal: 498750`, `|deltaYER| = 1250`). |
| 3 | Tokens: `ADMIN`, `MODERATOR`, vendor `779876543`, customer `771234567`; nightly jobs (`BR-PLT-01`) have run. |

## Test Data

| Field | Value |
|---|---|
| families | `orders`, `gmv`, `vendors`, `delivery`, `returns`, `kyc`, `users` |
| gmv request | `GET /admin/reports/gmv?from=2026-09-01&to=2026-09-30&groupBy=day&page=1&pageSize=50` |
| unknown family | `GET /admin/reports/refunds?…` → expect `400 VALIDATION_ERROR` |
| reconciliation | `GET /admin/reconciliation?date=2026-09-25` |

## Steps
1. As `ADMIN`, loop the seven families with the gmv-style request; capture `family`, `columns`, `rows`, `total`.
2. Inspect the `gmv` family: sum rows, check `total.value`/`relation`; call with `groupBy=bogus` and with an unknown family.
3. At `2026-09-26T01:30:00+03:00`, as `ADMIN`, `GET /admin/reconciliation?date=2026-09-25`; inspect both rows and `totals`.
4. As `MODERATOR`, call the reconciliation and the `gmv` report; as vendor and customer, call each.

## Expected Result
- Step 1 → seven `200` responses echoing their documented families with columns/rows/`total` (`API-ANL-007`).
- Step 2 → `Σ gmv rows = total.value = 451250` with `relation: "exact"` — reports reconcile to the ledger with zero unexplained variance (`AC-FR018-02`, `DATA-REQ-006`); `groupBy=bogus` → `400 VALIDATION_ERROR`; unknown family → `400 VALIDATION_ERROR` (documented enum, `API-ANL-007`).
- Step 3 → `200 { items: [ { date: "2026-09-25", source: "INTERNAL", ledgerTotal, providerTotal, deltaYER: 0, status: "MATCHED" }, { date: "2026-09-25", source: "BANK", ledgerTotal: 500000, providerTotal: 498750, deltaYER, status: "MISMATCH" } ], totals: { mismatches: 1, unresolvedYER: 1250 } }` — the previous day's result is available the next morning (`AC-FR018-04`, `BR-FIN-03`, `BR-ESC-08`); `|deltaYER| = |ledgerTotal − providerTotal| = 1250`.
- Step 4 → Moderator → `403 FORBIDDEN` on reconciliation (`API-ANL-009` is `ADMIN`-only) but `200` on the `gmv` report (aggregate read, `API-ANL-007`); vendor and customer → `403 FORBIDDEN` on both (`SEC-REQ-004`, `analytics.md` §2 — mismatches are admin-only).
