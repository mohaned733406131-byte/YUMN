# TC-088 — Marketing opt-out silences only the chosen channel and category

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that opting out of `PROMOTION` on `SMS` suppresses SMS for that user's campaign fan-out while WhatsApp/in-app/push still deliver, other users without the opt-out still receive SMS, and `ORDER` notifications on SMS are unaffected — with re-enable restoring the channel. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Buyer `771234567` (locale `ar`, push device registered) will opt out of `PROMOTION`/`SMS` only; buyer `771234570` keeps all channels enabled. |
| 2 | A seeded platform promotion campaign (coupon `RAMADAN25`-style) is queued for fan-out to both users (`PROMOTION` category, `BR-PRM-*`); a seeded `ORDER` event is available for the isolation probe. |
| 3 | SMS/WhatsApp/push adapters log every attempt; outboxes empty for the run window. |

## Test Data

| Field | Value |
|---|---|
| opt-out | `PUT /notifications/preferences {"updates":[{"category":"PROMOTION","channel":"SMS","enabled":false}]}` |
| campaign | seeded promotion fan-out to `771234567` and `771234570` |
| isolation probe | `ORD-7F3A21` → `PLACED` event for `771234567` |
| re-enable | same body with `"enabled": true` |

## Steps
1. As `771234567`, apply the opt-out body; `GET /notifications/preferences` → confirm only `PROMOTION.SMS = false` changed.
2. Run the campaign fan-out job; as each user, `GET /notifications?category=PROMOTION&limit=5` → inspect `channels[]`; read provider logs per channel.
3. As `771234567`, trigger the seeded `ORDER` event → inspect its `channels[]`.
4. Re-enable `PROMOTION`/`SMS` for `771234567` → run the campaign fan-out again → re-read the new `PROMOTION` notification.

## Expected Result
- Step 1 → `200` matrix shows exactly one flipped cell (`PROMOTION.SMS = false`); all other category/channel cells unchanged (`API-NTF-007`).
- Step 2 → `771234567`: `channels[] = [WHATSAPP SENT, IN_APP SENT, PUSH SENT]` with **no** SMS entry and zero SMS provider rows for this user; `771234570`: `channels[]` includes `{ channel: "SMS", status: "SENT" }` — the opt-out is per user, not global (`BR-NTF-05`, `AC-FR017-05`).
- Step 3 → the `ORDER` notification for `771234567` still includes `{ channel: "SMS", status: "SENT" }` — other categories are unaffected by the marketing opt-out (`BR-NTF-05`).
- Step 4 → the new `PROMOTION` notification includes SMS again — re-enabling restores exactly that channel (`API-NTF-006/007`); the security category was never touched (`BR-NTF-02`).
