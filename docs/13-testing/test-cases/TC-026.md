# TC-026 — Staff role matrix is enforced by the Owner, and followers receive new-product notifications

| Field | Value |
|---|---|
| Objective | Verify that only the Owner invites/changes/removes staff while Viewer/Editor/Manager each exercise exactly their permitted actions, and that following a store fans out new-product notifications per the customer's preferences. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Store `STORE-A` owner `774440001`; staff accounts exist: Viewer `774440004`, Editor `774440003`, Manager `774440005` (all with platform accounts).
- Customer `771234567` does not follow `STORE-A` yet; their `STORE_FOLLOW` notification preference is enabled (SMS + IN_APP).
- Staff roster is below `STAFF_LIMIT_REACHED`.

## Test Data

| Field | Value |
|---|---|
| Owner | `774440001` |
| Viewer / Editor / Manager | `774440004` / `774440003` / `774440005` |
| Invitation role | `EDITOR` |
| Invalid role | `OWNER` |
| Follower | `771234567` |
| New product | `هاتف نوكيا 105`, price `35000` YER |

## Steps
1. As **Viewer**: `GET /store/orders`, then `POST /store/products/{id}/publish`, then `PATCH /store/inventory/SKU-A1`.
2. As **Editor**: `POST /store/products` + `POST /store/products/{id}/publish`, then `POST /store/staff` (invite).
3. As **Manager**: `PUT /store/hours` and `GET /store/followers`.
4. As **Owner**: `POST /store/staff` inviting `774440006` as `EDITOR`; then as a non-Owner (Editor) try the same invite.
5. As Owner: `PATCH /store/staff/774440003/role` with `{"role":"MANAGER","reason":"ترقية"}`, then with `{"role":"OWNER"}` for self (`STAFF_SELF_ESCALATION` check from the Owner side) and an Editor attempting self-promotion.
6. As Owner: `POST /store/staff` with `{"phone":"774440004","role":"OWNER"}` (role not assignable) and repeat an invite beyond the roster cap.
7. Customer `771234567`: `POST /stores/STORE-A/follow`, repeat it, then `DELETE /stores/STORE-A/follow`, repeat again.
8. Re-follow, then publish the new product as Owner; read `GET /notifications` for the follower and `GET /store/followers` for the vendor.
9. As Owner: `DELETE /store/staff/774440003` and check that user's sessions.

## Expected Result
- Step 1: Viewer `GET` returns `200`; `publish` and `PATCH inventory` return `403 FORBIDDEN` — read-only role.
- Step 2: Editor product/publish succeed (`201`/`200`); `POST /store/staff` returns `403 FORBIDDEN` — only the Owner invites.
- Step 3: Manager `PUT /store/hours` returns `200`; `GET /store/followers` returns `200` (Manager scope allowed per matrix).
- Step 4: Owner invite returns `201 {"userId":"…","role":"EDITOR"}`; the Editor's identical invite returns `403 FORBIDDEN`.
- Step 5: role change to `MANAGER` returns `200` with an audit entry; self-promotion to `OWNER` returns `403 STAFF_SELF_ESCALATION` (`BR-VND-06`, `AC-FR002-03`); removing the last Owner is refused with `403 FORBIDDEN`.
- Step 6: `403 INVALID_ROLE` for `OWNER` as an invitable role; beyond cap → `422 STAFF_LIMIT_REACHED`.
- Step 7: first follow → `200 {"isFollowing":true,"followerCount":n}`; repeat → `200` idempotent (count unchanged); unfollow → `200 {"isFollowing":false,"followerCount":n-1}`; repeat → idempotent.
- Step 8: publishing fans out a `STORE_FOLLOW` notification to the follower on their enabled channels (`BR-VND-05`, `AC-FR008-02`); `GET /store/followers` shows `771234567` with `followedAt`; a follower with the preference disabled receives nothing.
- Step 9: staff removal returns `204` and revokes that staff member's sessions immediately (`API-VND-019`).
- Every staff mutation writes an actor/timestamp/reason audit row (`BR-PLT-06`).
