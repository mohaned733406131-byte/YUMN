# TC-025 — Store configuration: commission is read-only, zones must be domestic, suspension locks writes

| Field | Value |
|---|---|
| Objective | Verify that `PUT /store` and `PUT /store/shipping-zones` accept valid domestic configuration while the commission tier stays platform-owned and non-domestic zones are rejected, and that suspension of the store blocks all writes. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- KYC-approved store `STORE-A` (`متجر اليمن للتقنية`, owner `774440001`) with `status: ACTIVE`, commission `tierPercent: 10`.
- Admin token available for `POST /admin/stores/{id}/suspend|activate`.
- Customer `771234567` can request the public storefront.

## Test Data

| Field | Value |
|---|---|
| Store | `STORE-A` |
| New trade name | `متجر اليمن للتقنية - فرع صنعاء` |
| Attempted commission | `tierPercent: 5` (must be ignored/rejected) |
| Valid zone | `zoneSlug: sanaa-central`, `feeYER: 1500`, `freeOverYER: 50000` |
| Invalid zone | `zoneSlug: riyadh`, governorate `RIYADH` (outside Yemen) |
| Suspension reason | `مخالفة سياسة المحتوى` |

## Steps
1. `GET /store` as the owner and record `commission`, `status`, `kycStatus`.
2. `PUT /store` with the new trade name **plus** `commission: { tierPercent: 5 }` in the body.
3. `PUT /store/shipping-zones` with `[sanaa-central, alhudaydah]` (both domestic).
4. `PUT /store/shipping-zones` with `[riyadh]` (non-domestic).
5. As `ADMIN`: `POST /admin/stores/STORE-A/suspend` with the reason.
6. Repeat steps 2–3 as the owner; also `POST /store/products` and `GET /store/orders`.
7. `GET /stores/STORE-A-slug` as an anonymous customer; place (or attempt) an order for this store.
8. `POST /admin/stores/STORE-A/activate` with a reason, then repeat steps 2 and 7.

## Expected Result
- Step 1: `commission = { tierPercent: 10, min: 5, max: 20, source: "PLATFORM_DEFAULT" }`, `status: "ACTIVE"`, `kycStatus: "APPROVED"`.
- Step 2 returns `200`; the trade name changes but `commission.tierPercent` remains **10** — commission is never writable by the vendor (`BR-ESC-03`), only `SUPER_ADMIN` via `PUT /admin/settings/{key}` changes it (or `400 VALIDATION_ERROR` on the unknown field; either way the value is unchanged).
- Step 3 returns `200 {"items":[…],"domesticOnly":true}` with both zones saved.
- Step 4 returns `422 NO_SHIPPING_ZONE` — configuration outside domestic Yemen coverage is rejected (`AC-FR008-04`, `C-17`); no partial list is saved.
- Step 5 returns `200 {"status":"SUSPENDED","affected":{"productsDelisted":…,"ordersBlocked":…},"auditId":"…"}`.
- Step 6: every write returns `403 STORE_SUSPENDED` (`BR-VND-04`) — profile, zones, product creation and the order queue are all blocked.
- Step 7: `GET /stores/{slug}` returns `404 NOT_FOUND` (suspended storefront is hidden, `API-VND-012`); a new order for this store's items is refused with `STORE_SUSPENDED` / `CART_ITEM_INELIGIBLE`, and existing open orders are frozen, not cancelled.
- Step 8: after activation the storefront returns `200` again and writes succeed — suspension is reversible and never deletes data.
- Suspension and activation each write an audit entry (`SEC-REQ-010`).
