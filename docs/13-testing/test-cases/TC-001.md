# TC-001 — Registration with a valid phone dispatches a 5-minute OTP

| Field | Value |
|---|---|
| Objective | Verify that `POST /auth/register/start` creates an UNVERIFIED account and dispatches exactly one 6-digit OTP valid for 5 minutes, while rejecting an invalid phone, a weak password and a duplicate phone. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- No user exists for phone `771234567`; a verified user already exists for `731234567`.
- SMS provider sandbox is reachable and logs OTP deliveries; OTP rate counters are at 0.
- `GET /health/ready` returns 200 on the API base `/api/v1`.

## Test Data

| Field | Value |
|---|---|
| New phone | `771234567` (matches `^7[0-9]{8}$`) |
| Existing phone | `731234567` |
| Compliant password | `Yumn#2026a` |
| Weak password | `yumn2026a` (no upper-case letter) |
| OTP sampled from sandbox | `481902` |

## Steps
1. `POST /auth/register/start` with `{"phone":"771234567","password":"Yumn#2026a","locale":"ar","channel":"SMS"}` and record status, body and `X-Correlation-Id`.
2. `POST /auth/register/start` with `{"phone":"671234567","password":"Yumn#2026a"}` (does not start with 7).
3. `POST /auth/register/start` with `{"phone":"771234568","password":"yumn2026a"}`.
4. `POST /auth/register/start` with `{"phone":"731234567","password":"Yumn#2026a"}` (already registered).
5. Read the `users` row for `771234567`, its `passwordHash`, the OTP outbox entry, and the application log for the request.

## Expected Result
- Step 1 returns `201` with `{"status":"OTP_SENT","phoneMasked":"771***567","expiresAt":"2026-09-26T10:05:00Z","resendAfterSeconds":60}`; no access or refresh token is issued.
- Exactly one OTP record exists: 6 digits `481902`, expiry = dispatch time + 5 minutes, `attemptsAllowed` 3, channel SMS.
- The account row exists with verification status `UNVERIFIED`; `passwordHash` starts with `$2b$12$`; the phone is stored encrypted, never plaintext.
- Step 2 returns `422 PHONE_INVALID`, step 3 returns `422 PASSWORD_POLICY_VIOLATION`, step 4 returns `409 PHONE_ALREADY_REGISTERED`; none of them creates a row or dispatches an OTP.
- The literal password and the OTP code appear in no application log line.
- Every error body carries a localized `message` (Arabic default), `messageKey` `errors.<CODE>`, `retryable:false` and a `correlationId`.
