# TC-066 — First accept wins the delivery assignment; the losing courier gets 409

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that two concurrent `POST /deliveries/{id}/accept` calls commit exactly one assignment: the winner receives `ASSIGNED`, the loser receives `409 ASSIGNED_ELSEWHERE`, and no double booking ever exists. | integration | P0 | Yes — Jest + Supertest (concurrent requests) |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `DLV-4471` is `READY_FOR_PICKUP` in zone `sanaa-center` with `offerVersion = 7`; nothing has accepted it. |
| 2 | Couriers `790000011` and `790000012` are both eligible (same zone, ONLINE) and hold valid tokens. |
| 3 | Optimistic locking on `offerVersion` is active (`BR-SHP-04`); `order_status_history` for `SUB-9C1104` contains no `ASSIGNED` row. |

## Test Data

| Field | Value |
|---|---|
| delivery | `DLV-4471`, sub-order `SUB-9C1104`, offerVersion `7` |
| couriers | winner candidate `790000011`, loser candidate `790000012` |
| accept body | `{"offerVersion":7}` |
| expected winner version | `8` |

## Steps
1. Fire both requests concurrently (single barrier): `POST /deliveries/DLV-4471/accept {"offerVersion":7}` as `790000011` and as `790000012`.
2. Record both status codes and bodies.
3. The losing courier repeats `POST /deliveries/DLV-4471/accept {"offerVersion":7}`.
4. Read `SELECT courier_id, state, version FROM delivery WHERE id = 'DLV-4471';` and `SELECT COUNT(*) FROM order_status_history WHERE sub_order_id='SUB-9C1104' AND state='ASSIGNED';`.
5. The winner calls `POST /deliveries/DLV-4471/accept {"offerVersion":7}` again (stale version).

## Expected Result
- Step 1 → exactly one `200 { deliveryId: "DLV-4471", state: "ASSIGNED", version: 8, assignedAt: "..." }`; the other call returns `409 ASSIGNED_ELSEWHERE` (`retryable: true`) with a localized `message`/`messageKey errors.ASSIGNED_ELSEWHERE` (`AC-FR015-04`, `BR-SHP-04`).
- Step 3 → `409 ASSIGNED_ELSEWHERE` again — a second accept can never succeed after the race is decided.
- Step 4 → exactly one row, `state = ASSIGNED`, one non-null `courier_id`; `order_status_history` contains exactly one `ASSIGNED` entry (append-only, `BR-ORD-03`) — no double booking.
- Step 5 → `409 STATE_CONFLICT` (stale `offerVersion`, `C-09`/`DOC-SA-010` §5); the stored version and courier are unchanged.
- No response body contains GPS or position fields (`BR-SHP-05`, `C-16`).
