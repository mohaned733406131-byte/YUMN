# TC-040 — Multi-vendor checkout splits into one master and three sub-orders with per-vendor totals

| Field | Value |
|---|---|
| Objective | Verify that a cart spanning three vendors produces exactly one master order and one sub-order per vendor, that each sub-order carries its own items, VAT, shipping and total, and that the master total equals the sum of the sub-order totals with a single wallet debit. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Buyer `771234567` wallet funded with 100,000 YER; address `adr-771` in `sanaa-center`.
- Stores KYC `APPROVED` and active: `tech-store` (`779876543`), `sanaa-perfumes` (`779876544`), `hadhbooks` (`779876545`).
- Cart limit checks pass: 3 distinct products ≤ 50, quantities ≤ 10, stores = 3 ≤ 5 (`C-15`).

## Test Data

| Field | Value |
|---|---|
| Store A `tech-store` | `هاتف سامسونج` ×1 — `25000` + VAT `3750` + shipping `500` = `29250` YER |
| Store B `sanaa-perfumes` | `عطر يمني فاخر` ×2 — `8000` + VAT `1200` + shipping `400` = `9600` YER |
| Store C `hadhbooks` | `كتاب تاريخ اليمن` ×3 — `4500` + VAT `675` + shipping `300` = `5475` YER |
| Master total | `29250 + 9600 + 5475 = 44325` YER; keys `chk-040-01`, `ord-040-01` |

## Steps
1. `POST /cart/items` three times (one per store) and `GET /cart` → assert `distinctStores = 3`, `subtotal 37500`.
2. `POST /checkout/session` with `Idempotency-Key: chk-040-01`, body `{"addressId":"adr-771","shippingMethod":"STANDARD","paymentMethod":"wallet"}` → inspect `byStore` and `totals`.
3. `POST /orders` with `Idempotency-Key: ord-040-01`, body `{"checkoutSessionId":"cs-040","confirmTotals":true}`.
4. `GET /orders/{orderId}` → sub-order totals, items, per-store `totals` and `masterState`.
5. `GET /wallet`, `GET /wallet/transactions?type=ORDER_PAYMENT`, `GET /wallet/escrow?orderId={orderId}`.
6. SQL: count `orders` (master) and `sub_orders` rows; sum sub-order totals; check `order_status_history` rows.

## Expected Result
- Step 1 → `201`/`200` responses; a 6th store would be refused with `422 MAX_VENDORS_EXCEEDED` (guard proven in TC-029).
- Step 2 → `201` with `byStore` entries `29250`, `9600`, `5475` and `totals.grandTotal 44325`; each store's VAT = 15 % of its own undiscounted subtotal (`BR-FIN-01`).
- Step 3 → `201 {masterState:"PLACED", subOrders:[{…total:29250,state:"PLACED"},{…9600…},{…5475…}]}` — 1 master + 3 sub-orders (`AC-FR011-04`, `C-10`).
- Step 4 → `200` with `totals.grandTotal 44325 = 29250 + 9600 + 5475` (`BR-FIN-02`, `BR-ORD-02`); each sub-order lists only its own vendor's items.
- Step 5 → a **single** wallet debit of `44325` (balance `55675`); three escrow holds whose amounts sum to `44325`; ledger `SUM(amount) = 0`.
- Step 6 → exactly 1 master + 3 sub rows, 3 history rows `→ PLACED`, stock deducted per store, cart cleared.
