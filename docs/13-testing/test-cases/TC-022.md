# TC-022 — Moderation hide/restore excludes a review from ratings and every response is audited

| Field | Value |
|---|---|
| Objective | Verify the moderation path `report → hide → recompute → restore`: a hidden review leaves the public list and the rating summary with an audit entry, and the vendor's single response is enforced. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Product `PRD-M1` shows `ratingSummary { average: 4.5, count: 2 }` from reviews `REV-1` (5★) and `REV-2` (4★).
- `REV-1` was written by the purchaser of a `DELIVERED` order; a second customer (`731234567`) is available to report it.
- `MODERATOR` (`773330001`) and vendor `OWNER` (`774440001`) tokens are valid.
- The incremental recompute job (`b02.review.rating-recompute`) can be triggered on demand.

## Test Data

| Field | Value |
|---|---|
| Product | `PRD-M1` (`samsung-a15-m1`) |
| Reviews | `REV-1` (5★), `REV-2` (4★) |
| Report reason | `ABUSIVE` |
| Hide reason | `محتوى غير لائق` |
| Vendor response | `responseAr: شكرًا لتقييمك` |

## Steps
1. `GET /products/PRD-M1-slug/reviews` anonymously and record `ratingSummary`.
2. `POST /reviews/REV-1/report` with `{"reason":"ABUSIVE","note":"إساءة"}` as customer `731234567`.
3. `GET /admin/moderation?type=REVIEW&status=PENDING` as `MODERATOR`.
4. `POST /admin/moderation/review/REV-1/hide` **without** `reason`.
5. `POST /admin/moderation/review/REV-1/hide` with `{"reason":"محتوى غير لائق"}` as `MODERATOR`.
6. Trigger the rating recompute job, then repeat step 1.
7. `POST /admin/moderation/review/REV-1/hide` again (already hidden).
8. Vendor posts a response: `POST /store/reviews/REV-2/responses` with `{"responseAr":"شكرًا لتقييمك"}`, then repeats it.
9. `POST /admin/moderation/review/REV-1/restore` with `{"reason":"مراجعة يدوية"}`, re-run the recompute, repeat step 1.
10. Read the audit log entries created in steps 5, 8 and 9.

## Expected Result
- Step 1: `ratingSummary = { average: 4.5, count: 2 }`.
- Step 2 returns `201 {"reportId":"…","status":"OPEN"}`; step 3 lists the reported review with `reports: 1`.
- Step 4 returns `422 REASON_REQUIRED` — hiding is impossible without a reason.
- Step 5 returns `200 {"hidden":true,"hiddenBy":"MODERATOR","auditId":"…"}` (`BR-REV-04`).
- Step 6: the public list now returns only `REV-2` and `ratingSummary = { average: 4.0, count: 1 }` — the hidden review is excluded from average **and** visible count (`AC-FR006-04`, `BR-REV-05`).
- Step 7 returns `409 STATE_CONFLICT` (already hidden).
- Step 8: first response returns `201`; the repeat returns `409 RESPONSE_ALREADY_EXISTS` (one response per review).
- Step 9: restore returns `200 {"hidden":false,"auditId":"…"}`; after recompute the summary returns to `{ average: 4.5, count: 2 }`.
- Step 10: exactly one audit row per hide/restore/response exists with actor, action, entity id, reason and timestamp; no update or delete rows — moderation history is append-only (`SEC-REQ-010`).
- A Moderator token may perform steps 5/9; a Customer token on the same routes returns `403 FORBIDDEN`.
