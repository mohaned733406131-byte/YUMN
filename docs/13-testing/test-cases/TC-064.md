# TC-064 — Daily reconciliation proves the ledger balances and flags mismatch without silent fixes

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that after a full money cycle the daily reconciliation reports Σ ledger = 0 and wallet/escrow/payable totals that tie to the ledger, that ledger rows cannot be edited in place, and that an injected provider mismatch is reported and alerted but never auto-corrected. | integration | P1 | Yes — Jest + SQL assertions |

## Preconditions

| # | Precondition |
|---|---|
| 1 | A complete cycle has run: top-up 50,000 YER → order 14,875 YER → delivered + 7 days → release (commission 1,250) → payout 13,000 YER executed → one refund credited (TC-057…TC-063 fixtures). |
| 2 | BullMQ queue `b07.ledger.reconcile` (`data-flow.md` DF table) can be triggered for a chosen date; provider adapters are mockable (m-Floos statement fixture). |
| 3 | `ADMIN` (`770000001`), `MODERATOR` (`770000003`) and buyer (`771234567`) tokens exist; the app DB role is used for the negative write test. |

## Test Data

| Field | Value |
|---|---|
| reconciliation date | `2026-09-27` (first morning after the cycle) |
| injected delta | m-Floos statement overstated by **+100 YER** |
| expected global Σ | `SUM(amount_yer) = 0` across `b07.wallet_transaction` |
| accounts | buyer wallet 35,125 YER (50,000 − 14,875) + refund credit; vendor payable after payout 625 YER |
| alert budget | mismatch alert ≤ 15 minutes of detection (NFR-008) |

## Steps
1. Run `b07.ledger.reconcile` for `2026-09-27`, then `ADMIN` `GET /admin/reconciliation?date=2026-09-27`.
2. Run SQL: `SELECT COALESCE(SUM(amount_yer),0) FROM b07.wallet_transaction;` plus per-account sums, `SELECT balance_yer FROM b07.wallet WHERE user_id = '771234567';`, and escrow/payable totals from `b07.escrow`, `b07.payout`.
3. `UPDATE b07.wallet_transaction SET amount_yer = amount_yer + 1 WHERE id = (SELECT id FROM b07.wallet_transaction LIMIT 1);` executed with the application DB role; then `DELETE` on the same row.
4. Mock the m-Floos provider statement for `2026-09-27` with the +100 YER delta and run `b07.ledger.reconcile` again; `GET /admin/reconciliation?date=2026-09-27&status=MISMATCH`.
5. Capture the alert (metrics/webhook sink) and wait 15 minutes; then re-read the mismatch row and the ledger.
6. `MODERATOR` `GET /admin/reconciliation?date=2026-09-27`; buyer `GET /admin/reconciliation?date=2026-09-27`.
7. Admin records the resolution (`resolvedBy`, `note`) and posts the compensating entry via the documented correction procedure; re-run the reconciliation for the date and read `totals`.

## Expected Result
- Step 1 → `200 { items: [ { date, source, ledgerTotal, providerTotal, deltaYER: 0, status: "MATCHED" } ], totals: { mismatches: 0, unresolvedYER: 0 } }` — the report for the closed day is available next morning (`AC-FR018-02`, `OBJ-08`).
- Step 2 → global `SUM(amount_yer) = 0` and each wallet's balance equals the sum of its ledger rows; escrow + payable totals equal releases minus payouts (`AC-NFR-008-01`, `AC-S-14`, job `J1`/`J4`); every posting is a balanced debit/credit pair (`BR-PAY-06`).
- Step 3 → both statements fail: the ledger is append-only — `UPDATE`/`DELETE` rejected below the application layer, and no API endpoint mutates posted rows (`AC-DR007-01`, `DATA-REQ-007`).
- Step 4 → a new row `status = "MISMATCH"`, `deltaYER = 100`, counted in `totals.unresolvedYER = 100`; the wallet/escrow/payable rows for the same date stay `MATCHED`.
- Step 5 → exactly one alert fires within 15 minutes (`NFR-008`, `BR-PLT-02`); re-reading shows the row still `MISMATCH` — reconciliation **reports** and alerts, it never auto-fixes money (`BR-ESC-08`, `BR-FIN-03`).
- Step 6 → `MODERATOR` and buyer both get `403 FORBIDDEN` — reconciliation output is `ADMIN`-scoped (`API-ANL-009`, `SEC-REQ-004`).
- Step 7 → the row gains `resolvedBy`/`note`, the compensating entry restores `SUM(amount_yer) = 0`, and an audit entry records the correction (`BR-PLT-06`, `SEC-REQ-010`); a rerun reports `mismatches: 0` with no ledger row ever rewritten.
