# TC-037 — Top-up amount boundaries 999 / 1,000 / 5,000,000 / 5,000,001 YER rejected before any provider call

| Field | Value |
|---|---|
| Objective | Verify `BR-PAY-02`: top-ups are accepted only in the inclusive 1,000–5,000,000 YER band, out-of-band and non-integer amounts are refused with no provider contact and no ledger effect. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest (MockPaymentAdapter call counter) |

## Preconditions
- Customer `771234567` wallet `ACTIVE` with 0 YER; `MockPaymentAdapter` exposes a call counter that must stay at 0 for rejected requests.
- `GET /wallet` echoes `limits {"topUpMin":1000,"topUpMax":5000000,…}`.

## Test Data

| Field | Value |
|---|---|
| Amounts | `999` (reject), `1000` (accept), `5000000` (accept), `5000001` (reject), `1500.5` (reject) |
| Methods | `MFLOOS` (bounds cases), `ONECASH` (5,000,000 case) |
| Keys | `top-037-999`, `top-037-1k`, `top-037-5m`, `top-037-5m1`, `top-037-frac` |

## Steps
1. `GET /wallet` and record `limits`.
2. `POST /wallet/topups` five times, each with its own `Idempotency-Key` and body `{"amount":<value>,"method":"MFLOOS"}` (method `ONECASH` for the 5,000,000 case).
3. After each rejection, count `wallet_topup` rows, `wallet_transaction` rows and the adapter call counter.
4. `POST /wallet/topups` with `{"amount":1000,"method":"CARD"}` and key `top-037-card`.
5. Deliver the verified callback for the accepted 1,000 YER top-up and re-read `GET /wallet`.

## Expected Result
- Step 1 → `200` with `limits.topUpMin 1000`, `limits.topUpMax 5000000` (`API-WAL-001`).
- Step 2, `999` → `422` `error.code = TOPUP_LIMIT`, `details[].field = "amount"`, `retryable:false` (`AC-FR013-01`).
- Step 2, `5000001` → `422 TOPUP_LIMIT`, same envelope.
- Step 2, `1000` and `5000000` → `201 {status:"PENDING_PROVIDER", amount:<exact>}` — both boundaries inclusive.
- Step 2, `1500.5` → `400 VALIDATION_ERROR` — amounts are integer YER only (`BR-PAY-10`, `C-04`).
- Step 3 → rejected attempts create **0** top-up rows, **0** ledger rows and **0** provider calls (bounds checked before contacting any provider, `API-WAL-003`).
- Step 4 → `400 VALIDATION_ERROR` on the `method` enum — only `MFLOOS`, `ONECASH`, `BANK_TRANSFER` exist (`C-05`).
- Step 5 → balance `1000`, exactly one `TOPUP` credit pair, `SUM(amount) = 0` (`BR-PAY-06`).
