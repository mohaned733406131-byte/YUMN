# TC-004 — Login issues a 15-minute access token and a 7-day refresh token

| Field | Value |
|---|---|
| Objective | Verify that `POST /auth/login` with correct credentials returns a 15-minute access token, a 7-day single-use refresh token and a registered device session, and that wrong credentials or an unverified phone are refused without issuing tokens. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Verified, active account `771234567` with password `Yumn#2026a` and 0 failed login attempts.
- Unverified account exists for `776660001` (registered but OTP never verified).
- Login rate bucket (10/min/IP) is reset.

## Test Data

| Field | Value |
|---|---|
| Verified phone | `771234567` |
| Correct password | `Yumn#2026a` |
| Wrong password | `Yumn#2026b` |
| Unverified phone | `776660001` |
| Device name | `Galaxy-A15` |

## Steps
1. `POST /auth/login` with `{"phone":"771234567","password":"Yumn#2026a","deviceName":"Galaxy-A15"}`.
2. Decode both returned tokens; record `exp − iat` for each and the `sid` claim.
3. Call `GET /auth/sessions` with the access token.
4. Call `GET /orders` with the access token to prove it is accepted.
5. Wait until the access token is older than 15 minutes (or backdate `exp`), then call `GET /orders` again.
6. `POST /auth/login` with `{"phone":"771234567","password":"Yumn#2026b"}`.
7. `POST /auth/login` with `{"phone":"776660001","password":"Yumn#2026a"}`.

## Expected Result
- Step 1 returns `200` with `{"accessToken":"…","refreshToken":"…","expiresIn":900,"sessionId":"sess_…","user":{"id":"usr_…","roles":["CUSTOMER"],"displayName":"…","locale":"ar"}}`.
- Step 2: access token lifetime exactly 900 seconds, refresh token lifetime 604800 seconds (7 days); both carry the same `sid`.
- Step 3 returns `200` with one session entry for `Galaxy-A15`, `current: true`, `ipMasked` set — no full IP is exposed.
- Step 4 returns `200`; step 5 returns `401 TOKEN_EXPIRED` with `retryable:true` so the client performs a silent refresh.
- Step 6 returns `401 INVALID_CREDENTIALS` and increments the failure counter by exactly 1; step 7 returns `403 OTP_NOT_VERIFIED`.
- No token pair is returned for steps 6 and 7; `Cache-Control: no-store` is present on every auth response.
