# TC-032 — Insufficient balance and non-wallet payment method create no order and no ledger entry

| Field | Value |
|---|---|
| Objective | Verify that a confirmation whose total exceeds the wallet balance is refused with `INSUFFICIENT_FUNDS` (shortfall reported), that any non-wallet payment method is refused with `PAYMENT_METHOD_NOT_ALLOWED`, and that in both cases no order row, no ledger posting and no escrow hold exists. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Customer `771234567` wallet `ACTIVE` with exactly 10,000 YER; cart holds `PRD-P1` × 1 @ 10,000 YER with a 500 YER STANDARD shipment.
- MockPaymentAdapter scripted for a successful 2,000 YER m-Floos callback (used only in the final recovery step).
- No prior order exists for this buyer; ledger and escrow tables are empty for the order references used below.

## Test Data

| Field | Value |
|---|---|
| Balance / totals | balance `10000`; subtotal `10000` + VAT `1500` + shipping `500` = `12000` YER |
| Shortfall | `2000` YER |
| Keys | `chk-032-01`, `ord-032-01`, `pay-032-01`, `ord-032-02` |
| Rejected method | `"paymentMethod":"CARD"` |

## Steps
1. `POST /checkout/session` with `Idempotency-Key: chk-032-01`, body `{"addressId":"adr-771","shippingMethod":"STANDARD","paymentMethod":"wallet"}` → record `totals.grandTotal` and `wallet`.
2. `POST /orders` with `Idempotency-Key: ord-032-01`, body `{"checkoutSessionId":"cs-032","confirmTotals":true}`.
3. `POST /wallet/payments/authorize` with `Idempotency-Key: pay-032-01`, body `{"checkoutSessionId":"cs-032","amount":12000}`.
4. `POST /orders` with `Idempotency-Key: ord-032-01b`, body `{"checkoutSessionId":"cs-032","confirmTotals":true,"paymentMethod":"CARD"}`.
5. Assert persistence: count `orders`, `wallet_transaction`, `b07.escrow` rows created by steps 2–4; re-read `GET /wallet`.
6. Credit 2,000 YER through a verified m-Floos callback, then `POST /orders` with `Idempotency-Key: ord-032-02` and the original wallet body.

## Expected Result
- Step 2 → `422` with `error.code = INSUFFICIENT_FUNDS`, `retryable:false`, `details[].field = "amount"` carrying the 2,000 YER shortfall (`AC-FR011-03`).
- Step 3 → `422 INSUFFICIENT_FUNDS` — an authorization hold never exceeds the available balance (`API-WAL-006`).
- Step 4 → `422 PAYMENT_METHOD_NOT_ALLOWED`; no COD/card/BNPL path exists anywhere in the request schema (`BR-PAY-01`, `C-01`).
- Step 5 → **0** order rows, **0** ledger rows, **0** escrow rows; balance still `10000`; no `wallet_transaction` rows exist for this order reference (`AC-FR013-03`, `AC-FR013-04`).
- Step 6 → `201` with a single order in `PLACED`, balance `0` (never negative, `BR-PAY-05`), exactly one debit of 12,000 YER.
- Every error body carries `messageKey errors.<CODE>`, Arabic `message`, `correlationId` and `retryable:false` (`error-model.md` §1).
