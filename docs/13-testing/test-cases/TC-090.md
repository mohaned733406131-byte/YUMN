# TC-090 — Vendor dashboard shows exact own-store metrics and never another store's

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that `GET /store/dashboard` returns own-store totals for the requested period with `totalsMeta` annotations (sales exact from the ledger), a trend series that sums to the total, role/tenant isolation (other roles ⇒ 403, suspended store ⇒ `403 STORE_SUSPENDED`), and dashboard caching headers. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Period `2026-09-01…2026-09-30`: store `tech-store` (vendor `779876543`) has 12 paid orders totalling **178,500 YER** (avg 14,875); store B (vendor `779876544`) has 272,750 YER — both fully released from the ledger. |
| 2 | One refunded sub-order (12,500 YER) and the seed delivery metrics exist for `refundRatePercent` / `onTimeDeliveryPercent`; nightly aggregation job has run (totals `relation: "exact"`). |
| 3 | Tokens: vendor `779876543`, vendor `779876544`, customer `771234567`, `ADMIN`; a third store seeded as `SUSPENDED`. |

## Test Data

| Field | Value |
|---|---|
| request | `GET /store/dashboard?from=2026-09-01&to=2026-09-30&compare=none` |
| expected (tech-store) | `salesYER: 178500`, `orders: 12`, `avgBasketYER: 14875` |
| expected (store B) | `salesYER: 272750` |
| bad compare | `compare=prev_periodx` → expect `400 VALIDATION_ERROR` |

## Steps
1. As vendor `779876543`, call the dashboard request; inspect `totals`, `totalsMeta`, `trend`, `topProducts`, `breakdown`.
2. Sum `trend[].salesYER` and `trend[].orders`; recompute `avgBasketYER` from `totals`.
3. As vendor `779876544`, call the same endpoint; as the suspended-store vendor, call it; as customer `771234567`, call it.
4. Call with `compare=prev_periodx`; inspect `Cache-Control` on a valid response.

## Expected Result
- Step 1 → `200 { period, totals: { salesYER: 178500, orders: 12, avgBasketYER: 14875, refundRatePercent, onTimeDeliveryPercent, … }, trend: [...], topProducts: [...], breakdown: { paidByWallet }, totalsMeta: { sales: { value: 178500, relation: "exact" } } }` — money totals annotated, sales exact from the ledger (`API-ANL-001`, `analytics.md` §2).
- Step 2 → `Σ trend.salesYER = 178500`, `Σ trend.orders = 12`, `178500 / 12 = 14875 = avgBasketYER` — internally consistent, reconciling with zero variance (`AC-FR018-02`).
- Step 3 → store B sees `salesYER: 272750` (its own only); the suspended store → `403 STORE_SUSPENDED` (`error-model.md`); the customer → `403 FORBIDDEN` (deny-by-default role guard, `SEC-REQ-004`) — vendor queries are scoped to `store_id` (`BR-VND-07`, `AC-FR018-01`, `DATA-REQ-008`).
- Step 4 → invalid `compare` → `400 VALIDATION_ERROR` with per-field `details[]` (`api-conventions.md` §5); valid response carries `Cache-Control: max-age=30` (`analytics.md` §3).
