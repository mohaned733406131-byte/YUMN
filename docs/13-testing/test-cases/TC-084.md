# TC-084 — Notification channel set is locked to SMS/WhatsApp/in-app/push with no email anywhere

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that only the four v1 channels exist: preferences advertise `emailSupported: false`, an `EMAIL` channel is refused with `422 CHANNEL_NOT_SUPPORTED`, security preferences are immutable (`403 PREFERENCE_IMMUTABLE`), and delivered fan-out records contain only SMS/WHATSAPP/IN_APP/PUSH. | integration | P0 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Buyer `771234567` (locale `ar`) has a fresh session and default preferences (all four channels enabled per category). |
| 2 | A seeded order event (`ORD-7F3A21` → `PLACED`) is ready to trigger the `ORDER` fan-out; notification outbox empty for the run window. |
| 3 | Exported OpenAPI for group `API-NTF-001…010` available for the contract scan. |

## Test Data

| Field | Value |
|---|---|
| illegal channel | `{"updates":[{"category":"ORDER","channel":"EMAIL","enabled":true}]}` |
| locked category | `{"updates":[{"category":"SECURITY","channel":"SMS","enabled":false}]}` |
| legal change | `{"updates":[{"category":"PROMOTION","channel":"PUSH","enabled":false}]}` |
| allowed channels | `SMS`, `WHATSAPP`, `IN_APP`, `PUSH` |

## Steps
1. `GET /notifications/preferences` → inspect the category matrix and the `SECURITY` row.
2. `PUT /notifications/preferences` with the illegal-channel body; then with the locked-category body; then with the legal body.
3. Trigger the seeded `ORDER` event; `GET /notifications?category=ORDER&limit=10` → inspect the item's `channels[]` fan-out record.
4. Contract scan: grep the exported `API-NTF` schemas for `email` (case-insensitive) and inspect `GET /notifications/preferences` again.

## Expected Result
- Step 1 → `200 { categories: [ … ], emailSupported: false }`; the `SECURITY` row reads `security: true, locked: true, immutable: true` with all four channels enabled (`API-NTF-006`, `BR-NTF-01`, `BR-NTF-02`).
- Step 2 → illegal channel → `422 CHANNEL_NOT_SUPPORTED`; security category → `403 PREFERENCE_IMMUTABLE`; legal change → `200` with `PROMOTION.PUSH = false` persisted — exactly the three documented error codes (`API-NTF-007`, `GAP-03`).
- Step 3 → the notification item exists with `channels[]` containing only entries from `{SMS, WHATSAPP, IN_APP, PUSH}` (only the opted-in ones, each `{status: "SENT", sentAt}`) — no `EMAIL` entry, no email field anywhere (`BR-NTF-01`, `AC-FR017-01`).
- Step 4 → the only email-related key anywhere in the group is the advertised `emailSupported: false` — there is no `EMAIL` channel enum member, no email preference row and no email delivery field (`notifications.md` §1/§3, `BR-NTF-01`, `GAP-03`).
