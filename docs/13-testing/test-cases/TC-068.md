# TC-068 — Pickup → transit → out-for-delivery issues the 6-digit code to the buyer

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that the courier scan chain `ASSIGNED → PICKED_UP → IN_TRANSIT → OUT_FOR_DELIVERY` executes in order and that entering `OUT_FOR_DELIVERY` issues exactly one 6-digit code to the buyer on SMS/WhatsApp/in-app, visible only to the buyer. | e2e | P0 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `DLV-4471` is `ASSIGNED` to courier `790000011`; sub-order `SUB-9C1104` follows the same state. |
| 2 | Buyer `771234567` (locale `ar`) owns `ORD-7F3A21` and has an active in-app inbox and push token. |
| 3 | Seeded delivery code for this delivery is `482913`; SMS/WhatsApp adapters are mock sandboxes logging deliveries. |

## Test Data

| Field | Value |
|---|---|
| delivery / order | `DLV-4471` / `ORD-7F3A21` / `SUB-9C1104` |
| expected code | `482913` (buyer-only), masked form `**4829` |
| channels expected | `["SMS","WHATSAPP","IN_APP"]` |
| scans | pickup note `at_hub`, hubNote `to_sanaa_center` |

## Steps
1. `GET /deliveries/DLV-4471/pickup` → capture pickup screen payload.
2. `POST /deliveries/DLV-4471/pickup {"note":"at_hub"}`.
3. `POST /deliveries/DLV-4471/transit {"hubNote":"to_sanaa_center"}`.
4. `POST /deliveries/DLV-4471/out-for-delivery` (no body).
5. As buyer `771234567`, `GET /orders/ORD-7F3A21/delivery-code`.
6. As courier `790000011`, `GET /orders/ORD-7F3A21/delivery-code`; as customer `771234568`, repeat the same call.
7. Read the notification outbox for buyer `771234567` and the `order_status_history` rows for `SUB-9C1104`.

## Expected Result
- Step 1 → `200` with pickup address and `package.weightBand` — no GPS fields (`C-16`).
- Step 2 → `200 { state: "PICKED_UP", version, historyEntry, pickedUpAt }`; step 3 → `200 { state: "IN_TRANSIT", version, historyEntry }`; an out-of-order `POST /transit` before pickup returns `409 STATE_CONFLICT` (`C-09`).
- Step 4 → `200 { state: "OUT_FOR_DELIVERY", version, codeIssued: true, codeDeliveryChannels: ["SMS","WHATSAPP","IN_APP"], buyerCodeMasked: "**4829" }` — one code issued at this transition only (`BR-SHP-02`).
- Step 5 → `200 { code: "482913", issuedAt, attemptsRemaining: 3 }` for the order owner (`API-SHP-013`).
- Step 6 → `404 NOT_FOUND` for courier and for the other customer — the full code is buyer-only (`BR-ORD-09`, `DATA-REQ-008`).
- Step 7 → exactly one code notification with channels SMS/WhatsApp/in-app, Arabic template (`BR-NTF-04`); history rows `ASSIGNED → PICKED_UP → IN_TRANSIT → OUT_FOR_DELIVERY` in order, append-only (`BR-ORD-03`).
