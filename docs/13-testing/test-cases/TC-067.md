# TC-067 — Courier release returns the assignment to READY_FOR_PICKUP

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that `POST /deliveries/{id}/release` moves `ASSIGNED → READY_FOR_PICKUP` with a mandatory reason, puts the offer back in the same-zone pool, and never rewrites history. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `DLV-4471` is `ASSIGNED` to courier `790000011` (version 8, accepted per TC-066); sub-order `SUB-9C1104` is `ASSIGNED`. |
| 2 | Courier `790000012` (same zone, ONLINE) is watching `GET /deliveries/available?zone=sanaa-center`. |
| 3 | `order_status_history` already holds the `ASSIGNED` row; no pickup scan has happened. |

## Test Data

| Field | Value |
|---|---|
| delivery / sub-order | `DLV-4471` / `SUB-9C1104` |
| release reason | `vehicle_breakdown` |
| release body | `{"reason":"vehicle_breakdown"}` |
| assigned version | `8` → expected `9` after release |

## Steps
1. As courier `790000011`, `POST /deliveries/DLV-4471/release` with body `{}` (no reason).
2. `POST /deliveries/DLV-4471/release {"reason":"vehicle_breakdown"}`.
3. As courier `790000012`, `GET /deliveries/available?zone=sanaa-center`.
4. As courier `790000011`, repeat the release (job already back in the pool).
5. Read `SELECT state, version, courier_id FROM delivery WHERE id='DLV-4471';` and the `order_status_history` rows for `SUB-9C1104`.

## Expected Result
- Step 1 → `422 REASON_REQUIRED`, state unchanged (`ASSIGNED`) — release always documents why (`API-SHP-005`).
- Step 2 → `200 { state: "READY_FOR_PICKUP", version: 9, historyEntry: { ... } }` with actor, timestamp and reason appended (`BR-ORD-03`).
- Step 3 → `DLV-4471` reappears in the offer list with a fresh `offerVersion` for any same-zone courier (`BR-SHP-04`) — the package is never stranded.
- Step 4 → `409 STATE_CONFLICT` (transition `READY_FOR_PICKUP → READY_FOR_PICKUP` is not in the table, `C-09`).
- Step 5 → row is `READY_FOR_PICKUP`, `courier_id` cleared; history shows `ASSIGNED` then `READY_FOR_PICKUP` — both rows preserved, none edited or deleted (`BR-ORD-03`).
