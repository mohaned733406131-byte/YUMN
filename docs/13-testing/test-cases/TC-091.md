# TC-091 — Store report families paginate, reconcile to totals and reject unknown families

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that all four vendor report families (`sales`, `orders`, `returns`, `payouts`) return annotated tables with offset pagination, that rows sum to `total.value` exactly, that repeated reads are stable, and that an unknown family or malformed dates are rejected with `400 VALIDATION_ERROR`. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Store `tech-store` period `2026-09-01…2026-09-30`: 12 sales orders totalling **178,500 YER**, 1 return (12,500 YER), 1 executed payout — enough rows to span two pages at `pageSize=10`. |
| 2 | Store B holds its own rows (never visible to `tech-store`); tokens: vendor `779876543`, vendor `779876544`. |
| 3 | Pagination defaults per `pagination.md` §3 (`page`/`pageSize` offset tables). |

## Test Data

| Field | Value |
|---|---|
| families | `sales`, `orders`, `returns`, `payouts` |
| paging probe | `GET /store/reports/sales?from=2026-09-01&to=2026-09-30&page=1&pageSize=10` then `page=2` |
| unknown family | `GET /store/reports/margins?from=2026-09-01&to=2026-09-30` |
| malformed range | `from=2026-13-40&to=2026-09-30` |

## Steps
1. For each of the four families, `GET /store/reports/{family}?from=2026-09-01&to=2026-09-30&page=1&pageSize=100` → capture `family`, `columns`, `rows`, `total`.
2. Sales family: page 1 with `pageSize=10`, then `page=2`; count rows and sum the amount column across both pages.
3. Repeat the page-1 sales call a second time (read stability); as store B, call the sales family for the same period.
4. `GET /store/reports/margins?…` and `GET /store/reports/sales?from=2026-13-40&to=2026-09-30`.

## Expected Result
- Step 1 → four `200` responses, each echoing its `family` with a non-empty `columns` definition and `total: { value, relation }` — the four documented families only (`API-ANL-002`).
- Step 2 → page 1 returns 10 rows, page 2 returns the remaining 2 (12 total, no overlap, no gap — offset pagination per `pagination.md` §3); `Σ rows.amount = total.value = 178500` with `relation: "exact"` (`AC-FR018-02`, `DATA-REQ-006`).
- Step 3 → identical rows and totals on the repeat (all endpoints are pure reads, `analytics.md` §2); store B's response contains only its own rows and its own `total` — cross-store rows are never returned (`BR-VND-07`, `AC-FR018-01`, `DATA-REQ-008`).
- Step 4 → unknown family → `400 VALIDATION_ERROR` (documented family enum, `API-ANL-002`); malformed date → `400 VALIDATION_ERROR` with `details[]` — no partial data or 500 (`api-conventions.md` §5).
