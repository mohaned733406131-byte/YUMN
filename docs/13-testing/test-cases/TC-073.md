# TC-073 — Shipping contract and data store contain no GPS/location coordinates

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that no shipping endpoint, DTO, response payload or database column ever requests, accepts or stores GPS/location data (`C-16`, `BR-SHP-05`), and that delivery/code data stays strictly scoped by role (assignee courier, order owner, admin). | security | P0 | Yes — Jest + Supertest + contract scan |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Exported OpenAPI document for group `API-SHP-001…016` and the database migration set are available to the test runner as build artifacts. |
| 2 | `DLV-4471` is `OUT_FOR_DELIVERY` (code `482913`), assignee courier `790000011`; courier `790000012` is a same-zone courier **not** assigned to it; buyer `771234567` owns `ORD-7F3A21`. |
| 3 | Tokens seeded for: assignee courier `790000011`, non-assignee courier `790000012`, buyer `771234567`, customer `771234568`, `ADMIN`. |

## Test Data

| Field | Value |
|---|---|
| delivery / order | `DLV-4471` / `ORD-7F3A21` / `SUB-9C1104` |
| injected GPS keys | body extras `{"lat":15.3694,"lng":44.1910,"latitude":15.3694,"longitude":44.1910,"accuracy":5}` |
| forbidden-key regex | `lat\|lng\|latitude\|longitude\|geo\|accuracy\|heading\|speed\|location` |

## Steps
1. Contract scan: grep the exported OpenAPI for `API-SHP-001…016` request/response schemas with the forbidden-key regex; list any hits.
2. Strict-DTO probe: `POST /deliveries/DLV-4471/pickup`, `POST /deliveries/DLV-4471/transit` and `POST /deliveries/DLV-4471/failed-attempt` each with a valid body **plus** the injected GPS keys.
3. Persisted-data scan: inspect the delivery/shipment/order tables and migrations for coordinate columns or GIS types (`geometry`, `geography`, `point`, `lat`, `lng`).
4. As non-assignee courier `790000012`, `GET /deliveries/DLV-4471`; as customer `771234568`, same call; as `ADMIN`, same call.
5. As assignee courier `790000011`, `GET /deliveries/DLV-4471` → inspect `dropoff` and `pickup` fields; as buyer `771234567`, `GET /orders/ORD-7F3A21/delivery-code`.

## Expected Result
- Step 1 → zero hits across all `API-SHP` schemas — no endpoint requests or returns location data (`BR-SHP-05`, `C-16`, `AC-FR015-05`).
- Step 2 → every call returns `400 VALIDATION_ERROR` with per-field `details[]` naming the offending unknown properties (strict whitelist DTO pipes, `api-conventions.md` §5); nothing is persisted — no coordinate values appear in any subsequent response or row.
- Step 3 → no coordinate/GIS columns exist anywhere in the shipping path — location data is never stored (`BR-SHP-05`, `C-16`).
- Step 4 → non-assignee courier → `404 NOT_FOUND` (couriers see only assigned jobs); other customer → `403 FORBIDDEN` (`BR-ORD-09`, `DATA-REQ-008`); `ADMIN` → `200` with `recipientNameMasked` / `recipientPhoneMasked` only (`API-SHP-003`, `BR-FIN-02` masking).
- Step 5 → assignee sees address lines, district and package data only — no coordinates anywhere in the payload; buyer receives the full code `482913` for the own order only (`API-SHP-013`, `BR-SHP-02`); any courier attempt at `GET /orders/{id}/delivery-code` → `404 NOT_FOUND` (`TC-068`).
