# TC-058 — Escrow releases exactly once 7 days after DELIVERED

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that escrow stays held until exactly 7 days after DELIVERED, then releases to vendor payable once with commission booked, and that a repeated release job is a no-op. | integration | P1 | Yes — Jest + BullMQ test clock |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Order `ORD-7F3A21` / sub-order `SUB-9C1104` exists with escrow `HELD` at 14,875 YER (TC-057). |
| 2 | Sub-order is `OUT_FOR_DELIVERY`; buyer knows delivery code `482913`; test clock is controllable. |
| 3 | BullMQ queue `b07.escrow.release` can be triggered manually in staging. |

## Test Data

| Field | Value |
|---|---|
| deliveredAt | `2026-09-19T10:00:00Z` |
| release eligible at | `2026-09-26T10:00:00Z` (7 days, `C-12`) |
| commission base / rate | 12,500 YER at 10% (1000 bps) → **1,250 YER** |
| expected payable credit | 14,875 − 1,250 = **13,625 YER** |
| delivery code | `482913` |

## Steps
1. `POST /deliveries/del-881/code` body `{"code":"482913"}` → 200 `DELIVERED` stamped `2026-09-19T10:00:00Z`.
2. `GET /wallet/escrow?orderId=ORD-7F3A21` → `deliveredAt`, `releaseEligibleAt = 2026-09-26T10:00:00Z`.
3. Set clock to `2026-09-25T23:59:00Z`, run job `b07.escrow.release`, re-read the escrow row.
4. Set clock to `2026-09-26T10:00:00Z` and run `b07.escrow.release` twice (two sweeps, same payload).
5. `GET /wallet/escrow`, `GET /store/finance/overview`, `GET /orders/ORD-7F3A21/timeline`.
6. Query `SELECT COUNT(*) FROM b07.wallet_transaction WHERE reference_id = 'SUB-9C1104' AND type = 'ESCROW_RELEASE';`

## Expected Result
- Step 3: escrow unchanged — `state = HELD`, `availablePayable = 0` YER (release never precedes day 7, `BR-ESC-01`).
- Step 4 first run: `state = RELEASED`, `released_at = 2026-09-26T10:00:00Z`, `commission_rate_bps = 1000`, `commission_amount_yer = 1250`.
- Second run: no-op — exactly one release ledger pair; `availablePayable = 13625` YER, never 27,250 YER (`BR-PAY-08` idempotent release).
- Timeline gains exactly one `DELIVERED → COMPLETED` entry with `actorRole = SYSTEM`, `BR-ORD-03` append-only.
- `SUM(amount_yer) = 0` and an immutable audit row `action = escrow.release` exists (`SEC-REQ-010`).
