# TC-077 — Undecided return past 48 hours auto-escalates to the admin queue and the admin decision is audited

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that a return left `RETURN_REQUESTED` for more than 48 hours is flagged `overdue` for the vendor, auto-escalated to `GET /admin/returns` with `escalated: true` and an admin notification, that only `ADMIN` may decide (Moderator read-only), and that every admin decision writes an immutable audit entry. | integration | P0 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | `RET-8847` (order `ORD-7F3A24`, `SUB-9C1108`) is `RETURN_REQUESTED`, openedAt `2026-09-24T09:00:00+03:00` ⇒ decisionDueAt `2026-09-26T09:00:00+03:00`; clock `2026-09-26T13:00:00+03:00` (4 h past SLA). |
| 2 | Tokens: vendor `779876543`, `ADMIN`, `MODERATOR`. |
| 3 | `GET /admin/returns?overdue=true` returns no item for `RET-8847` before the scheduler tick. |

## Test Data

| Field | Value |
|---|---|
| return | `RET-8847`, decisionDueAt `2026-09-26T09:00:00+03:00` |
| admin decision | `POST /admin/returns/RET-8847/approve {"reason":"vendor missed the decision SLA; policy supports the return"}` |
| audit probe | `POST /admin/audit-log` (must be refused) |

## Steps
1. Run the scheduler tick at `2026-09-26T13:00:00+03:00`; as vendor, `GET /store/returns?page=1&sort=decisionDueAt_asc`.
2. As `ADMIN`, `GET /admin/returns?overdue=true&sort=decisionDueAt_asc`; read the admin notification outbox.
3. As `MODERATOR`, `GET /admin/returns?overdue=true`, then `POST /admin/returns/RET-8847/approve {"reason":"moderator attempt"}`.
4. As `ADMIN`, `POST /admin/returns/RET-8847/approve {}` (no reason), then with the full reason body.
5. `GET /admin/audit-log?targetId=RET-8847`; then attempt `POST /admin/audit-log {"action":"test"}`.
6. As `ADMIN`, `POST /admin/returns/RET-8847/reject {"reason":"..."}` (already decided).

## Expected Result
- Step 1 → the vendor queue item shows `overdue: true` (`API-RET-004`) — the case is surfaced, never left pending (`returns.md` §2 escalation note).
- Step 2 → `200` queue contains `{ returnId: "RET-8847", escalated: true, vendorDecisionOverdue: true, decisionDueAt: "2026-09-26T09:00:00+03:00" }` (`API-RET-010`); an admin notification for the breached SLA was emitted (`BR-NTF-01`).
- Step 3 → Moderator read succeeds (`200`, scoped fields) but the approve attempt returns `403 FORBIDDEN` — no decision powers outside `ADMIN` (`SEC-REQ-004`, `API-RET-011`).
- Step 4 → first call `422 REASON_REQUIRED`; second call `200 { state: "RETURN_APPROVED", version, auditId }` — admin is final authority with an audit entry (`BR-RET-06`, `BR-PLT-06`, `AC-FR020-01`).
- Step 5 → one audit item `{ action: "return.approve", actorRole: "ADMIN", targetId: "RET-8847", reason, correlationId }` readable via `API-ADM-024`; the write attempt returns `405 AUDIT_LOG_IMMUTABLE` — the log is append-only (`SEC-REQ-010`).
- Step 6 → `409 STATE_CONFLICT` — a decided return cannot be decided again (`C-09`, `BR-RET-02`).
