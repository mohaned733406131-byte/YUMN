# TC-052 — Vendor force-actions on a DELIVERED order are denied with no state, money or history change

| Field | Value |
|---|---|
| Objective | Verify that a vendor cannot act on a sub-order that has reached `DELIVERED`: cancellation is refused with `409 CANCEL_WINDOW_CLOSED`, re-confirmation with `409 STATE_CONFLICT`, admin-force endpoints with `403 FORBIDDEN`, and foreign sub-orders with `404` — leaving escrow, ledger and history untouched. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Order `ORD-052` (vendor `779876543`, sub `SUB-052A`, total 14,875 YER) is `DELIVERED`, escrow held, `releaseEligibleAt = deliveredAt + 7 d`.
- Vendor staff account `779876546` (role `Editor`) and a second vendor `779876547` (store `sanaa-perfumes`) hold valid tokens.

## Test Data

| Field | Value |
|---|---|
| Target | `ORD-052` / `SUB-052A`, state `DELIVERED` |
| Attempts | vendor cancel, vendor re-confirm, admin force as vendor, cross-store cancel |
| Snapshot | `version`, history count, `amountHeld 14875`, balance, ledger sum before each attempt |

## Steps
1. Vendor `POST /store/orders/{id}/cancel` `{"reason":"نحتاج إعادة الشحن"}`.
2. Vendor `POST /store/orders/{id}/confirm` `{"note":"تأكيد مجدد"}`.
3. Vendor `POST /admin/orders/{id}/transition` `{"subOrderId":"SUB-052A","toState":"CANCELLED","reason":"override"}`.
4. Vendor of `sanaa-perfumes` calls `POST /store/orders/{ORD-052}/cancel` (foreign sub-order).
5. Re-read `GET /orders/{id}`, `GET /orders/{id}/timeline`, `GET /wallet/escrow?orderId={id}`, `GET /wallet`, ledger sum.

## Expected Result
- Step 1 → `409 CANCEL_WINDOW_CLOSED` — vendor cancellation ends at `READY_FOR_PICKUP` (`BR-ORD-04`).
- Step 2 → `409 STATE_CONFLICT` — `DELIVERED → CONFIRMED` is not in the canonical table (`C-09`).
- Step 3 → `403 FORBIDDEN` — only `ADMIN` may call the force-transition endpoint (`API-ORD-014`, `FR-002`); no audit entry is written for a denied call.
- Step 4 → `404 NOT_FOUND` — cross-store access is denied at the service layer (`BR-VND-07`).
- Step 5 → state still `DELIVERED`, `version` unchanged, history row count unchanged, escrow still `HELD` for `14875` with `releaseEligibleAt` intact, **0** refund rows, wallet balance and `SUM(ledger)` unchanged.
- No cancellation/refund notification is emitted for any denied attempt; every denial carries `correlationId` and never discloses the foreign sub-order's data (`SEC-REQ-008`).
