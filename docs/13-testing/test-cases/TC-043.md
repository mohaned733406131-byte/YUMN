# TC-043 — Full lifecycle walk PLACED → COMPLETED with one immutable history row per transition

| Field | Value |
|---|---|
| Objective | Verify the canonical happy path: a single-vendor order advances through all nine fulfillment transitions to DELIVERED via the 6-digit code and reaches COMPLETED by the 7-day escrow release, with exactly one append-only `order_status_history` row per transition carrying actor, timestamp and reason where required. |
| Level | e2e |
| Priority | P0 |
| Automation | Yes — Playwright API chain (customer/vendor/courier/system roles) + BullMQ test clock |

## Preconditions
- Buyer `771234567` funded; store `tech-store` (vendor `779876543`) KYC `APPROVED`; courier `779009999` ONLINE in zone `sanaa-center`.
- Order fixture `ORD-043` is created through the real checkout (1 master + 1 sub-order, `PLACED`).
- Injectable clock; delivery code issued only at `OUT_FOR_DELIVERY` (`BR-SHP-02`).

## Test Data

| Field | Value |
|---|---|
| Order | `ORD-043` / `SUB-043A`, total `14875` YER (12,500 + 1,875 VAT + 500 shipping) |
| Actors | customer `771234567`, vendor `779876543`, courier `779009999`, `SYSTEM` |
| Delivery code | `482196` (fixture from DOC-TST-005) |
| Timing | delivered at `T0`; release eligible at `T0 + 7 days` |

## Steps
1. Vendor: `POST /store/orders/{id}/confirm` → then `/processing` → then `/ready` with `{"weightKg":1.2}`.
2. Courier: `GET /deliveries/available`, `POST /deliveries/{id}/accept` `{"offerVersion":1}`, `/pickup`, `/transit`, `/out-for-delivery`.
3. Buyer: `GET /orders/{id}/delivery-code`; courier: `POST /deliveries/{id}/code` `{"code":"482196"}`.
4. `GET /orders/{id}` → assert `state DELIVERED`, escrow `releaseEligibleAt = deliveredAt + 7d`.
5. Advance the injected clock to `T0 + 7 days + 1 min` and run the escrow release job twice.
6. `GET /orders/{id}`, `GET /orders/{id}/timeline`; SQL: read all `order_status_history` rows, `version` and escrow/ledger rows.

## Expected Result
- Step 1 → `200` each: `CONFIRMED`, `PROCESSING`, `READY_FOR_PICKUP` with `version` +1 per call and a `historyEntry` (guard: KYC approved + store active).
- Step 2 → `200` each: `ASSIGNED`, `PICKED_UP`, `IN_TRANSIT`, `OUT_FOR_DELIVERY` with `codeIssued:true` (buyer code visible only to the buyer, masked for others).
- Step 3 → `200 {state:"DELIVERED", deliveredAt, proof:{code:true, courierId}}`; wrong code would be `422 CODE_INVALID` (`BR-SHP-03`) — the delivery path never bypasses the code (`BR-ORD-08`, `C-16`).
- Step 5 → first run releases escrow exactly once; the second run is a no-op (`BR-ESC-01/02`, `BR-PAY-08`).
- Step 6 → `masterState COMPLETED`, sub-order `COMPLETED`, escrow `releasedAt` set with commission booked at release (`BR-ESC-03`).
- Timeline → exactly **9** ordered entries `PLACED→CONFIRMED→…→DELIVERED→COMPLETED`, each with `actorRole` (CUSTOMER/VENDOR/COURIER/SYSTEM), `at`, and `reason` where the transition requires one; `version` incremented 1 → 10 (`BR-ORD-03`).
- No row is ever rewritten; the walk exercises the canonical table rows only (`DOC-SA-010` §2, `TST-CON-09`).
