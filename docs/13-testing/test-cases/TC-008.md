# TC-008 — Authenticated password change invalidates every existing session

| Field | Value |
|---|---|
| Objective | Verify that `PUT /auth/password` with current password plus a `SENSITIVE_CHANGE` OTP succeeds, applies the policy to the new password, and revokes all previously issued sessions. |
| Level | integration |
| Priority | P1 |
| Automation | Yes — Jest + Supertest |

## Preconditions
- Account `771234567` has 3 active sessions: `sess_WEB` (current), `sess_ANDROID`, `sess_IOS`.
- No `SENSITIVE_CHANGE` OTP has been requested for this phone in the last 10 minutes.
- The new password differs from the stored hash.

## Test Data

| Field | Value |
|---|---|
| Phone | `771234567` |
| Current password | `Yumn#2026a` |
| New password | `Yumn#2026b` |
| Rejected new password | `Yumn2026a` (no special class change check — must still satisfy upper/lower/digit) |
| Step-up context | `SENSITIVE_CHANGE` |

## Steps
1. `POST /auth/otp/request` with `{"phone":"771234567","context":"SENSITIVE_CHANGE"}` and read the sandbox OTP `512734`.
2. `PUT /auth/password` with only `{"newPassword":"Yumn#2026b","currentPassword":"Yumn#2026a"}` (no OTP).
3. `PUT /auth/password` with `{"newPassword":"Yumn#2026b","currentPassword":"Yumn#2026a","otpCode":"512734"}`.
4. Try `GET /orders` with `sess_WEB`'s access token, then `POST /auth/refresh` with `sess_WEB`'s refresh token.
5. Repeat step 4 with `sess_ANDROID` and `sess_IOS` refresh tokens.
6. `POST /auth/login` with `{"phone":"771234567","password":"Yumn#2026a"}` (old password), then with `Yumn#2026b`.

## Expected Result
- Step 2 returns `403 OTP_NOT_VERIFIED` — a step-up OTP is mandatory for password change; no password is modified.
- Step 3 returns `204`; the stored hash is replaced with a bcrypt cost-12 hash of `Yumn#2026b`.
- Step 4 returns `401 SESSION_NOT_FOUND` on refresh — the current session is dead; the access token is rejected on its next authenticated call.
- Step 5: both other devices also fail with `401 SESSION_NOT_FOUND` — **all** sessions are invalidated, not just the current one.
- Step 6 first returns `401 INVALID_CREDENTIALS`, then `200` with a fresh single session.
- A mandatory security notification for the password change is delivered on SMS/in-app even if the user opted out of marketing.
- The OTP consumed in step 3 cannot be replayed.
