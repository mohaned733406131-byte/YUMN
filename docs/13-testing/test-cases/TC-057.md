# TC-057 — Escrow funded at PLACED on wallet payment

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that a successful wallet checkout funds one escrow hold per sub-order while the order is still PLACED and posts balanced append-only ledger rows. | integration | P1 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Buyer `771234567` wallet holds 50,000 YER credited by a verified m-Floos callback (`BR-PAY-03`). |
| 2 | Vendor `779876543` store `tech-store` is KYC APPROVED, active, commission tier 10%, selling `هاتف سامسونج` at 12,500 YER with stock 10. |
| 3 | Shipping zone `sanaa-center` prices the STANDARD method at 500 YER; API base `/api/v1` returns 200 on `/health/ready`. |

## Test Data

| Field | Value |
|---|---|
| buyer | phone `771234567`, password `Yumn#2026a` |
| totals | subtotal 12,500 + VAT 1,875 + shipping 500 = **14,875 YER** |
| idempotency keys | `chk-2026-09-26-01` (checkout session), `ord-2026-09-26-01` (order confirm) |
| expected escrow | `HELD`, 14,875 YER, sub-order `SUB-9C1104` |
| balance after payment | 35,125 YER |

## Steps
1. `POST /wallet/topups` with `Idempotency-Key: top-2026-09-26-01`, body `{"amount":50000,"method":"MFLOOS"}`; deliver the sandbox callback, then `GET /wallet` → balance 50,000 YER.
2. `POST /checkout/session` with `Idempotency-Key: chk-2026-09-26-01`, body `{"addressId":"adr-771","shippingMethod":"STANDARD","paymentMethod":"wallet"}` → 201 with `totals.grandTotal = 14875`.
3. `POST /orders` with `Idempotency-Key: ord-2026-09-26-01`, body `{"checkoutSessionId":"cs-5501","confirmTotals":true}` → 201.
4. Repeat step 3 byte-identical (same key, same body).
5. `GET /wallet/escrow?orderId=ORD-7F3A21` and `GET /wallet/transactions?type=ORDER_PAYMENT`.
6. Run `SELECT SUM(amount_yer) FROM b07.wallet_transaction;` and read the `b07.escrow` row.

## Expected Result
- Step 3 → `201 {"orderId":"ORD-7F3A21","masterState":"PLACED","subOrders":[{"id":"SUB-9C1104","total":14875,"state":"PLACED"}]}` with one balanced capture ledger pair.
- Step 4 → the **original** order and status code; no second wallet debit (`BR-ORD-06`, `BR-PAY-08`).
- `b07.escrow` row: `amount_held_yer = 14875`, `state = HELD`, `released_at IS NULL`, `release_eligible_at` absent (only `DELIVERED` starts the clock, `BR-ESC-01`).
- Wallet balance 35,125 YER and `SUM(amount_yer) = 0` (double-entry balanced, `BR-PAY-06`).
- No `b07.escrow.release` job is enqueued at `PLACED`.
