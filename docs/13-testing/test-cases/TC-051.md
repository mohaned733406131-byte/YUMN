# TC-051 — Customer order status and timeline API shape per state with correct visibility scoping

| Field | Value |
|---|---|
| Objective | Verify that the customer-facing order detail and timeline return the documented shape for orders in different states — current state, totals, escrow summary and per-transition history — and that foreign callers are denied without leaking data. |
| Level | integration |
| Priority | P2 |
| Automation | Yes — Jest + Supertest (state fixtures `PLACED`/`PROCESSING`/`DELIVERED` from DOC-TST-005) |

## Preconditions
- Orders seeded in `PLACED` (`ORD-051-P`), `PROCESSING` (`ORD-051-C`) and `DELIVERED` (`ORD-051-D`), each with complete history.
- A second customer `771999888`, the order's vendor `779876543`, and an unassigned courier `779009999` hold valid tokens.

## Test Data

| Field | Value |
|---|---|
| Orders | `ORD-051-P` (`PLACED`), `ORD-051-C` (`PROCESSING`), `ORD-051-D` (`DELIVERED`) |
| Caller | owner `771234567`; foreign customer `771999888`; vendor `779876543`; courier `779009999` (unassigned) |
| Locales | default `ar`, then `Accept-Language: en` |

## Steps
1. `GET /orders/{ORD-051-D}` and `GET /orders/{ORD-051-D}/timeline` as the owning customer.
2. Repeat step 1 for `ORD-051-P` and `ORD-051-C`; compare `masterState`, sub-order `state` and history length against each fixture's known state.
3. `GET /orders` (cursor feed) and confirm the list rows mirror the same states and totals.
4. Customer `771999888` requests `GET /orders/{ORD-051-D}` and its timeline.
5. Vendor requests `GET /orders/{ORD-051-D}` (master detail) and an unassigned courier requests the timeline.
6. Repeat step 1 with `Accept-Language: en`, then with the header omitted.

## Expected Result
- Step 1 → `200` detail `{orderId, masterState, version, totals:{subtotal, discount, vat, shippingFee, grandTotal}, payment:{method:"wallet", amount, ledgerReference, paidAt}, subOrders:[{id, storeId, storeName, state, items:[…], escrow:{status, releaseEligibleAt}}]}`.
- Step 1 timeline → `200 {orderId, entries:[{subOrderId, from, to, actorRole, actorName?, reason?, at}]}` ordered ascending by `at`, each `to` inside the 17-state vocabulary, ending at the current state.
- Step 2 → states match the fixtures exactly; history lengths differ per state (1 row at `PLACED`, 3 at `PROCESSING`, 9 at `DELIVERED`); totals identical across list and detail.
- Step 4 → `404 NOT_FOUND` with zero order fields in the body (IDOR-safe, `BR-ORD-09`, `DATA-REQ-008`).
- Step 5 → vendor master detail is served with a **masked** ship-to and only its own sub-order rows; the unassigned courier gets `403 TIMELINE_ACCESS_DENIED` (outside the visibility matrix).
- Step 6 → identical structure in both locales; localized strings and Arabic-Indic money formatting in `ar` (`BR-PAY-10`, `C-24`); all responses `Cache-Control: no-store`.
