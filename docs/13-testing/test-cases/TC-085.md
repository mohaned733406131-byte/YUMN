# TC-085 — Security notifications survive a fully opted-out user while optional categories stay silent

## Objective

| Objective | Level | Priority | Automation |
|---|---|---|---|
| Verify that after a user disables every optional (non-security) category on every channel, an OTP/security event is still delivered on all applicable channels, while an `ORDER` event produces no delivery — and that re-enabling one channel restores exactly that channel. | integration | P0 | Yes — Jest + Supertest |

## Preconditions

| # | Precondition |
|---|---|
| 1 | Buyer `771234567` (locale `ar`) has a registered push device (`token: "pushtest-buyer-1"`, `ANDROID`) so push fan-out has an active target. |
| 2 | Buyer will disable all channels for `ORDER`, `DELIVERY`, `RETURN`, `PROMOTION`, `STORE_FOLLOW`, `SYSTEM` via `PUT /notifications/preferences`; `SECURITY` cannot be touched (`PREFERENCE_IMMUTABLE`). |
| 3 | SMS and WhatsApp provider adapters are mock sandboxes logging every attempt; seeded `ORDER` event available for the post-opt-out probe. |

## Test Data

| Field | Value |
|---|---|
| opt-out matrix | every non-security category × `{SMS, WHATSAPP, IN_APP, PUSH}` → `enabled: false` |
| security probe | `POST /auth/otp/start {"phone":"771234567","context":"LOGIN"}` |
| optional probe | seeded `ORD-7F3A21` → `PLACED` event |
| channels expected (security) | `SMS`, `WHATSAPP`, `IN_APP`, `PUSH` all `SENT` |

## Steps
1. Build the opt-out `updates[]` array for all six non-security categories × four channels and `PUT /notifications/preferences`.
2. `GET /notifications/preferences` → verify the persisted matrix and the `SECURITY` row.
3. `POST /auth/otp/start {"phone":"771234567","context":"LOGIN"}` → read the security notification record from `GET /notifications?category=SECURITY` and the provider delivery logs.
4. Trigger the seeded `ORDER` event → `GET /notifications?category=ORDER&limit=10` and the delivery logs for that event.
5. `PUT /notifications/preferences {"updates":[{"category":"ORDER","channel":"PUSH","enabled":true}]}` → trigger another `ORDER` event → re-read inbox and logs.

## Expected Result
- Step 1 → `200` with the updated matrix; any attempt inside the same batch touching `SECURITY` would have failed — security rows are immutable (`API-NTF-007`, `BR-NTF-02`).
- Step 2 → all six optional categories show `channels: { SMS: false, WHATSAPP: false, IN_APP: false, PUSH: false }`; `SECURITY` row still `security: true, locked: true` with all channels `true` (`API-NTF-006`).
- Step 3 → the OTP notification exists with `channels[] = [SMS SENT, WHATSAPP SENT, IN_APP SENT, PUSH SENT]` — security notices are always delivered on all applicable channels regardless of preferences (`BR-NTF-02`, `AC-FR017-02`); the OTP itself is received and verifiable (`BR-AUTH-03`).
- Step 4 → **no** new `ORDER` notification and **no** provider delivery rows for the event — an opted-out channel receives nothing (`BR-NTF-05`, `AC-FR017-05`); unread-count by `ORDER` is unchanged.
- Step 5 → the next `ORDER` event is delivered on `PUSH` only (`channels[] = [PUSH SENT]`) — other channels remain opted out and other categories were never affected (`BR-NTF-05`).
