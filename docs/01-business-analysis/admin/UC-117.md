# UC-117 — Create a Category Node

## Header Info
- **Use Case ID:** UC-117
- **Title:** Create a Category Node
- **Actor:** Admin (ACT-04)
- **Trigger:** A new product family needs a place in the taxonomy
- **Priority:** P1
- **Goal:** Add a category node with localized name/slug that respects tree depth and slug uniqueness.
- **Preconditions:** Admin authenticated with taxonomy-write permission (ACT-04); the intended parent node exists (or a root node is chosen).

## Main Scenario
1. Admin opens the tree (UC-116), selects the parent and chooses "New category".
2. Admin enters ar/en `name`, ar/en `slug`, optional `sortOrder` and `attributeIds` → client `POST /admin/categories` (API-ADM-015).
3. System enforces the structural rules (BR-CAT-03): resulting depth ≤ 5 (`CATEGORY_DEPTH_EXCEEDED`) and slug unique within the level (`SLUG_TAKEN`).
4. On success → `201 { …category, level }`; the node appears in the tree and in storefront browsing on next read.

## Alternative Scenarios
- **A1 — Root node:** Admin omits `parentId` → a top-level category is created at level 1.
- **A2 — Attribute binding:** Admin attaches `attributeIds` so products in the node inherit filterable attributes.
- **A3 — Ordering:** Admin supplies `sortOrder` to place the node among its siblings.

## Exception Scenarios
- **E1 — Validation failure:** Empty localized name or malformed slug → 400 `VALIDATION_ERROR`; no node created.
- **E2 — Depth or slug rule violated:** 6th level or duplicate slug at the level → `CATEGORY_DEPTH_EXCEEDED`/`SLUG_TAKEN` (BR-CAT-03); nothing created.
- **E3 — Permission denied:** Moderator or non-admin attempts create → 403 `FORBIDDEN`; tree unchanged.
- **E4 — Concurrent create (same slug):** Two admins create the same slug under one parent → one `201`, the other `SLUG_TAKEN`.

## Postconditions
- A new node exists at the chosen parent with a unique per-level slug (BR-CAT-03); depth ≤ 5 holds.
- No product, order, or price change originates from taxonomy creation.

## Business Rules Applied
- BR-CAT-03

## Related Requirements
- FR-004 (Product Catalog Management)

## Permissions / Data / External Dependencies
- **Permissions:** Admin taxonomy-write scope; Moderator read-only on the tree.
- **Data involved:** Categories (name, slug, parent, sortOrder, attribute links).
- **External dependencies:** Storefront browsing and search indexing consume the new node after commit.

## Acceptance Criteria
- **AC-UC117-01:** Given a valid payload, when `POST /admin/categories` is called, then `201` returns the node with its `level` (API-ADM-015).
- **AC-UC117-02:** Given a parent at level 5, when a child is created, then `CATEGORY_DEPTH_EXCEEDED` is returned and no node is created (BR-CAT-03).
- **AC-UC117-03:** Given an existing slug at the same level, when create is attempted, then `SLUG_TAKEN` is returned (BR-CAT-03).
- **AC-UC117-04:** Given a Moderator, when create is attempted, then 403 `FORBIDDEN` and the tree is unchanged.
