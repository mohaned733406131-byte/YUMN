# UC-038 — Review Flagged Content

## Header Info
- **Use Case ID:** UC-038
- **Title:** Review Flagged Content
- **Actor:** Moderator (ACT-06)
- **Trigger:** Reviews, product listings, Q&A, or support threads receive user reports or auto-flags
- **Priority:** P1
- **Goal:** Triage and decide on flagged content (keep / hide / escalate) with audit entries and support escalation.
- **Preconditions:** Moderator authenticated with content-moderation scope (DOC-OVR-007); flagged items queued (auto-flag by system or report by Customer "report only").

## Main Scenario
1. Moderator opens the moderation queue → client `GET /moderation/flags` lists items by severity/age: review text + images, product listing, vendor response.
2. Moderator opens an item → sees content, report reasons, reporter count, author history, and policy references (BR-REV-03 format rules, BR-CAT-05 product types).
3. Moderator decides:
   - **Keep:** dismiss flags with reason → content stays visible.
   - **Hide:** `POST /moderation/{type}/{id}/hide` → review/product hidden with audit entry (BR-REV-04); author notified with reason (BR-NTF-01); store rating recomputes (BR-REV-05).
   - **Escalate:** hand to Admin for vendor-level action (suspension BR-VND-04, dispute input for UC-033) or support resolution (UC-014).
4. System writes an append-only audit entry per decision (BR-PLT-06) — Moderator cannot hide without a recorded reason.
5. Reporter(s) receive status updates on their report where applicable (BR-NTF-01, opt-out per BR-NTF-05 for non-mandatory categories).

## Alternative Scenarios
- **A1 — Vendor response to a hidden review:** Vendor may appeal through support (UC-014); Admin can restore, audited.
- **A2 — Auto-flag false positive:** System auto-flagged but content is compliant → dismiss; flagging thresholds reviewed by Admin (FR-018 metrics).
- **A3 — Support escalation path:** Moderator routes customer support threads needing platform action to Admin (support escalation is ACT-06's stated duty, DOC-OVR-007).

## Exception Scenarios
- **E1 — Moderator lacks permission for action:** Hide requires moderation scope; order/dispute actions are Admin-only → `403`, Moderator escalates instead (DOC-OVR-007).
- **E2 — Concurrent decision:** Admin and Moderator act on the same item → optimistic lock; one wins with `409` for the other.
- **E3 — Queue flood:** Flag volume spike → prioritized queue + alert; nothing dropped (NFR-014 observability).

## Postconditions
- Every flagged item reaches a decided state (kept/hidden/escalated) with audit entry (BR-PLT-06).
- No order, wallet, or escrow change directly from moderation.

## Business Rules Applied
- BR-REV-03, BR-REV-04, BR-REV-05, BR-CAT-05, BR-CAT-06, BR-VND-04, BR-NTF-01, BR-NTF-05, BR-PLT-06

## Related Requirements
- FR-006 (Reviews & Ratings), FR-017 (Notifications & Messaging), FR-020 (Platform Administration)

## Permissions / Data / External Dependencies
- **Permissions:** Moderator: content flags + support escalation only; cannot touch orders, roles, KYC, or money (DOC-OVR-007).
- **Data involved:** Flags/reports, content items, audit log, notifications.
- **External dependencies:** Auto-flag engine (System, B13); rating recompute job; support ticketing (B13).

## Acceptance Criteria
- **AC-UC038-01:** Given a flagged review, when hidden, then it is hidden with reason + audit row (BR-REV-04, BR-PLT-06).
- **AC-UC038-02:** Given a Moderator attempting a KYC decision, when submitted, then access is denied (scope per DOC-OVR-007).
- **AC-UC038-03:** Given a dismissed flag, when the author checks, then the content remains visible and no penalty is recorded.
