# UC-287 — Run the Orders Report

## Header Info
- **Use Case ID:** UC-287
- **Title:** Run the Orders Report
- **Actor:** Admin (ACT-04)
- **Trigger:** Operations or finance asks for platform order volumes, states and totals over a date range
- **Priority:** P2
- **Goal:** Produce the platform orders report for a chosen period, paged and (optionally) exported, from the same dataset the dashboard reads.
- **Preconditions:** Report family `orders` exists on the admin report endpoint (API-ANL-007); Admin holds analytics read (FR-018); date range supplied.

## Main Scenario
1. Admin requests `GET /admin/reports/orders` with `?from&to&page&pageSize&groupBy?` (API-ANL-007).
2. System validates the range and family, then returns `{ family, columns, rows, page, total }` with offset pagination.
3. Admin reads `totalsMeta` to see whether money totals are `exact` (ledger-sourced) or `estimate` (pre-backfill rollup).
4. Admin pages through the rows or narrows the range until the needed slice is visible.
5. Admin exports the same report as CSV when a file is needed (`GET /admin/reports/orders/export`, API-ANL-008) — Admin-only, capped at 50,000 rows.

## Alternative Scenarios
- **A1 — Aggregated view:** `groupBy` (e.g. by day or state) collapses rows for trend reading; totals keep their exact/estimate annotation.
- **A2 — Export refused at the cap:** more than 50,000 rows → `LIMIT_EXCEEDED`; Admin narrows the date range and re-runs (API-ANL-008).
- **A3 — Moderator viewing:** Moderator may read the report table (API-ANL-007) but is excluded from the CSV export (API-ANL-008).

## Exception Scenarios
- **E1 — Unknown family or malformed range:** `VALIDATION_ERROR` → no rows returned (API-ANL-007).
- **E2 — Non-admin export attempt:** `FORBIDDEN` → no file streamed, nothing written (API-ANL-008).
- **E3 — Analytics store slow/unavailable:** the read fails with a temporary error → no partial table is shown; retries use the same request.

## Postconditions
- Success: Admin holds the orders report for the requested period (screen or CSV); all report endpoints are reads — no order state changed.
- Failure: no partial table or file exists; the underlying orders are untouched.

## Business Rules Applied
- BR-ORD-02 (master/sub totals the report aggregates)

## Related Requirements
- FR-018 (Analytics & Reporting)
- FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Admin (ACT-04) report + export; Moderator report read only (API-ANL-007/008).
- **Data involved:** order aggregates, per-state counts, money totals with exact/estimate annotation (read).
- **External dependencies:** pre-aggregation rollups refreshed on state transitions plus nightly backfill; append-only ledger for exact money (block B07).

## Acceptance Criteria
- **AC-UC287-01:** Given a valid date range, when the `orders` report is requested, then columns, paged rows and totals are returned (API-ANL-007).
- **AC-UC287-02:** Given a report run, when totals are inspected, then each is labelled `exact` or `estimate` — never an unlabelled number.
- **AC-UC287-03:** Given an Admin export request within 50,000 rows, when it is made, then a CSV matching the on-screen report is streamed (API-ANL-008).
- **AC-UC287-04:** Given a Moderator, when export is attempted, then it returns `FORBIDDEN` (API-ANL-008).
