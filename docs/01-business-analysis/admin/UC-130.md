# UC-130 — Run the Delivery Performance Report

## Header Info
- **Use Case ID:** UC-130
- **Title:** Run the Delivery Performance Report
- **Actor:** Admin (ACT-04)
- **Trigger:** Operations want delivery KPIs (on-time rate, failed attempts, confirmation outcomes) for a period
- **Priority:** P2
- **Goal:** Produce a read-only delivery performance report with correctly labeled totals for a chosen period.
- **Preconditions:** Admin authenticated with analytics-read permission (ACT-04); date range selected; report families exist server-side (`delivery` among them).

## Main Scenario
1. Admin opens the reports console and selects family `delivery` with a date range and optional grouping → client `GET /admin/reports/delivery` (API-ANL-007, family=delivery).
2. System queues the report computation on the analytics queue named per the `{block}.{entity}.{action}` convention (BR-PLT-01).
3. System returns columns and rows: on-time delivery percentage, failed attempt counts, confirmation outcomes, and per-period aggregates for the range.
4. Every total carries exact/estimate metadata so pre-backfill aggregates are labeled rather than presented as exact.
5. Admin groups/filters by period, compares against the prior period, and reads the labeled totals.
6. The report is a pure read — no operational state changes; CSV export is a separate use case (UC-086).

## Alternative Scenarios
- **A1 — Grouping change:** admin re-runs with week/month grouping → same family, new projection.
- **A2 — Estimate before rollup:** heavy aggregates land before the nightly backfill → totals labeled as estimates until refreshed.
- **A3 — Moderator read:** a Moderator may read platform reports (report family access includes MODERATOR) but exports stay Admin-only.
- **A4 — Narrow range:** single-day range → small result set with exact totals where sourced from the ledger/order history.

## Exception Scenarios
- **E1 — Invalid parameters:** unknown family or malformed dates → `VALIDATION_ERROR`, no data returned.
- **E2 — Empty range:** no deliveries in the period → zero rows with an exact `0` total, not an error.
- **E3 — Permission denied:** caller without analytics scope → `403 FORBIDDEN`.
- **E4 — Job delayed:** computation still queued → client waits/retries; the job stays on its named queue (BR-PLT-01) until served.

## Postconditions
- Report delivered for family `delivery` with labeled totals; platform data unchanged.
- Admin has a defensible read of delivery performance for the period.

## Business Rules Applied
- BR-PLT-01

## Related Requirements
- FR-015 (Shipping & Delivery), FR-018 (Analytics & Reporting)

## Permissions / Data / External Dependencies
- **Permissions:** Admin analytics-read; Moderator read permitted for report families, export Admin-only (UC-086).
- **Data involved:** Delivery/order aggregates, report rows/columns, totals metadata.
- **External dependencies:** Analytics report queue (B11); pre-aggregated rollups from order/delivery history.

## Acceptance Criteria
- **AC-UC130-01:** Given family `delivery` and a date range, when run, then columns and rows for that family return.
- **AC-UC130-02:** Given a report job, when queued, then it lands on the `{block}.{entity}.{action}` analytics queue (BR-PLT-01).
- **AC-UC130-03:** Given aggregates computed before nightly backfill, when rendered, then totals carry exact/estimate labels.
- **AC-UC130-04:** Given an unknown family parameter, when submitted, then `VALIDATION_ERROR` returns with no rows.
