# UC-120 — List the Attribute Dictionary

## Header Info
- **Use Case ID:** UC-120
- **Title:** List the Attribute Dictionary
- **Actor:** Admin (ACT-04)
- **Trigger:** An admin reviews the attributes that drive variants and filters
- **Priority:** P2
- **Goal:** Read the full attribute dictionary with types, options, active flags, and usage counts in one offset list.
- **Preconditions:** Admin (or Moderator read scope) authenticated (ACT-04); the dictionary exists or is empty.

## Main Scenario
1. Admin opens Catalog → Attributes → client `GET /admin/attributes` (API-ADM-018) with `?page&pageSize&type&active`.
2. System returns offset rows: ar/en `name`, `type` (TEXT/NUMBER/SELECT/MULTI_SELECT), `options?`, `active`, `productCount`, plus exact `total`.
3. Admin reviews dictionary coverage against product needs — attributes underpin variant dimensions whose limits are ≤5 dimensions and ≤50 combinations (BR-CAT-02).
4. No record is modified; create/update/delete happen in UC-121…UC-123.

## Alternative Scenarios
- **A1 — Filter by type:** Admin filters `type=SELECT` to see option-based attributes.
- **A2 — Active-only view:** Admin filters `active=true` for the currently usable set.
- **A3 — Moderator read:** A Moderator opens the same read-only dictionary; attribute writes stay Admin-only.

## Exception Scenarios
- **E1 — Permission denied:** A caller outside admin/moderator read scope → 403 `FORBIDDEN`; no data returned.
- **E2 — Validation failure:** Unknown `type` value or non-numeric paging → 400 `VALIDATION_ERROR`; no data returned.
- **E3 — Concurrent edit:** Another admin updates or disables an attribute while this list is open → the row is stale; reload shows the current options/active flag.

## Postconditions
- Dictionary reviewed read-only; no attribute state changed by listing.
- List reflects latest committed attribute records after reload.

## Business Rules Applied
- BR-CAT-02

## Related Requirements
- FR-004 (Product Catalog Management)

## Permissions / Data / External Dependencies
- **Permissions:** Admin and Moderator read; attribute create/update/delete is Admin-only (UC-121…UC-123).
- **Data involved:** Attributes (name, type, options, active, productCount); no audit entries from reads.
- **External dependencies:** Product variant and filter/faceting features consume the same dictionary.

## Acceptance Criteria
- **AC-UC120-01:** Given attributes of several types, when the list is read, then each row shows `type`, `options`, `active` and `productCount` (API-ADM-018).
- **AC-UC120-02:** Given `type=SELECT`, when filtered, then only option-based attributes are returned.
- **AC-UC120-03:** Given the dictionary, when inspected, then variant limits of ≤5 dimensions and ≤50 combinations remain the governing constraint (BR-CAT-02).
- **AC-UC120-04:** Given an invalid filter, when requested, then 400 `VALIDATION_ERROR` and no partial data.
