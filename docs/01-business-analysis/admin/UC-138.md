# UC-138 — Read the Return Queue as Moderator (Read-Only)

## Header Info
- **Use Case ID:** UC-138
- **Title:** Read the Return Queue as Moderator (Read-Only)
- **Actor:** Moderator (ACT-06)
- **Trigger:** A Moderator needs return-case context to advise on an escalated or disputed return
- **Priority:** P2
- **Goal:** Read the platform return queue and case details to prepare advisory input for Admin, changing no return state.
- **Preconditions:** Moderator authenticated with READ-ONLY scope (ACT-06); may list and open returns but cannot approve, reject, or decide — those writes are Admin-only and refused server-side; escalation hand-off to Admin is the only output.

## Main Scenario
1. Moderator opens the returns view → `GET /admin/returns` (API-RET-010, roles include MODERATOR) with state/overdue filters and the Moderator's scoped fields.
2. System returns rows whose states follow the canonical return sequence `RETURN_REQUESTED → APPROVED/REJECTED → RETURN_RECEIVED → REFUNDED` (BR-RET-02), with overdue/escalated markers.
3. Moderator opens a case → items, reason, policy window, decision history, and inspection notes — all read-only projections.
4. Moderator interprets the case posture (stalled, escalated, or conflicting) and prepares an advisory note for Admin; no decision is written.
5. Any approve/reject attempt is refused server-side with `403 FORBIDDEN` — those endpoints are Admin-only.
6. When a decision is warranted, Moderator escalates to Admin (UC-125), which issues the final audited decision.

## Alternative Scenarios
- **A1 — Filter by state/overdue:** narrow to `RETURN_REQUESTED` + overdue → scoped rows, still read-only.
- **A2 — Escalated case review:** case marked escalated after the vendor SLA → Moderator gathers context and hands off (UC-125).
- **A3 — Empty queue:** no matching returns → friendly empty state, not an error.

## Exception Scenarios
- **E1 — Permission denied:** Moderator attempts approve/reject → `403 FORBIDDEN`; return state unchanged.
- **E2 — Already-resolved case:** return already `RETURN_REJECTED`/`REFUNDED` → read-only terminal view; no further input possible.
- **E3 — Empty queue:** zero rows for the filter → empty state with filters intact.
- **E4 — SLA breach seen:** overdue/escalated flag observed → Moderator escalates to Admin (UC-125) rather than deciding.

## Postconditions
- No return state changed; queue and case read successfully.
- Advisory input delivered to Admin where a decision is needed.

## Business Rules Applied
- BR-RET-02

## Related Requirements
- FR-016 (Returns & Refunds)

## Permissions / Data / External Dependencies
- **Permissions:** Moderator READ-ONLY on returns — no approve/reject/inspection writes; Admin holds all return decisions (UC-125).
- **Data involved:** Return queue rows, states, policy windows, decision history (read projections).
- **External dependencies:** Admin return arbitration (B09) for hand-off; delivery/pickup state feeds (B08).

## Acceptance Criteria
- **AC-UC138-01:** Given a Moderator, when the return queue opens, then rows render read-only with canonical states (BR-RET-02).
- **AC-UC138-02:** Given a Moderator approve attempt, when submitted, then `403 FORBIDDEN` returns and the state is unchanged.
- **AC-UC138-03:** Given an escalated return, when listed, then the overdue/escalated marker is visible.
- **AC-UC138-04:** Given an empty queue, when opened, then an empty state renders without an error.
