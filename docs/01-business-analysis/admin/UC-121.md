# UC-121 — Create an Attribute

## Header Info
- **Use Case ID:** UC-121
- **Title:** Create an Attribute
- **Actor:** Admin (ACT-04)
- **Trigger:** Products need a new variant dimension or filter facet
- **Priority:** P1
- **Goal:** Add a localized attribute to the dictionary that products can use for variants and filtering within variant limits.
- **Preconditions:** Admin authenticated with taxonomy-write permission (ACT-04); the attribute name is not already used.

## Main Scenario
1. Admin opens Catalog → Attributes → "New attribute" and enters ar/en `name`, `type`, optional `options` (for SELECT/MULTI_SELECT), `unit`, and `filterable`.
2. Client sends `POST /admin/attributes` (API-ADM-019).
3. System validates the payload — localized name required, `options` mandatory for option types, no duplicate name (`DUPLICATE_RESOURCE`) → `201 { …attribute }`.
4. The new attribute becomes available for product variant dimensions and filters, within the variant budget of ≤5 dimensions and ≤50 combinations (BR-CAT-02).

## Alternative Scenarios
- **A1 — Filterable facet:** Admin sets `filterable: true` → the attribute is exposed in catalog filtering.
- **A2 — Option list:** Admin creates a SELECT attribute with explicit options → each option may feed variant combinations (BR-CAT-02).
- **A3 — Descriptive attribute:** Admin creates a non-filterable TEXT/NUMBER attribute used only for display.

## Exception Scenarios
- **E1 — Validation failure:** Empty localized name or a SELECT type without options → 400 `VALIDATION_ERROR`; nothing created.
- **E2 — Duplicate name:** Name already exists → `DUPLICATE_RESOURCE`; admin picks another name.
- **E3 — Permission denied:** Moderator or non-admin attempts create → 403 `FORBIDDEN`; dictionary unchanged.
- **E4 — Concurrent create (same name):** Two admins submit the same name → one `201`, the other `DUPLICATE_RESOURCE`.

## Postconditions
- One attribute exists in the dictionary, localized and typed; variant limits remain satisfiable (BR-CAT-02).
- No product, order, or price record is modified by attribute creation.

## Business Rules Applied
- BR-CAT-02

## Related Requirements
- FR-004 (Product Catalog Management)

## Permissions / Data / External Dependencies
- **Permissions:** Admin taxonomy-write scope; Moderator read-only on the dictionary.
- **Data involved:** Attributes (name, type, options, unit, filterable, active).
- **External dependencies:** Product editing and catalog filters consume the new attribute after commit.

## Acceptance Criteria
- **AC-UC121-01:** Given a valid payload, when `POST /admin/attributes` is called, then `201` returns the attribute (API-ADM-019).
- **AC-UC121-02:** Given a SELECT attribute without options, when created, then 400 `VALIDATION_ERROR` and no record exists.
- **AC-UC121-03:** Given an existing name, when create is attempted, then `DUPLICATE_RESOURCE` is returned.
- **AC-UC121-04:** Given a Moderator, when create is attempted, then 403 `FORBIDDEN` and the dictionary is unchanged.
