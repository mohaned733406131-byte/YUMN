# UC-123 — Delete an Unused Attribute

## Header Info
- **Use Case ID:** UC-123
- **Title:** Delete an Unused Attribute
- **Actor:** Admin (ACT-04)
- **Trigger:** A mistakenly created or obsolete attribute must be purged
- **Priority:** P2
- **Goal:** Permanently delete an attribute that no product uses, refusing deletion while any product references it.
- **Preconditions:** Admin authenticated with taxonomy-write permission (ACT-04); the target attribute exists and reports `productCount: 0` (UC-120).

## Main Scenario
1. Admin verifies in the dictionary that the attribute's `productCount` is 0.
2. Admin selects "Delete" and confirms → client `DELETE /admin/attributes/{id}` (API-ADM-021).
3. System rechecks usage at commit time; if any product references the attribute → `STATE_CONFLICT` with the guidance to disable instead.
4. On success → `204`: the attribute is hard-deleted; variant/SKU integrity of remaining products is untouched (BR-CAT-02).

## Alternative Scenarios
- **A1 — In use → disable instead:** Usage is non-zero → admin falls back to disabling the attribute (UC-122) rather than deleting.
- **A2 — Delete after cleanup:** Products are edited to drop the attribute first, then deletion succeeds.
- **A3 — Keep for filters:** Attribute still filters the catalog → admin cancels the delete.

## Exception Scenarios
- **E1 — Attribute in use:** Any product references it → `STATE_CONFLICT`; nothing is deleted (BR-CAT-02 integrity preserved).
- **E2 — Permission denied:** Moderator or non-admin attempts delete → 403 `FORBIDDEN`; attribute remains.
- **E3 — Concurrent first-use:** A product starts referencing the attribute between check and commit → `STATE_CONFLICT`; the delete is refused.

## Postconditions
- The attribute is hard-deleted (or untouched on failure); no product loses variant/SKU data (BR-CAT-02).
- Product counts and filters of other attributes are unaffected.

## Business Rules Applied
- BR-CAT-02

## Related Requirements
- FR-004 (Product Catalog Management)

## Permissions / Data / External Dependencies
- **Permissions:** Admin taxonomy-write scope; Moderator read-only on the dictionary.
- **Data involved:** Attributes (hard delete), product-attribute references.
- **External dependencies:** Product editing and catalog filters refresh after commit.

## Acceptance Criteria
- **AC-UC123-01:** Given an attribute with `productCount: 0`, when delete is called, then `204` is returned and the attribute is gone from the list.
- **AC-UC123-02:** Given an attribute referenced by products, when delete is attempted, then `STATE_CONFLICT` is returned and the attribute persists (BR-CAT-02).
- **AC-UC123-03:** Given a rejected delete, when products are checked, then every variant/SKU value is unchanged.
- **AC-UC123-04:** Given a Moderator, when delete is attempted, then 403 `FORBIDDEN` and the dictionary is unchanged.
