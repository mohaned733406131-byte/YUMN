# UC-271 — Assemble the Order Timeline Evidence Pack for a Dispute

## Header Info
- **Use Case ID:** UC-271
- **Title:** Assemble the Order Timeline Evidence Pack for a Dispute
- **Actor:** Admin (ACT-04)
- **Trigger:** A dispute needs an evidence pack before resolution — the panels the flow expects are the order timeline, messages, delivery proof, and photos (user-flows.md FL-07)
- **Priority:** P1
- **Goal:** Gather every read-only evidence slice for one dispute into a single reviewable pack while escrow stays frozen.
- **Preconditions:** Dispute exists and is open (`GET /disputes/{id}`, API-RET-015); escrow for affected sub-orders is frozen (BR-ORD-05); Admin holds scoped order-timeline read (BR-ORD-09).

## Main Scenario
1. Admin opens the dispute record → ground, notes, submitted evidence items, and the dispute timeline (API-RET-015).
2. Admin appends the order timeline (`GET /orders/{id}/timeline`, API-ORD-005): every `from → to` entry with actor, reason, and timestamp — append-only, never editable (BR-ORD-03).
3. Admin adds delivery proof: code verification record plus timestamp and courier identity; the optional photo is included only if stored (BR-SHP-07), with attempt history from `GET /deliveries/{id}` (API-SHP-003).
4. Admin attaches the support thread for the case (`GET /support/tickets/{id}`, API-ADM-037) and any party messages linked to the order.
5. Admin confirms visibility scope: entries are shown per BR-ORD-09 (buyer own, vendor own sub-orders, courier assigned, Admin/Moderator scoped) and the pack is stored against the dispute as read-only evidence.

## Alternative Scenarios
- **A1 — No dispute opened yet:** the pack is assembled pre-emptively for an escalation (e.g. failed-delivery escalation, BR-SHP-06) and reused when the dispute is filed.
- **A2 — Missing delivery photo:** the photo is optional and never required — code + timestamp + courier identity already constitute proof (BR-SHP-07).
- **A3 — Delivery-code lock instead:** the 3rd failed attempt auto-created a support ticket with the full timeline (BR-SHP-03) → that ticket is the delivery evidence slice.

## Exception Scenarios
- **E1 — Timeline access denied:** `TIMELINE_ACCESS_DENIED` when the caller sits outside the visibility matrix → the entry is withheld, not faked (BR-ORD-09).
- **E2 — Dispute already resolved:** further evidence submission returns `STATE_CONFLICT` (API-RET-016 rule) → pack is read-only from the resolution record.
- **E3 — Delivery record missing:** no delivery row for the sub-order → the pack notes the gap explicitly; resolution is never blocked on a fabricated proof.

## Postconditions
- A complete, read-only evidence pack exists for the dispute: dispute record, order timeline, delivery proof, support thread (FL-07).
- Escrow for the affected sub-orders remains frozen until resolution (BR-ORD-05); no timeline, history, or proof row was modified.

## Business Rules Applied
- BR-ORD-03, BR-ORD-05, BR-ORD-09, BR-SHP-03, BR-SHP-06, BR-SHP-07

## Related Requirements
- FR-012 (Order Lifecycle Management), FR-016 (Returns & Refunds)

## Permissions / Data / External Dependencies
- **Permissions:** Admin (ACT-04) scoped timeline/dispute read (rbac.md rows 3, 19); parties see only their own slice (BR-ORD-09).
- **Data involved:** dispute record and evidence, order status history, delivery attempts and proof, support thread, escrow hold state.
- **External dependencies:** delivery module (API-SHP); support ticketing (API-ADM-037); object storage for attached images (SEC-REQ-011 upload rules).

## Acceptance Criteria
- **AC-UC271-01:** Given an open dispute, when the Admin assembles the pack, then timeline, delivery proof, and support thread are all present (FL-07).
- **AC-UC271-02:** Given the order timeline, when it is exported, then every entry shows actor, reason, and timestamp and none was edited (BR-ORD-03).
- **AC-UC271-03:** Given the dispute is open, when the pack is read, then escrow for affected sub-orders is still frozen (BR-ORD-05).
- **AC-UC271-04:** Given an out-of-scope timeline entry, when the Admin requests it, then it is withheld with `TIMELINE_ACCESS_DENIED` (BR-ORD-09).
