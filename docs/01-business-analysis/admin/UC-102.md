# UC-102 — Reply to a Support Ticket Thread

## Header Info
- **Use Case ID:** UC-102
- **Title:** Reply to a Support Ticket Thread
- **Actor:** Admin (ACT-04) — support operations scope
- **Trigger:** Admin answers a customer's message in a ticket thread
- **Priority:** P1
- **Goal:** Reply to the customer in the ticket thread and notify them on their preferred channels in their locale.
- **Preconditions:** Admin or Moderator authenticated (API-ADM-038); ticket is `OPEN`/`IN_PROGRESS` (not resolved or closed); the customer ticket exists (UC-014).

## Main Scenario
1. Admin opens the ticket detail → `GET /support/tickets/{id}` (API-ADM-037) reads the full append-only thread and linked entities.
2. Admin writes a reply → `POST /support/tickets/{id}/messages` with `{ body, attachmentFileIds? }` (API-ADM-038).
3. The message is appended and the ticket moves to `IN_PROGRESS` once a staff member replies; the thread is never rewritten.
4. The customer is notified on their enabled channels — SMS, WhatsApp, in-app, push, no email in v1 (BR-NTF-01) — with the template rendered in their locale, Arabic default (BR-NTF-04).
5. The customer sees the reply in their ticket feed (rel UC-014 step4, staff side of the same thread).

## Alternative Scenarios
- **A1 — Reply with attachment:** The file passes the shared upload scan; a rejected file drops the attachment but the text is still saved.
- **A2 — Moderator reply:** Moderator replies within scope (API-ADM-038 roles) — same thread, same notification behaviour.

## Exception Scenarios
- **E1 — Resolved or closed ticket:** `TICKET_STATE_CONFLICT`; staff cannot append — the customer holds the single reopen (UC-103).
- **E2 — Foreign ticket:** Unknown or other ticket → `404 NOT_FOUND`; the ownership boundary is enforced.
- **E3 — Notification outage:** Channel delivery fails → the in-app thread remains the source of truth and the send retries in the background.
- **E4 — Concurrent customer message:** Both messages append in timestamp order; the thread stays append-only and consistent.

## Postconditions
- A staff message is appended and the ticket is `IN_PROGRESS`.
- Customer notified per preferences and locale (BR-NTF-01, BR-NTF-04); no order state changed.

## Business Rules Applied
- BR-NTF-01, BR-NTF-04

## Related Requirements
- FR-020 (Platform Administration, Settings & Audit)
- Cross-reference: rel UC-014 step4 (staff side of the customer-facing thread).

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN`/`MODERATOR` reply; the customer reads only their own thread.
- **Data involved:** Ticket messages (append-only), scanned attachments, notification fan-out records.
- **External dependencies:** Notification channels (SMS/WhatsApp/in-app/push), file scanning.

## Acceptance Criteria
- **AC-UC102-01:** Given an open ticket, when a staff reply is posted, then the message appends and status becomes `IN_PROGRESS`.
- **AC-UC102-02:** Given a customer with Arabic locale, when notified, then the template renders in Arabic (BR-NTF-04).
- **AC-UC102-03:** Given that v1 has no email channel, when notified, then only SMS/WhatsApp/in-app/push are used (BR-NTF-01).
- **AC-UC102-04:** Given a resolved ticket, when a reply is posted, then `TICKET_STATE_CONFLICT` is returned.
