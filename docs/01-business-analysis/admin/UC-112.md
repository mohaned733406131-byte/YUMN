# UC-112 — Remove a Banner

## Header Info
- **Use Case ID:** UC-112
- **Title:** Remove a Banner
- **Actor:** Admin (ACT-04)
- **Trigger:** A campaign ends early or a banner must be withdrawn
- **Priority:** P2
- **Goal:** Remove a banner from all surfaces with an audited, idempotent delete.
- **Preconditions:** Admin authenticated with content-write permission (ACT-04); the target banner exists.

## Main Scenario
1. Admin opens the banner list (UC-109), selects the banner and confirms "Remove".
2. Client sends `DELETE /admin/banners/{id}` (API-CNT-014) → `204` (idempotent).
3. System removes the banner from the admin list and from every home surface on next read.
4. System appends an audit entry for the removal — actor, entity, before/after (BR-PLT-06).

## Alternative Scenarios
- **A1 — Repeat removal:** The banner was already removed → the endpoint still answers `204` idempotently with no second content change.
- **A2 — Schedule-expired cleanup:** Admin removes a banner whose window already ended to keep the list tidy; no visible change occurs.
- **A3 — Replace campaign:** Admin removes the old banner and creates the successor (UC-110) in sequence.

## Exception Scenarios
- **E1 — Permission denied:** Moderator or non-admin attempts removal → 403 `FORBIDDEN`; banner still rendered.
- **E2 — Not found:** Unknown/foreign id → 404 `NOT_FOUND`; nothing changed.
- **E3 — Concurrent removal:** A colleague removes the banner first → this call returns `204` without duplicating the content change; the audit trail reflects the removal once (BR-PLT-06).

## Postconditions
- Banner no longer appears on any surface or in the admin list; one audit row records the removal (BR-PLT-06).
- Pages, coupons, and orders are untouched.

## Business Rules Applied
- BR-PLT-06

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))

## Permissions / Data / External Dependencies
- **Permissions:** Admin content-write scope; Moderator cannot remove banners.
- **Data involved:** Banners (removed), audit log, home surface payload.
- **External dependencies:** Home surface rendering reflects the removal on next read.

## Acceptance Criteria
- **AC-UC112-01:** Given an existing banner, when delete is called, then `204` is returned and the banner is absent from `GET /admin/banners`.
- **AC-UC112-02:** Given a removed banner, when delete is repeated, then `204` idempotently and no duplicate content change occurs.
- **AC-UC112-03:** Given a successful removal, when the audit log is read, then a removal entry with before/after exists (BR-PLT-06).
- **AC-UC112-04:** Given a Moderator, when delete is attempted, then 403 `FORBIDDEN` and the banner still renders.
