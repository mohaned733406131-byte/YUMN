# UC-095 — Approve a Newly Created Store

## Header Info
- **Use Case ID:** UC-095
- **Title:** Approve a Newly Created Store
- **Actor:** Admin (ACT-04) — vendor operations scope
- **Trigger:** Admin opens a store in `PENDING` state awaiting activation
- **Priority:** P1
- **Goal:** Activate a newly created store so its owner can start trading, but only once KYC is approved.
- **Preconditions:** Admin authenticated with approve permission (API-ADM-011 `ADMIN`); store is `PENDING`; KYC status is `APPROVED` (BR-VND-01).

## Main Scenario
1. Admin opens the pending store (UC-094) → Approve → optional note.
2. Client `POST /admin/stores/{id}/approve` (API-ADM-011).
3. System validates the KYC gate first — without `KYC = APPROVED` the call fails with `KYC_NOT_APPROVED` (BR-VND-01: no publishing before KYC approval).
4. Status transitions `PENDING → ACTIVE` and the storefront becomes visible to customers.
5. An append-only audit entry records actor, entity and before/after state (BR-PLT-06) and the `auditId` is returned.

## Alternative Scenarios
- **A1 — KYC not yet decided:** Admin is routed to the KYC decision first (UC-031); approval is impossible without it.
- **A2 — Already active:** Server returns `STATE_CONFLICT`; no duplicate activation is recorded.

## Exception Scenarios
- **E1 — Permission denied:** Moderator → `403 FORBIDDEN`; no lifecycle change.
- **E2 — KYC missing or rejected:** `KYC_NOT_APPROVED` → the store stays `PENDING`.
- **E3 — Concurrent suspension:** Another admin suspends mid-flight → `STATE_CONFLICT`; latest state wins on refetch.
- **E4 — Decision delayed:** The store waits beyond the KYC decision window while approval stays blocked — escalation is handled in the KYC queue (UC-031).

## Postconditions
- The store is `ACTIVE` and publishable (BR-VND-01), or unchanged on refusal.
- Exactly one audit entry exists for a successful approval (BR-PLT-06).

## Business Rules Applied
- BR-VND-01, BR-PLT-06

## Related Requirements
- FR-007 (Vendor Onboarding & KYC)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN` only; Moderator cannot activate stores.
- **Data involved:** Store status, KYC status, audit entry.
- **External dependencies:** KYC service (gate check); audit writer (BR-PLT-06).

## Acceptance Criteria
- **AC-UC095-01:** Given a pending store with approved KYC, when approve is posted, then status becomes `ACTIVE` and an `auditId` returns.
- **AC-UC095-02:** Given KYC not approved, when approve is posted, then `KYC_NOT_APPROVED` returns and status stays `PENDING`.
- **AC-UC095-03:** Given an already-active store, when posted, then `STATE_CONFLICT` is returned.
- **AC-UC095-04:** Given a Moderator session, when posted, then `403 FORBIDDEN` is returned.
