# UC-295 — Isolate Auto-Created Delivery-Code Tickets in the Support Queue

## Header Info
- **Use Case ID:** UC-295
- **Title:** Isolate Auto-Created Delivery-Code Tickets in the Support Queue
- **Actor:** Admin (ACT-04)
- **Trigger:** The support queue mixes manual tickets with system-generated delivery-code lockout tickets, and the auto slice needs its own triage
- **Priority:** P2
- **Goal:** Filter the support queue to `source=AUTO`, see the delivery-code lockouts clearly, and work them as a distinct backlog.
- **Preconditions:** Tickets exist with `source` and `category` fields; auto tickets were created by the delivery-code lockout rule (BR-SHP-03); Admin holds support queue read (API-ADM-039).

## Main Scenario
1. Admin opens the support queue filtered to system tickets (`GET /admin/tickets?source=AUTO`, API-ADM-039).
2. System returns ticket rows with `number`, `category`, `source`, `status`, `orderId`, `assignedTo` and `overdue`.
3. Admin reads the delivery-code lockout context: 3rd failed code attempt locked confirmation for 24 hours and auto-created the ticket (BR-SHP-03).
4. Admin opens the linked order/delivery to judge whether the lockout was courier error or buyer-side confusion.
5. Admin assigns, resolves or escalates each ticket — the auto flag distinguishes machine-created work from customer reports.

## Alternative Scenarios
- **A1 — Lockout already expired:** the 24-hour window elapsed and confirmation unlocked → Admin closes the ticket as aged-out, noting the outcome.
- **A2 — Manual tickets only:** `source=MANUAL` filter shows customer-raised tickets — no delivery-code auto tickets in view; triage continues on that slice.
- **A3 — Overdue flag set:** tickets past their SLA sort first (`overdue`), so the auto backlog is worked oldest-first.

## Exception Scenarios
- **E1 — Invalid filter combination:** `VALIDATION_ERROR` → no rows returned, nothing assigned (API-ADM-039).
- **E2 — Ticket already resolved:** assignment/resolve attempts on a closed ticket hit `STATE_CONFLICT` → queue refreshed, no double-close.
- **E3 — Linked order missing:** the ticket references a purged/unknown order → ticket handled standalone with a note; no orphan pointer is created.

## Postconditions
- Success: the auto-created slice is isolated and each ticket carries an owner/status; the underlying delivery lockout state is unchanged by the queue work itself.
- Failure: no ticket mutated — the queue read is non-destructive and no delivery state was touched.

## Permissions / Data / External Dependencies
- **Permissions:** Admin (ACT-04) support queue (API-ADM-039); Moderator may read the queue subset; assignment/resolve is Admin-scoped.
- **Data involved:** support tickets (source, category, status, assignee, overdue), linked delivery/order rows (read).
- **External dependencies:** delivery code verification flow that raises the lockout (block B08); notification of the affected parties (block B10).

## Acceptance Criteria
- **AC-UC295-01:** Given auto-created tickets exist, when `source=AUTO` is applied, then only system-created tickets are returned (API-ADM-039).
- **AC-UC295-02:** Given a 3rd failed delivery-code attempt, when the rule fires, then confirmation is locked 24 h and a support ticket exists (BR-SHP-03).
- **AC-UC295-03:** Given an invalid filter, when the queue is requested, then `VALIDATION_ERROR` is returned and no rows change.
- **AC-UC295-04:** Given a resolved ticket, when it is re-resolved, then `STATE_CONFLICT` prevents a duplicate closure.
