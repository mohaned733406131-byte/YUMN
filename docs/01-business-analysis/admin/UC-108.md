# UC-108 — Archive a CMS Page

## Header Info
- **Use Case ID:** UC-108
- **Title:** Archive a CMS Page
- **Actor:** Admin (ACT-04)
- **Trigger:** A CMS page is obsolete, superseded, or requested for removal
- **Priority:** P2
- **Goal:** Soft-archive a page so its public route stops resolving while history is preserved and the action is audited.
- **Preconditions:** Admin authenticated with content-write permission (ACT-04); the target page exists (DRAFT or PUBLISHED).

## Main Scenario
1. Admin opens Content → Pages (API-CNT-005), locates the page and selects "Archive".
2. Client sends `DELETE /admin/pages/{id}` (API-CNT-010) after confirmation.
3. System soft-deletes the page → `204`; the public route `GET /pages/{slug}` immediately returns 404 (route stops resolving) while the record and history are kept.
4. System appends an audit entry for the privileged removal — actor, entity, before/after (BR-PLT-06).
5. The page leaves the default admin list; it remains inspectable through status filters/history.

## Alternative Scenarios
- **A1 — Archive an unpublished draft:** Page never published → same soft archive, no public impact ever occurred.
- **A2 — Replacement content:** Admin archives the old page, then creates and publishes a replacement (UC-105, UC-107) under a new slug.
- **A3 — Archive for campaign review:** Page referenced by marketing material → admin re-checks references before archiving.

## Exception Scenarios
- **E1 — Permission denied:** Moderator or non-admin attempts archive → 403 `FORBIDDEN`; page still resolves publicly.
- **E2 — Referenced by an active campaign:** System refuses with `STATE_CONFLICT`; the admin detaches the campaign reference first, then retries.
- **E3 — Concurrent/duplicate archive:** A colleague archives first → this call returns `NOT_FOUND`/conflict; the page is archived once with a single audit row (BR-PLT-06).

## Postconditions
- Page is archived: public route 404, record retained (soft delete), one audit row exists (BR-PLT-06).
- No order, coupon, or banner change originates from archiving.

## Business Rules Applied
- BR-PLT-06

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))

## Permissions / Data / External Dependencies
- **Permissions:** Admin content-write scope; Moderator cannot archive.
- **Data involved:** CMS pages (archive flag, history), audit log, public content cache.
- **External dependencies:** Public page route/cache invalidation so the slug stops resolving immediately.

## Acceptance Criteria
- **AC-UC108-01:** Given a PUBLISHED page, when archive succeeds, then `204` is returned and the public read returns 404.
- **AC-UC108-02:** Given an archived page, when the admin list is read, then the page is absent from the default list but its record persists.
- **AC-UC108-03:** Given a successful archive, when the audit log is read, then an archive entry with before/after exists (BR-PLT-06).
- **AC-UC108-04:** Given a page referenced by an active campaign, when archive is attempted, then `STATE_CONFLICT` is returned and the page still resolves.
