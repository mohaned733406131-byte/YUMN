# UC-289 — Run the Returns and Refunds Report

## Header Info
- **Use Case ID:** UC-289
- **Title:** Run the Returns and Refunds Report
- **Actor:** Admin (ACT-04)
- **Trigger:** Finance or operations reviews return volume and refund payouts for a period (SLA checks, dispute trends, wallet outflow)
- **Priority:** P2
- **Goal:** Produce the platform returns/refunds report for a date range, with refund amounts that tie to the refund rules.
- **Preconditions:** Report family `returns` exists on the admin report endpoint (API-ANL-007); Admin holds analytics read (FR-018); date range supplied.

## Main Scenario
1. Admin requests `GET /admin/reports/returns` with `?from&to&page&pageSize&groupBy?` (API-ANL-007).
2. System returns columns, paged rows and totals for returns and refunds in the range.
3. Admin reads `totalsMeta` — money totals carry exact/estimate labels; ledger-sourced refund amounts are exact.
4. Admin reconciles the figures against the refund receipt view for spot-checked orders (API-WAL-014).
5. Admin exports CSV when needed (`GET /admin/reports/returns/export`, API-ANL-008) within the 50,000-row cap.

## Alternative Scenarios
- **A1 — Refund composition check:** rows are compared against the refund composition rule — item value always, shipping only for platform/vendor fault (BR-RET-03).
- **A2 — SLA cross-check:** refunded rows feed the 3-business-day credit verification (UC-286) for the same period.
- **A3 — Moderator viewing:** Moderator reads the table but cannot export (API-ANL-008).

## Exception Scenarios
- **E1 — Unknown family or malformed range:** `VALIDATION_ERROR` → no rows returned (API-ANL-007).
- **E2 — Export over the cap:** `LIMIT_EXCEEDED` → no partial file; Admin narrows the range (API-ANL-008).
- **E3 — Report disagrees with receipts on a spot check:** the discrepancy is escalated as a reconciliation issue — money data is never adjusted to make the report balance.

## Postconditions
- Success: Admin holds the returns/refunds report for the period; all endpoints are reads — no return, refund or ledger row changed.
- Failure: no partial table or file exists; the underlying records are untouched.

## Permissions / Data / External Dependencies
- **Permissions:** Admin (ACT-04) report + export; Moderator report read only (API-ANL-007/008).
- **Data involved:** return counts, refund amounts, credit statuses, period totals (read).
- **External dependencies:** pre-aggregation rollups + nightly backfill; wallet/ledger for exact refund amounts (block B07).

## Acceptance Criteria
- **AC-UC289-01:** Given a valid range, when the `returns` report is requested, then columns, paged rows and totals are returned (API-ANL-007).
- **AC-UC289-02:** Given refund rows in the report, when amounts are inspected, then they follow the refund composition rule (BR-RET-03).
- **AC-UC289-03:** Given money totals, when they are read, then each carries an exact/estimate label.
- **AC-UC289-04:** Given a Moderator, when export is attempted, then it returns `FORBIDDEN` (API-ANL-008).
