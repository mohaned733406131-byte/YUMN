# UC-109 — List Banners with Schedule and Targeting

## Header Info
- **Use Case ID:** UC-109
- **Title:** List Banners with Schedule and Targeting
- **Actor:** Admin (ACT-04)
- **Trigger:** An admin reviews the home-banner inventory and its schedule/targeting
- **Priority:** P2
- **Goal:** See every banner with its schedule window, surface, and role targeting in one offset list without changing state.
- **Preconditions:** Admin authenticated with content read permission (ACT-04); at least the admin/moderator role is present.

## Main Scenario
1. Admin opens Content → Banners → client `GET /admin/banners` (API-CNT-011) with `?page&pageSize&active`.
2. System returns offset rows: `label`, `imageUrl`, `surface`, `visibleTo` role list, `startsAt?`, `endsAt?`, computed `active` flag; labels are localized ar/en (BR-PLT-05).
3. Admin checks schedule windows and role targeting against the merchandising plan — no record is modified.
4. Admin may cross-check what each audience actually sees via the home payload (`GET /home`, role-aware surfaces).

## Alternative Scenarios
- **A1 — Active-only view:** Admin filters `?active=true` to see banners currently inside their window.
- **A2 — Moderator read:** A Moderator opens the same read-only list (read permitted; all banner writes stay Admin-only).
- **A3 — Empty state:** No banners exist → empty `items` with `total: 0`; admin proceeds to UC-110.

## Exception Scenarios
- **E1 — Permission denied:** A non-admin/non-moderator caller → 403 `FORBIDDEN`; no data returned.
- **E2 — Validation failure:** Non-numeric `page`/`pageSize` or unknown filter → 400 `VALIDATION_ERROR`; no data returned.
- **E3 — Concurrent edit:** Another admin edits or removes a banner while this list is open → the row is stale; reload shows the updated window/targeting.

## Postconditions
- Banner inventory reviewed; no banner state changed by listing (read-only).
- List reflects the latest committed banner records after reload.

## Business Rules Applied
- BR-PLT-05

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))

## Permissions / Data / External Dependencies
- **Permissions:** Admin and Moderator read; banner creation/edit/removal is Admin-only (UC-110…UC-112).
- **Data involved:** Banners (label, schedule, targeting), no audit entries from reads.
- **External dependencies:** Home surface rendering consumes the same banner records (`GET /home`).

## Acceptance Criteria
- **AC-UC109-01:** Given banners with different windows, when the list is read, then each row shows `startsAt`/`endsAt`, `visibleTo`, and a computed `active` flag (API-CNT-011).
- **AC-UC109-02:** Given the list request, when paging parameters are applied, then offset pagination returns consistent `page`/`total`.
- **AC-UC109-03:** Given a valid Moderator session, when the list is read, then 200 is returned with no write capability exposed.
- **AC-UC109-04:** Given an invalid filter value, when the list is requested, then 400 `VALIDATION_ERROR` and no partial data.
