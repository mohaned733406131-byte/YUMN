# UC-105 — Create a CMS Page Draft

## Header Info
- **Use Case ID:** UC-105
- **Title:** Create a CMS Page Draft
- **Actor:** Admin (ACT-04)
- **Trigger:** An admin needs new static content (terms, privacy, about, help topic)
- **Priority:** P1
- **Goal:** Register a new CMS page as a DRAFT with localized content that stays invisible to the public until published.
- **Preconditions:** Admin authenticated with content-write permission (ACT-04); no page exists yet at the requested slug.

## Main Scenario
1. Admin opens Content → Pages → "New page" and enters the slug, Arabic/English titles (ar default, en parity — BR-PLT-05) and body blocks.
2. Client sends `POST /admin/pages` (API-CNT-006); the system validates the payload (schema and title parity, BR-PLT-05) plus slug uniqueness (`SLUG_TAKEN`).
3. System creates the page → `201 { id, status: "DRAFT", createdAt }`; the public read `GET /pages/{slug}` still returns 404.
4. System appends an append-only audit entry for the privileged write — actor, action, entity, before/after (BR-PLT-06).
5. Admin opens the draft detail `GET /admin/pages/{id}` (API-CNT-007) to confirm the create history before continuing in UC-106.

## Alternative Scenarios
- **A1 — Arabic-first authoring:** Admin drafts Arabic copy first and completes English parity before submit (BR-PLT-05); parity is enforced at validation.
- **A2 — Attach images:** Admin uploads images through the shared upload endpoint, then embeds the returned references in body blocks.
- **A3 — Content not ready:** Page stays DRAFT indefinitely; editing continues in UC-106 and publishing in UC-107.

## Exception Scenarios
- **E1 — Permission denied:** A Moderator or non-admin calls the create endpoint → 403 `FORBIDDEN`; no page persisted.
- **E2 — Validation failure:** Missing/empty localized title or malformed body block → 400 `VALIDATION_ERROR`; nothing written.
- **E3 — Slug collision (concurrent):** Another admin creates the same slug first → `SLUG_TAKEN`; this request is rejected and a new slug is chosen.

## Postconditions
- A DRAFT page exists, unreachable from public routes; an audit row records the creation (BR-PLT-06).
- No banner, coupon, order, or publicly cached content change originates from draft creation.

## Business Rules Applied
- BR-PLT-05, BR-PLT-06

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))

## Permissions / Data / External Dependencies
- **Permissions:** Admin content-write scope; Moderator is read-only on pages (create denied).
- **Data involved:** CMS pages (draft state), audit log.
- **External dependencies:** Shared file upload endpoint for embedded images; public page route stays 404 until publish (UC-107).

## Acceptance Criteria
- **AC-UC105-01:** Given an admin with a valid payload, when `POST /admin/pages` is called, then `201` returns `status: "DRAFT"` (API-CNT-006).
- **AC-UC105-02:** Given a created draft, when the public page route is read, then it returns 404 until the page is published.
- **AC-UC105-03:** Given a successful draft creation, when the audit log is read, then a creation entry with actor and before/after exists (BR-PLT-06).
- **AC-UC105-04:** Given a Moderator, when the create endpoint is called, then 403 `FORBIDDEN` is returned and no page is created.
