# UC-122 — Update or Disable an Attribute

## Header Info
- **Use Case ID:** UC-122
- **Title:** Update or Disable an Attribute
- **Actor:** Admin (ACT-04)
- **Trigger:** An attribute's name, options, or availability must change
- **Priority:** P2
- **Goal:** Adjust an attribute or disable it while historical product values stay readable and variant limits hold.
- **Preconditions:** Admin authenticated with taxonomy-write permission (ACT-04); the target attribute exists (UC-120/UC-121).

## Main Scenario
1. Admin opens the dictionary (UC-120), selects the attribute and edits `name`, `options`, `active`, or `filterable`.
2. Client sends `PUT /admin/attributes/{id}` (API-ADM-020) with only the changed fields.
3. System validates the payload → `200 { …attribute }`; disabling (`active: false`) keeps historical product values readable rather than erasing them.
4. Option edits stay within the variant budget of ≤5 dimensions and ≤50 combinations (BR-CAT-02); existing product variant/SKU data remains intact.

## Alternative Scenarios
- **A1 — Disable, keep history:** Admin sets `active: false` → new products cannot select it, existing values remain readable.
- **A2 — Add an option:** Admin extends a SELECT list → future variants may use the new option within BR-CAT-02 limits.
- **A3 — Make non-filterable:** Admin turns `filterable` off → the attribute stops appearing in catalog filters without data loss.

## Exception Scenarios
- **E1 — Validation failure:** Option removed while products still use it, or malformed localized name → 400 `VALIDATION_ERROR`; nothing written.
- **E2 — Permission denied:** Moderator or non-admin attempts update → 403 `FORBIDDEN`; attribute unchanged.
- **E3 — Concurrent edit:** Another admin saves the same attribute first → stale-write conflict (expected version mismatch) → 409; reload and reapply.

## Postconditions
- Attribute reflects the last accepted edit; historical product values stay readable.
- Variant/SKU integrity and the ≤5 dimensions / ≤50 combinations budget remain satisfied (BR-CAT-02).

## Business Rules Applied
- BR-CAT-02

## Related Requirements
- FR-004 (Product Catalog Management)

## Permissions / Data / External Dependencies
- **Permissions:** Admin taxonomy-write scope; Moderator read-only on the dictionary.
- **Data involved:** Attributes (name, options, active, filterable), referenced product values.
- **External dependencies:** Product editing and catalog filters pick up the change after commit.

## Acceptance Criteria
- **AC-UC122-01:** Given an attribute with product values, when it is disabled, then `200` returns `active: false` and stored product values still read back.
- **AC-UC122-02:** Given an option still used by products, when it is removed, then 400 `VALIDATION_ERROR` and the options list is unchanged (BR-CAT-02).
- **AC-UC122-03:** Given a valid edit, when saved, then `200` returns the updated attribute (API-ADM-020).
- **AC-UC122-04:** Given two admins editing one attribute, when both save, then the second save gets 409 and no silent overwrite occurs.
