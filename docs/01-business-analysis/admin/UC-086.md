# UC-086 — Export a Platform Report as CSV

## Header Info
- **Use Case ID:** UC-086
- **Title:** Export a Platform Report as CSV
- **Actor:** Admin (ACT-04) — reporting scope
- **Trigger:** Admin clicks Export on a platform report (UC-085)
- **Priority:** P2
- **Goal:** Download the currently viewed platform report as a hardened CSV file without mutating report data.
- **Preconditions:** Admin authenticated with export permission (API-ANL-008 is `ADMIN` only — Moderators excluded); a report family and period are selected.

## Main Scenario
1. Admin clicks Export → client `GET /admin/reports/{family}/export?from=&to=` (API-ANL-008).
2. System streams `text/csv` inline (`Content-Disposition: attachment`) with UTF-8 BOM, whole-YER amounts and formula-injection hardening (cells starting `= + - @` prefixed with `'`), capped at 50,000 rows.
3. Rows beyond the cap → `LIMIT_EXCEEDED`; the queued generation path is the shared export queue `b11.analytics.export` (BR-PLT-01) with 3 retries and exponential backoff, then dead-letter + alert (BR-PLT-02).
4. Export is a pure read of the same dataset as UC-085: repeated downloads return the current figures (FR-018).
5. A rejected export (role or limit) changes nothing.

## Alternative Scenarios
- **A1 — Queued generation:** Large or scheduled exports run as background files instead of the inline stream — rel UC-081 (system generates export files from `b11.analytics.export`).
- **A2 — Moderator attempt:** Moderator keeps report viewing (UC-085) but is refused on the export path.

## Exception Scenarios
- **E1 — Permission denied:** Moderator or non-staff → `403 FORBIDDEN`; no partial file is streamed.
- **E2 — Row cap exceeded:** More than 50,000 rows → `LIMIT_EXCEEDED`; Admin narrows the period or uses the queued path.
- **E3 — Export job failure:** Job retries 3× with backoff then dead-letters and alerts (BR-PLT-02); the on-screen report stays available.
- **E4 — Concurrent data change:** Figures advance while the file streams → the file is a request-time snapshot; no locking is applied.

## Postconditions
- A CSV file is produced or an error is reported; report and platform data unchanged (FR-018).
- Failed generations are visible through retry/DLQ alerting (BR-PLT-02).

## Business Rules Applied
- BR-PLT-01, BR-PLT-02

## Related Requirements
- FR-018 (Analytics & Reporting)
- Cross-reference: rel UC-081 (system generates export files for this trigger).

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN` only for export; Moderator read-only reports; streaming response is `no-store`.
- **Data involved:** Read-only report rows written to CSV; only report columns, no extra PII.
- **External dependencies:** BullMQ export queue `b11.analytics.export` (BR-PLT-01) with retry/DLQ (BR-PLT-02).

## Acceptance Criteria
- **AC-UC086-01:** Given an admin export request, when served, then the response is `text/csv` with UTF-8 BOM and an attachment disposition.
- **AC-UC086-02:** Given a cell starting with `=`, when exported, then it is prefixed with `'` to block spreadsheet formula injection.
- **AC-UC086-03:** Given a report over 50,000 rows, when exported, then `LIMIT_EXCEEDED` returns or the queued path is used.
- **AC-UC086-04:** Given a Moderator session, when export is requested, then `403 FORBIDDEN` and no file is streamed.
