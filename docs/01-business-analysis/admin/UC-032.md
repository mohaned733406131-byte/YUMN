# UC-032 — Moderate Product or Review

## Header Info
- **Use Case ID:** UC-032
- **Title:** Moderate Product or Review
- **Actor:** Admin (ACT-04) — with Moderator (ACT-06) able to perform the same content actions (UC-038)
- **Trigger:** A product or review is flagged (auto-flag or user report) or sampled for review
- **Priority:** P1
- **Goal:** Hide/remove policy-violating content with audit trail while preserving vendor due-process (resubmission/appeal).
- **Preconditions:** Admin authenticated with moderation permission; target exists (ACTIVE product or visible review).

## Main Scenario
1. Admin opens the moderation queue → client `GET /admin/moderation` lists flagged products/reviews with reporter count, reason, and context (product page, review text, images).
2. Admin inspects the item against catalog/review policy (BR-CAT-05 product types, BR-REV-03 review format).
3. Admin chooses "Hide/Remove" → client `POST /admin/moderation/{type}/{id}/hide` with reason; system soft-hides the content: product → hidden from search/storefront (BR-CAT-06 semantics), review → hidden from display (BR-REV-04).
4. System appends an audit entry (actor, entity, before/after — BR-PLT-06, SEC-REQ-010) and notifies the vendor/author (BR-NTF-01).
5. Or Admin dismisses the flag → content stays visible; flag resolved with reason recorded.
6. Store rating recomputes incrementally after a review hide (BR-REV-05).

## Alternative Scenarios
- **A1 — Vendor appeal:** Vendor contests via support (UC-014) → Admin reviews and may restore content; restore also audited (BR-PLT-06).
- **A2 — Repeat offender:** Pattern of violations → Admin may suspend the vendor (BR-VND-04): products hidden, orders frozen, payouts held.
- **A3 — Pre-emptive rejection:** Admin rejects a product before publish → vendor sees reason; product stays DRAFT/rejected (BR-CAT-01 validation context).

## Exception Scenarios
- **E1 — Concurrent vendor edit:** Vendor edits while moderation runs → version lock decides; hidden state wins once committed; vendor sees moderation banner.
- **E2 — Bulk flag spike:** Queue overload → priority sorting + alerting; no content silently dropped (FR-018 dashboards).
- **E3 — Malicious mass-reporting:** Rate limits + report credibility weighting (SEC-REQ-009); false flags dismissed with audit.

## Postconditions
- Target content is visible or hidden, never half-applied; audit row exists (BR-PLT-06).
- No order, wallet, or escrow change originates from moderation (suspension affects future orders only, BR-VND-04).

## Business Rules Applied
- BR-CAT-05, BR-CAT-06, BR-REV-03, BR-REV-04, BR-REV-05, BR-VND-04, BR-NTF-01, BR-PLT-06

## Related Requirements
- FR-006 (Reviews & Ratings), FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Admin + Moderator content scope (DOC-OVR-007); vendors respond/appeal only (BR-REV-04).
- **Data involved:** Products, reviews, flags/reports, audit log, notifications.
- **External dependencies:** Search index refresh (B04); rating recompute job (BR-PLT-01).

## Acceptance Criteria
- **AC-UC032-01:** Given a flagged review, when hidden, then it disappears from display and an audit entry exists (BR-REV-04, BR-PLT-06).
- **AC-UC032-02:** Given a hidden product, when searched, then it is excluded (BR-CAT-06).
- **AC-UC032-03:** Given a dismissed flag, when reviewed, then content remains visible with the dismissal reason recorded.
