# UC-273 — Investigate an Escalated Illegal Order-State Transition

## Header Info
- **Use Case ID:** UC-273
- **Title:** Investigate an Escalated Illegal Order-State Transition
- **Actor:** Admin (ACT-04)
- **Trigger:** The state guard rejected an illegal transition and escalated the attempt to the audit trail (DQ-06: transitions legal only; illegal attempt escalated)
- **Priority:** P1
- **Goal:** Find who or what attempted the illegal move, prove the order state was left untouched, and drive the corrective action with evidence.
- **Preconditions:** Escalation exists in the audit trail; order states are constrained to exactly the 17 canonical states (BR-ORD-01, C-09); history is append-only (BR-ORD-03); Admin holds platform-scope audit read.

## Main Scenario
1. Admin opens the audit stream filtered to the escalated attempt (API-ADM-024 by target/order id and action) → rejected attempt with actor, reason, timestamp, and `ipHash` (BR-PLT-06).
2. Admin reads the sub-order timeline (API-ORD-005) → the rejected attempt produced **no** history row; the state still matches the last legal entry (BR-ORD-03).
3. Admin classifies the source: a background job (queue/DLQ evidence), a vendor client bug (vendor-scoped call), or an Admin tool misuse (audit actor id).
4. Admin confirms no partial write: state unchanged, escrow untouched, no balance effect — the guard rejected before commit (BR-ORD-01).
5. Admin records the disposition (source, corrective owner, prevention note) in the audit trail and, for job-originated faults, hands the queue/DLQ branch to the platform owner (BR-PLT-02).

## Alternative Scenarios
- **A1 — Stale-version conflict, not illegal:** the actor used a legal transition with an old `version` → that is `STATE_CONFLICT`, not an illegal-transition escalation (BR-ORD-03).
- **A2 — Repeated attempts from one source:** escalation pattern indicates a defective client → corrective action escalates with the attempt count as evidence.
- **A3 — Attempt from a privileged actor:** if the audit actor is a Super Admin identity, the finding routes through role/permission review (rbac.md §3, UC-037) rather than a code fix.

## Exception Scenarios
- **E1 — Audit chain verification failure:** J10 reports a chain break while investigating → privileged writes are frozen for investigation before the probe continues (data-quality.md §5).
- **E2 — No matching audit entry:** escalation referenced but nothing found → treated as an observability gap and escalated as its own finding (FR-020), never closed silently.
- **E3 — Attempt touched money-bearing state:** any suspicion of ledger drift → reconciliation is run and, if imbalanced, the freeze contingency applies (UC-279).

## Postconditions
- The illegal attempt is explained with an identified source and a recorded disposition; the order state is provably unchanged (BR-ORD-01, BR-ORD-03).
- One audit entry documents the investigation outcome (BR-PLT-06); no state, history, or ledger row was rewritten.

## Business Rules Applied
- BR-ORD-01, BR-ORD-03, BR-PLT-02, BR-PLT-06

## Related Requirements
- FR-012 (Order Lifecycle Management), FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Admin (ACT-04) platform-scope audit read + order read; investigation is read-only (rbac.md rows 3, 22).
- **Data involved:** audit entries, order status history, sub-order state/version, queue and DLQ records, escrow rows.
- **External dependencies:** audit hash-chain job J10 (data-quality.md §5); BullMQ retry/DLQ path (BR-PLT-02); state machine (C-09).

## Acceptance Criteria
- **AC-UC273-01:** Given an escalated illegal attempt, when the audit filter runs, then the attempt appears with actor, action, reason, and timestamp (BR-PLT-06).
- **AC-UC273-02:** Given the attempt was rejected, when the timeline is read, then no history row corresponds to it and the state is unchanged (BR-ORD-03, BR-ORD-01).
- **AC-UC273-03:** Given the investigation closes, when the disposition is recorded, then a source and corrective owner are named (FR-020).
- **AC-UC273-04:** Given the audit chain fails verification, when J10 reports it, then privileged writes are frozen pending investigation (data-quality.md §5).
