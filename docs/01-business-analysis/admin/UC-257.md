# UC-257 — Execute the Incident Rotation Runbook for a Leaked Secret

## Header Info
- **Use Case ID:** UC-257
- **Title:** Execute the Incident Rotation Runbook for a Leaked Secret
- **Actor:** Super Admin (ACT-05) — secrets authority (ops owner custody, secrets-management.md §5)
- **Trigger:** A credential leak is detected — CI secret-scan hit, provider anomaly alert, or a report of suspected exposure
- **Priority:** P0
- **Goal:** Contain, rotate, verify, and record a leaked secret so the exposed value stops being accepted everywhere, with no secret value ever written to logs, tickets, or code.
- **Preconditions:** Incident declared; secret class identified in the inventory (S-01…S-14, secrets-management.md §2); Super Admin holds ops/host access to the affected env files; health gating available (BR-PLT-07).

## Main Scenario
1. Super Admin records detection time and suspected exposure scope (step 1 *Detect* of the incident rotation runbook, secrets-management.md §7).
2. *Contain:* the exposed secret is revoked/rotated first and the old value is verified as rejected (provider-side revoke where available) — no waiting on downstream steps.
3. *Issue:* a new value is generated and distributed only through host env files; affected services restart rolling, gated on liveness/readiness (BR-PLT-07).
4. *Verify:* the dependent flow is smoke-tested on staging then production (auth refresh, top-up initiate, OTP send) before the incident is closed.
5. *Assess:* if the JWT signing material (S-01) was retired, sessions are revalidated so replayed refresh tokens die with their family (BR-AUTH-05); if money-path secrets (S-04/S-05) were exposed, wallet activity is frozen first (BR-PAY-09).
6. *Audit:* an append-only entry records secret class, reason, and operator — never the value (BR-PLT-06) — and the finding is noted in the security-findings report; *Review* updates this document's cadence if needed.

## Alternative Scenarios
- **A1 — Scheduled cadence rotation:** a 90-day class reaches its rotation window → same steps without incident scoping or exposure assessment.
- **A2 — Staff departure:** a human-held class (S-10 bank portal) rotates on personnel change even with no leak → contain/issue/verify/audit only.
- **A3 — Provider dual-secret grace:** where the provider supports it, the old value keeps a bounded overlap so no live flow breaks mid-rotation (design note, INFERENCE).

## Exception Scenarios
- **E1 — Rotation breaks a dependent flow:** smoke test fails after the new value lands → rollout halts and on-call is paged; the old value is already revoked, so recovery is a fix-forward, never a rollback to the leaked value (FR-001).
- **E2 — Money paths implicated during assess:** fraudulent use suspected since exposure → wallet freeze is applied before any money operation resumes (BR-PAY-09).
- **E3 — Secret found in repo history:** CI scan blocks the merge (secrets-management.md §6) → rotate, purge the literal, and re-verify the repository scan; no credential is ever re-committed (FR-020).

## Postconditions
- The leaked value is rejected by every consumer; services run the new value and dependent flows pass smoke tests.
- One complete audit entry exists (secret class, reason, operator — no value); no secret appears in logs, errors, tickets, or metrics.

## Business Rules Applied
- BR-AUTH-05, BR-PAY-09, BR-PLT-06, BR-PLT-07

## Related Requirements
- FR-001 (Identity, Authentication & Session Management), FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Super Admin (ACT-05) only — key/secrets authority; Admin may read the audit trail but cannot rotate; values never pasted into tickets or chat.
- **Data involved:** env-file secret values (never logged), secret inventory rows, session registry entries, audit entries, security finding records.
- **External dependencies:** provider revocation endpoints for S-04/S-05/S-06 classes; CI secret scanning (secrets-management.md §6); health probes (BR-PLT-07).

## Acceptance Criteria
- **AC-UC257-01:** Given a leaked secret, when containment runs, then the old value is rejected by the affected consumer before new value distribution completes.
- **AC-UC257-02:** Given the JWT signing material was retired, when assessment runs, then replayed refresh tokens cannot renew a session (BR-AUTH-05).
- **AC-UC257-03:** Given money-path secrets were exposed, when assessment runs, then wallet activity is frozen before money operations resume (BR-PAY-09).
- **AC-UC257-04:** Given the incident closes, when the audit entry is read, then it names secret class, reason, and operator with no secret value present (BR-PLT-06).
