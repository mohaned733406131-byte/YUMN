# UC-133 — Run the User Growth Report

## Header Info
- **Use Case ID:** UC-133
- **Title:** Run the User Growth Report
- **Actor:** Admin (ACT-04)
- **Trigger:** Operations want account growth and composition metrics for a period
- **Priority:** P2
- **Goal:** Produce a read-only user growth report with registrations, status mix, and role distribution for a period.
- **Preconditions:** Admin authenticated with analytics-read permission (ACT-04); date range selected; account data exists for the period.

## Main Scenario
1. Admin opens the reports console and selects family `users` with a date range → client `GET /admin/reports/users` (conceptual touchpoint for the platform report families).
2. System queues the computation on the analytics queue named per the `{block}.{entity}.{action}` convention (BR-PLT-01).
3. System returns rows: registrations over time, active vs suspended status mix, and role distribution (customers, vendors, staff) for the period.
4. Every total carries exact/estimate metadata so rollup-derived figures are labeled.
5. Admin filters by segment and compares periods to read growth trajectory and suspension share.
6. The run is read-only — account actions (suspend, reactivate, role changes) happen in their own admin use cases, never from the report.

## Alternative Scenarios
- **A1 — Filter by segment:** admin narrows to newly registered accounts → same family, subset projection.
- **A2 — Estimate before rollup:** aggregates land before nightly backfill → labeled as estimates until refreshed.
- **A3 — Moderator read:** Moderator may read the family (report access includes MODERATOR) while export stays Admin-only (UC-086).
- **A4 — Empty period:** no registrations in range → zero rows with exact zero totals.

## Exception Scenarios
- **E1 — Invalid parameters:** malformed range or unknown family → `VALIDATION_ERROR`, no data.
- **E2 — Empty queue:** no users match the filters → friendly empty state, not a failure.
- **E3 — Permission denied:** caller without analytics scope → `403 FORBIDDEN`.
- **E4 — Job delayed:** computation queued → client waits/retries; the job remains on its named queue (BR-PLT-01).

## Postconditions
- User growth report delivered with labeled totals; no account state changed.
- Admin has a period-comparable read of registration growth and account status mix.

## Business Rules Applied
- BR-PLT-01

## Related Requirements
- FR-003 (User & Profile Management), FR-018 (Analytics & Reporting)

## Permissions / Data / External Dependencies
- **Permissions:** Admin analytics-read; Moderator read for families, export Admin-only (UC-086).
- **Data involved:** Account aggregates (registrations, statuses, roles), totals metadata.
- **External dependencies:** Analytics report queue (B11); user read models (B01).

## Acceptance Criteria
- **AC-UC133-01:** Given family `users` and a date range, when run, then user rows for that family return.
- **AC-UC133-02:** Given a report job, when queued, then it lands on the `{block}.{entity}.{action}` analytics queue (BR-PLT-01).
- **AC-UC133-03:** Given accounts in the period, when rendered, then registrations, status mix, and role distribution appear with labeled totals.
- **AC-UC133-04:** Given an unknown family parameter, when submitted, then `VALIDATION_ERROR` returns with no rows.
