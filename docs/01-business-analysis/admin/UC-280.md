# UC-280 — Run the Pre-Launch Money-Cycle Audit

## Header Info
- **Use Case ID:** UC-280
- **Title:** Run the Pre-Launch Money-Cycle Audit
- **Actor:** Admin (ACT-04) — Finance (Admin) owns this launch-gate audit (risk-register.md RISK-001 mitigation)
- **Trigger:** The pre-launch gate calls for the full money-cycle audit: top-up → order → escrow → commission → payout → refund
- **Priority:** P0
- **Goal:** Prove end-to-end that every money movement posts balanced double-entry rows and reconciles clean, before real funds flow at scale.
- **Preconditions:** Environments available for a controlled run; reconciliation jobs active (BR-FIN-03 daily automated reconciliation); ledger append-only (BR-PAY-06); Admin holds finance read + report execution rights.

## Main Scenario
1. Admin plans the cycle scope: top-up (bank + provider rail), order payment, escrow hold and release, commission calculation, payout execution, refund credit — one pass per leg (risk-register.md RISK-001 mitigation, launch phase).
2. Admin executes or observes each leg in sequence and captures evidence: ledger references, statuses, and timestamps per movement.
3. Admin verifies the invariant on every movement: each balance change posted a balanced debit+credit pair, append-only (BR-PAY-06).
4. Admin runs the daily reconciliation over the cycle (BR-FIN-03 — ledger, wallets, escrows, payables vs provider statements) and requires zero mismatch for the exercised window (BR-ESC-08).
5. Admin confirms cycle semantics: escrow held on delivery per the 7-day rule (C-12), commission computed within the 5–20% tier at release (BR-ESC-03), payouts batched per the floor rule (BR-ESC-05), refunds credited to wallet only (BR-PAY-07).
6. Admin compiles the audit result — pass with evidence set, or failed legs with deltas — as launch-gate evidence; failures block the gate.

## Alternative Scenarios
- **A1 — Re-run after an incident:** the same cycle runs as a post-incident backstop before money flows again (RISK-001 mitigation, continuous).
- **A2 — Partial environment:** sandbox first, then production confirmation — each environment's result recorded separately (design note, INFERENCE).
- **A3 — One leg unavailable:** the leg is marked not-exercised with reason; the gate cannot be called passed on an unexercised leg (FR-013 scope).

## Exception Scenarios
- **E1 — Any non-zero reconciliation delta:** the audit fails → gate blocked, escalation per RISK-001; no "close enough" acceptance (BR-ESC-08).
- **E2 — Unbalanced posting found:** CRITICAL — freeze payouts/crediting immediately and run the containment path (UC-279, DQ-08).
- **E3 — Evidence missing for a leg:** recorded as a gap, never inferred — the audit result cites only captured references (BR-PAY-06).

## Postconditions
- A signed-off audit record exists listing every exercised leg, its evidence set, and the reconciliation result (BR-FIN-03).
- No ledger row was created outside normal posting paths; findings, if any, carry owners and gate status.

## Business Rules Applied
- BR-PAY-06, BR-PAY-07, BR-ESC-03, BR-ESC-05, BR-ESC-08, BR-FIN-03

## Related Requirements
- FR-013 (Wallet & Payment Processing), FR-014 (Escrow, Commission & Vendor Payouts)

## Permissions / Data / External Dependencies
- **Permissions:** Admin (ACT-04) finance read/execute for controlled test movements; Super Admin oversight; Moderator denied finance (rbac.md §4); no direct ledger writes (rows 15/16).
- **Data involved:** top-ups, orders, escrow rows, commission calculations, payouts, refunds, ledger entries, reconciliation runs.
- **External dependencies:** reconciliation jobs (BR-FIN-03, J1–J6); provider/bank rails for test movements (INT-REQ-001/002); audit log for evidence (BR-PLT-06).

## Acceptance Criteria
- **AC-UC280-01:** Given a full cycle pass, when each movement is inspected, then balanced debit/credit pairs exist for every balance change (BR-PAY-06).
- **AC-UC280-02:** Given the cycle completes, when reconciliation runs, then the exercised window reports zero mismatch (BR-FIN-03, BR-ESC-08).
- **AC-UC280-03:** Given a refund leg, when it credits, then the customer wallet receives it with no external cash-out (BR-PAY-07).
- **AC-UC280-04:** Given any non-zero delta, when found, then the launch gate is blocked and containment starts (RISK-001).
