# UC-119 — Delete an Empty Category

## Header Info
- **Use Case ID:** UC-119
- **Title:** Delete an Empty Category
- **Actor:** Admin (ACT-04)
- **Trigger:** A category became redundant after products or child nodes were moved away
- **Priority:** P2
- **Goal:** Soft-delete a truly empty category node while refusing any deletion that would strand products or children.
- **Preconditions:** Admin authenticated with taxonomy-write permission (ACT-04); the target node exists and reports `productCount: 0` with no children (UC-116).

## Main Scenario
1. Admin verifies in the tree that the node has no children and `productCount` is 0.
2. Admin selects "Delete" and confirms → client `DELETE /admin/categories/{id}` (API-ADM-017).
3. System rechecks emptiness at commit time; if children or products are present → `STATE_CONFLICT` (move them first).
4. On success → `204`: the node is soft-deleted (history kept) and stops resolving in browsing; only ACTIVE products remain surfaced in search/storefront (BR-CAT-06 semantics).
5. Remaining siblings keep their per-level slug uniqueness (BR-CAT-03).

## Alternative Scenarios
- **A1 — Deactivate instead:** Admin is unsure → sets `isActive: false` (UC-118) rather than deleting.
- **A2 — Move products first:** Node still has products → admin moves them (UC-118/product flows), then deletes the emptied node.
- **A3 — Remove child first:** Node has one child → admin deletes/moves the child, then deletes this node.

## Exception Scenarios
- **E1 — Non-empty category:** Children or products still present → `STATE_CONFLICT`; the system refuses and the admin must move them first.
- **E2 — Permission denied:** Moderator or non-admin attempts delete → 403 `FORBIDDEN`; node remains.
- **E3 — Concurrent attach (empty check races):** A product or child is added between check and commit → `STATE_CONFLICT`; nothing is deleted.

## Postconditions
- The category is soft-deleted (or untouched on failure); store browsing and slug uniqueness remain consistent (BR-CAT-03, BR-CAT-06).
- No product, order, or price record is deleted by this action.

## Business Rules Applied
- BR-CAT-03, BR-CAT-06

## Related Requirements
- FR-004 (Product Catalog Management)

## Permissions / Data / External Dependencies
- **Permissions:** Admin taxonomy-write scope; Moderator read-only on the tree.
- **Data involved:** Categories (soft-delete flag, history), product-to-category references.
- **External dependencies:** Storefront/search stop listing the node after commit (index refresh is system-owned).

## Acceptance Criteria
- **AC-UC119-01:** Given a node with `productCount: 0` and no children, when delete is called, then `204` is returned and the node disappears from the tree.
- **AC-UC119-02:** Given a node with children or products, when delete is attempted, then `STATE_CONFLICT` is returned and the node persists (BR-CAT-03).
- **AC-UC119-03:** Given a deleted category, when storefront/search is read, then only ACTIVE products of remaining categories are listed (BR-CAT-06).
- **AC-UC119-04:** Given a Moderator, when delete is attempted, then 403 `FORBIDDEN` and the tree is unchanged.
