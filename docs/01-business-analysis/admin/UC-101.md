# UC-101 — Claim or Assign a Support Ticket

## Header Info
- **Use Case ID:** UC-101
- **Title:** Claim or Assign a Support Ticket
- **Actor:** Admin (ACT-04) — support operations scope
- **Trigger:** Admin picks up or delegates an unassigned ticket
- **Priority:** P1
- **Goal:** Put a named owner on a ticket so it moves into active work and accountability is recorded.
- **Preconditions:** Admin authenticated with assign permission (API-ADM-040 `ADMIN`); ticket exists in `OPEN` state; a target assignee (self or a Moderator) is chosen.

## Main Scenario
1. Admin opens a ticket from the queue (UC-100) → Claim/assign → optionally picks an assignee.
2. Client `POST /admin/tickets/{id}/assign` with `{ assigneeId? }` (API-ADM-040); an empty `assigneeId` means self-claim.
3. System transitions `OPEN → IN_PROGRESS`, stores `assignedTo` and returns an `auditId`.
4. The assignment writes an append-only audit entry with actor, entity and before/after state (BR-PLT-06).
5. The customer sees the status change to `IN_PROGRESS` in their own ticket feed (rel UC-014 step3).

## Alternative Scenarios
- **A1 — Self-claim:** No `assigneeId` supplied → the acting admin becomes the owner.
- **A2 — Delegate to Moderator:** Assign to a moderator who then works the thread (UC-102, UC-103).

## Exception Scenarios
- **E1 — Permission denied:** Moderator cannot reassign another's ticket (`403 FORBIDDEN`); non-staff is denied outright.
- **E2 — Wrong state:** Already `IN_PROGRESS` or `RESOLVED` → `TICKET_STATE_CONFLICT`; no reassignment occurs.
- **E3 — Concurrent claim:** Two staff claim at once → first wins, second gets `TICKET_STATE_CONFLICT` on refetch.
- **E4 — Overdue ticket:** Claiming a ticket already flagged `overdue` keeps the flag until resolution, so SLA accountability stays visible.

## Postconditions
- The ticket is `IN_PROGRESS` with a named assignee.
- One audit entry exists for the assignment (BR-PLT-06).

## Business Rules Applied
- BR-PLT-06

## Related Requirements
- FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN` assigns to self or a Moderator; a Moderator cannot reassign others' tickets.
- **Data involved:** Ticket status and assignee, audit entry.
- **External dependencies:** Audit writer (BR-PLT-06); customer status feed.

## Acceptance Criteria
- **AC-UC101-01:** Given an open ticket, when claim is posted, then status becomes `IN_PROGRESS` with `assignedTo` set.
- **AC-UC101-02:** Given the assignment, when completed, then an `auditId` returns (BR-PLT-06).
- **AC-UC101-03:** Given a resolved ticket, when assigned, then `TICKET_STATE_CONFLICT` is returned.
- **AC-UC101-04:** Given a Moderator reassigning another's ticket, when posted, then `403 FORBIDDEN` is returned.
