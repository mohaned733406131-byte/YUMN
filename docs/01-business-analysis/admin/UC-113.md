# UC-113 — List Platform Coupons

## Header Info
- **Use Case ID:** UC-113
- **Title:** List Platform Coupons
- **Actor:** Admin (ACT-04)
- **Trigger:** An admin reviews platform-wide and store coupon inventory
- **Priority:** P2
- **Goal:** See every coupon with scope, window, status, and usage in one offset list without changing any coupon.
- **Preconditions:** Admin authenticated with content read permission (ACT-04); coupons exist or the list is empty.

## Main Scenario
1. Admin opens Promotions → Coupons → client `GET /admin/coupons` (API-CNT-015) with `?page&pageSize&status&scope`.
2. System returns offset rows: `code`, `scope` (PLATFORM/STORE), `storeId?`, `discountPercent`, `startsAt`, `endsAt`, `status` (ACTIVE/DISABLED/EXPIRED), `usageCount`, `usageLimit?`.
3. Scope semantics are respected: platform coupons are admin-created, store coupons are vendor-created, and the admin list covers both with list/disable rights (BR-PRM-03).
4. Admin reviews usage and windows; disablement is a separate action (UC-115).

## Alternative Scenarios
- **A1 — Platform-only view:** Admin filters `scope=PLATFORM` to see admin-created coupons.
- **A2 — Vendor store coupons:** Store-scoped coupons created by vendors (UC-023 step4) appear here under `scope=STORE` for oversight (BR-PRM-03).
- **A3 — Status view:** Admin filters `status=EXPIRED` or `DISABLED` for housekeeping.

## Exception Scenarios
- **E1 — Permission denied:** A caller outside admin/moderator read scope → 403 `FORBIDDEN`; no data returned.
- **E2 — Validation failure:** Unknown `status`/`scope` value or non-numeric paging → 400 `VALIDATION_ERROR`; no data returned.
- **E3 — Concurrent status change:** A coupon is disabled or expires while this list is open → the row shows stale status; reload shows `DISABLED`/`EXPIRED`.

## Postconditions
- Coupon inventory reviewed; listing is read-only and changes no coupon state.
- List reflects latest committed coupon records after reload.

## Business Rules Applied
- BR-PRM-03

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))
- **Cross-reference:** UC-023 step4 — the vendor creates a store coupon; it becomes visible in this admin list under `scope=STORE` (BR-PRM-03).

## Permissions / Data / External Dependencies
- **Permissions:** Admin and Moderator read; coupon create/disable is Admin-only (UC-114, UC-115).
- **Data involved:** Coupons (code, scope, window, status, usage counters); no audit entries from reads.
- **External dependencies:** Cart/checkout validation consumes the same coupon records when applied.

## Acceptance Criteria
- **AC-UC113-01:** Given coupons of both scopes, when the list is read, then each row shows `scope`, `status`, window and `usageCount` (API-CNT-015).
- **AC-UC113-02:** Given `scope=PLATFORM`, when filtered, then only admin-created coupons are returned.
- **AC-UC113-03:** Given a vendor store coupon, when the admin list is read, then it appears with `scope=STORE` (BR-PRM-03).
- **AC-UC113-04:** Given an invalid status filter, when requested, then 400 `VALIDATION_ERROR` and no partial data.
