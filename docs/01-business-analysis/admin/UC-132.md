# UC-132 — Run the KYC Throughput Report

## Header Info
- **Use Case ID:** UC-132
- **Title:** Run the KYC Throughput Report
- **Actor:** Admin (ACT-04)
- **Trigger:** Operations measure KYC decision throughput and timeliness against the onboarding SLA
- **Priority:** P2
- **Goal:** Produce a read-only KYC throughput report showing decision volume, outcomes, and age distribution for a period.
- **Preconditions:** Admin authenticated with analytics-read permission (ACT-04); date range selected; KYC submissions/decisions exist in the period.

## Main Scenario
1. Admin opens the reports console and selects family `kyc` with a date range → client `GET /admin/reports/kyc` (conceptual touchpoint for the platform report families).
2. System queues the computation on the analytics queue named per the `{block}.{entity}.{action}` convention (BR-PLT-01).
3. System returns rows: submissions received, decisions by outcome (approved/rejected), queue depth, and decision age buckets against the ≤48-hour KYC SLA (FR-007).
4. Every total carries exact/estimate metadata so rollup-derived figures are labeled.
5. Admin compares periods to spot SLA drift (rising share of decisions aging toward or past the SLA).
6. The run is read-only — individual KYC approve/reject decisions happen in their own admin use case, never from the report.

## Alternative Scenarios
- **A1 — Filter by outcome:** admin narrows to rejected submissions → same family, outcome-filtered projection.
- **A2 — Estimate before rollup:** aggregates land before nightly backfill → labeled as estimates until refreshed.
- **A3 — Moderator read:** Moderator may read the family (report access includes MODERATOR) while export stays Admin-only (UC-086).
- **A4 — Empty period:** no KYC activity in range → zero rows with exact zero totals.

## Exception Scenarios
- **E1 — Invalid parameters:** malformed range or unknown family → `VALIDATION_ERROR`, no data.
- **E2 — Empty queue:** no submissions match the filters → friendly empty state, not a failure.
- **E3 — Permission denied:** caller without analytics scope → `403 FORBIDDEN`.
- **E4 — Job delayed:** computation queued → client waits/retries; the job remains on its named queue (BR-PLT-01).

## Postconditions
- KYC throughput report delivered with labeled totals; no KYC submission or decision state changed.
- Admin has a period-comparable read of decision timeliness (FR-007 SLA posture).

## Business Rules Applied
- BR-PLT-01

## Related Requirements
- FR-007 (Vendor Onboarding & KYC), FR-018 (Analytics & Reporting)

## Permissions / Data / External Dependencies
- **Permissions:** Admin analytics-read; Moderator read for families, export Admin-only (UC-086).
- **Data involved:** KYC submission/decision aggregates, age buckets, totals metadata.
- **External dependencies:** Analytics report queue (B11); KYC read models (B03).

## Acceptance Criteria
- **AC-UC132-01:** Given family `kyc` and a date range, when run, then KYC rows for that family return.
- **AC-UC132-02:** Given a report job, when queued, then it lands on the `{block}.{entity}.{action}` analytics queue (BR-PLT-01).
- **AC-UC132-03:** Given decisions in the period, when rendered, then outcomes and age buckets appear with labeled totals.
- **AC-UC132-04:** Given an unknown family parameter, when submitted, then `VALIDATION_ERROR` returns with no rows.
