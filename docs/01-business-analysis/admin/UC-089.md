# UC-089 — Search the User Directory

## Header Info
- **Use Case ID:** UC-089
- **Title:** Search the User Directory
- **Actor:** Admin (ACT-04) — user administration scope
- **Trigger:** Admin opens Users in the admin console
- **Priority:** P1
- **Goal:** Find any user account by role, status, KYC state or free-text query so the right action can be taken on it.
- **Preconditions:** Admin or Moderator authenticated with directory read access (API-ADM-001); at least one user record exists besides the caller.

## Main Scenario
1. Admin opens `/[locale]/admin/users` → `GET /admin/users?page=&pageSize=&role=&q=&status=&kycStatus=&sort=createdAt_desc` (API-ADM-001).
2. System returns offset-paginated rows: id, masked phone, display name, roles, status, linked store/KYC projection, createdAt — the phone stays masked in the projection.
3. The vendor/KYC queue is this same list filtered (`?role=VENDOR&kycStatus=&storeStatus=`); there is no separate directory.
4. Admin reviews a record and opens its detail (UC-090); reaching into user records is a privileged admin action recorded in the append-only audit trail (BR-PLT-06).
5. The listing is read-only — suspension and reactivation live in UC-091 and UC-092 (FR-003, FR-020).

## Alternative Scenarios
- **A1 — Moderator read:** Moderator searches the directory (API-ADM-001 roles) but receives no suspend/activate affordances.
- **A2 — Vendor triage:** Filtering `role=VENDOR` reuses this list as the vendor/KYC work queue handled in UC-031.

## Exception Scenarios
- **E1 — Permission denied:** Non-staff session → `403 FORBIDDEN`; foreign PII is never returned.
- **E2 — No matches:** Filters yield zero rows → empty state with reset-filters action, not an error.
- **E3 — Concurrent status change:** A user is suspended while the list is on screen → the row is stale until refresh; the detail re-checks server state.
- **E4 — Overdue vendor decisions:** The filtered vendor queue surfaces records already past their decision window as overdue for follow-up (UC-031).

## Postconditions
- The directory reflects server state at request time; no account was changed (FR-003, FR-020).
- The target user is located and opened for the follow-up use case.

## Business Rules Applied

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN`/`MODERATOR` read; phone masked; write actions belong to UC-091/UC-092.
- **Data involved:** User records (id, masked phone, roles, status, store/KYC projection).
- **External dependencies:** Users service (directory projection); audit writer (BR-PLT-06).

## Acceptance Criteria
- **AC-UC089-01:** Given a phone or display-name query, when searched, then matching users return with the phone masked.
- **AC-UC089-02:** Given `role=VENDOR`, when filtered, then the vendor/KYC queue projection returns from the same list.
- **AC-UC089-03:** Given a non-admin session, when queried, then `403 FORBIDDEN` is returned.
- **AC-UC089-04:** Given filters with no matches, when submitted, then an empty result set returns with HTTP 200.
