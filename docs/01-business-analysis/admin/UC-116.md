# UC-116 — View the Category Tree (Admin Scope)

## Header Info
- **Use Case ID:** UC-116
- **Title:** View the Category Tree (Admin Scope)
- **Actor:** Admin (ACT-04)
- **Trigger:** An admin inspects the platform taxonomy before editing it
- **Priority:** P1
- **Goal:** Read the full category tree with levels, per-locale slugs, and product counts to plan taxonomy changes.
- **Preconditions:** Admin (or Moderator read scope) authenticated (ACT-04); taxonomy exists or is empty.

## Main Scenario
1. Admin opens Catalog → Categories → client `GET /admin/categories` (API-ADM-014) with `?includeHidden`.
2. System returns the whole tree (not paged): `id`, `parentId`, ar/en `name`, ar/en `slug`, `level`, `path`, `sortOrder`, `isActive`, `productCount`.
3. Admin verifies the structural rules — depth ≤ 5 levels and slugs unique per level (BR-CAT-03) — and reviews where products are attached.
4. No record is modified; edits happen in UC-117…UC-119.

## Alternative Scenarios
- **A1 — Hidden nodes included:** `?includeHidden=true` also shows inactive nodes for audit-style review.
- **A2 — Moderator read:** A Moderator opens the same read-only tree; taxonomy writes remain Admin-only.
- **A3 — Empty taxonomy:** No categories → empty `items`; admin proceeds to UC-117.

## Exception Scenarios
- **E1 — Permission denied:** A caller outside admin/moderator read scope → 403 `FORBIDDEN`; no tree returned.
- **E2 — Validation failure:** Malformed `includeHidden` value → 400 `VALIDATION_ERROR`; no tree returned.
- **E3 — Concurrent taxonomy edit:** Another admin creates/moves a node while this tree is open → the view is stale; reload shows the new structure and recomputed levels.

## Postconditions
- Taxonomy reviewed read-only; no node state changed by viewing.
- Observed depth and per-level slugs conform to BR-CAT-03 or violations are identified for correction.

## Business Rules Applied
- BR-CAT-03

## Related Requirements
- FR-004 (Product Catalog Management), FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Admin and Moderator read; node create/update/delete is Admin-only (UC-117…UC-119).
- **Data involved:** Categories (tree, levels, slugs, product counts); no audit entries from reads.
- **External dependencies:** Storefront/search consume the same taxonomy for browsing and indexing.

## Acceptance Criteria
- **AC-UC116-01:** Given a nested taxonomy, when the tree is read, then every node reports `level`, `path`, ar/en `slug` and `productCount` (API-ADM-014).
- **AC-UC116-02:** Given the stored tree, when inspected, then depth never exceeds 5 levels and slugs are unique within each level (BR-CAT-03).
- **AC-UC116-03:** Given a Moderator session, when the tree is read, then 200 is returned with no write capability exposed.
- **AC-UC116-04:** Given a malformed query parameter, when requested, then 400 `VALIDATION_ERROR` and no tree data.
