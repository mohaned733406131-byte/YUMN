# UC-291 — Review a CMS Page's Publish History Before Republishing

## Header Info
- **Use Case ID:** UC-291
- **Title:** Review a CMS Page's Publish History Before Republishing
- **Actor:** Admin (ACT-04)
- **Trigger:** A static/CMS page is about to be edited and republished, and the last publisher must be known before content changes go live
- **Priority:** P2
- **Goal:** Read the page's publish history, confirm who changed what and when, then republish deliberately instead of silently overwriting a live page.
- **Preconditions:** Page exists in the CMS; Admin holds content management rights (API-CNT-007/008); a reason for the change is available.

## Main Scenario
1. Admin opens the page detail (`GET /admin/pages/{id}`, API-CNT-007).
2. System returns the draft content, `publishedAt` and `history: [ { at, by, action } ]`.
3. Admin reviews each entry — who published, who edited, when — to establish the current live state's provenance.
4. Admin edits the draft (`PUT /admin/pages/{id}`, API-CNT-008) — the update never mutates a live page silently.
5. The republish is applied deliberately from the reviewed draft; the change is recorded in the page history and the platform audit trail (BR-PLT-06).

## Alternative Scenarios
- **A1 — History is clean:** the last publisher and content match expectations → Admin proceeds with the planned edit.
- **A2 — Unexpected prior change:** an unknown actor or unexpected action appears → Admin investigates via the audit log before editing (BR-PLT-06).
- **A3 — Moderator reviewing only:** Moderator may read the page detail and history (API-CNT-007) but cannot write; edits and republish stay with Admin (API-CNT-008).

## Exception Scenarios
- **E1 — Page not found:** `NOT_FOUND` → no history, no edit (API-CNT-007).
- **E2 — Malformed update payload:** `VALIDATION_ERROR` → draft unchanged, live page unchanged (API-CNT-008).
- **E3 — Concurrent edit by another Admin:** the later save wins on the draft only — the live page never changes without an explicit publish step, and both actions are auditable (BR-PLT-06).

## Postconditions
- Success: the publish history has been reviewed, the draft carries the intended content, and the republish is attributable to Admin with a history entry.
- Failure: no history entry, no content change — the live page remains exactly as published.

## Business Rules Applied
- BR-PLT-06

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))

## Permissions / Data / External Dependencies
- **Permissions:** Admin (ACT-04) page write (API-CNT-008); Moderator read-only (API-CNT-007).
- **Data involved:** CMS page records, draft content, publish history rows, audit entries.
- **External dependencies:** append-only audit log (`GET /admin/audit-log`, API-ADM-024).

## Acceptance Criteria
- **AC-UC291-01:** Given an existing page, when Admin opens its detail, then `publishedAt` and the full publish history are returned (API-CNT-007).
- **AC-UC291-02:** Given an update to the draft, when `PUT` completes, then the live page is unchanged until the deliberate republish.
- **AC-UC291-03:** Given a republish, when it completes, then a history entry and an audit entry name Admin and the timestamp (BR-PLT-06).
- **AC-UC291-04:** Given a Moderator, when an edit is attempted, then it is rejected and the page is unchanged (API-CNT-008).
