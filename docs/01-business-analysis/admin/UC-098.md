# UC-098 — Freeze a Customer Wallet

## Header Info
- **Use Case ID:** UC-098
- **Title:** Freeze a Customer Wallet
- **Actor:** Admin (ACT-04) — finance scope
- **Trigger:** Admin freezes a wallet for legal, fraud or abuse reasons
- **Priority:** P0
- **Goal:** Block a customer's wallet from paying and topping up while refunds still land on it.
- **Preconditions:** Admin authenticated with freeze permission (API-ADM-033 `ADMIN`); target wallet is `ACTIVE`; a mandatory reason is supplied.

## Main Scenario
1. Admin opens Finance → Wallet freezes → selects the customer → `POST /admin/wallets/{userId}/freeze` with `{ reason, note? }` (API-ADM-033).
2. System sets wallet status → `FROZEN`: payments and top-ups are rejected, while refunds continue to credit the balance (BR-PAY-09).
3. The balance itself is untouched — a freeze is a state flag, not a ledger posting.
4. An append-only audit entry records actor, reason and before/after state (BR-PLT-06) and the `auditId` is returned.
5. Customer-visible effect: the next payment or top-up attempt fails the wallet check; no money moves.

## Alternative Scenarios
- **A1 — Already frozen:** `STATE_CONFLICT`; Admin reviews the existing freeze list instead (UC-128).
- **A2 — Refunds during freeze:** Incoming refunds still credit (BR-PAY-09) and remain unspendable until the freeze is lifted.

## Exception Scenarios
- **E1 — Permission denied:** Moderator or non-admin → `403 FORBIDDEN`; nothing changes.
- **E2 — Missing reason:** `REASON_REQUIRED`; no state change and no audit row.
- **E3 — Concurrent unfreeze:** Another admin lifts the freeze meanwhile → `STATE_CONFLICT`, refetch before retry.
- **E4 — Payment in flight:** An authorized payment either completes atomically before the freeze or fails afterwards — the balance check is atomic, so no partial state exists.

## Postconditions
- The wallet is `FROZEN`; balance unchanged; pay/top-up blocked, refunds still credit (BR-PAY-09).
- One audit entry exists (BR-PLT-06).

## Business Rules Applied
- BR-PAY-09, BR-PLT-06

## Related Requirements
- FR-013 (Wallet & Payment Processing)
- FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN` finance scope only; customers can never freeze their own wallet.
- **Data involved:** Wallet status flag, balance (unchanged), audit entry.
- **External dependencies:** Wallet/ledger service (B07); audit writer (BR-PLT-06).

## Acceptance Criteria
- **AC-UC098-01:** Given an active wallet, when freeze is posted with a reason, then status becomes `FROZEN` and an `auditId` returns.
- **AC-UC098-02:** Given a frozen wallet, when a payment is attempted, then the payment is rejected.
- **AC-UC098-03:** Given a frozen wallet, when a refund arrives, then the balance still credits (BR-PAY-09).
- **AC-UC098-04:** Given the freeze, when completed, then the balance is unchanged (state flag only).
