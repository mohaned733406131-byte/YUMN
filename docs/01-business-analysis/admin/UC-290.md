# UC-290 — Monitor Queue Depths and SLA Breaches as Moderator

## Header Info
- **Use Case ID:** UC-290
- **Title:** Monitor Queue Depths and SLA Breaches as Moderator
- **Actor:** Moderator (ACT-06)
- **Trigger:** The Moderator triages the console and needs the current backlog picture and breached SLAs before routing work to Admin
- **Priority:** P2
- **Goal:** Read platform queue depths and SLA breach counts from the dashboard so escalations are spotted early and handed to the right owner.
- **Preconditions:** Moderator holds the dashboard read subset (API-ANL-006); queues emit depth metrics; the 24-hour order SLA rule is in force (BR-ORD-10).

## Main Scenario
1. Moderator opens the platform dashboard (`GET /admin/dashboard`, API-ANL-006).
2. System returns `queues: { kyc, returns, disputes, topups }`, `sla: { sla24hEscalations, overdueDecisions }` and fulfillment figures.
3. Moderator reads queue depths to spot growing backlogs and `sla24hEscalations` for orders stuck at `CONFIRMED` (BR-ORD-10).
4. Moderator cross-checks a flagged case in the operations queue (`GET /admin/orders?escalated=true`, API-ORD-013) — read-only in the Moderator subset.
5. Moderator routes the finding to the owning Admin (KYC, disputes, order escalation) with the dashboard figures as evidence.

## Alternative Scenarios
- **A1 — Quiet period:** all queues within normal depth and zero escalations → nothing routed; the check itself is the record of the round.
- **A2 — Queue depth grows during an incident:** Moderator escalates immediately rather than waiting for the next round; depth is a live metric, not a report (BR-PLT-02).
- **A3 — Report instead of dashboard:** Moderator runs a report family for detail (`GET /admin/reports/{family}`, API-ANL-007) — export remains Admin-only.

## Exception Scenarios
- **E1 — Moderator requests an admin-only surface (export, write action):** `FORBIDDEN` → nothing is streamed or changed; the dashboard read subset still works (API-ANL-006/008).
- **E2 — Invalid date range:** `VALIDATION_ERROR` → no payload, no state touched.
- **E3 — Metrics scrape gap:** stale panels are treated as unavailable, never as zero — a silent backlog is exactly what this monitor exists to catch (BR-PLT-02).

## Postconditions
- Success: Moderator holds a current queue/SLA picture and any breach has been routed to its owning Admin; no queue or order state changed.
- Failure: no dashboard is produced and nothing is written — an unreadable dashboard is escalated, not faked.

## Business Rules Applied
- BR-ORD-10, BR-PLT-02

## Related Requirements

## Permissions / Data / External Dependencies
- **Permissions:** Moderator (ACT-06) dashboard read subset; exports and privileged actions stay Admin (API-ANL-006/008).
- **Data involved:** queue depth metrics, SLA escalation counters, escalated order rows (read).
- **External dependencies:** Prometheus/Grafana metrics pipeline (INT-REQ-007); operations queue (API-ORD-013).

## Acceptance Criteria
- **AC-UC290-01:** Given Moderator credentials, when the dashboard is opened, then queue depths and SLA breach counters are returned (API-ANL-006).
- **AC-UC290-02:** Given an order still at `CONFIRMED` 24 h after confirmation, when the dashboard is read, then it is counted as an escalation (BR-ORD-10).
- **AC-UC290-03:** Given a Moderator, when report export is attempted, then `FORBIDDEN` is returned (API-ANL-008).
- **AC-UC290-04:** Given a stale metrics scrape, when panels are unread, then the state is reported unavailable rather than shown as zero.
