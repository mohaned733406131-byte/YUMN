# UC-137 — Read the Orders Queue as Moderator (Read-Only)

## Header Info
- **Use Case ID:** UC-137
- **Title:** Read the Orders Queue as Moderator (Read-Only)
- **Actor:** Moderator (ACT-06)
- **Trigger:** A Moderator needs order context to advise on a case — dispute input, escalation triage, or support hand-off
- **Priority:** P1
- **Goal:** Read the platform orders queue and timelines to prepare advisory input for Admin, changing nothing.
- **Preconditions:** Moderator authenticated with READ-ONLY operations scope (ACT-06); may read queues and timelines but cannot transition, cancel, or override any order state — all writes are Admin-only and refused server-side; escalation hand-off is the only output.

## Main Scenario
1. Moderator opens the orders console (Admin+ with Moderator read-only, routing.md §4) → `GET /admin/orders` (API-ORD-013, roles include MODERATOR) with state/escalated/disputed filters.
2. System returns the scoped queue projection with no write affordances rendered and no privileged actions available.
3. Moderator opens an order → sub-order states, totals, flags; timeline via `GET /orders/{id}/timeline` filtered to the admin/moderator visibility slice (BR-ORD-09: admin/moderator scoped visibility).
4. Moderator assesses context — escalation flags, dispute posture, timeline — to prepare advice for Admin; no state change is made or attempted.
5. Reads never create audit rows; privileged and money actions are the ones that write append-only audit entries (BR-PLT-06) — and none occur in this UC.
6. When action is required, Moderator hands the case to Admin with the recommendation (UC-033); Admin executes any decision.

## Alternative Scenarios
- **A1 — Filter drill-down:** narrow by `SLA_24H`/`disputed` flags → scoped rows only, still read-only.
- **A2 — Timeline review:** open the append-only timeline slice → actor/timestamp/reason entries for the visible sub-orders (BR-ORD-09).
- **A3 — Advisory hand-off:** findings passed to Admin (UC-033) — Moderator never acts on orders directly.
- **A4 — Empty queue:** no matching orders → friendly empty state, not an error.

## Exception Scenarios
- **E1 — Permission denied:** Moderator attempts `POST /admin/orders/{id}/transition` → `403 FORBIDDEN`; no state change, no audit row (BR-PLT-06 governs privileged actions, none taken).
- **E2 — Out-of-scope order:** row not present in the scoped projection → `404`/`TIMELINE_ACCESS_DENIED`, nothing revealed.
- **E3 — Empty queue:** zero rows for the filter → empty state with filters intact.
- **E4 — SLA breach seen:** `SLA_24H`/delivery flags observed → Moderator escalates to Admin (UC-135/UC-136) instead of acting.

## Postconditions
- Queue and timeline read; zero state changes; no audit rows created by the read itself.
- Advisory input delivered to Admin where action is needed.

## Business Rules Applied
- BR-PLT-06, BR-ORD-09

## Related Requirements
- FR-012 (Order Lifecycle Management), FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Moderator READ-ONLY on orders — no transitions, cancels, overrides, or finance actions (deny-by-default); Admin holds all writes.
- **Data involved:** Order queue rows, sub-order states, timeline slices (scoped), escalation flags.
- **External dependencies:** Admin order tooling (B06) for hand-off; escalation watcher (B06) producing flags.

## Acceptance Criteria
- **AC-UC137-01:** Given a Moderator, when the orders queue opens, then rows render read-only (API-ORD-013 roles=MODERATOR).
- **AC-UC137-02:** Given a Moderator, when a transition is attempted, then `403 FORBIDDEN` returns and state is unchanged.
- **AC-UC137-03:** Given an order, when the Moderator opens the timeline, then only the admin/moderator-scoped append-only slice shows (BR-ORD-09).
- **AC-UC137-04:** Given a Moderator read, when checked afterwards, then no audit row was created by the read (BR-PLT-06).
