# UC-099 — Unfreeze a Customer Wallet

## Header Info
- **Use Case ID:** UC-099
- **Title:** Unfreeze a Customer Wallet
- **Actor:** Admin (ACT-04) — finance scope
- **Trigger:** Admin lifts a wallet freeze after investigation
- **Priority:** P1
- **Goal:** Restore a customer's ability to pay and top up without altering the recorded balance.
- **Preconditions:** Admin authenticated with unfreeze permission (API-ADM-034 `ADMIN`); wallet status is `FROZEN`; a reason is supplied.

## Main Scenario
1. Admin opens the frozen wallet from the freeze monitor (UC-128) → Unfreeze → mandatory reason.
2. Client `POST /admin/wallets/{userId}/unfreeze` (API-ADM-034).
3. System sets status → `ACTIVE`; payments and top-ups are accepted again; balance and ledger history are untouched.
4. An append-only audit entry records actor, reason and before/after state (BR-PLT-06) and the `auditId` is returned.
5. Refunds accumulated during the freeze become spendable immediately (BR-PAY-09).

## Alternative Scenarios
- **A1 — Not frozen:** `STATE_CONFLICT`; the call is a no-op.
- **A2 — Account or store still suspended:** Wallet is active but store-scoped actions stay blocked until UC-092/UC-097 clear them.

## Exception Scenarios
- **E1 — Permission denied:** Moderator → `403 FORBIDDEN`; nothing changes.
- **E2 — Missing reason:** `REASON_REQUIRED`; no state change and no audit row.
- **E3 — Concurrent freeze:** Another admin re-freezes meanwhile → `STATE_CONFLICT`, refetch before retry.
- **E4 — Rapid freeze/unfreeze churn:** Every transition is separately audited (BR-PLT-06); toggling never changes the balance.

## Postconditions
- The wallet is `ACTIVE`; balance and ledger unchanged.
- One audit entry per state change (BR-PLT-06).

## Business Rules Applied
- BR-PAY-09, BR-PLT-06

## Related Requirements
- FR-013 (Wallet & Payment Processing)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN` finance scope only.
- **Data involved:** Wallet status, balance (read-only), audit entry.
- **External dependencies:** Wallet/ledger service (B07); audit writer (BR-PLT-06).

## Acceptance Criteria
- **AC-UC099-01:** Given a frozen wallet, when unfreeze is posted with a reason, then status becomes `ACTIVE` and an `auditId` returns.
- **AC-UC099-02:** Given refunds accumulated during the freeze, when unfrozen, then they are spendable with no balance change.
- **AC-UC099-03:** Given an already-active wallet, when posted, then `STATE_CONFLICT` is returned.
- **AC-UC099-04:** Given the unfreeze, when completed, then no ledger rows are added (status flag only).
