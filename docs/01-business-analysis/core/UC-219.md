# UC-219 — Purge Orphaned Product Images Only When No Order References Them

## Header Info
- **Use Case ID:** UC-219
- **Title:** Purge Orphaned Product Images Only When No Order References Them
- **Actor:** System (ACT-07) — object-sweep job (no interactive login)
- **Trigger:** The periodic orphan sweep finds product-image objects whose owning product row no longer exists
- **Priority:** P2
- **Goal:** Reclaim orphaned image bytes while guaranteeing that any image still referenced by an order survives.
- **Preconditions:** Product deletion is soft-delete while the row lives (BR-CAT-06); order lines carry product/image snapshots; object store reachable; quarantine re-check before delete.

## Main Scenario
1. The orphan sweep compares product-image objects in the object store against live product rows and order references.
2. Suspected orphans land on the report first, then are re-checked immediately before any delete.
3. Re-check: no product row owns the object **and** no order line references it → object bytes and versions are deleted.
4. Any order referencing the image keeps it — catalog history in orders survives the purge (BR-CAT-06).
5. A soft-deleted product that still has its row keeps its images; only a purged row makes its images candidates.
6. The sweep result — counts, deletes, keeps-due-to-reference — is recorded as evidence.

## Alternative Scenarios
- **A1 — Product soft-deleted:** row alive → images retained; only ACTIVE products surface anyway (BR-CAT-06).
- **A2 — Store closure:** products de-published and later purged, but order-referenced images persist through the sweep.
- **A3 — Object already missing:** reported as a reference mismatch; nothing to delete.

## Exception Scenarios
- **E1 — Reference scan fails or times out:** the sweep aborts without deleting — never delete on an uncertain scan.
- **E2 — Order created referencing the image mid-sweep:** the quarantine window plus the pre-delete re-check absorb the race; the object survives.
- **E3 — Delete fails:** retried per job policy with alerting (BR-PLT-02); an undeletable orphan is reported rather than silently ignored.

## Postconditions
- Success: no orphan object remains and every order-referenced image still exists.
- Failure: nothing is deleted when references are uncertain; live catalog and order history are untouched.

## Business Rules Applied
- BR-CAT-06

## Related Requirements
- FR-004 (Product Catalog Management)

## Permissions / Data / External Dependencies
- **Permissions:** service identity only (ACT-07) — object-store delete rights scoped to product-image prefixes; no human role.
- **Data involved:** product image objects, product rows, order line image references, orphan report.
- **External dependencies:** MinIO object store; PostgreSQL for reference scans.

## Acceptance Criteria
- **AC-UC219-01:** Given an image owned by a live product, when the sweep runs, then it is not deleted.
- **AC-UC219-02:** Given an image referenced by an order line, when the sweep runs, then the object survives.
- **AC-UC219-03:** Given an object with no product row and no order reference, when the sweep completes, then it is deleted and reported.
