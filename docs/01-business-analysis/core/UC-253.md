# UC-253 — Run the Daily Retention Purge With Floor Guards and Evidence

## Header Info
- **Use Case ID:** UC-253
- **Title:** Run the Daily Retention Purge With Floor Guards and Evidence
- **Actor:** System (ACT-07) — daily retention purge job (no interactive login)
- **Trigger:** The daily `system.retention.purge` schedule fires
- **Priority:** P1
- **Goal:** Delete only what is past its retention floor, prove it with evidence, and never touch protected classes.
- **Preconditions:** Retention classes and periods are configured; financial/audit floors (≥5 years) are enforced by guards (NFR-019); a privileged maintenance path exists.

## Main Scenario
1. The job starts under its queue name following the `{block}.{entity}.{action}` scheme (BR-PLT-01).
2. Guard check runs first: any class below its floor → skip and alert, never delete (NFR-019).
3. Archive step: rows leaving hot storage are copied to cold storage before becoming purge-eligible.
4. Class-specific deletion runs for what passed the guards.
5. Cascade: search index, cache keys and object orphans are updated in the same run.
6. Evidence is written per run — actor, scope, row counts, timestamp — feeding the weekly report (UC-247).
7. Failures retry 3 times with backoff, then dead-letter with a depth alert (BR-PLT-02).

## Alternative Scenarios
- **A1 — Nothing due:** the job completes with zero counts and still writes its evidence entry (an empty run is a recorded run).
- **A2 — A guard trips:** skip and alert; zero rows deleted for that class; nothing is force-removed.
- **A3 — Backlog from a failed run:** today's run processes what is due; backlog age surfaces in the weekly report (UC-247).

## Exception Scenarios
- **E1 — Job crashes mid-run:** completed sets stay deleted (idempotent) and the remainder is re-evaluated next run — no untracked half-state.
- **E2 — Purge attempt on a young financial row:** the guard blocks and alerts — the row is never deleted (NFR-019).
- **E3 — Cascade store unreachable:** retries then dead-letter with an alert (BR-PLT-02); the evidence flags an incomplete cascade for re-run.

## Postconditions
- Success: only past-floor data is gone; guarded data is intact; an evidence row exists for the run.
- Failure: nothing is deleted without evidence; guards block rather than delete; protected floors are never crossed (NFR-019).

## Business Rules Applied
- BR-PLT-01, BR-PLT-02

## Related Requirements
- FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** privileged maintenance path only — the application role holds no delete rights over retained data.
- **Data involved:** retention class rows, guard state, evidence entries, derived-store copies (index/cache/objects).
- **External dependencies:** BullMQ purge queue; cold archive storage; search index; Redis; MinIO object store.

## Acceptance Criteria
- **AC-UC253-01:** Given a class below its floor, when the job runs, then it is skipped and alerted with zero deletions (NFR-019).
- **AC-UC253-02:** Given eligible rows, when the job completes, then evidence records actor, scope, counts and timestamp (FR-020).
- **AC-UC253-03:** Given a failing cascade step, when retries exhaust, then it dead-letters with an alert (BR-PLT-02).
- **AC-UC253-04:** Given the queue, when the job registers, then its name follows `{block}.{entity}.{action}` (BR-PLT-01).
