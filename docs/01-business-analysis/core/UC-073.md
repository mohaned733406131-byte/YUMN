# UC-073 — Escalate KYC Decisions Past the 48-Hour SLA

## Header Info
- **Use Case ID:** UC-073
- **Title:** Escalate KYC Decisions Past the 48-Hour SLA
- **Actor:** System (ACT-07) — SLA monitor (no interactive login)
- **Trigger:** Scheduled SLA sweep (`b03.vendor.kyc.sla`) at 48 hours after a KYC submission
- **Priority:** P1
- **Goal:** Surface undecided KYC cases to admins the moment the 48-hour decision SLA is exceeded, so onboarding never stalls silently.
- **Preconditions:** KYC case submitted and `UNDER_REVIEW`; submission timestamp recorded; admin KYC queue available (UC-031).

## Main Scenario
1. The scheduler enqueues `b03.vendor.kyc.sla` jobs; at 48 h after submission the worker evaluates each open case.
2. If no decision exists, the case is escalated: flagged as SLA-breached, appended to the admin review queue, and admins are notified with the case age.
3. The breach is recorded (actor = System, reason = SLA escalation) so SLA performance is measurable.
4. The human admin still decides — approve or reject with reason — within the admin flow (UC-031); the system never auto-approves.
5. Rejection allows resubmission under a fresh submission clock (BR-VND-03).

## Alternative Scenarios
- **A1 — Decision made before 48 h:** The sweep finds the case decided → no escalation; the SLA was met.
- **A2 — Rejection with resubmission:** The vendor resubmits; a new submission timestamp starts a new 48-hour window with its own escalation check (BR-VND-03).
- **A3 — Case still open days later:** Escalation repeats/remains visible until decided — the case cannot age out of attention.

## Exception Scenarios
- **E1 — SLA sweep job fails:** Retried with backoff, then dead-lettered with an alert; because breach detection derives from stored timestamps, the next successful run catches up — no case is permanently missed.
- **E2 — Decision races the escalation:** Whichever commits first wins; a case decided just before escalation completes without a stale flag, and an escalation landing on a just-decided case is marked moot.
- **E3 — Notification to admins fails:** The escalation flag and queue entry are already persisted; notification retries independently.

## Postconditions
- Decided cases: no escalation; decision recorded with reason (BR-VND-03).
- Undecided cases past 48 h: flagged, queued for admin review, admins notified.
- SLA breach history append-only and reportable.

## Business Rules Applied
- BR-VND-03

## Related Requirements
- FR-007 (Vendor Onboarding & KYC)

## Permissions / Data / External Dependencies
- **Permissions:** Service identity (System, ACT-07) flags and notifies only; the decision itself requires the Admin actor (UC-031).
- **Data involved:** KYC case rows (status, submittedAt, SLA due, decision), escalation flags, admin notifications.
- **External dependencies:** BullMQ (`b03.vendor.kyc.sla`); admin KYC queue; notification channels.

## Acceptance Criteria
- **AC-UC073-01:** Given a case undecided at 47 h 59 m, when the sweep runs, then no escalation occurs.
- **AC-UC073-02:** Given a case undecided past 48 h, when the sweep runs, then it is flagged and queued for admin review (BR-VND-03).
- **AC-UC073-03:** Given a rejected case that is resubmitted, when the new submission is made, then a fresh 48-hour window applies (BR-VND-03).
- **AC-UC073-04:** Given an escalation in flight when an admin decides, when both commit, then no stale escalation remains on the decided case.
