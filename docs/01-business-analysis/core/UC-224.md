# UC-224 — Alert on Search Indexing Lag Beyond the Five-Minute Delete SLO

## Header Info
- **Use Case ID:** UC-224
- **Title:** Alert on Search Indexing Lag Beyond the Five-Minute Delete SLO
- **Actor:** System (ACT-07) — monitoring stack (no interactive login)
- **Trigger:** Measured search indexing lag exceeds the five-minute delete SLO
- **Priority:** P2
- **Goal:** Make silent index drift loud — a deleted product that lingers past five minutes pages the right owner instead of staying invisible.
- **Preconditions:** Indexer lag exported by the Elasticsearch exporter; Prometheus rules provisioned from the repo; delete SLO ≤ 5 minutes; only ACTIVE products discoverable (BR-CAT-06).

## Main Scenario
1. The exporter scrapes indexing lag; Prometheus evaluates the lag rule continuously.
2. A source row is deleted or soft-deleted → its document must leave the index within the five-minute delete SLO (BR-CAT-06).
3. Measured lag exceeds five minutes → the alert rule fires from its provisioned rule file.
4. The alert routes per severity to the search dashboard owner and on-call with a runbook link.
5. The operator drains the backlog or resyncs the index; lag falls under the SLO and the alert resolves.
6. An alert-coverage check fails CI if this signal ever loses its rule.

## Alternative Scenarios
- **A1 — Lag within SLO:** no alert; the metric stays visible on the search dashboard.
- **A2 — Search fully down:** health and fallback alerts take over (UC-222, UC-223) — this rule covers silent lag, not outage.
- **A3 — Soft-delete only:** removing a product from discovery counts as a deletion for the SLO (BR-CAT-06).

## Exception Scenarios
- **E1 — Alerting pipeline dead:** a weekly dead-man's-switch proves the paging path itself still works.
- **E2 — Backlog keeps growing:** the alert stays firing until lag is under the SLO; it is never auto-silenced without an expiry.
- **E3 — False calm during rebuild:** a rebuild job in progress still reports lag — the alert remains the source of truth until measured lag clears.

## Postconditions
- Success: lag breaches are observable and routed; deleted products leave the index inside five minutes.
- Failure: no silent drift — a missed delete remains visible as a firing alert until fixed.

## Business Rules Applied

## Related Requirements

## Permissions / Data / External Dependencies
- **Permissions:** monitoring plane only — reads metrics; no data mutation; alert routing per ops roles.
- **Data involved:** indexing-lag metric, alert rules, alert instances, runbook links.
- **External dependencies:** Prometheus/Grafana/Alertmanager; Elasticsearch exporter (DEP-04 side).

## Acceptance Criteria
- **AC-UC224-01:** Given index lag above five minutes, when the rule evaluates, then an alert fires and routes to the search owner (FR-009).
- **AC-UC224-02:** Given a product soft-deleted at its source, when the SLO runs, then the document is gone from the index within five minutes (BR-CAT-06).
- **AC-UC224-03:** Given lag back under the SLO, when the rule re-evaluates, then the alert resolves.
