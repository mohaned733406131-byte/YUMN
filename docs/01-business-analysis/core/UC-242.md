# UC-242 — Auto-Escalate Return Decisions Stalled Past 48 Hours

## Header Info
- **Use Case ID:** UC-242
- **Title:** Auto-Escalate Return Decisions Stalled Past 48 Hours
- **Actor:** System (ACT-07) — return decision escalation job (no interactive login)
- **Trigger:** A return approval decision remains pending for 48 hours
- **Priority:** P1
- **Goal:** Hand stalled return decisions to an admin reviewer instead of leaving the customer waiting indefinitely.
- **Preconditions:** Return at RETURN_REQUESTED with no APPROVED/REJECTED decision; the decision SLA is 48 hours (return-decision escalation register); the admin review queue exists (FR-020).

## Main Scenario
1. The `b09.return.decision-escalate` sweep finds returns pending a decision for 48 hours.
2. The case is flagged escalated and placed in the admin review queue (FR-020).
3. The admin is notified; the escalation is recorded on the case so the timeline explains the hand-off.
4. The admin reviews the request, policy and evidence, then decides approve or reject with a reason (BR-RET-02).
5. The decision is written append-only to the return and order history (BR-ORD-03).
6. Re-runs never escalate the same case twice — the escalated flag guards the sweep.

## Alternative Scenarios
- **A1 — Decision made within 48 hours:** the vendor or admin decides first → the sweep skips the case; no escalation is created.
- **A2 — Vendor responds after escalation:** the vendor's decision is still accepted — escalation routes the case, it does not lock the vendor out (BR-RET-02).
- **A3 — Escalated case decided by the admin:** the queue entry closes with the decision and the reason recorded.

## Exception Scenarios
- **E1 — Escalation job fails:** retries then dead-letter with an alert; the case stays pending and is re-detected next run — never auto-decided (BR-PLT-02).
- **E2 — Admin queue backlog:** cases age visibly in the queue; the customer's timeline shows the escalation rather than silence.
- **E3 — Decision races the escalation flag:** whichever commits first wins — a case decided at hour 47.9 is not queued at hour 48 (BR-RET-02).

## Postconditions
- Success: no decision stalls beyond 48 hours — every pending case sits in the admin queue with an owner; escalation is recorded.
- Failure: the case remains pending and un-decided — no approval or rejection is ever fabricated by the job.

## Business Rules Applied
- BR-RET-02, BR-ORD-03 — the 48-hour deadline itself has no BR in DOC-BA-005; it is the return-decision SLA (FR-016).

## Related Requirements
- FR-016 (Returns & Refunds)

## Permissions / Data / External Dependencies
- **Permissions:** service identity only (ACT-07) — flags cases and enqueues them; the decision itself stays with vendor/admin (human).
- **Data involved:** return record, escalation flag, admin review queue entry, order history row, notifications.
- **External dependencies:** BullMQ `b09.return.decision-escalate` queue; admin review console (B13); notification pipeline.

## Acceptance Criteria
- **AC-UC242-01:** Given a return pending a decision for 48 hours, when the sweep runs, then it is escalated into the admin review queue (FR-016).
- **AC-UC242-02:** Given a return decided at hour 47, when the sweep runs, then no escalation is created (BR-RET-02).
- **AC-UC242-03:** Given an escalated case, when the admin decides, then the decision lands in append-only history with a reason (BR-ORD-03).
- **AC-UC242-04:** Given the same case on the next sweep, when the job runs, then it is not escalated a second time.
