# UC-221 — Purge KYC Objects and Metadata Five Years After Account Closure

## Header Info
- **Use Case ID:** UC-221
- **Title:** Purge KYC Objects and Metadata Five Years After Account Closure
- **Actor:** System (ACT-07) — retention job (no interactive login)
- **Trigger:** The retention sweep finds a closed account whose KYC retention window has elapsed
- **Priority:** P2
- **Goal:** Remove KYC document bytes and metadata five years after closure, blocked by guards if any floor or hold applies.
- **Preconditions:** Account closed — clock starts at closure, not submission; retention floor ≥ 5 years (NFR-019); guards run before every delete.

## Main Scenario
1. The retention job evaluates closed accounts against the KYC retention window — five years from closure.
2. Not yet due → the set is retained for fraud/dispute exposure; the job skips it.
3. Due → guards check that no floor or open-investigation hold applies; a tripped guard blocks and alerts instead of deleting.
4. Guards pass → object lifecycle deletes the KYC document objects from the store.
5. KYC metadata rows are purged; no tombstone is needed because workflow history lives in the audit trail.
6. Purge evidence (class, counts, timestamp) is recorded for the retention report.

## Alternative Scenarios
- **A1 — Account never closed:** the clock never starts; nothing is eligible.
- **A2 — Closed under five years:** retained — a purge attempt on a guarded set blocks and alerts, never deletes early (NFR-019).
- **A3 — Open investigation:** the purge is withheld and the case flagged; deletion happens only after the hold clears.

## Exception Scenarios
- **E1 — Guard detects protected data:** block + alert; zero rows deleted — financial and audit floors are never in scope here.
- **E2 — Object already missing:** the metadata purge proceeds and the mismatch is reported.
- **E3 — Job crash mid-run:** already-deleted sets stay deleted (idempotent) and remaining sets are re-evaluated next run — no metadata-only half state survives a rerun.

## Postconditions
- Success: document bytes and metadata are gone five years after closure; audit history remains.
- Failure: nothing is deleted early; guarded sets stay intact and alerted.

## Business Rules Applied
- None — behavior is governed by the retention schedule and guards (FR-007); no BR applies directly.

## Related Requirements
- FR-007 (Vendor Onboarding & KYC)

## Permissions / Data / External Dependencies
- **Permissions:** privileged maintenance path only — the application role has no delete rights over retained KYC data.
- **Data involved:** KYC document objects, KYC metadata rows, guard/hold state, purge evidence.
- **External dependencies:** MinIO object store lifecycle; PostgreSQL metadata; audit pipeline for evidence.

## Acceptance Criteria
- **AC-UC221-01:** Given an account closed five years ago, when the job runs, then KYC objects and metadata are purged (FR-007).
- **AC-UC221-02:** Given an account closed less than five years ago, when the job runs, then its KYC data is untouched.
- **AC-UC221-03:** Given a purge attempt on a protected set, when guards trip, then the run blocks and alerts instead of deleting (NFR-019).
