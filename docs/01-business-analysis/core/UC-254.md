# UC-254 — Create Next-Month Table Partitions Ahead of Deployment

## Header Info
- **Use Case ID:** UC-254
- **Title:** Create Next-Month Table Partitions Ahead of Deployment
- **Actor:** System (ACT-07) — partition maintenance job (no interactive login)
- **Trigger:** The pre-deployment checklist runs, alongside the job's monthly schedule
- **Priority:** P1
- **Goal:** Next month's partitions exist before the deploy that could write into them — no insert failures at month rollover.
- **Preconditions:** Partitioned tables exist (`order_item`, `wallet_transaction`, `order_status_history`, `audit_log`); the maintenance job is registered; partition DDL lives only inside Prisma migration folders (NFR-017).

## Main Scenario
1. The maintenance job checks current partition coverage for every partitioned table.
2. A missing next-month range → created with `CREATE TABLE … PARTITION OF` / `ATTACH` statements inside the migration folder.
3. Financial tables run in dry-run mode first — the plan is produced, reviewed, then applied (NFR-017).
4. The pre-deploy checklist verifies "next partition created before deploy" — a missing partition fails the gate.
5. CI rehearsal runs the job dry so drift surfaces before production, not during rollover.
6. The same job retires partitions past the retention window — creation and retirement share one owner.

## Alternative Scenarios
- **A1 — Partitions already exist:** the check passes and nothing is created — the job is idempotent.
- **A2 — Mid-month deploy:** next month is still verified — the rule is "ahead", not "imminent".
- **A3 — New partitioned table added:** it joins the job's table list when its migration lands; the DDL ships with the schema change.

## Exception Scenarios
- **E1 — DDL fails (permissions, locks):** the job fails loudly → the deploy gate blocks; no deploy proceeds over missing partitions (BR-PLT-02).
- **E2 — Dry-run plan looks wrong:** apply is skipped and humans intervene — no unplanned financial-table DDL ever runs.
- **E3 — Job crash:** the re-run detects existing partitions and fills only the gaps — never a duplicate partition (BR-PLT-02).

## Postconditions
- Success: every partitioned table has next month's partition and the deploy gate is green.
- Failure: missing partitions remain missing but the deploy is blocked — a rollover insert failure is never discovered in production.

## Business Rules Applied
- BR-PLT-01 (the registered background job that owns partition maintenance), BR-PLT-02

## Related Requirements
- FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** service identity only (ACT-07) — DDL through the migration path; no interactive role runs partition DDL ad hoc.
- **Data involved:** partition metadata, partition bound definitions, migration SQL files, pre-deploy checklist state.
- **External dependencies:** PostgreSQL partition DDL; BullMQ maintenance job; CI pre-deploy gate.

## Acceptance Criteria
- **AC-UC254-01:** Given partitioned tables without a next-month range, when the job runs, then the partitions are created before deploy (NFR-017).
- **AC-UC254-02:** Given a financial table, when changes are planned, then the job runs dry-run first and applies only after review (NFR-017).
- **AC-UC254-03:** Given a missing next-month partition at gate time, when the checklist runs, then the deploy is blocked.
- **AC-UC254-04:** Given an already-covered range, when the job runs, then no duplicate partition is created (BR-PLT-01).
