# UC-081 — Generate Report Export Files

## Header Info
- **Use Case ID:** UC-081
- **Title:** Generate Report Export Files
- **Actor:** System (ACT-07) — export generator (no interactive login)
- **Trigger:** An admin or vendor requests a report export (`b11.analytics.export`)
- **Priority:** P2
- **Goal:** Produce downloadable report files asynchronously with correct scope and consistent data, without blocking the requesting user.
- **Preconditions:** Report definition and requester's scope resolved; rollup/source data available; export queue running.

## Main Scenario
1. The export request is validated against the requester's role and scope, accepted with a job reference, and enqueued as `b11.analytics.export` (BR-PLT-01 naming).
2. The worker streams the scoped rows into a CSV/XLSX file in the requested locale/format — no full result set buffered in memory.
3. On success the file is stored with access bound to the requester; the UI polls job status until the download link appears.
4. Failures retry 3× with exponential backoff, then dead-letter with a depth alert; the requester sees the export as failed (BR-PLT-02).
5. The completed export is downloaded; the download and generation are logged for audit.

## Alternative Scenarios
- **A1 — Large dataset:** The export streams in chunks/pages and completes without timing out; size does not change correctness.
- **A2 — Same export requested twice:** Each request produces its own job and file — concurrent jobs never append into one file.
- **A3 — Report spans a changing dataset:** Rows are taken as-of job start, so the file is a consistent snapshot even while live data moves.

## Exception Scenarios
- **E1 — Worker crash mid-generation:** Partial output is discarded; the retry regenerates a clean file — a truncated file is never published (BR-PLT-02).
- **E2 — Retries exhausted:** The job dead-letters with an alert; the requester is told it failed — silent non-delivery is impossible.
- **E3 — Access revoked before download:** The download re-checks scope at fetch time and denies — scope is enforced on read, not only at request.

## Postconditions
- Successful request → scoped, consistent file available to its requester.
- Failed request → visible failure with retry/DLQ trail (BR-PLT-02); no corrupt file delivered.
- Generation/download recorded for audit.

## Business Rules Applied
- BR-PLT-01, BR-PLT-02

## Related Requirements
- FR-018 (Analytics & Reporting)
- Cross-reference: export generation is triggered from the portal report flows (UC-086 platform export, UC-201 store export).

## Permissions / Data / External Dependencies
- **Permissions:** Requesters export only their scope — Admin platform-wide, Vendor own store; System generates the file.
- **Data involved:** Report definitions, scoped rows, export files, job status, audit entries.
- **External dependencies:** BullMQ (`b11.analytics.export`); object storage for files; report/rollup read models.

## Acceptance Criteria
- **AC-UC081-01:** Given a valid export request, when the job completes, then a downloadable file matching the requested scope exists.
- **AC-UC081-02:** Given a generation failure, when retries exhaust, then the job dead-letters with an alert and the user sees failure (BR-PLT-02).
- **AC-UC081-03:** Given a worker crash mid-file, when retry runs, then only a complete file becomes downloadable.
- **AC-UC081-04:** Given a requester whose access was revoked, when they fetch the file, then the download is denied.
