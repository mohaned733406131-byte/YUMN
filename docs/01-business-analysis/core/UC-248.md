# UC-248 — Enforce Retention Windows on Metrics, Logs, and Traces

## Header Info
- **Use Case ID:** UC-248
- **Title:** Enforce Retention Windows on Metrics, Logs, and Traces
- **Actor:** System (ACT-07) — telemetry retention sweep (no interactive login)
- **Trigger:** Observability data ages past its retention window (store TTL or sweep)
- **Priority:** P2
- **Goal:** Bound telemetry storage — metrics, logs and traces age out on schedule while audit and financial records are untouched.
- **Preconditions:** Windows are configured (metrics 13 months; logs 30 days hot / 90 days non-security; sampled traces 7 days); telemetry stores support native aging; audit rows live in a separate store with longer floors (NFR-019).

## Main Scenario
1. The metrics store drops series older than 13 months — year-over-year comparison stays possible.
2. Application logs stay queryable for 30 days hot; non-security logs are archived on schedule and then aged out.
3. Sampled traces expire after 7 days.
4. Alert history and CI run logs age out at 90 days.
5. Audit entries and financial records are never in scope — their floors are enforced by the retention job, not this sweep (NFR-019).
6. Each store reports retained volume so the window is observable (NFR-014).

## Alternative Scenarios
- **A1 — Traces are sampled:** only what was sampled exists; expiry applies to the kept 7-day set.
- **A2 — Logs with potential PII:** log bodies carry no PII by rule — aging-out is the primary telemetry control alongside that rule.
- **A3 — Older data needed:** beyond the window the data is not queryable by design; long-horizon figures come from archived reports instead.

## Exception Scenarios
- **E1 — A store fails to age out:** volume grows past the window → capacity alerting fires rather than silent unbounded growth (NFR-014).
- **E2 — Audit rows inside a telemetry purge scope:** impossible by construction — audit lives in its own store; this sweep never touches it (NFR-019).
- **E3 — Window changed by config:** the window is configuration; the next sweep applies the new value — no data is cut early mid-cycle.

## Postconditions
- Success: no telemetry store exceeds its window; audit and financial records are untouched (NFR-019).
- Failure: nothing is deleted early — a failed sweep keeps data one extra cycle and alerts; audit data is never truncated by this path.

## Business Rules Applied
- None — telemetry windows are observability configuration (FR-018, NFR-014); no BR in DOC-BA-005 governs them.

## Related Requirements
- FR-018 (Analytics & Reporting)

## Permissions / Data / External Dependencies
- **Permissions:** service identity only (ACT-07) — ages out only telemetry stores; the application role holds no delete rights over audit data.
- **Data involved:** metric series, log streams, sampled traces, alert history, CI run logs (audit rows excluded).
- **External dependencies:** Prometheus TSDB retention; Loki log retention; trace backend TTL; Grafana dashboards.

## Acceptance Criteria
- **AC-UC248-01:** Given metrics older than 13 months, when the store ages them, then they are no longer queryable (FR-018).
- **AC-UC248-02:** Given application logs past their window, when the sweep runs, then they are removed while audit rows remain (NFR-019).
- **AC-UC248-03:** Given sampled traces older than 7 days, when cleanup runs, then they are gone (NFR-014).
- **AC-UC248-04:** Given a sweep that fails, when it retries, then no data below its window is ever deleted early.
