# UC-241 — Auto-Approve Returns Left Uninspected for 72 Hours

## Header Info
- **Use Case ID:** UC-241
- **Title:** Auto-Approve Returns Left Uninspected for 72 Hours
- **Actor:** System (ACT-07) — return inspection SLA job (no interactive login)
- **Trigger:** A return sits in RETURN_RECEIVED for 72 hours without a vendor inspection conclusion
- **Priority:** P1
- **Goal:** Close the inspection decision automatically so a stalled vendor cannot block the customer's refund.
- **Preconditions:** Return reached RETURN_RECEIVED; the inspection window is 72 hours from that state (BR-RET-05); the refund path exists (BR-RET-04).

## Main Scenario
1. The `b09.return.inspect-check` sweep finds returns in RETURN_RECEIVED older than 72 hours.
2. No inspection conclusion is recorded → the return auto-approves (BR-RET-05).
3. The auto-approval concludes the inspection and the return advances RETURN_RECEIVED → REFUNDED with append-only history, actor System (BR-RET-02).
4. `b09.return.refund-credit` initiates the wallet credit within 3 business days (BR-RET-04).
5. Customer and vendor are notified of the automatic approval (FR-017).
6. The run's outcome is recorded so the decision is explainable after the fact.

## Alternative Scenarios
- **A1 — Vendor concludes within 72 hours:** the human decision stands; the sweep skips the return (BR-RET-05).
- **A2 — Vendor rejects within the window:** the RETURN_REJECTED path runs instead; no auto-approval happens (BR-RET-02).
- **A3 — Return not yet at RETURN_RECEIVED:** the 72-hour clock has not started; the job ignores it.

## Exception Scenarios
- **E1 — Sweep job fails:** retries then dead-letter with an alert; returns stay unapproved — conservative, refunds are never paid twice (BR-PLT-02).
- **E2 — Refund credit job fails after approval:** the approval stands; the credit retries under its own job (BR-RET-04, BR-PLT-02).
- **E3 — Vendor conclusion races the boundary:** whichever write commits first wins — the outcome is single, human or automatic, never both (BR-RET-02).

## Postconditions
- Success: the inspection is concluded by auto-approval; the return advances toward REFUNDED; wallet credit is scheduled within 3 business days.
- Failure: nothing advances; the return remains RETURN_RECEIVED and is re-evaluated next run — no double refund, no lost return.

## Business Rules Applied
- BR-RET-05, BR-RET-02, BR-RET-04, BR-PLT-02

## Related Requirements
- FR-016 (Returns & Refunds)

## Permissions / Data / External Dependencies
- **Permissions:** service identity only (ACT-07) — writes return state and refund scheduling; the vendor owns the inspection it failed to conclude.
- **Data involved:** return record, state history, refund credit job, notification messages.
- **External dependencies:** BullMQ SLA sweep and refund-credit queue; wallet credit posting.

## Acceptance Criteria
- **AC-UC241-01:** Given a return in RETURN_RECEIVED for 72 hours without a conclusion, when the sweep runs, then it auto-approves (BR-RET-05).
- **AC-UC241-02:** Given a vendor conclusion at hour 71, when the sweep runs, then no auto-approval occurs (BR-RET-05).
- **AC-UC241-03:** Given auto-approval, when it commits, then the return advances toward REFUNDED with actor System in history (BR-RET-02).
- **AC-UC241-04:** Given the approval, when it completes, then the wallet credit is scheduled within 3 business days (BR-RET-04).
