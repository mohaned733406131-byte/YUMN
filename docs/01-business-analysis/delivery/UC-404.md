# UC-404 — Hear Code Attempt Feedback via Screen Reader

## Header Info
- **Use Case ID:** UC-404
- **Title:** Hear Code Attempt Feedback via Screen Reader
- **Actor:** Delivery Provider (ACT-03)
- **Trigger:** Courier verifies the delivery code with TalkBack or VoiceOver active
- **Priority:** P2
- **Goal:** Deliver every attempt result, counter and lock notice as perceivable speech — never colour alone.
- **Preconditions:** Screen reader enabled on the device; job `OUT_FOR_DELIVERY`; journey FL-06 covers job offer through code verification on S5.

## Main Scenario
1. Courier opens CodeEntry (S5) with the screen reader running; each slot exposes an accessibility role and label.
2. Digit entry and focus changes are announced so the courier knows the input state (6-digit LTR island inside the Arabic screen).
3. On a failed submit, the error text and the attempts-remaining counter are announced through a polite live region (screen-states §7).
4. On the third failure the lock notice ("confirmation locked for 24 hours") and the support ticket reference are announced as text.
5. On success the verified state is announced once (status role) and the proof screen is announced as the new context.

## Alternative Scenarios
- **A1 — English locale:** announcements use the English strings; the digits stay Latin (NFR-013 parity).
- **A2 — Arabic locale:** Arabic announcement text around the same Latin digits (UC-420).
- **A3 — No screen reader active:** identical feedback exists as visible text under each state — never colour-only.

## Exception Scenarios
- **E1 — Live region missing or label dropped:** the feedback still renders visually; the gap is a release-blocking accessibility defect (NFR-011, FL-06).
- **E2 — Rapid consecutive submissions:** announcements are debounced and polite so the latest attempt result is the one spoken.
- **E3 — Locale switched mid-entry:** labels re-localize while the counter value and lock state remain unchanged (UC-412).

## Postconditions
- Success: every attempt outcome, counter and lock state is perceivable as text in the active locale.
- Failure: no feedback depends on colour alone in any locale.

## Business Rules Applied
- BR-SHP-03, BR-PLT-05

## Related Requirements
- FR-015 (Shipping & Delivery)
- **Related:** accessibility expression of the UC-401 and UC-403 feedback; conformance target FL-06 in `12-non-functional/core/accessibility.md`.

## Permissions / Data / External Dependencies
- **Permissions:** same assignee-only verification — the accessibility layer changes nothing server-side.
- **Data involved:** attempt counter, lock state, localized UI strings, live-region announcements.
- **External dependencies:** OS screen readers (TalkBack / VoiceOver); React Native accessibility wrappers.

## Acceptance Criteria
- **AC-UC404-01:** Given a wrong code with two attempts left, when the error renders, then a screen reader announces the message and "attempts remaining 2" as text (BR-SHP-03).
- **AC-UC404-02:** Given the third failure, when the lock applies, then the 24-hour lock and ticket reference are announced (BR-SHP-03).
- **AC-UC404-03:** Given attempt feedback in either locale, when rendered, then no indicator relies on colour alone (NFR-011, FL-06).
- **AC-UC404-04:** Given a successful verification, when it completes, then the success state is announced exactly once via a status role.
