# UC-412 — Switch the Courier App Language Between Arabic and English

## Header Info
- **Use Case ID:** UC-412
- **Title:** Switch the Courier App Language Between Arabic and English
- **Actor:** Delivery Provider (ACT-03)
- **Trigger:** Courier changes the app language from the in-app settings row
- **Priority:** P2
- **Goal:** Flip the whole courier app between Arabic and English in one interaction, persisted to the profile, with no restart.
- **Preconditions:** Locale setting row exists on S5 (`11-ui-ux/core/information-architecture.md` §8); only `ar` and `en` exist (C-24); Arabic is the default.

## Main Scenario
1. Courier opens Settings → language row → picks `العربية` or `English`.
2. The toggle updates `lang`/`dir` and the layout re-flows RTL or LTR immediately.
3. UI strings re-render from the selected locale and catalogs reload without an app restart (IA §8).
4. The choice persists to the courier profile (FR-003) so it survives logout and other devices; Arabic remains the default for new users.
5. Later server-side content follows the profile locale — notification templates are delivered in the new language (BR-NTF-04).

## Alternative Scenarios
- **A1 — Switching mid-job:** open delivery and code screens re-localize without losing job state or attempt counters (UC-404).
- **A2 — Preference save deferred:** the switch applies to the session and syncs to the profile on the next successful write.
- **A3 — Notification queued before the switch:** templates resolve locale at send time, so messages sent after the switch arrive in the new language (BR-NTF-04).

## Exception Scenarios
- **E1 — Profile write fails:** the switch still applies locally and a toast offers retry — no crash and no restart (screen-states §4).
- **E2 — String missing in the target locale:** Arabic copy is used as fallback; parity gaps are release defects (NFR-013).
- **E3 — Offline:** cached strings switch immediately and uncached content refreshes on reconnection (screen-states §5).

## Postconditions
- Success: the app UI is fully in the chosen locale and direction, and the preference is stored on the profile.
- Failure: the app stays usable in the previous locale; no restart and no data loss occurs.

## Business Rules Applied
- BR-PLT-05, BR-NTF-04

## Related Requirements
- FR-003 (User & Profile Management)
- **Related:** S5 locale row (IA §8) — complements UC-420, where code slots stay Latin in both locales.

## Permissions / Data / External Dependencies
- **Permissions:** any authenticated courier edits the own profile locale; no admin involvement.
- **Data involved:** profile locale preference, localized string catalogs, layout direction.
- **External dependencies:** locale bundles shipped in the app; notification templates resolved per BR-NTF-04.

## Acceptance Criteria
- **AC-UC412-01:** Given the Arabic UI, when English is selected, then visible labels re-render in English with LTR layout and no restart.
- **AC-UC412-02:** Given a switched locale, when the courier signs in on another device, then the profile preference is restored (FR-003).
- **AC-UC412-03:** Given a failed profile save, when the toggle is applied, then the UI still switches and offers a retry toast.
- **AC-UC412-04:** Given a notification sent after the switch, when it arrives, then its template matches the new locale (BR-NTF-04).
