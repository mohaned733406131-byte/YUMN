# UC-210 — Open a Support Ticket About a Delivery

## Header Info
- **Use Case ID:** UC-210
- **Title:** Open a Support Ticket About a Delivery
- **Actor:** Delivery Provider (ACT-03)
- **Trigger:** Courier needs platform help with a delivery (bad address, disputed outcome, lockout follow-up)
- **Priority:** P2
- **Goal:** Let the courier raise a support ticket about a delivery, with an audited record and a trackable ticket number.
- **Preconditions:** Courier authenticated with at least one current or past delivery; ticket references an order in the courier's own scope.

## Main Scenario
1. Courier opens Help from job detail or the Profile tab (S5) → fills category, subject, body, optional order reference and attachments.
2. Courier submits `POST /support/tickets` (API-ADM-035, roles include `COURIER`) with an idempotency key.
3. System validates the role, payload and attachment scan, then creates the ticket with status `OPEN`, a ticket number and `createdAt`.
4. The action writes an append-only audit entry (actor, action, entity, timestamp) per BR-PLT-06.
5. Courier receives the ticket number in-app and can reopen the thread later to read staff replies (conceptual `GET /support/tickets`); staff responses reach the courier.
6. If the auto-created lockout ticket already exists (UC-065), the courier adds detail to that thread instead of opening a duplicate.

## Alternative Scenarios
- **A1 — Lockout ticket already open:** courier replies to the system-created ticket (UC-065) rather than filing a new one.
- **A2 — Attachment included:** the file is scanned before acceptance; a clean file is linked to the ticket body.
- **A3 — Double submission:** the same idempotency key returns the already-created ticket number; no duplicate ticket is produced.

## Exception Scenarios
- **E1 — Missing idempotency key:** request rejected (`IDEMPOTENCY_KEY_REQUIRED`); no ticket is created.
- **E2 — Attachment fails scanning:** submission rejected with a file error; the courier retries without the file or with a clean one.
- **E3 — Rate limiting or transient outage:** request refused with `RATE_LIMITED` / temporary error; no partial ticket exists, the courier resubmits.

## Postconditions
- Success: one `OPEN` ticket with a number, courier and order reference, plus an audit entry (BR-PLT-06).
- Failure: no ticket and no state change; the courier can retry with the same payload.

## Business Rules Applied
- BR-PLT-06

## Related Requirements
- FR-020 (Platform Administration, Settings & Audit)
- **Related:** complements UC-014 (customer-side support entry) — same ticketing service, courier-side actor and scope.

## Permissions / Data / External Dependencies
- **Permissions:** `COURIER` role may open and read only its own tickets; support staff answer on the staff side (UC-100 / UC-102).
- **Data involved:** ticket row (category, subject, body, order ref, status, number), attachments (scanned), audit entry.
- **External dependencies:** support ticketing service (B13); file scanning for attachments; notifications for staff replies (B10).

## Acceptance Criteria
- **AC-UC210-01:** Given a `COURIER` with a valid payload and idempotency key, when submitted, then a ticket number with status `OPEN` is returned.
- **AC-UC210-02:** Given a created ticket, when the audit trail is read, then an entry records actor, action, entity and timestamp (BR-PLT-06).
- **AC-UC210-03:** Given a duplicate submission with the same idempotency key, when retried, then the same ticket is returned and no duplicate exists.
- **AC-UC210-04:** Given a request without an idempotency key, when submitted, then it is rejected and no ticket is created.
