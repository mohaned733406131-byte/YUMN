# UC-416 — Handle Access Denied When Opening a Delivery You Do Not Own

## Header Info
- **Use Case ID:** UC-416
- **Title:** Handle Access Denied When Opening a Delivery You Do Not Own
- **Actor:** Delivery Provider (ACT-03)
- **Trigger:** Courier opens a delivery by deep link, stale entry or edited id that is not theirs
- **Priority:** P2
- **Goal:** Deny the read honestly with a recovery path, without leaking whether the foreign delivery exists.
- **Preconditions:** Delivery reads are scoped to assignee and admin (BR-ORD-09); error codes map to localized copy (`07-api/core/error-model.md`).

## Main Scenario
1. Courier opens a delivery that belongs to another courier or to nobody.
2. The server denies the read and answers **not-found** so existence is never leaked (API-SHP-003 `NOT_FOUND`, BR-ORD-09).
3. The client maps the error code to a localized "غير متاح / Not available" message — never a raw code (screen-states §4).
4. A recovery action returns the courier to Queue or Active (P5: never a dead end).
5. The stale entry is dropped from local state so it cannot be reopened from cache.

## Alternative Scenarios
- **A1 — Admin opens the same delivery:** permitted under the `ADMIN` role on the same endpoint; no denial occurs.
- **A2 — Job was this courier's but was released:** identical not-found outcome; past ownership is not exposed (BR-ORD-09).
- **A3 — Resource genuinely nonexistent:** identical response, so a foreign id cannot be probed for existence (IDOR hygiene, routing §6).

## Exception Scenarios
- **E1 — Transient network error:** a distinguishable failure with retry — the app must not label it "not available".
- **E2 — Cached detail still on screen:** invalidated on the denial; any reopen hits the server again.
- **E3 — Repeated foreign attempts:** attempts are logged while the scope check stays server-side and never relies on hidden UI.

## Postconditions
- Success: the denial is communicated with a recovery path and zero data about the foreign delivery is shown.
- Failure: no unauthorized read, no existence leak, and the local cache entry is removed.

## Permissions / Data / External Dependencies
- **Permissions:** `COURIER` reads own deliveries only; `ADMIN`/`SUPER ADMIN` hold scoped dispatch reads; everyone else is denied.
- **Data involved:** delivery detail (denied), localized error strings, local cache (evicted).
- **External dependencies:** delivery API error model (`07-api/core/error-model.md`).

## Acceptance Criteria
- **AC-UC416-01:** Given a delivery not assigned to the courier, when opened, then the server responds not-found and the UI shows a localized denial (BR-ORD-09).
- **AC-UC416-02:** Given a foreign id matching an existing resource, when probed, then the response is identical to a nonexistent id.
- **AC-UC416-03:** Given the denial, when the UI renders, then a return-to-queue action is offered and no raw error code is displayed.
- **AC-UC416-04:** Given a cached copy of the denied delivery, when the denial lands, then the cache entry is removed.
