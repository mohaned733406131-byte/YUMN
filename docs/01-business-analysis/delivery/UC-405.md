# UC-405 — Track Personal Delivery Stats on the Courier Profile

## Header Info
- **Use Case ID:** UC-405
- **Title:** Track Personal Delivery Stats on the Courier Profile
- **Actor:** Delivery Provider (ACT-03)
- **Trigger:** Courier opens the Profile tab to check their own performance and availability
- **Priority:** P2
- **Goal:** Show courier-scoped delivery statistics and availability without exposing any platform-wide or peer data.
- **Preconditions:** Courier authenticated; profile endpoint reachable; at least the courier's own delivery history exists (may be empty).

## Main Scenario
1. Courier taps Profile (S5 tab bar) → client calls `GET /courier/profile` (API-SHP-014).
2. The response renders display name, masked phone, served zones, availability and stats: active deliveries, completed, success-rate percent.
3. Values are scoped to this courier's own deliveries — nothing platform-wide or peer-level is exposed (BR-ORD-09).
4. Courier may flip availability on the same screen (`PUT /courier/availability`, API-SHP-016) — offline removes them from offer broadcast (BR-SHP-04).
5. Values refresh on tab focus; plain viewing writes nothing.

## Alternative Scenarios
- **A1 — First-time courier:** stats are zero → empty-state copy rather than invented numbers (screen-states §3).
- **A2 — Offline:** last known values show behind the offline banner; the refresh waits for reconnection.
- **A3 — Edit profile:** display name and zones update via `PUT /courier/profile` (API-SHP-015) without touching stats.

## Exception Scenarios
- **E1 — `AUTH_INVALID`:** re-auth prompt, then the profile reloads (UC-411).
- **E2 — Partial payload:** loaded sections render and the failed section shows a block error with retry (screen-states §1 partial data).
- **E3 — A job completes while the screen is open:** the next focus refresh reconciles counters — no local arithmetic is authoritative.

## Postconditions
- Success: courier sees current, own-scope statistics and availability.
- Failure: nothing written — counters are untouched by the read.

## Business Rules Applied
- BR-ORD-09, BR-SHP-04

## Related Requirements
- FR-015 (Shipping & Delivery)
- **Related:** Profile tab of the S5 IA (`11-ui-ux/core/information-architecture.md` §6) — complements UC-415 (per-job history list).

## Permissions / Data / External Dependencies
- **Permissions:** courier reads the own profile only (`COURIER` role); admin oversight uses separate views (BR-ORD-09).
- **Data involved:** courier profile, served zones, availability flag, aggregate delivery statistics (read).
- **External dependencies:** delivery API; no location data of any kind is requested or stored (BR-SHP-05, C-16).

## Acceptance Criteria
- **AC-UC405-01:** Given a courier with completed jobs, when the Profile tab opens, then completed and success-rate values are returned for that courier only (BR-ORD-09).
- **AC-UC405-02:** Given availability set to `OFFLINE`, when offers are broadcast, then this courier receives none (BR-SHP-04).
- **AC-UC405-03:** Given a courier with no history, when the profile loads, then zero/empty statistics are shown instead of an error.
- **AC-UC405-04:** Given an expired session, when the profile is opened, then re-authentication is prompted and data loads after login.
