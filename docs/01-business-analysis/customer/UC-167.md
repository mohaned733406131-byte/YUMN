# UC-167 — Report a Review for Moderation

## Header Info
- **Use Case ID:** UC-167
- **Title:** Report a Review for Moderation
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer flags an abusive or inappropriate review in the product review feed
- **Priority:** P2
- **Goal:** Let a customer file a moderation report on a review so Moderator/Admin can hide it with an audit entry.
- **Preconditions:** Authenticated; the review is visible in the public feed; the customer has not just been rate-limited.

## Main Scenario
1. Customer reads the product review feed (`GET /products/{slug}/reviews`) and picks Report on a suspicious review.
2. Customer chooses a reason and optional note → `POST /reviews/{id}/report` (API-CAT-020).
3. System creates a report record with `status: OPEN` and routes it into the moderation queue (cross-reference: UC-038 flagged content, UC-032 admin moderation).
4. Moderator/Admin decides; a hidden review drops out of the feed and the rating averages, with an audit entry written (BR-REV-04).
5. Customer receives the `reportId` acknowledgment; the review stays visible until a moderation decision lands.

## Alternative Scenarios
- **A1 — Several reports on one review:** each submission creates its own `OPEN` report; moderation works the queue.
- **A2 — Review already hidden:** it no longer appears in the feed → nothing to report.
- **A3 — Report after a vendor response:** the report targets the review itself, not the vendor's response row.

## Exception Scenarios
- **E1 — Reporting abuse/spam:** `RATE_LIMITED`; no report row.
- **E2 — Unknown or deleted review:** `NOT_FOUND`.
- **E3 — Missing/invalid reason:** `VALIDATION_ERROR`; no report created (BR-REV-04).

## Postconditions
- Success: an `OPEN` moderation report exists; the review's visibility is unchanged until moderation acts.
- Failure: no report row; feed unchanged.

## Business Rules Applied
- BR-REV-04

## Related Requirements
- FR-006 (Reviews & Ratings), FR-020 (Platform Administration — moderation)
- **Relation:** UC-032 (hide/dismiss) and UC-038 (flagged content review) — the admin/moderator side that consumes these reports.

## Permissions / Data / External Dependencies
- **Permissions:** any authenticated customer may report a visible review; hiding remains Moderator/Admin-only with audit entry (BR-REV-04).
- **Data involved:** review row, moderation report (reason, note, status), audit entry.
- **External dependencies:** catalog service (B02); admin/moderator queues (B13).

## Acceptance Criteria
- **AC-UC167-01:** Given a visible review, when a reason is submitted, then `201` with a `reportId` whose status is `OPEN`.
- **AC-UC167-02:** Given a review hidden by a moderator, when the feed is read, then it is excluded from the list and from the averages (BR-REV-04).
- **AC-UC167-03:** Given rapid repeated reports, when submitted, then `RATE_LIMITED` may reject them.
- **AC-UC167-04:** Given an unknown review id, when reported, then `NOT_FOUND`.
