# UC-159 — Track a Guest Order via a Tokenized Link

## Header Info
- **Use Case ID:** UC-159
- **Title:** Track a Guest Order via a Tokenized Link
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer (or guest holding the link) opens the tokenized tracking URL for a placed order
- **Priority:** P2
- **Goal:** Show the order state and timeline through the tokenized `/track/{order-id}` view without requiring a full login.
- **Preconditions:** Route `/{locale}/track/{order-id}` exists for the owner or a tokenized guest view of a placed order (routing.md §2); order placed under the customer's phone identity.

## Main Scenario
1. Customer/guest opens the tokenized link `/{locale}/track/{order-id}`.
2. Server validates the token (or ownership) independently of the frontend guard; on success it returns the order projection: master state, per-vendor sub-order states, totals and the buyer's append-only timeline slice (BR-ORD-09).
3. Refresh shows live transitions as the order advances through the 17-state machine.
4. Without a valid token or ownership the server denies the request regardless of what the client renders — guards are UX only (SEC-REQ-004).

## Alternative Scenarios
- **A1 — Signed-in owner opens the link:** identical data is served as the owner view (UC-012); the token is redundant but harmless.
- **A2 — Unauthenticated without a valid token:** guard redirects to `/{locale}/login?next=...` (`routing.md` §9); the server still denies until the customer is authenticated and owns the order.

## Exception Scenarios
- **E1 — Another customer's order id without a token:** `404`, never 403 — existence of foreign resources is not leaked (SEC-REQ-004).
- **E2 — Network error:** customer retries; the view is read-only so a repeat call is safe.

## Postconditions
- Success: order state and timeline displayed to a scoped reader; no order, wallet or stock change (read-only, FR-012).
- Failure: access denied with login redirect or 404; no data exposed.

## Business Rules Applied
- BR-ORD-09

## Related Requirements
- FR-012 (Order Lifecycle Management)

## Permissions / Data / External Dependencies
- **Permissions:** owner or valid-token holder only; visibility limited to the buyer slice of the timeline (BR-ORD-09).
- **Data involved:** master/sub-order states, totals, append-only status history rows.
- **External dependencies:** none — server-rendered read of order data.

## Acceptance Criteria
- **AC-UC159-01:** Given a valid tokenized link, when opened signed-out, then the order timeline renders without login.
- **AC-UC159-02:** Given another customer's order id without a token, when opened, then 404 returns and no order data is disclosed (BR-ORD-09).
- **AC-UC159-03:** Given the same order viewed signed-in, when rendered, then both views show identical state data.
