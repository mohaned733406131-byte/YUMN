# UC-313 — Attach Photos to a Product Review and Handle Upload Rejections

## Header Info
- **Use Case ID:** UC-313
- **Title:** Attach Photos to a Product Review and Handle Upload Rejections
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer picks photos while writing a review for a delivered order item
- **Priority:** P2
- **Goal:** Publish a review with up to five compliant images, or reject non-compliant uploads with a precise, localized reason.
- **Preconditions:** Order item `DELIVERED` and within the 30-day window (BR-REV-01); no review yet for this order item (BR-REV-02); review form open (UC-165, FL-09).

## Main Scenario
1. Customer selects a 1–5 star rating, writes text and picks up to 5 photos of ≤5 MB each (BR-REV-03).
2. Client pre-checks count and size for instant feedback; the server re-validates on submit (UX checks are never authoritative).
3. `POST /reviews` verifies eligibility (purchaser, `DELIVERED`, ≤30 days, one per order item) and media bounds (BR-REV-01/02/03).
4. Accepted files are scanned, re-encoded and stored; the review is created `PUBLISHED` with images attached (201).
5. The store rating recompute job picks up the new visible review (BR-REV-05).

## Alternative Scenarios
- **A1 — Text-only review:** no images attached; submission follows the same eligibility path (rejoins UC-165).
- **A2 — Sixth photo selected:** the client blocks it at the fifth; a direct submit would return `VALIDATION_ERROR` (>5 images).
- **A3 — Replacing a photo later:** the single edit within 7 days may swap images (API-CAT-018, BR-REV-02, UC-166).

## Exception Scenarios
- **E1 — File over 5 MB or wrong format:** `VALIDATION_ERROR`; nothing is published and the offending file is dropped.
- **E2 — Malware scan fails:** submission rejected with `FILE_SCAN_FAILED`; no review row exists, the customer retries without that file.
- **E3 — Eligibility lost before submit (window passed):** `REVIEW_NOT_ELIGIBLE`; no row created (BR-REV-01).

## Postconditions
- Success: one published review for the order item with ≤5 stored images; rating recompute queued; no second review possible (BR-REV-02).
- Failure: no review row, no stored media for the failed attempt, averages unchanged.

## Business Rules Applied
- BR-REV-03, BR-REV-01, BR-REV-02, BR-REV-05

## Related Requirements
- FR-006 (Reviews & Ratings — reviews with images)
- **Relation:** UC-165 writes the review; UC-166 performs the single edit; UC-314 covers the expired-window rejection.

## Permissions / Data / External Dependencies
- **Permissions:** CUSTOMER role — only the purchasing customer may attach images to their own order item's review.
- **Data involved:** review row, review image files (≤5, ≤5 MB), order-item eligibility read, rating recompute job.
- **External dependencies:** object storage + file scan pipeline; catalog review service (B02); BullMQ recompute job (BR-PLT-01).

## Acceptance Criteria
- **AC-UC313-01:** Given an eligible delivered item, when 5 photos of ≤5 MB are attached, then the review is published with all images (BR-REV-03).
- **AC-UC313-02:** Given a sixth photo, when selected or submitted, then it is rejected with a localized limit message and no review is published (BR-REV-03).
- **AC-UC313-03:** Given a file over 5 MB, when submitted, then `VALIDATION_ERROR` returns and no review row exists.
- **AC-UC313-04:** Given a file that fails the scan, when detected, then the submission is rejected with `FILE_SCAN_FAILED` and nothing is published.
