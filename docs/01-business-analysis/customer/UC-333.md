# UC-333 — Handle a Shipping-Zone Gap for the Selected Address

## Header Info
- **Use Case ID:** UC-333
- **Title:** Handle a Shipping-Zone Gap for the Selected Address
- **Actor:** Customer (ACT-01)
- **Trigger:** Checkout cannot resolve a shipping zone for the selected address, so no fee can be computed
- **Priority:** P1
- **Goal:** Explain the gap honestly and route the customer to a covered address — never a silent fee or a dead end.
- **Preconditions:** Address selected at checkout step 2 (FR-011); store zones configured (BR-SHP-01); governorate/district are seeded reference data, domestic only (C-17).

## Main Scenario
1. Customer proceeds to the shipping step; the system resolves the zone from the address's governorate/district against the store's zones (BR-SHP-01).
2. No zone matches (district uncovered, or outside domestic coverage) → `NO_SHIPPING_ZONE`; the fee cannot be computed (WF-003 step 3).
3. UI shows the localized explanation plus two recoveries: choose another saved address (UC-005) or leave — no dead end (NFR-012).
4. Customer selects a covered address → the session re-resolves the zone and computes the fee (BR-SHP-01).
5. Checkout continues to wallet payment with the fee now part of the authoritative totals (UC-011).

## Alternative Scenarios
- **A1 — No covered address in the book:** the customer edits/adds an address (UC-005, ≤10 FR-003) or abandons; no order row either way (WF-003).
- **A2 — Store has no zones configured at all:** every address hits `NO_SHIPPING_ZONE`; the same recoveries are offered (support path via UC-014).
- **A3 — Address edited to a covered district:** the next pass through the step re-resolves successfully (BR-SHP-01).

## Exception Scenarios
- **E1 — Zone configuration unreadable:** session error with retry; no fee is invented client-side (server-side totals only).
- **E2 — Session expires while choosing:** `CHECKOUT_SESSION_EXPIRED`; the cart and addresses are intact and checkout restarts.
- **E3 — Zone config changes mid-session:** the fee is re-resolved server-side inside the order transaction; failure aborts with no rows (BR-PLT-04).

## Postconditions
- Success: checkout session holds a resolved zone and fee; still no order until confirm.
- Failure: no fee, no order row, no debit; cart, addresses and session inputs unchanged.

## Business Rules Applied
- BR-SHP-01, BR-PLT-04

## Related Requirements
- FR-011 (Checkout & Order Placement — shipping step), FR-015 (Shipping & Delivery — zones & fees)
- **Relation:** UC-005 manages the addresses offered as recovery; UC-306/UC-308 cover address lifecycle; UC-011 resumes the checkout.

## Permissions / Data / External Dependencies
- **Permissions:** CUSTOMER role, own checkout session and own addresses only; zone configuration is vendor/platform-owned (FR-008/FR-020).
- **Data involved:** address governorate/district, store shipping zones, checkout session fee, cart totals (updated on success).
- **External dependencies:** shipping/zone service (B08); store configuration (B03); checkout session (B05).

## Acceptance Criteria
- **AC-UC333-01:** Given an address in an uncovered district, when the shipping step runs, then `NO_SHIPPING_ZONE` returns and no fee is set (BR-SHP-01).
- **AC-UC333-02:** Given the rejection, when the screen renders, then a localized explanation plus an address-switch recovery are offered (NFR-012).
- **AC-UC333-03:** Given a covered address is selected, when the step re-runs, then the zone resolves and the fee joins the totals (BR-SHP-01).
- **AC-UC333-04:** Given the gap, when the customer leaves, then no order row, debit or ledger entry exists.
