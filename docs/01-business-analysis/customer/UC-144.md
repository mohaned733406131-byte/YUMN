# UC-144 — Log Out of All Devices

## Header Info
- **Use Case ID:** UC-144
- **Title:** Log Out of All Devices
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer selects "Sign out of all devices" (typically after noticing an unfamiliar device)
- **Priority:** P1
- **Goal:** Revoke every session of the account across all devices in a single action.
- **Preconditions:** Customer authenticated on at least one device; account not locked; session list reviewable (UC-146).

## Main Scenario
1. Account → Security → "Sign out of all devices" → customer confirms the warning dialog.
2. Client calls `POST /auth/logout-all` (API-ATH-007) → `204`.
3. Server clears the whole session registry: every refresh token becomes invalid immediately, including the calling session — all existing sessions invalidated in one sweep (BR-AUTH-07 pattern).
4. Each affected device fails its next refresh or token verification and is forced back to login; single-use rotation cannot resurrect a pre-sweep token (BR-AUTH-05).
5. The acting device also ends signed out → redirected to login; customer can confirm the empty list in UC-146.

## Alternative Scenarios
- **A1 — Single-device sign-out wanted:** customer uses UC-143 instead — only the current `sid` is revoked.
- **A2 — Called from a dead session:** `AUTH_INVALID` → client clears local state; no sweep runs without a valid credential.

## Exception Scenarios
- **E1 — Network error mid-call:** client retries; the sweep either completed or did not — there is no partial registry state to repair.
- **E2 — Concurrent new login racing the sweep:** a session created after the sweep is not covered — customer re-checks the session list (UC-146) and repeats if needed; no pre-sweep token survives (BR-AUTH-05).

## Postconditions
- Success: session registry empty; all refresh tokens dead; every device requires a fresh login (FR-001).
- Failure: registry unchanged; devices signed in before the attempt remain signed in.

## Business Rules Applied
- BR-AUTH-05, BR-AUTH-07

## Related Requirements
- FR-001 (Identity, Authentication & Session Management)

## Permissions / Data / External Dependencies
- **Permissions:** authenticated customer sweeping only their own sessions; no admin involvement.
- **Data involved:** all session registry rows, refresh-token families of the account.
- **External dependencies:** none — server-side revocation only.

## Acceptance Criteria
- **AC-UC144-01:** Given three signed-in devices, when one calls logout-all, then all three sessions are revoked and each subsequent refresh fails (BR-AUTH-05, BR-AUTH-07).
- **AC-UC144-02:** Given a successful logout-all, when `GET /auth/sessions` is read (UC-146), then zero sessions are returned.
- **AC-UC144-03:** Given a network error during the call, when retried, then the sweep completes once with no duplicate or partial effect.
