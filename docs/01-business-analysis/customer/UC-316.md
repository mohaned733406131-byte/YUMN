# UC-316 — Read the Vendor's Published Response Beneath Your Review

## Header Info
- **Use Case ID:** UC-316
- **Title:** Read the Vendor's Published Response Beneath Your Review
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens a product's review list that already contains a vendor response
- **Priority:** P2
- **Goal:** Show the vendor's single published reply nested under the review it answers, in the customer's locale.
- **Preconditions:** The vendor published exactly one response to the review (BR-REV-04, vendor side UC-024); review is visible (not hidden).

## Main Scenario
1. Customer opens the review list on the product page (public read, API-CAT-019).
2. Each review payload carries `vendorResponse?` when the vendor has replied (FR-006).
3. The response renders nested beneath its review, localized to the current locale from the bilingual record (BR-PLT-05).
4. The customer reads it in context — author name, rating, text and images remain grouped with the reply.
5. The customer may report the review itself if it is abusive (UC-167); the response is read-only from this side.

## Alternative Scenarios
- **A1 — No response yet:** the nested block is simply absent; the review renders normally (no empty placeholder).
- **A2 — Second locale:** the same response record renders in `ar` (default) or `en` per the user's locale (BR-PLT-05).
- **A3 — Review hidden after the reply:** the whole review-with-response leaves the list and the aggregates (BR-REV-04, rejoins UC-315).

## Exception Scenarios
- **E1 — Review list fetch fails:** block error with retry inside the section; the product page keeps working.
- **E2 — Review removed between renders:** a refresh drops the row cleanly; no orphan response is rendered.
- **E3 — Unknown product slug:** `404 NOT_FOUND` page with search/home links (BR-CAT-06 — inactive products are not readable).

## Postconditions
- Success: the published response is read in the customer's locale; no row changed — this use case performs no writes.
- Failure: the previous list stays on screen; nothing is fabricated or partially rendered.

## Business Rules Applied
- BR-REV-04, BR-PLT-05

## Related Requirements
- FR-006 (Reviews & Ratings — vendor responses, moderation visibility)
- **Relation:** UC-024 (vendor) publishes the response read here; UC-165/UC-166 author the review it sits under; UC-167 reports it.

## Permissions / Data / External Dependencies
- **Permissions:** Public read of visible reviews; responses are vendor-authored and immutable to customers.
- **Data involved:** review row, nested vendor response (bilingual), locale preference — read-only.
- **External dependencies:** catalog review service (B02); locale resolution from user preferences (B01); no third-party providers.

## Acceptance Criteria
- **AC-UC316-01:** Given a review with a published response, when the list renders, then the response appears nested directly beneath that review (FR-006).
- **AC-UC316-02:** Given an Arabic-locale customer, when the response renders, then the Arabic text of the bilingual record is shown (BR-PLT-05).
- **AC-UC316-03:** Given a review without a response, when the list renders, then no response placeholder appears.
- **AC-UC316-04:** Given a hidden review, when the list is fetched, then neither review nor response is returned (BR-REV-04).
