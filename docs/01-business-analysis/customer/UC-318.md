# UC-318 — List the Stores You Follow

## Header Info
- **Use Case ID:** UC-318
- **Title:** List the Stores You Follow
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens Account → Following (`/[locale]/account/following`)
- **Priority:** P2
- **Goal:** Show every store the customer follows, with a working path to each storefront and to unfollow.
- **Preconditions:** Authenticated (UC-003); at least one follow may exist (UC-008); route guarded as Customer (routing §2, FR-008/BR-VND-05).

## Main Scenario
1. Customer navigates to `/[locale]/account/following` (CSR, login-gated).
2. Client fetches the followed-store list (conceptual `GET /stores/followed`; contract owned by `07-api`) — name, logo, rating summary and `isFollowing: true` (BR-VND-05).
3. Each row links to the storefront page, where the following state and follower count are visible (UC-008).
4. The customer can unfollow directly from a row (UC-319); the list refreshes with the updated count (BR-VND-05).
5. Older entries page in as a bounded list; the empty case is handled by A1 below.

## Alternative Scenarios
- **A1 — Nothing followed yet:** localized empty state "not following any stores" with an "Explore stores" recovery action — never a dead end (NFR-012).
- **A2 — Open a row:** the storefront opens showing the customer's following state and active products (rejoins UC-008/UC-007).
- **A3 — Guest hits the URL:** 307 to `/[locale]/login?next=<encoded>`; after login the route resumes (routing §6/§9).

## Exception Scenarios
- **E1 — List fetch fails:** page error with retry plus home/search links; no partial list is rendered (screen-states, page error).
- **E2 — Session expired:** the route stays, a re-auth prompt appears, then the list reloads (routing §9).
- **E3 — A followed store was suspended or removed:** its storefront opens as unavailable (UC-320); the row never leaks hidden store data.

## Postconditions
- Success: the customer's own follow list is displayed; read-only — no follow relationship changes.
- Failure: no list rendered; follow state unchanged on both client and server.

## Business Rules Applied
- BR-VND-05, BR-PLT-05

## Related Requirements
- FR-008 (Store Management & Storefront Configuration — follow-store feature)
- **Relation:** UC-008 performs the follow; UC-319 unfollows from this list; UC-320 covers the suspended-storefront case (E3).

## Permissions / Data / External Dependencies
- **Permissions:** CUSTOMER role, owner scope — only the caller's own follow relationships are returned.
- **Data involved:** follow rows (store id, followed-at), store summary (name, logo, rating), follower counts — read-only.
- **External dependencies:** store service (B03); account session guard; no third-party providers.

## Acceptance Criteria
- **AC-UC318-01:** Given three followed stores, when the route opens, then all three are listed with their names and `isFollowing: true` (BR-VND-05).
- **AC-UC318-02:** Given no follows, when the route opens, then the localized empty state with an "Explore stores" action renders (NFR-012).
- **AC-UC318-03:** Given another customer's follows, when the list is requested, then only the caller's relationships are returned.
- **AC-UC318-04:** Given a guest, when `/account/following` is opened, then a login redirect runs and returns to the route after login.
