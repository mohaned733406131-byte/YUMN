# UC-160 — Clear the Entire Cart

## Header Info
- **Use Case ID:** UC-160
- **Title:** Clear the Entire Cart
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer taps "Clear cart" in the cart screen
- **Priority:** P2
- **Goal:** Remove every cart line at once and release all reserved stock immediately.
- **Preconditions:** Customer authenticated with a server-side cart (FR-010); cart may be empty (clear is idempotent).

## Main Scenario
1. Cart → "Clear cart" → confirmation prompt.
2. Client calls `DELETE /cart` (API-CRT-005) → `204`.
3. Every line is removed and all reserved stock is released at once — the 15-minute reservation countdown stops for the whole cart (BR-CRT-02).
4. Cart view re-renders empty: subtotals, vendor groups and `reservationExpiresAt` are gone (FR-010).

## Alternative Scenarios
- **A1 — Single line removal instead:** removing one line uses `DELETE /cart/items/{id}` (rel UC-010 step4 — single remove); clear-all is the whole-cart variant.
- **A2 — Empty cart:** `204` idempotently; the UI simply shows the empty state without an error.

## Exception Scenarios
- **E1 — No cart row found:** `NOT_FOUND` treated as empty; empty state rendered.
- **E2 — Network error before the response:** server cart is unchanged; client re-syncs with `GET /cart` before offering a retry (FR-010).

## Postconditions
- Success: cart empty; every reservation released; held stock returns to available (BR-CRT-02).
- Failure: cart unchanged; reservations remain held until their own 15-minute expiry.

## Business Rules Applied
- BR-CRT-02

## Related Requirements
- FR-010 (Shopping Cart)
- Cross-reference: rel UC-010 step4 (single line remove) — this UC covers the whole-cart clear only (API-CRT-005).

## Permissions / Data / External Dependencies
- **Permissions:** owner-scoped — only the customer's own cart is affected (one cart per account).
- **Data involved:** cart lines, stock reservations and their countdowns, cart totals.
- **External dependencies:** reservation release handled server-side (inventory bookkeeping).

## Acceptance Criteria
- **AC-UC160-01:** Given a cart holding reserved lines, when cleared, then `204` returns and all reservations are released (BR-CRT-02).
- **AC-UC160-02:** Given an already-empty cart, when cleared, then `204` returns (idempotent).
- **AC-UC160-03:** Given a successful clear, when `GET /cart` runs, then `itemCount` is 0 with no `reservationExpiresAt`.
