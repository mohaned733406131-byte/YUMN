# UC-143 — Log Out of the Current Device

## Header Info
- **Use Case ID:** UC-143
- **Title:** Log Out of the Current Device
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer selects "Sign out" in the account menu of the device in use
- **Priority:** P1
- **Goal:** Revoke exactly the current session so every other signed-in device keeps working.
- **Preconditions:** Customer has an active session on this device; client holds the refresh credential (httpOnly `yumn_refresh` cookie on web, token pair on mobile).

## Main Scenario
1. Customer opens Account → "Sign out" and confirms the prompt.
2. Client calls `POST /auth/logout` (API-ATH-006) with the current refresh credential.
3. Server revokes only the current `sid`: the session row is removed from the registry and that session's refresh tokens stop working immediately → `204`.
4. The access token dies at its next server-side verification (≤15 min); client clears local auth state and redirects to `/[locale]/login` (routing guard).
5. Other device sessions remain active and the session cap is unchanged (FR-001).

## Alternative Scenarios
- **A1 — Session already revoked:** `SESSION_NOT_FOUND`/`AUTH_INVALID` → client still clears local state and treats the device as signed out.
- **A2 — Web vs mobile cleanup:** web clears the httpOnly `yumn_refresh` cookie, mobile discards the stored token pair — same server effect.
- **A3 — Cart state on logout:** client-side cart slice is cleared; the guest cart survives and the server-side account cart stays intact.

## Exception Scenarios
- **E1 — Network error on logout:** client retries the call; until it succeeds the server session persists — UC-147 lets the customer revoke it remotely from another device.
- **E2 — Refresh-token replay after logout:** presenting the consumed refresh token revokes the entire session family and alerts the user (BR-AUTH-05).

## Postconditions
- Success: current session revoked; this device is signed out; all other sessions untouched (FR-001).
- Failure: no session revoked (server unreachable); local credentials are cleared only after a confirmed revoke.

## Business Rules Applied
- BR-AUTH-05

## Related Requirements
- FR-001 (Identity, Authentication & Session Management)

## Permissions / Data / External Dependencies
- **Permissions:** any authenticated customer, own `sid` only — revoking another device is UC-147.
- **Data involved:** session registry row, refresh-token family, client token store / cookie.
- **External dependencies:** none — revocation is server-side only.

## Acceptance Criteria
- **AC-UC143-01:** Given two signed-in devices, when one logs out, then only that session is revoked and the other device keeps working.
- **AC-UC143-02:** Given a successful logout, when the same refresh token is replayed, then the session family is revoked and the user is alerted (BR-AUTH-05).
- **AC-UC143-03:** Given a network failure during logout, when retried, then revocation completes and no other session is touched.
