# UC-154 — Cancel a Pending Deletion Request

## Header Info
- **Use Case ID:** UC-154
- **Title:** Cancel a Pending Deletion Request
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer sees the pending-deletion notice with the countdown to `effectiveAt` and selects "Cancel request"
- **Priority:** P2
- **Goal:** Withdraw a scheduled account deletion before it executes so the account stays fully active.
- **Preconditions:** A deletion request in status `PENDING` exists for the account and `effectiveAt` has not passed (UC-153).

## Main Scenario
1. Account shows the pending deletion with the time remaining until `effectiveAt`.
2. Customer selects "Cancel request" → client calls `DELETE /users/me/deletion-request` (API-USR-013).
3. Server withdraws the request → `204`; the scheduled purge never runs and the account remains active (FR-003).
4. The cancellation appends an audit entry (BR-PLT-06) and the pending notice disappears from the account screen.

## Alternative Scenarios
- **A1 — After `effectiveAt`:** the request already executed → `DELETION_BLOCKED`; this path cannot revive the account.
- **A2 — No pending request:** `404 NOT_FOUND`; the UI never shows the cancel row in that state.

## Exception Scenarios
- **E1 — Network error before the response:** client retries; after a successful cancel the repeat returns `404`, so the UI re-reads state first.
- **E2 — Concurrent execution at `effectiveAt`:** whichever wins decides — if purge already ran, cancel fails with `DELETION_BLOCKED`.

## Postconditions
- Success: deletion cancelled; account fully active; audit entry appended (BR-PLT-06).
- Failure: request stays PENDING and still scheduled for `effectiveAt`.

## Business Rules Applied
- BR-PLT-06

## Related Requirements
- FR-003 (User & Profile Management)

## Permissions / Data / External Dependencies
- **Permissions:** owner-scoped; only the account that opened the request may cancel it.
- **Data involved:** deletion request row (status transition), audit log.
- **External dependencies:** purge job which must observe the cancellation before `effectiveAt`.

## Acceptance Criteria
- **AC-UC154-01:** Given a PENDING request before `effectiveAt`, when cancelled, then `204` returns and the account remains active.
- **AC-UC154-02:** Given an already-executed request, when cancelled, then `DELETION_BLOCKED` returns.
- **AC-UC154-03:** Given a successful cancellation, when queried, then no pending deletion remains and an audit entry exists (BR-PLT-06).
