# UC-172 — Submit Dispute Evidence

## Header Info
- **Use Case ID:** UC-172
- **Title:** Submit Dispute Evidence
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens their open dispute and adds supporting evidence
- **Priority:** P1
- **Goal:** Let the customer attach text and file evidence to their own open dispute before the evidence due date so the admin arbiter can decide.
- **Preconditions:** Authenticated; dispute owned by the customer; dispute state `OPEN` (not yet resolved); `evidenceDueBy` not passed.

## Main Scenario
1. Customer opens the dispute detail (`GET /disputes/{id}`, API-RET-015) → ground, evidence list, timeline and `evidenceDueBy`.
2. Customer adds a note and up to 5 files → `POST /disputes/{id}/evidence` (API-RET-016).
3. System scans the files (type, size, malware) and appends the evidence entry `{ by, fileId, at }` → `201 { evidenceId }`.
4. Evidence from both parties becomes visible in the timeline for the admin arbiter, whose decision is final and audit-logged (BR-RET-06).
5. Customer may add further entries while the dispute stays `OPEN`.

## Alternative Scenarios
- **A1 — Text-only evidence:** `note` without files is accepted.
- **A2 — Counterparty evidence:** the vendor's entries appear in the same timeline (read-only for the customer).
- **A3 — Submit near the due date:** allowed while `OPEN`; after resolution the endpoint rejects (E1).

## Exception Scenarios
- **E1 — Dispute already resolved:** `STATE_CONFLICT`; no new evidence accepted (BR-RET-06).
- **E2 — File rejected:** `PAYLOAD_TOO_LARGE`/`UNSUPPORTED_MEDIA_TYPE`/`FILE_SCAN_FAILED`; the entry is not stored.
- **E3 — Empty payload:** `EVIDENCE_REQUIRED`; nothing persisted.

## Postconditions
- Success: evidence appended to the dispute timeline; dispute remains `OPEN`; nothing else changes.
- Failure: no evidence row; dispute unchanged.

## Business Rules Applied
- BR-RET-06

## Related Requirements
- FR-016 (Returns & Refunds — dispute evidence)
- **Relation:** UC-171 opened the dispute; UC-173 shows the outcome decided on this evidence.

## Permissions / Data / External Dependencies
- **Permissions:** parties submit only to their own dispute; admin reads all and is the only arbiter (BR-RET-06).
- **Data involved:** dispute row, evidence entries (note + scanned files), timeline.
- **External dependencies:** returns/disputes service (B09); file scanning pipeline.

## Acceptance Criteria
- **AC-UC172-01:** Given an `OPEN` dispute, when note + 2 images are submitted, then `201` with `evidenceId` and both files listed (BR-RET-06).
- **AC-UC172-02:** Given a resolved dispute, when evidence is submitted, then `STATE_CONFLICT` (BR-RET-06).
- **AC-UC172-03:** Given a 6 MB file, when submitted, then `PAYLOAD_TOO_LARGE` and no evidence row.
- **AC-UC172-04:** Given an empty payload, when submitted, then `EVIDENCE_REQUIRED`.
