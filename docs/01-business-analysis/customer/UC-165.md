# UC-165 — Write a Product Review After Delivery

## Header Info
- **Use Case ID:** UC-165
- **Title:** Write a Product Review After Delivery
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer taps the review prompt after delivery confirmation, or opens the review form from their order
- **Priority:** P1
- **Goal:** Let the purchasing customer publish a verified 1–5 star review with optional images for a delivered order item within the review window.
- **Preconditions:** Authenticated; customer purchased the order; order state `DELIVERED`; within 30 days of delivery confirmation (BR-REV-01); not yet reviewed for that order item.

## Main Scenario
1. Delivery flow prompts the buyer to review (cross-reference: UC-030 step5 — prompt only); customer opens the order item → review form.
2. System validates eligibility server-side: purchaser only, order `DELIVERED`, window ≤30 days from delivery confirmation (BR-REV-01).
3. Customer sets an integer rating 1–5, optional comment and up to 5 images of ≤5 MB each (BR-REV-03).
4. Client `POST /reviews` (API-CAT-017) with `orderItemId` → `201` review `PUBLISHED` with `verifiedPurchase: true`.
5. The product's rating summary refreshes in the background and the review appears in the public product review feed.

## Alternative Scenarios
- **A1 — Review with images:** image file IDs are uploaded first (scanned, EXIF stripped) then referenced by the review payload (BR-REV-03).
- **A2 — Rating only:** comment omitted — accepted; `comment` is optional.
- **A3 — Second item of the same order:** each order item has its own single review slot.

## Exception Scenarios
- **E1 — Not eligible:** order not `DELIVERED`, window elapsed, or not the purchaser → `REVIEW_NOT_ELIGIBLE`; nothing is stored (BR-REV-01).
- **E2 — Review already exists** for that order item → `REVIEW_ALREADY_EXISTS`.
- **E3 — Payload out of bounds:** rating outside 1–5, >5 images, >5 MB, or scan failure → `VALIDATION_ERROR`/`FILE_SCAN_FAILED`; no review row (BR-REV-03).

## Postconditions
- Success: a `PUBLISHED` review exists with verified purchase; product aggregates update; timeline of the order unchanged.
- Failure: no review row; product data unchanged.

## Business Rules Applied
- BR-REV-01, BR-REV-03

## Related Requirements
- FR-006 (Reviews & Ratings)
- **Relation:** UC-030 step5 (prompt only) — delivery confirmation surfaces the review prompt; writing the review is this use case.

## Permissions / Data / External Dependencies
- **Permissions:** only the purchasing customer may review their own delivered item; eligibility re-checked server-side.
- **Data involved:** order item, review (rating, comment, images), product rating aggregate.
- **External dependencies:** catalog service (B02); file scanning for review images; background rating recompute job.

## Acceptance Criteria
- **AC-UC165-01:** Given a `DELIVERED` order within 30 days, when the purchaser submits rating 4, then a `PUBLISHED` review with `verifiedPurchase: true` exists (BR-REV-01).
- **AC-UC165-02:** Given rating 6, when submitted, then `VALIDATION_ERROR` and no review row (BR-REV-03).
- **AC-UC165-03:** Given an order still `OUT_FOR_DELIVERY`, when submit is attempted, then `REVIEW_NOT_ELIGIBLE` (BR-REV-01).
- **AC-UC165-04:** Given 6 images attached, when submitted, then `VALIDATION_ERROR` (BR-REV-03).
