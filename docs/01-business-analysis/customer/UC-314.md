# UC-314 — Attempt a Review After the 30-Day Window and Get Rejected

## Header Info
- **Use Case ID:** UC-314
- **Title:** Attempt a Review After the 30-Day Window and Get Rejected
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer tries to review an order item more than 30 days after delivery confirmation
- **Priority:** P2
- **Goal:** Enforce the review window server-side and explain the rejection with the governing dates.
- **Preconditions:** The customer's order item was delivered ≥30 days ago (BR-REV-01); review entry point reachable from the order (FL-09) or via direct submit.

## Main Scenario
1. Customer opens the review entry for the item 31 days after delivery and submits the form.
2. Server recomputes eligibility: purchaser only, order `DELIVERED`, within 30 days of delivery (BR-REV-01).
3. The window check fails → `REVIEW_NOT_ELIGIBLE`; no review row is created.
4. UI shows the localized rejection with the policy reason and the delivery/window dates (BR-PLT-05).
5. The review action for that item becomes unavailable; averages and store rating are untouched (BR-REV-05).

## Alternative Scenarios
- **A1 — Still inside the window:** the form submits normally → UC-165 publishes the review.
- **A2 — Order not yet delivered:** the action is hidden with an explanation, never shown as a failing button (FL-09 D1).
- **A3 — Editing an old review after 7 days:** a different cap fires — `REVIEW_EDIT_WINDOW_CLOSED` (BR-REV-02, UC-166).

## Exception Scenarios
- **E1 — Eligibility check unavailable:** the submit is refused; the client never decides eligibility, so no bypassed review exists.
- **E2 — Duplicate submission (retry/double-tap):** `REVIEW_ALREADY_EXISTS`; still exactly one review for the order item (BR-REV-02).
- **E3 — Non-buyer direct API call:** eligibility is validated against the caller's own order server-side; the request is rejected.

## Postconditions
- Failure end state (this path): no review row, no images stored, rating distribution and store average unchanged; customer informed of the dates.
- Success path: unaffected — one published review per delivered order item inside the window.

## Business Rules Applied
- BR-REV-01, BR-REV-02, BR-REV-05

## Related Requirements
- FR-006 (Reviews & Ratings — eligibility window)
- **Relation:** UC-165 is the in-window write path; UC-313 covers photo bounds on that path; UC-315 lists and filters published reviews.

## Permissions / Data / External Dependencies
- **Permissions:** CUSTOMER role — only the purchasing customer, only own order items; server-side validation is authoritative.
- **Data involved:** order-item state, delivery-confirmation date, review rows (unchanged), rating aggregates.
- **External dependencies:** order service (B06) for state/date; catalog review service (B02); no third-party providers.

## Acceptance Criteria
- **AC-UC314-01:** Given delivery 31 days ago, when a review is submitted, then `REVIEW_NOT_ELIGIBLE` returns and no review row exists (BR-REV-01).
- **AC-UC314-02:** Given the rejection, when the message renders, then it names the window and shows the delivery date (BR-PLT-05).
- **AC-UC314-03:** Given the rejected attempt, when aggregates are read, then average and count are identical to before (BR-REV-05).
- **AC-UC314-04:** Given delivery 10 days ago, when the same review is submitted, then it publishes normally (BR-REV-01).
