# UC-151 — Manage Account Preferences

## Header Info
- **Use Case ID:** UC-151
- **Title:** Manage Account Preferences
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens Account → Preferences and toggles a setting
- **Priority:** P2
- **Goal:** Let the customer persist locale, default address, confirmation channel and marketing opt-ins per channel, with security rows locked.
- **Preconditions:** Customer authenticated; preference row exists (FR-003).

## Main Scenario
1. Client calls `GET /users/me/preferences` (API-USR-009) → `locale`, `defaultAddressId`, `orderConfirmationChannel`, `marketingOptIn { sms, whatsapp, push }`.
2. Customer toggles marketing opt-ins per channel → `PUT /users/me/preferences` (API-USR-010).
3. Security categories cannot be changed from here — attempts return `PREFERENCE_IMMUTABLE` and their rows stay enabled (FR-003).
4. The per-category, per-channel notification matrix lives in the notification center (UC-177); customers may opt out of marketing categories independently per channel (BR-NTF-05).
5. Stored preferences steer future fan-outs; every label renders localized with Arabic default and English parity (BR-PLT-05).

## Alternative Scenarios
- **A1 — Locale via the switcher:** UC-152 writes the same stored locale preference; the URL/request header overrides it for the current view only.
- **A2 — Everything opted out:** the customer still receives transactional and security messages — those categories are locked, not optional.

## Exception Scenarios
- **E1 — Attempt to change a security row:** `PREFERENCE_IMMUTABLE` → nothing written; the UI shows the row as locked.
- **E2 — Invalid payload:** `VALIDATION_ERROR` → stored preferences unchanged; previous matrix re-served (FR-003).

## Postconditions
- Success: preference set stored; later fan-outs honour it; security rows untouched (BR-NTF-05).
- Failure: stored preferences unchanged.

## Business Rules Applied
- BR-PLT-05, BR-NTF-05

## Related Requirements
- FR-003 (User & Profile Management)

## Permissions / Data / External Dependencies
- **Permissions:** owner-scoped preferences; security rows are server-locked regardless of the request.
- **Data involved:** preference row (locale, default address, channel opt-ins), notification category matrix.
- **External dependencies:** notification fan-out service consuming the opt-in matrix.

## Acceptance Criteria
- **AC-UC151-01:** Given push marketing opt-out, when a promotion fans out, then the push channel is skipped for that customer (BR-NTF-05).
- **AC-UC151-02:** Given an attempt to flip a security preference, when submitted, then `PREFERENCE_IMMUTABLE` returns and the row stays enabled.
- **AC-UC151-03:** Given a saved locale preference, when the profile is next read, then the stored locale is returned (BR-PLT-05).
