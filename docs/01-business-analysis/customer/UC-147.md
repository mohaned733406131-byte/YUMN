# UC-147 — Revoke Another Device's Session

## Header Info
- **Use Case ID:** UC-147
- **Title:** Revoke Another Device's Session
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer picks an unfamiliar session in the session list and selects "Sign out this device"
- **Priority:** P1
- **Goal:** Terminate one specific device session so its refresh token stops working while the current device stays signed in.
- **Preconditions:** Customer authenticated; session list loaded (UC-146); target session belongs to the same customer (≤5 active sessions, BR-AUTH-06).

## Main Scenario
1. Customer selects a foreign session row → "Sign out this device" → confirmation.
2. Client calls `DELETE /auth/sessions/{sessionId}` (API-ATH-012) → `204`.
3. Server removes the session; the target device's refresh token fails on its next use (`SESSION_NOT_FOUND`) and that device returns to login.
4. The active-session count drops below the 5-session cap (BR-AUTH-06), so the customer can sign in a new device without evicting an old one.
5. Repeating the same delete still returns `204` — the operation is idempotent.

## Alternative Scenarios
- **A1 — Revoking the current session:** same effect as UC-143 — this device signs out too.
- **A2 — Session already revoked:** by logout-all (UC-144) or by cap eviction → idempotent `204`, no error surfaced.

## Exception Scenarios
- **E1 — Foreign or unknown sessionId:** `404 NOT_FOUND` — ownership rule never confirms another user's resources.
- **E2 — Network error before the response:** client retries; the delete is idempotent so a duplicate is safe (FR-003).

## Postconditions
- Success: target session revoked; its refresh token unusable; all other sessions untouched (BR-AUTH-06).
- Failure: no session revoked; list unchanged.

## Business Rules Applied
- BR-AUTH-06

## Related Requirements
- FR-003 (User & Profile Management)

## Permissions / Data / External Dependencies
- **Permissions:** authenticated customer managing only their own session rows (ownership enforced server-side, SEC-REQ-004).
- **Data involved:** session registry row, refresh-token family of the target device.
- **External dependencies:** none.

## Acceptance Criteria
- **AC-UC147-01:** Given a second signed-in device, when its session is revoked, then its next refresh fails and the device returns to login (BR-AUTH-06).
- **AC-UC147-02:** Given an already-revoked session id, when deleted again, then `204` returns (idempotent).
- **AC-UC147-03:** Given another customer's session id, when requested, then `404` returns and that session survives.
