# UC-315 — Filter a Product's Reviews by Rating

## Header Info
- **Use Case ID:** UC-315
- **Title:** Filter a Product's Reviews by Rating
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer taps a star bucket in the review list's rating summary
- **Priority:** P2
- **Goal:** Narrow the review list to one star rating while the full rating summary stays trustworthy.
- **Preconditions:** Product detail page open with its review list (UC-007, API-CAT-019 public read); at least one review exists (else the empty state shows).

## Main Scenario
1. Customer opens the review list and reads `ratingSummary` — average, count and per-star distribution (BR-REV-05).
2. Taps the 5-star bucket → the client requests the list with `?rating=5` (conceptual `GET /products/{slug}/reviews`).
3. Server returns only 5-star reviews, cursor-paged, while the summary still reflects all visible reviews (BR-REV-05).
4. Hidden (moderated) reviews are excluded from both the list and the aggregates (BR-REV-04).
5. Customer clears the filter → the full list returns on the first cursor.

## Alternative Scenarios
- **A1 — Zero reviews at that rating:** localized empty state with a per-facet "remove filter" recovery action (screen-states, no-results-under-filter).
- **A2 — Combined with sort:** `?rating&sort` applies both; counts are order-independent so the summary does not change.
- **A3 — Guest browsing:** the review list is a public read, so no login is required to filter.

## Exception Scenarios
- **E1 — Invalid rating value (0, 6, non-numeric):** `VALIDATION_ERROR`; the previous list stays rendered.
- **E2 — Stale/bad cursor:** the request fails validation and the list resets to the first page of the current filter.
- **E3 — Review section fetch fails:** block error with retry inside the section; the product page keeps working (partial-data rule).

## Postconditions
- Success: filtered list rendered in the active locale/RTL direction; summary unchanged; read-only — no rows written.
- Failure: previous valid list remains; no fabricated reviews.

## Business Rules Applied
- BR-REV-05, BR-REV-04

## Related Requirements
- FR-006 (Reviews & Ratings — review list & aggregates)
- **Relation:** UC-007 hosts the review list; UC-316 reads vendor responses within it; UC-167 reports a review from the same list.

## Permissions / Data / External Dependencies
- **Permissions:** Public read (no session required); hidden reviews excluded for every caller alike.
- **Data involved:** review rows (read), rating summary/distribution (read), cursor page state — no writes.
- **External dependencies:** catalog review service (B02); Redis facet/summary cache (NFR-004); cursor pagination.

## Acceptance Criteria
- **AC-UC315-01:** Given 12 reviews across ratings, when `?rating=5` is applied, then only 5-star reviews are listed (BR-REV-05).
- **AC-UC315-02:** Given the filter active, when the summary renders, then average, count and distribution still reflect all visible reviews (BR-REV-05).
- **AC-UC315-03:** Given a moderator-hidden review, when results return, then it is absent from list and aggregates (BR-REV-04).
- **AC-UC315-04:** Given a star bucket with zero reviews, when selected, then an empty state with a remove-filter action shows.
