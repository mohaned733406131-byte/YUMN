# UC-176 — Mark Notifications Read or Remove Them

## Header Info
- **Use Case ID:** UC-176
- **Title:** Mark Notifications Read or Remove Them
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens, marks, or deletes notifications in the in-app inbox
- **Priority:** P2
- **Goal:** Let the customer clear their unread badge by marking items read (one or all) and remove in-app records without affecting already-sent channel deliveries.
- **Preconditions:** Authenticated; inbox loaded (UC-175); target items belong to the customer (owner scope).

## Main Scenario
1. Customer opens an item → `POST /notifications/{id}/read` (API-NTF-003) → `{ id, readAt }`; the call is idempotent.
2. Bulk clear → `POST /notifications/read-all` (API-NTF-004) with optional `?category` → `{ marked: n }` resets the badge.
3. Remove → `DELETE /notifications/{id}` (API-NTF-005) → `204`; the in-app record disappears.
4. Mark/remove touch only the in-app record — SMS, WhatsApp and push deliveries already sent stay immutable and logged (BR-NTF-01 channel set).
5. The badge (`GET /notifications/unread-count`) reflects the change immediately.

## Alternative Scenarios
- **A1 — Category-scoped bulk clear:** `read-all?category=ORDER` marks only that category; others stay unread.
- **A2 — Re-marking a read item:** idempotent — same `readAt`, no error.
- **A3 — Delete vs read:** removal also drops the item from the feed and the unread count; read keeps it visible.

## Exception Scenarios
- **E1 — Foreign or unknown notification:** `NOT_FOUND` (owner scope).
- **E2 — Repeat delete:** `NOT_FOUND` on the second call; the client treats it as already done.
- **E3 — Invalid or expired session:** `AUTH_INVALID`; no change applied.

## Postconditions
- Success: read state and/or inbox membership updated for the owner; channel delivery logs untouched; badge correct.
- Failure: notification state unchanged; no partial bulk update.

## Business Rules Applied
- BR-NTF-01

## Related Requirements
- FR-017 (Notifications & Messaging — read state & removal)
- **Relation:** UC-175 lists the items managed here; UC-177 decides which categories produce them at all.

## Permissions / Data / External Dependencies
- **Permissions:** owner-only mutations; foreign ids return `NOT_FOUND`; no admin path needed for own inbox.
- **Data involved:** notification read state (`readAt`), in-app record membership, unread counters — channel logs immutable (BR-NTF-01).
- **External dependencies:** notification service (B10).

## Acceptance Criteria
- **AC-UC176-01:** Given an unread item, when marked read, then `readAt` is set and the unread count decreases by 1.
- **AC-UC176-02:** Given 10 unread in `ORDER`, when `read-all?category=ORDER` runs, then `marked = 10` and other categories are unchanged.
- **AC-UC176-03:** Given a removed notification, when the feed reloads, then it is absent while its SMS delivery log remains (BR-NTF-01).
- **AC-UC176-04:** Given a foreign notification id, when marked read, then `NOT_FOUND`.
