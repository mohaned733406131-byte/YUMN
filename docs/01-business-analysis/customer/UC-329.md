# UC-329 — Merge the Guest Cart Into the Account Cart on Login

## Header Info
- **Use Case ID:** UC-329
- **Title:** Merge the Guest Cart Into the Account Cart on Login
- **Actor:** Customer (ACT-01)
- **Trigger:** Login or registration succeeds while a client-side guest cart exists
- **Priority:** P1
- **Goal:** Combine guest and account carts into one server cart, with server values winning conflicts and limits never exceeded.
- **Preconditions:** Guest cart held client-side with a guest id (BR-CRT-03); account cart exists server-side; login just succeeded (UC-003/UC-002).

## Main Scenario
1. On auth success the client calls `POST /cart/merge` with the guest lines and an `Idempotency-Key` (BR-PLT-03).
2. Server merges: new lines are added to the account cart (BR-CRT-03).
3. Quantity conflicts resolve with the server value winning; the response reports `merged.added`, `merged.updated`, `merged.rejected[]` with reasons.
4. Guard violations (50/10/5 — C-15) reject only the affected guest lines, never the whole merge (BR-CRT-01).
5. The server cart replaces local state, the local guest cart is cleared, and the customer resumes the pre-login route (FL-01 step 7).

## Alternative Scenarios
- **A1 — Empty guest cart:** merge is a no-op; the account cart is untouched.
- **A2 — Same product in both carts:** server quantity wins; the line appears once in `merged.updated` (EC-05).
- **A3 — Merge would breach a limit:** the offending guest lines are listed in `merged.rejected[]`; accepted lines still merge.

## Exception Scenarios
- **E1 — Missing idempotency key:** `IDEMPOTENCY_KEY_REQUIRED`; nothing is merged and the guest cart stays local.
- **E2 — Key replayed after a timeout:** the same response returns — one merge, no duplicate lines (BR-PLT-03).
- **E3 — Merge service error:** the client keeps the guest cart locally and retries; the server cart is unchanged (no partial local clear).

## Postconditions
- Success: exactly one server cart holding the union within all guards; local guest cart cleared; no duplicate lines.
- Failure: server cart untouched and guest cart preserved locally — no half-merged state.

## Business Rules Applied
- BR-CRT-03, BR-CRT-01, BR-PLT-03

## Related Requirements
- FR-010 (Shopping Cart — guest carts merge on login)
- **Relation:** UC-003/UC-002 are the auth entry; UC-325 enforces the same guard ladder during merge; UC-011 checks out the merged cart.

## Permissions / Data / External Dependencies
- **Permissions:** CUSTOMER role just established — the merge is attributed to the authenticated `sub`, never to the anonymous guest id alone.
- **Data involved:** guest cart lines (client), server cart lines, quantities, per-store grouping, idempotency key.
- **External dependencies:** cart service (B05); client localStorage/ Zustand cart slice; no third-party providers.

## Acceptance Criteria
- **AC-UC329-01:** Given a guest cart of 3 lines and an account cart of 2 (no overlap), when login completes, then the server cart holds 5 lines (BR-CRT-03).
- **AC-UC329-02:** Given the same product in both carts, when merge runs, then the server quantity wins and one line exists (EC-05).
- **AC-UC329-03:** Given a merge that would exceed a guard, when it commits, then only the offending guest line is rejected (BR-CRT-01).
- **AC-UC329-04:** Given a retried merge with the same key, when it runs, then the original response returns with no duplicated lines (BR-PLT-03).
