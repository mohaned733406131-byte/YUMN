# UC-179 — Manage Registered Push Devices

## Header Info
- **Use Case ID:** UC-179
- **Title:** Manage Registered Push Devices
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens Settings → Devices (push devices)
- **Priority:** P2
- **Goal:** Let the customer see their registered push devices and unregister a lost or old device so pushes stop targeting it.
- **Preconditions:** Authenticated; at least the device registered in UC-178 may exist (empty list valid — A1); tokens are owner-scoped.

## Main Scenario
1. Customer opens the screen → `GET /devices` (API-NTF-010) lists own tokens: platform, deviceName, `registeredAt`, `lastPushAt` (bounded list mirroring the 5-session cap).
2. Customer identifies an old or lost device → `DELETE /devices/{token}` (API-NTF-009) → `204`, idempotent.
3. System marks the token unregistered; future notifications target only active tokens (BR-NTF-01 — push stays a channel for the remaining active devices).
4. Logout on a device unregisters only that device's token; other sessions keep theirs.
5. The list refreshes to show the remaining devices.

## Alternative Scenarios
- **A1 — Empty list:** no registered devices (web-only usage) — valid response with zero items.
- **A2 — Remove the current device:** pushes stop on this device while the session stays signed in.
- **A3 — Stale tokens:** replaced earlier by re-registration in UC-178 A2; only current tokens are listed.

## Exception Scenarios
- **E1 — Foreign token:** `NOT_FOUND` (owner scope).
- **E2 — Unknown token:** `DEVICE_NOT_FOUND`; treated as already removed (BR-NTF-01 keeps sending to active tokens only).
- **E3 — Invalid or expired session:** `AUTH_INVALID`; no change applied.

## Postconditions
- Success: listed devices match the owner's active tokens; removed token receives no further pushes; other devices unaffected.
- Failure: token list unchanged; no push routing change.

## Business Rules Applied
- BR-NTF-01

## Related Requirements
- FR-017 (Notifications & Messaging — device management)
- **Relation:** UC-178 registers the tokens listed here; account deletion (system path) purges all of them.

## Permissions / Data / External Dependencies
- **Permissions:** customer manages only their own tokens; other users' tokens return `NOT_FOUND`.
- **Data involved:** device token rows (platform, deviceName, registeredAt, lastPushAt) — owner-scoped.
- **External dependencies:** notification service (B10); FCM/APNs token lifecycle in the push adapter.

## Acceptance Criteria
- **AC-UC179-01:** Given 2 registered tokens, when the list loads, then both appear with platform and `lastPushAt` (BR-NTF-01).
- **AC-UC179-02:** Given a valid token, when deleted, then `204` and it receives no further pushes.
- **AC-UC179-03:** Given the same delete repeated, when called again, then `204` (idempotent).
- **AC-UC179-04:** Given another user's token, when deleted, then `NOT_FOUND`.
