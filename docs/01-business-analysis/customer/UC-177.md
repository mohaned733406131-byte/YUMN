# UC-177 — Configure Notification Preferences

## Header Info
- **Use Case ID:** UC-177
- **Title:** Configure Notification Preferences
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens Settings → Notifications
- **Priority:** P1
- **Goal:** Let the customer opt in or out of each notification category independently per channel, without touching security notices.
- **Preconditions:** Authenticated; a default preference matrix exists for the user; security categories are locked by design.

## Main Scenario
1. Customer opens the screen → `GET /notifications/preferences` (API-NTF-006) returns the category × channel matrix with `emailSupported: false`.
2. Customer toggles categories independently per channel (SMS, WhatsApp, in-app, push) — per-category, per-channel opt-out is allowed (BR-NTF-05).
3. Customer saves → `PUT /notifications/preferences` with `updates: [{ category, channel, enabled }]` (API-NTF-007).
4. System applies the changes; later fan-out uses the stored matrix for non-security categories; security rows are returned `locked: true` and immutable.
5. The response echoes the updated matrix so the UI reflects persisted state.

## Alternative Scenarios
- **A1 — Re-enable a category:** same endpoint with `enabled: true`; effective from the next fan-out (BR-NTF-05).
- **A2 — Single-channel opt-out:** e.g. `PROMOTION` off for SMS but still on for in-app.
- **A3 — Security categories:** displayed as locked in the matrix and never offered as toggles.

## Exception Scenarios
- **E1 — Changing a security category:** `PREFERENCE_IMMUTABLE`; matrix unchanged.
- **E2 — Unsupported channel (e.g. `EMAIL`):** `CHANNEL_NOT_SUPPORTED`; nothing persisted (`emailSupported` stays false).
- **E3 — Malformed payload:** `VALIDATION_ERROR`; no preference row updated.

## Postconditions
- Success: stored matrix matches the customer's choices; security categories untouched; next fan-out honors the new opt-ins/outs (BR-NTF-05).
- Failure: matrix byte-for-byte unchanged.

## Business Rules Applied
- BR-NTF-05

## Related Requirements
- FR-017 (Notifications & Messaging — preferences)
- **Relation:** UC-175/UC-176 show and clear the notifications whose delivery these preferences gate.

## Permissions / Data / External Dependencies
- **Permissions:** customer edits only their own matrix; security categories are never user-editable.
- **Data involved:** preference rows (category × channel), channel capability flags — no notification content.
- **External dependencies:** notification service (B10); fan-out job consumes the matrix.

## Acceptance Criteria
- **AC-UC177-01:** Given `PROMOTION`/SMS enabled, when disabled, then the stored matrix shows `false` and later promotions skip SMS (BR-NTF-05).
- **AC-UC177-02:** Given a `SECURITY` row, when a change is attempted, then `PREFERENCE_IMMUTABLE` and the row stays `locked: true`.
- **AC-UC177-03:** Given channel `EMAIL`, when submitted, then `CHANNEL_NOT_SUPPORTED` and `emailSupported` stays `false`.
- **AC-UC177-04:** Given two categories changed in one call, when saved, then both are persisted in the returned matrix.
