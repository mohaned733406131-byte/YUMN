# UC-320 — Open a Suspended Storefront and Find It Unavailable

## Header Info
- **Use Case ID:** UC-320
- **Title:** Open a Suspended Storefront and Find It Unavailable
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens a storefront link (bookmark, Following list, shared URL) for a suspended store
- **Priority:** P2
- **Goal:** Withhold a suspended storefront and its products without leaking the reason, while offering a recovery path.
- **Preconditions:** The store exists with `status = SUSPENDED` (BR-VND-04); customer holds a link or residue reference (UC-318/UC-008).

## Main Scenario
1. Customer opens `/[locale]/store/{store-slug}` for the suspended store.
2. The storefront read is refused — suspended/hidden stores return `404` (API-VND-012, BR-VND-04).
3. Client renders the standard localized 404 page with search and home links — no suspension reason is revealed (routing §9).
4. The store's products are also absent from search and category browse: exclusion is enforced at index time and re-checked at query time (BR-VND-04, BR-CAT-06).
5. The customer recovers through search or the home link (never a dead end).

## Alternative Scenarios
- **A1 — Store not suspended:** the storefront renders normally with products, rating and following state (rejoins UC-008).
- **A2 — Suspension lifted later:** the same URL resolves again with no redirect needed.
- **A3 — Deep link to one of its products:** the product is not discoverable and resolves to the same 404 treatment (BR-CAT-06).

## Exception Scenarios
- **E1 — Genuinely unknown slug:** identical 404 treatment — existence of stores is never leaked either way.
- **E2 — Session expired while opening:** re-auth prompt on the route, then the request repeats (routing §9).
- **E3 — Network failure:** page error with retry plus home/search links; no store content is cached into the page.

## Postconditions
- Success (recovery): the customer is back on marketplace pages; the store stays suspended — no data changed.
- Failure: no store profile, products, follower data or reason text is displayed.

## Business Rules Applied
- BR-VND-04, BR-CAT-06

## Related Requirements
- FR-008 (Store Management & Storefront Configuration — storefront visibility)
- **Relation:** UC-318 may link here from the Following list; UC-008 follows stores; UC-001/UC-006 are the recovery browse/search paths.

## Permissions / Data / External Dependencies
- **Permissions:** Public storefront reads gated on store status; suspension decided on the vendor/admin side (FR-007/FR-020), never by the customer.
- **Data involved:** store status, storefront profile, product index entries (excluded) — read-only for the customer.
- **External dependencies:** store service (B03); search index (DEP-04) exclusion; static 404 page (B04/B05 unaffected).

## Acceptance Criteria
- **AC-UC320-01:** Given a suspended store, when its storefront URL opens, then a localized 404 page renders with search and home links (BR-VND-04).
- **AC-UC320-02:** Given the suspended store's products, when search runs, then none of them appear in results (BR-VND-04, BR-CAT-06).
- **AC-UC320-03:** Given the 404, when its copy renders, then no suspension or deletion reason is disclosed.
- **AC-UC320-04:** Given the same store after reinstatement, when the URL opens, then the storefront renders normally.
