# UC-150 — Upload a Profile Avatar

## Header Info
- **Use Case ID:** UC-150
- **Title:** Upload a Profile Avatar
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer taps the avatar in the profile and picks an image
- **Priority:** P2
- **Goal:** Replace the profile picture with a scanned, sanitized image that satisfies the platform image rules.
- **Preconditions:** Customer authenticated; an image file jpg/png/webp ≤5 MB is selected (BR-CAT-08, SEC-REQ-011).

## Main Scenario
1. Account → Profile → avatar → customer picks an image; client pre-checks format and size (BR-CAT-08).
2. Client sends `POST /users/me/avatar` as `multipart/form-data { file }` (API-USR-011).
3. Server validates type/size, malware-scans the file, strips EXIF and re-encodes it (BR-CAT-08, SEC-REQ-011) → `201 { fileId, avatarUrl, width, height }`.
4. The new `avatarUrl` replaces the previous one and renders wherever the profile picture appears (FR-003).

## Alternative Scenarios
- **A1 — No avatar yet:** default placeholder is shown until the first successful upload.
- **A2 — Rejected by client pre-check:** wrong format or oversized file never reaches the server; the error renders in the current locale.

## Exception Scenarios
- **E1 — Oversized or unsupported file:** `PAYLOAD_TOO_LARGE`/`UNSUPPORTED_MEDIA_TYPE` per the image rules; profile unchanged (BR-CAT-08).
- **E2 — Malware scan failure:** `FILE_SCAN_FAILED` → upload discarded, previous avatar retained (SEC-REQ-011).
- **E3 — Network error mid-upload:** client retries; nothing changes until a `201` confirms the new avatar.

## Postconditions
- Success: `avatarUrl` updated; EXIF removed; scan passed; old image superseded.
- Failure: avatar unchanged; no partial or unscreened file is served.

## Business Rules Applied
- BR-CAT-08

## Related Requirements
- FR-003 (User & Profile Management)

## Permissions / Data / External Dependencies
- **Permissions:** authenticated customer uploading only to their own profile (owner-scoped, SEC-REQ-004).
- **Data involved:** uploaded image file, file metadata (`fileId`, dimensions), profile `avatarUrl`.
- **External dependencies:** file scanning/storage service shared with KYC, product and proof uploads.

## Acceptance Criteria
- **AC-UC150-01:** Given a 6 MB jpg, when uploaded, then it is rejected under the ≤5 MB rule (BR-CAT-08).
- **AC-UC150-02:** Given a valid png carrying EXIF, when processed, then the stored file has EXIF stripped (BR-CAT-08).
- **AC-UC150-03:** Given a file failing the malware scan, when submitted, then `FILE_SCAN_FAILED` returns and the old avatar remains.
