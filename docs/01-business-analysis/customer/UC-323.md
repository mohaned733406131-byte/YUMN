# UC-323 — Recover from a Zero-Result Search with Suggestions and Popular Categories

## Header Info
- **Use Case ID:** UC-323
- **Title:** Recover from a Zero-Result Search with Suggestions and Popular Categories
- **Actor:** Customer (ACT-01)
- **Trigger:** A search returns zero matches for the query or filter combination
- **Priority:** P1
- **Goal:** Turn a dead-end query into a recoverable state with spelling suggestions and popular categories (never a blank page).
- **Preconditions:** Search page open (UC-006); zero-result response is a `200` with empty `items` plus `facets`, `didYouMean` and `popularCategories` (API-SRC-001).

## Main Scenario
1. Customer submits a query with no matches; the server answers `200` with empty `items` and recovery metadata — zero results are never an error status.
2. UI renders the localized "no results for «{query}»" empty state (screen-states §3).
3. Three recovery actions are offered: spelling suggestion, clear/remove filters, popular categories.
4. Accepting `didYouMean` re-runs the query with the corrected term (suggestions from `GET /search/suggest`, API-SRC-003).
5. Tapping a popular category opens category browse (`GET /categories/{slug}`) with real products (BR-CAT-03, BR-CAT-06).

## Alternative Scenarios
- **A1 — Filters caused the zero results:** the query may be fine; "remove filter" per facet widens the context and results return (rejoins UC-321).
- **A2 — Query too short:** `QUERY_TOO_SHORT` with a localized hint to type more characters.
- **A3 — Typeahead used instead:** the customer corrects the term from live suggestions before submitting (UC-156).

## Exception Scenarios
- **E1 — Search endpoint unavailable (503):** falls back to the category-browse path (UC-324, NFR-007).
- **E2 — Popular-categories card fails to load:** block error for that card only; the other recovery actions keep working (partial-data rule).
- **E3 — Suggest request fails:** the suggestion area stays empty; the list and other actions are unaffected.

## Postconditions
- Success: the customer reaches results or category browse; no rows written, no cart impact.
- Failure: the customer is still on a recoverable empty state — never an unrecoverable dead end (NFR-012).

## Business Rules Applied
- BR-CAT-03, BR-CAT-06, BR-PLT-05

## Related Requirements
- FR-009 (Search & Discovery — zero-result recovery)
- **Relation:** UC-006 is the search entry; UC-156 is typeahead; UC-324 covers search unavailability rather than empty results.

## Permissions / Data / External Dependencies
- **Permissions:** Public read — suggestions, categories and empty-state copy need no session.
- **Data involved:** search response (`items`, `facets`, `didYouMean`, `popularCategories`), category tree — read-only.
- **External dependencies:** Elasticsearch cluster (DEP-04); category tree cache (NFR-004); localized empty-state strings (BR-PLT-05).

## Acceptance Criteria
- **AC-UC323-01:** Given a query with no matches, when results return, then status 200 with empty `items`, `didYouMean` and `popularCategories` are present (FR-009).
- **AC-UC323-02:** Given the empty state, when it renders, then spelling, clear-filter and popular-category actions are all offered (NFR-012).
- **AC-UC323-03:** Given a misspelled query, when the suggestion is accepted, then the corrected query runs and returns results.
- **AC-UC323-04:** Given the popular category is tapped, when the page loads, then only `ACTIVE` products are listed (BR-CAT-06).
