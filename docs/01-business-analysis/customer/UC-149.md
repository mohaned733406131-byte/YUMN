# UC-149 — Add and Verify an Optional Email

## Header Info
- **Use Case ID:** UC-149
- **Title:** Add and Verify an Optional Email
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer adds an email address in the profile and enters the code sent to it
- **Priority:** P2
- **Goal:** Record a verified optional email without ever making it a login or OTP-delivery factor.
- **Preconditions:** Customer authenticated; email field empty or unverified; phone remains the sole primary identifier (BR-AUTH-08).

## Main Scenario
1. Profile → "Add email" → customer enters an address → `PATCH /users/me { email }` (API-USR-002) stores it unverified and dispatches a 6-digit code to that address.
2. Customer opens the email inbox and enters the code → `POST /users/me/email/verify { code }` (API-USR-003).
3. System validates the code (expiry and attempt limits as in the OTP flow) → `emailVerified: true` (BR-AUTH-08).
4. Profile now displays the verified email; login and OTP delivery remain phone-only (BR-AUTH-08).

## Alternative Scenarios
- **A1 — Email left unverified:** profile stays fully usable; only the badge shows unverified and no feature depends on it (BR-AUTH-08).
- **A2 — Address changed before verifying:** the new address is stored unverified, a fresh code is sent, and the old code no longer matches.

## Exception Scenarios
- **E1 — Code expired or attempts exhausted:** `OTP_EXPIRED`/`OTP_MAX_ATTEMPTS` → customer requests a fresh code and retries.
- **E2 — Email already registered:** `EMAIL_ALREADY_REGISTERED` at the PATCH; the stored email is unchanged (FR-003).

## Postconditions
- Success: verified email recorded; authentication behaviour unchanged — phone-only (BR-AUTH-08).
- Failure: email stays unverified or unchanged; no other profile field affected.

## Business Rules Applied
- BR-AUTH-08

## Related Requirements
- FR-003 (User & Profile Management)

## Permissions / Data / External Dependencies
- **Permissions:** owner-scoped profile edit; verification code only confirms control of the address.
- **Data involved:** profile email field, `emailVerified` flag, email code hash.
- **External dependencies:** outbound email delivery for the verification code (no email auth path exists).

## Acceptance Criteria
- **AC-UC149-01:** Given a valid email code, when verified, then `emailVerified: true` is returned (BR-AUTH-08).
- **AC-UC149-02:** Given a verified email, when login is attempted, then no email login path is offered — only phone works (BR-AUTH-08).
- **AC-UC149-03:** Given an address already used by another account, when added, then `EMAIL_ALREADY_REGISTERED` returns.
