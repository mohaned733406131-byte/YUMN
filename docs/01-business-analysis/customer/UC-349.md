# UC-349 — Follow Delivery Progress Without a Map

## Header Info
- **Use Case ID:** UC-349
- **Title:** Follow Delivery Progress Without a Map
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens tracking while a delivery is in flight
- **Priority:** P2
- **Goal:** Follow each delivery step through a state timeline — the platform never requests or stores GPS.
- **Preconditions:** Order in delivery flow (FR-015); tracking route reachable (routing §4); no location data exists by design (BR-SHP-05).

## Main Scenario
1. Customer opens `/{locale}/track/{order-id}` → state badge plus append-only history with actor and timestamp (FL-03 step 1).
2. Progress renders as a step timeline (`READY_FOR_PICKUP → ASSIGNED → PICKED_UP → IN_TRANSIT → OUT_FOR_DELIVERY → DELIVERED`) — no map anywhere (BR-SHP-05).
3. At `OUT_FOR_DELIVERY` the 6-digit code panel appears for the handover (BR-SHP-02, UC-346).
4. State changes are announced politely to screen readers and pushed per preferences (NFR-011, FR-017).
5. `DELIVERED` surfaces the 7-day escrow countdown, then `COMPLETED` appears as a System transition (BR-ESC-01, WF-006).

## Alternative Scenarios
- **A1 — Failed attempt:** the timeline regresses to `IN_TRANSIT` with a new entry (UC-347).
- **A2 — Live refresh:** detail polls every 10–15 s while the tab is visible and pauses when hidden.
- **A3 — Deep link from a notification:** lands on the same tracking screen with current state re-fetched.

## Exception Scenarios
- **E1 — Tracking fetch fails:** page error with retry; a cached badge is never presented as authoritative.
- **E2 — Foreign order:** `404` — tracking is owner-only (BR-ORD-09).
- **E3 — Offline:** persistent banner plus the last loaded timeline marked stale; views auto-refresh on reconnect (screen-states §5).

## Postconditions
- Success: the customer knows the exact state and the next step without any map or GPS.
- Failure: no location coordinates were requested, transmitted or stored at any point (BR-SHP-05).

## Business Rules Applied
- BR-SHP-05, BR-ORD-03

## Related Requirements
- FR-015 (Shipping & Delivery — progress visibility)
- **Relation:** UC-012 opens tracking; UC-346 provides the code panel; UC-347 records attempts; UC-348 handles the lockout notice.

## Permissions / Data / External Dependencies
- **Permissions:** CUSTOMER role, own delivery view only; courier sees its own job, admin dispatch view (BR-ORD-09).
- **Data involved:** order/delivery state, timeline entries, attempt log, code panel state — no location fields exist.
- **External dependencies:** delivery service (B08); order timeline (B06); notification deep links (B10).

## Acceptance Criteria
- **AC-UC349-01:** Given an in-transit order, when tracking loads, then a step timeline with state badge renders and no map element exists (BR-SHP-05).
- **AC-UC349-02:** Given the order reaches `OUT_FOR_DELIVERY`, when the screen updates, then the code panel appears (BR-SHP-02).
- **AC-UC349-03:** Given any tracking session, when the network trace is inspected, then no GPS/location coordinates are requested or stored (BR-SHP-05).
- **AC-UC349-04:** Given a state change, when it renders, then it is announced politely to screen readers (NFR-011).
