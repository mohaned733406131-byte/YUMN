# UC-006 — Search Products

## Header Info
- **Use Case ID:** UC-006
- **Title:** Search Products
- **Actor:** Customer (ACT-01) — guest or authenticated
- **Trigger:** User enters a query or applies filters on the search screen
- **Priority:** P1
- **Goal:** Find ACTIVE, purchasable products quickly using Arabic-aware full-text search with filters and sorting.
- **Preconditions:** Catalog indexed; guest or logged-in session; no suspended-vendor content in the index (BR-VND-04).

## Main Scenario
1. User types a query (Arabic or English) → client `GET /search/products?q=…&page=…`.
2. System runs Arabic-aware full-text search (stemming/diacritics handling, FR-009) over ACTIVE products only (BR-CAT-06).
3. Results show image, Arabic name, YER price, store name, rating snippet (BR-REV-05), paginated with stable ordering.
4. User applies filters (category ≤5 levels BR-CAT-03, price range, store, rating) and sorting (price/date/relevance) → system re-queries with filters combined server-side.
5. User taps a result → product detail opens (UC-007).
6. Search analytics events are recorded for the admin/vendor dashboards (FR-018).

## Alternative Scenarios
- **A1 — Zero results:** Empty result set → localized suggestions (popular categories, spelling hints); no error state.
- **A2 — Typo/near-match:** No exact hit → system applies fuzzy/normalized matching before falling back to A1.
- **A3 — Category browse instead:** User picks a category tile → same result rendering via category endpoint (UC-001 step 2).

## Exception Scenarios
- **E1 — Search engine down:** Index service unavailable → degraded mode serves category browse from cache (NFR-007); a non-blocking alert is raised.
- **E2 — Heavy load:** p95 exceeds target → results served from cache (NFR-004); stale-flagged results are acceptable briefly.
- **E3 — Malicious query payload:** Injection/XSS attempt → parameterized query and output encoding neutralize it (SEC-REQ-008); request rate-limited (SEC-REQ-009).

## Postconditions
- No cart, order, or wallet change; search is read-only.
- Results never include inactive products, soft-deleted products (BR-CAT-06), or suspended stores (BR-VND-04).

## Business Rules Applied
- BR-CAT-03, BR-CAT-06, BR-REV-05, BR-PLT-05, BR-VND-04

## Related Requirements
- FR-009 (Search & Discovery)

## Permissions / Data / External Dependencies
- **Permissions:** Public read; results scoped to publishable catalog only.
- **Data involved:** Products, categories, stores, rating aggregates, search events.
- **External dependencies:** Search index (built by BullMQ indexing jobs, BR-PLT-01); Redis cache.

## Acceptance Criteria
- **AC-UC006-01:** Given an Arabic query with diacritics, when searched, then matching ACTIVE products are returned (Arabic-aware, FR-009).
- **AC-UC006-02:** Given a soft-deleted product, when searched, then it is excluded (BR-CAT-06).
- **AC-UC006-03:** Given filters + sort applied, when re-queried, then ordering matches the requested sort with pagination intact.
