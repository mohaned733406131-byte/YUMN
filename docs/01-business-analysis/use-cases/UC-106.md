# UC-106 — Edit a CMS Page Draft

## Header Info
- **Use Case ID:** UC-106
- **Title:** Edit a CMS Page Draft
- **Actor:** Admin (ACT-04)
- **Trigger:** An admin revises the content of an existing CMS page draft
- **Priority:** P1
- **Goal:** Update draft page content with localized parity while never mutating a live page silently.
- **Preconditions:** Admin authenticated with content-write permission (ACT-04); the target page exists (created in UC-105).

## Main Scenario
1. Admin opens Content → Pages → client `GET /admin/pages` (API-CNT-005) filtered to `DRAFT`, then selects the page.
2. Admin changes title/body blocks with Arabic/English parity kept (BR-PLT-05) → client `PUT /admin/pages/{id}` (API-CNT-008).
3. System validates the payload (schema + locale parity — BR-PLT-05) → `200 { …page, updatedAt }`.
4. The edit lands on the draft only; while the page is DRAFT the public read `GET /pages/{slug}` remains 404, so a live page is never mutated silently (API-CNT-008).
5. Page detail (API-CNT-007) shows the `{ at, by, action }` history entry for the update.

## Alternative Scenarios
- **A1 — Partial edit:** Admin changes only the Arabic title → English field untouched, parity still holds (BR-PLT-05).
- **A2 — Editing published content:** Admin edits a PUBLISHED page → changes are staged for a new publish (UC-107); the live public output is unchanged until then.
- **A3 — Abandon edits:** Admin leaves the form → no request issued, draft content unchanged.

## Exception Scenarios
- **E1 — Permission denied:** Moderator or non-admin attempts the update → 403 `FORBIDDEN`; content unchanged.
- **E2 — Validation failure:** Malformed body block or a title missing one locale → 400 `VALIDATION_ERROR`; nothing written.
- **E3 — Concurrent edit:** Another admin saves the same draft first → stale-write conflict (expected version mismatch) → 409; this admin reloads the page detail and reapplies changes.

## Postconditions
- Draft content reflects the last accepted edit; page status unchanged (DRAFT unless already PUBLISHED).
- Public payload changes only through a later publish (UC-107).

## Business Rules Applied
- BR-PLT-05

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))

## Permissions / Data / External Dependencies
- **Permissions:** Admin content-write scope; Moderator read-only on pages (update denied).
- **Data involved:** CMS pages (draft content, revision history).
- **External dependencies:** Public content reads (`API-CNT-001` family) cache only published pages; draft edits never hit them.

## Acceptance Criteria
- **AC-UC106-01:** Given a DRAFT page, when valid changes are saved, then `200` returns `updatedAt` and the public read still returns 404.
- **AC-UC106-02:** Given a PUBLISHED page, when its content is edited, then the live public output stays unchanged until a publish (UC-107).
- **AC-UC106-03:** Given an Arabic title without its English counterpart, when saved, then validation rejects the write (BR-PLT-05).
- **AC-UC106-04:** Given two admins editing one draft, when both save, then the second save gets a 409 conflict and no silent overwrite occurs.
