# UC-111 — Edit Banner Content, Targeting, and Schedule

## Header Info
- **Use Case ID:** UC-111
- **Title:** Edit Banner Content, Targeting, and Schedule
- **Actor:** Admin (ACT-04)
- **Trigger:** A banner's creative, audience, or schedule must change
- **Priority:** P1
- **Goal:** Update a banner's label/image, role targeting, or schedule so the rendered home surface reflects the new plan without a republish step.
- **Preconditions:** Admin authenticated with content-write permission (ACT-04); the banner exists (created in UC-110).

## Main Scenario
1. Admin opens the banner from the list (UC-109) and changes the localized label (ar/en parity — BR-PLT-05), `visibleTo`, or `startsAt`/`endsAt`.
2. Client sends `PUT /admin/banners/{id}` (API-CNT-013) with the changed fields.
3. System validates the payload → `200 { …banner }`; the schedule window is authoritative and takes effect without any republish step.
4. Home surfaces immediately reflect the new label/targeting/window on next read (localized per BR-PLT-05).

## Alternative Scenarios
- **A1 — Extend a campaign:** Admin only moves `endsAt` forward → banner keeps showing until the new end.
- **A2 — Retarget roles:** Admin adds `VENDOR` to `visibleTo` → vendor surface starts receiving the banner in-window.
- **A3 — Reschedule only:** Label and image unchanged; window shifted → visibility follows the new window.

## Exception Scenarios
- **E1 — Permission denied:** Moderator or non-admin attempts update → 403 `FORBIDDEN`; banner unchanged.
- **E2 — Validation failure:** Empty label, unsupported surface, or inverted window (`endsAt` before `startsAt`) → 400 `VALIDATION_ERROR`; nothing written.
- **E3 — Concurrent edit:** Another admin saves the same banner first → stale-write conflict (expected version mismatch) → 409; this admin reloads the banner (or finds it removed → 404) and reapplies.

## Postconditions
- Banner reflects the last accepted edit; visibility follows the stored schedule/targeting.
- No page, coupon, or order change originates from a banner edit.

## Business Rules Applied
- BR-PLT-05

## Related Requirements
- FR-019 (Content & Promotions (CMS + Coupons))

## Permissions / Data / External Dependencies
- **Permissions:** Admin content-write scope; Moderator read-only on banners.
- **Data involved:** Banners (label, image, targeting, schedule).
- **External dependencies:** Home surface rendering (`GET /home`) picks up changes on next read.

## Acceptance Criteria
- **AC-UC111-01:** Given a changed schedule, when the banner is saved, then `200` returns the updated record and visibility follows the new window without a republish.
- **AC-UC111-02:** Given a localized label edit, when saved, then both locales render with ar as default and en parity (BR-PLT-05).
- **AC-UC111-03:** Given an inverted window (`endsAt` < `startsAt`), when saved, then 400 `VALIDATION_ERROR` and the stored banner is unchanged.
- **AC-UC111-04:** Given two admins editing one banner, when both save, then the second save gets 409 and no silent overwrite occurs.
