# UC-175 — Open the Notification Inbox

## Header Info
- **Use Case ID:** UC-175
- **Title:** Open the Notification Inbox
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer taps the notification bell/badge on any surface (S1 web, S4 mobile)
- **Priority:** P1
- **Goal:** Show the customer their own in-app notifications with read state, category, channel delivery record and a deterministic deep link.
- **Preconditions:** Authenticated with a valid session; notifications may be empty (A1); owner-scoped inbox.

## Main Scenario
1. Customer opens the bell → client reads `GET /notifications/unread-count` (API-NTF-002) for the badge.
2. Inbox loads `GET /notifications` (API-NTF-001), a cursor feed with `?unreadOnly&category` filters.
3. Each item shows category (`SECURITY`/`ORDER`/`DELIVERY`/`RETURN`/`PROMOTION`/`STORE_FOLLOW`/`SYSTEM`), localized title/body, severity, `readAt` and the per-channel delivery record — SMS, WhatsApp, in-app, push; no email in v1 (BR-NTF-01).
4. Items carry a server-generated `deepLink` (surface, route, entity, action, locale) so tapping navigates deterministically to the right screen.
5. Customer pages older items via cursor and may narrow by unread or category.

## Alternative Scenarios
- **A1 — Empty inbox:** zero items with unread total 0 — a valid response, no fabricated rows.
- **A2 — Unread-only / category filter:** `?unreadOnly=true` or `?category=ORDER` narrows the feed.
- **A3 — Delivery record detail:** each item lists which channels actually delivered it (`SENT`/`FAILED`) for that notification (BR-NTF-01).

## Exception Scenarios
- **E1 — Invalid or expired session:** `AUTH_INVALID`; inbox not rendered.
- **E2 — Invalid cursor or filter value:** `VALIDATION_ERROR`; no data returned.
- **E3 — Read failure:** error state; no partial list is rendered.

## Postconditions
- Success: customer views their own notifications; opening one may mark it read (UC-176) — no other state change.
- Failure: no data rendered; session either invalid (→ login) or intact.

## Business Rules Applied
- BR-NTF-01

## Related Requirements
- FR-017 (Notifications & Messaging — in-app inbox)
- **Relation:** UC-176 manages read/remove state of items listed here; UC-177 governs which categories reach this inbox.

## Permissions / Data / External Dependencies
- **Permissions:** any authenticated customer reads only their own inbox (owner scope).
- **Data involved:** notification rows, read state, channel delivery log, deep-link payload — read-only.
- **External dependencies:** notification service (B10); cursor pagination.

## Acceptance Criteria
- **AC-UC175-01:** Given 3 unread notifications, when the inbox opens, then all 3 are listed with category, title and `readAt` unset.
- **AC-UC175-02:** Given a notification delivered via SMS and PUSH, when its record is shown, then both channels appear with status `SENT` (BR-NTF-01).
- **AC-UC175-03:** Given another user's notifications, when the feed is requested, then only the owner's items are returned.
- **AC-UC175-04:** Given `?unreadOnly=true`, when applied, then read items are excluded.
