# UC-009 — Add Product to Cart

## Header Info
- **Use Case ID:** UC-009
- **Title:** Add Product to Cart
- **Actor:** Customer (ACT-01) — guest or authenticated
- **Trigger:** User taps "Add to cart" on a product or variant
- **Priority:** P0
- **Goal:** Place a purchasable item into the cart under all cart guards while starting a 15-minute stock reservation.
- **Preconditions:** Product ACTIVE, store active (BR-CAT-06, BR-VND-04); stock > 0; guest cart stored client-side until login (BR-CRT-03).

## Main Scenario
1. User selects a variant (if any, BR-CAT-02) and quantity (default 1) → client `POST /cart/items` with product/variant ID and quantity.
2. System validates guards: ≤50 distinct products, ≤10 units per product, ≤5 vendors per cart (BR-CRT-01, C-15); rejects with `CART_LIMIT_EXCEEDED` on violation.
3. System checks ACTIVE status, stock integer ≥0 and availability (BR-CAT-07), and store not suspended (BR-VND-04).
4. On success, system starts/refreshes the 15-minute reservation countdown for the cart (BR-CRT-02, C-13) and returns the updated cart with server-computed line totals in integer YER (BR-PAY-10).
5. Cart badge/UI updates; user may proceed to manage cart (UC-010) or checkout (UC-011).
6. For a guest, the item is written to the client-side cart and merged on login (BR-CRT-03).

## Alternative Scenarios
- **A1 — Item already in cart:** Same product/variant present → quantity increments (subject to ≤10 cap) and reservation countdown refreshes (BR-CRT-02).
- **A2 — Fifth vendor blocked:** Adding from a 6th store → `MAX_VENDORS_EXCEEDED`; user must remove items from another store first (BR-CRT-01).
- **A3 — Guest then login:** Guest adds items, then registers/logs in (UC-002/UC-003) → carts merge; server value wins on quantity conflict (BR-CRT-03).

## Exception Scenarios
- **E1 — Stock conflict:** Reserved stock taken by another checkout between check and write → atomic reservation fails; user sees "only N left" or out-of-stock (BR-CAT-07).
- **E2 — Reservation expired:** 15-minute TTL lapses → reserved stock auto-releases (BR-CRT-02); cart entry remains but checkout re-reserves (C-13).
- **E3 — Network failure:** Timeout after server commit → client retry with idempotency key returns the same cart state (BR-PLT-03); no double reservation.

## Postconditions
- Cart contains the item with server-computed totals; reservation countdown running (authenticated carts).
- No order, payment, or ledger entry yet.

## Business Rules Applied
- BR-CAT-02, BR-CAT-06, BR-CAT-07, BR-CRT-01, BR-CRT-02, BR-CRT-03, BR-PAY-10, BR-PLT-03, BR-VND-04

## Related Requirements
- FR-010 (Shopping Cart), FR-005 (Inventory Management)

## Permissions / Data / External Dependencies
- **Permissions:** Guests may build a client-side cart; server cart requires a session (login gate before checkout).
- **Data involved:** Cart lines, stock reservations (TTL rows), price snapshot.
- **External dependencies:** Inventory service (B02) for atomic reservation; BullMQ TTL release job (BR-PLT-01).

## Acceptance Criteria
- **AC-UC009-01:** Given a cart with 5 vendors' items, when adding from a 6th store, then `MAX_VENDORS_EXCEEDED` is returned (BR-CRT-01).
- **AC-UC009-02:** Given an item added, when 15 minutes elapse, then its stock reservation is released automatically (BR-CRT-02).
- **AC-UC009-03:** Given two guests' race on the last unit, when both submit, then exactly one reservation succeeds (BR-CAT-07).
