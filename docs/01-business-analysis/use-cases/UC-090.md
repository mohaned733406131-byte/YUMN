# UC-090 — View a User's Profile and Active Sessions

## Header Info
- **Use Case ID:** UC-090
- **Title:** View a User's Profile and Active Sessions
- **Actor:** Admin (ACT-04) — user administration scope
- **Trigger:** Admin opens a user row from the directory (UC-089)
- **Priority:** P1
- **Goal:** Inspect one user's full profile, role set, session count and recent privileged actions before deciding on an account action.
- **Preconditions:** Admin or Moderator authenticated (API-ADM-002); the target user exists.

## Main Scenario
1. Admin opens a user → `GET /admin/users/{id}` (API-ADM-002).
2. System returns the profile: roles, active-session count, linked store and KYC projection, the fixed `assignableRoles` catalog, and recent audit actions (`at`, `action`, `actorId`).
3. Admin weighs session pressure and recent actions to choose between suspension (UC-091), reactivation (UC-092) or a role change (UC-037).
4. Reaching into privileged account data is itself recorded in the append-only audit trail (BR-PLT-06).
5. Read-only: no profile, role or status changes here (FR-003).

## Alternative Scenarios
- **A1 — Vendor owner:** The profile carries a store projection; Admin jumps to the store detail (UC-094) from the same screen.
- **A2 — Moderator read:** Moderator opens the profile read-only (API-ADM-002 roles) with no assignment or role affordances.

## Exception Scenarios
- **E1 — Permission denied:** Non-staff → `403 FORBIDDEN`; unknown id → `404 NOT_FOUND` so existence is never leaked.
- **E2 — No history:** New account → zero sessions and empty recent actions render as empty states.
- **E3 — Concurrent action:** Another admin suspends the user meanwhile → refetch shows `SUSPENDED`; session counts refresh on reload.
- **E4 — Trail too large:** Only the count and recent actions are projected here; the full history is paged in UC-036 (audit log).

## Postconditions
- The profile view is displayed; account state unchanged (FR-003).
- Admin holds the evidence needed for the follow-up action.

## Business Rules Applied
- BR-PLT-06

## Related Requirements
- FR-003 (User & Profile Management)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN`/`MODERATOR` read; role and scope writes belong to UC-037, UC-091, UC-092.
- **Data involved:** User profile, active-session count, store/KYC projection, recent audit actions.
- **External dependencies:** Session store (count projection); audit log (read).

## Acceptance Criteria
- **AC-UC090-01:** Given a valid user id, when opened, then roles, active-session count and store/KYC projection return.
- **AC-UC090-02:** Given a new account, when opened, then empty session and history states render without error.
- **AC-UC090-03:** Given a non-existent id, when requested, then `404 NOT_FOUND` is returned with no existence leak.
- **AC-UC090-04:** Given an admin opens the profile, when served, then an audit entry records the privileged access (BR-PLT-06).
