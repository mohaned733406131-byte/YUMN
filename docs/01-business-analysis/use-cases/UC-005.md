# UC-005 — Manage Addresses

## Header Info
- **Use Case ID:** UC-005
- **Title:** Manage Addresses
- **Actor:** Customer (ACT-01)
- **Trigger:** User opens "My Addresses" or reaches the address step of checkout (UC-011)
- **Priority:** P1
- **Goal:** Maintain up to 10 delivery addresses (governorate/district, street, landmark, phone) with one default.
- **Preconditions:** User is authenticated (UC-003); domestic Yemen addresses only (C-17).

## Main Scenario
1. User opens address book → system `GET /addresses` returns own addresses only (ownership scoping, DOC-OVR-007).
2. User taps "Add address" and fills governorate, district, street, optional landmark, recipient phone → client `POST /addresses`.
3. System validates required fields, address count ≤10 (`MAX_ADDRESSES_REACHED` beyond), and zone eligibility against shipping zones (FR-015).
4. System stores the address; if it is the first one it becomes default → audit-light profile update (BR-PLT-06 for privileged/profile changes).
5. User may set default (`PUT /addresses/{id}/default`), edit (`PUT /addresses/{id}`), or delete (`DELETE /addresses/{id}`).
6. UI renders all labels/inputs RTL in Arabic by default with English parity (BR-PLT-05, C-24).

## Alternative Scenarios
- **A1 — Address used by an active order:** Delete requested → system blocks deletion while referenced by a non-terminal order; user may still edit the label details.
- **A2 — Out-of-zone district:** Selected district has no shipping zone (C-17) → validation error before save; user picks another district.
- **A3 — Default address removed:** Deleted address was default → system promotes the oldest remaining address to default.

## Exception Scenarios
- **E1 — Concurrent edit:** Two devices edit the same address → optimistic version conflict returns `409`; client reloads latest before retry.
- **E2 — Network failure on save:** Request times out → client shows retry; idempotent create prevents duplicate rows on retry (BR-PLT-03).
- **E3 — Validation server drift:** Client-side checks pass but server rejects → server message shown verbatim; nothing persisted.

## Postconditions
- Address book reflects ≤10 addresses with exactly one default (or empty).
- No change to wallet, cart, or orders.
- Deleted addresses are removed from future checkout choices; historical orders keep their snapshot.

## Business Rules Applied
- BR-PLT-03, BR-PLT-05, BR-PLT-06

## Related Requirements
- FR-003 (User & Profile Management — addresses ≤10)

## Permissions / Data / External Dependencies
- **Permissions:** Customer owns and may only CRUD own addresses (DATA-REQ-008); no cross-customer access.
- **Data involved:** Address records (PII — classified per DATA-REQ-002).
- **External dependencies:** Shipping zone table (B08) for eligibility checks.

## Acceptance Criteria
- **AC-UC005-01:** Given 10 saved addresses, when the user adds an 11th, then `MAX_ADDRESSES_REACHED` is returned.
- **AC-UC005-02:** Given a first address, when saved, then it is automatically set as default.
- **AC-UC005-03:** Given another customer's address ID, when accessed via API, then the request is denied (ownership/IDOR check).
