# UC-131 — Run the Vendor Health Report

## Header Info
- **Use Case ID:** UC-131
- **Title:** Run the Vendor Health Report
- **Actor:** Admin (ACT-04)
- **Trigger:** Operations want a platform-wide view of vendor/store condition for a period
- **Priority:** P2
- **Goal:** Produce a read-only vendor health report with labeled totals covering store status, KYC posture, and exposure.
- **Preconditions:** Admin authenticated with analytics-read permission (ACT-04); date range selected; vendor/store data exists for the period.

## Main Scenario
1. Admin opens the reports console and selects family `vendors` with a date range → client `GET /admin/reports/vendors` (conceptual touchpoint for the platform report families).
2. System queues the computation on the analytics queue named per the `{block}.{entity}.{action}` convention (BR-PLT-01).
3. System returns rows per vendor/store: status mix (pending/active/suspended), KYC posture, product counts, and open-case exposure for the period.
4. Every total carries exact/estimate metadata so aggregates from rollups are labeled.
5. Admin filters and compares periods to spot deteriorating vendors (rising suspensions, stalled KYC, growing open exposure).
6. The run is read-only — actions against a specific vendor (suspend, KYC decision) happen in their own admin use cases, not from the report.

## Alternative Scenarios
- **A1 — Filter by segment:** admin narrows to new vendors in the period → subset projection of the same family.
- **A2 — Estimate before rollup:** heavy aggregates land before nightly backfill → labeled as estimates until refreshed.
- **A3 — Moderator read:** Moderator may read the family (report access includes MODERATOR) while export stays Admin-only (UC-086).
- **A4 — Empty period:** no vendor activity in range → zero rows with exact zero totals.

## Exception Scenarios
- **E1 — Invalid parameters:** malformed range or unknown family → `VALIDATION_ERROR`, no data.
- **E2 — Empty queue:** no vendors match the filters → friendly empty state, not a failure.
- **E3 — Permission denied:** caller without analytics scope → `403 FORBIDDEN`.
- **E4 — Job delayed:** computation queued → client waits/retries; the job remains on its named queue (BR-PLT-01).

## Postconditions
- Vendor health report delivered with labeled totals; no vendor or store state changed.
- Admin has a period-comparable read of platform vendor condition.

## Business Rules Applied
- BR-PLT-01

## Related Requirements
- FR-007 (Vendor Onboarding & KYC), FR-018 (Analytics & Reporting)

## Permissions / Data / External Dependencies
- **Permissions:** Admin analytics-read; Moderator read for families, export Admin-only (UC-086).
- **Data involved:** Vendor/store aggregates, KYC posture counts, exposure metrics, totals metadata.
- **External dependencies:** Analytics report queue (B11); vendor/KYC read models (B03).

## Acceptance Criteria
- **AC-UC131-01:** Given family `vendors` and a date range, when run, then vendor/store rows for that family return.
- **AC-UC131-02:** Given a report job, when queued, then it lands on the `{block}.{entity}.{action}` analytics queue (BR-PLT-01).
- **AC-UC131-03:** Given aggregates pre-backfill, when rendered, then totals carry exact/estimate labels.
- **AC-UC131-04:** Given an unknown family parameter, when submitted, then `VALIDATION_ERROR` returns with no rows.
