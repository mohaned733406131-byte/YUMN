# UC-053 — Roll Over Payouts Below the 1,000 YER Minimum

## Header Info
- **Use Case ID:** UC-053
- **Title:** Roll Over Payouts Below the 1,000 YER Minimum
- **Actor:** System (ACT-07) — payout batch threshold rule (no interactive login)
- **Trigger:** The payout batch job finds a released payable below 1,000 YER (FR-014)
- **Priority:** P2
- **Goal:** Defer sub-threshold payables to future batches instead of paying or discarding them, until the accumulated amount reaches 1,000 YER.
- **Preconditions:** Payout batch is running (UC-052); the payable's released amount is known and tracked per vendor.

## Main Scenario
1. During `b07.payout.batch` the job evaluates an eligible payable amount against the 1,000 YER minimum (FR-014).
2. The amount is below the minimum → the payout is marked `ROLLED_OVER` and excluded from this execution (BR-ESC-05).
3. The amount stays credited to the vendor's payable, accumulating with subsequent escrow releases (FR-014).
4. On a later batch run the accumulated eligible amount is re-evaluated (FR-014).
5. Once the total reaches 1,000 YER the vendor passes the threshold and the payout executes in that batch (BR-ESC-05).
6. The rollover state is visible to the vendor in the finance overview as pending payout below minimum (FR-014).

## Alternative Scenarios
- **A1 — Accumulation crosses the threshold:** the next batch pays the full accumulated amount, including the rolled-over portion (BR-ESC-05).
- **A2 — Vendor requests payout early:** a request below the minimum returns `PAYOUT_BELOW_MINIMUM`; the rollover path still applies (FR-014).
- **A3 — Refund draws the payable down:** a refund reduces the balance before it matures → the payable continues rolling over at its new lower amount (FR-014).

## Exception Scenarios
- **E1 — Long-term below minimum:** a low-volume vendor stays under 1,000 YER indefinitely → no payout executes, but no funds are lost — the payable keeps accumulating (BR-ESC-05).
- **E2 — Job fails during rollover marking:** transaction rolls back → the payable is unchanged and simply re-evaluated on the next run (FR-014).
- **E3 — Store suspended while rolling over:** the eligibility gate skips the vendor entirely; the rollover resumes when reinstated (FR-014).

## Postconditions
- Success: sub-threshold payables marked `ROLLED_OVER`, amounts remain credited to payable, no payout executed below 1,000 YER.
- Failure: no state change; the payable is re-evaluated on the next batch window.

## Business Rules Applied
- BR-ESC-05

## Related Requirements
- FR-014 (Escrow, Commission & Vendor Payouts)

## Permissions / Data / External Dependencies
- **Permissions:** service identity only (ACT-07); vendors can view rollover state but cannot force a sub-threshold payout.
- **Data involved:** vendor payables, payout batch records, rollover amounts.
- **External dependencies:** `b07.payout.batch` queue (C-20), finance overview read model.

## Acceptance Criteria
- **AC-UC053-01:** Given an eligible payable of 700 YER, when the batch runs, then no payout executes and the amount rolls over (BR-ESC-05).
- **AC-UC053-02:** Given rolled-over amounts totaling 1,500 YER, when the next batch runs, then the full amount pays out (BR-ESC-05).
- **AC-UC053-03:** Given a rolled-over payable, when viewed by the vendor, then it shows as below-minimum pending payout (FR-014).
