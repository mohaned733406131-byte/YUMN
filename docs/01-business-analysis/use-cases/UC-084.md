# UC-084 — View the Admin Operations Dashboard

## Header Info
- **Use Case ID:** UC-084
- **Title:** View the Admin Operations Dashboard
- **Actor:** Admin (ACT-04) — platform monitoring scope
- **Trigger:** Admin signs in and lands on the admin console home (`routing.md` §6 → `/admin/dashboard`)
- **Priority:** P1
- **Goal:** See platform health at a glance — GMV, orders by state, SLA counters, queue depths and top vendors — on one screen.
- **Preconditions:** Admin or Super Admin authenticated with dashboard read access (API-ANL-006 roles `ADMIN`/`MODERATOR`); rollup jobs have produced at least one snapshot.

## Main Scenario
1. Admin opens `/[locale]/admin/dashboard` → client `GET /admin/dashboard?from=&to=` (API-ANL-006).
2. System returns the pre-aggregated object: GMV, orders by state, SLA breach counters, on-time/failed-attempt metrics, queue depths (KYC, returns, disputes, top-ups), top vendors, plus exact/estimate totals metadata.
3. Admin changes the date range → server reads the `b11.analytics.rollup` output (BR-PLT-01), refreshed on state transitions plus nightly backfill.
4. Admin clicks a queue tile → deep link into the matching queue (`GET /admin/kyc`, `GET /admin/tickets`, `GET /admin/reconciliation`).
5. The screen is read-only: no order, money or configuration state changes (FR-018, FR-020).

## Alternative Scenarios
- **A1 — Moderator subset:** Moderator opens the same aggregates (API-ANL-006 roles) but finance exports stay Admin-only (UC-086).
- **A2 — Comparison mode:** Admin compares against the previous period; trend series render from the same rollup.

## Exception Scenarios
- **E1 — Permission denied:** Session without an admin role → `403 FORBIDDEN`; the route guard is UX only and the server denies independently.
- **E2 — Empty window:** No orders in the selected range → zero-valued tiles and an empty state, never an error.
- **E3 — Concurrent activity:** Orders advance while another admin refreshes → each response is an independent point-in-time snapshot; no locks are held.
- **E4 — Stale rollup:** Nightly backfill has not landed → the previous snapshot is served and labelled as an estimate; figures are never fabricated.

## Postconditions
- Dashboard reflects the latest computed rollups; no platform data was mutated.
- Admin has current visibility into queues and breaches to prioritize work (FR-018, FR-020).

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN`/`MODERATOR` read on the dashboard object; no write scope (server-side check, `SEC-REQ-004`).
- **Data involved:** Read-only aggregates derived from the ledger and order history; no customer PII beyond store names.
- **External dependencies:** BullMQ rollup queue `b11.analytics.rollup` (BR-PLT-01).

## Acceptance Criteria
- **AC-UC084-01:** Given an authenticated admin, when `/admin/dashboard` is requested, then GMV, order-state and queue tiles all return in one object.
- **AC-UC084-02:** Given a range with no orders, when loaded, then tiles render zeros with an empty state and HTTP 200.
- **AC-UC084-03:** Given a non-admin session, when `GET /admin/dashboard` is called, then `403 FORBIDDEN` is returned.
- **AC-UC084-04:** Given a heavy aggregate, when rendered, then exact vs estimate totals carry their rollup metadata labels.
