# UC-097 — Re-Activate a Suspended Store

## Header Info
- **Use Case ID:** UC-097
- **Title:** Re-Activate a Suspended Store
- **Actor:** Admin (ACT-04) — vendor operations scope
- **Trigger:** Admin lifts a store suspension after review
- **Priority:** P1
- **Goal:** Restore a suspended store to trading with its catalog, orders and payouts unblocked and the reason recorded.
- **Preconditions:** Admin authenticated with activate permission (API-ADM-013 `ADMIN`); store is `SUSPENDED`; a reason is supplied; KYC still valid.

## Main Scenario
1. Admin opens the suspended store (UC-094) → Re-activate → mandatory reason.
2. Client `POST /admin/stores/{id}/activate` (API-ADM-013).
3. System validates KYC (`KYC_NOT_APPROVED` if invalid) then transitions `SUSPENDED → ACTIVE`, lifting the BR-VND-04 effects: products return to the storefront, orders unblock, held payouts regain eligibility.
4. The reversal writes an append-only audit entry with actor, reason and before/after state (BR-PLT-06) and the `auditId` is returned.
5. If the owner account itself is still suspended, Admin reactivates it first (UC-092).

## Alternative Scenarios
- **A1 — Owner account also suspended:** Store activation may fail until the account scope is restored (UC-092).
- **A2 — Store never suspended:** `STATE_CONFLICT`; the call is a no-op.

## Exception Scenarios
- **E1 — Permission denied:** Moderator → `403 FORBIDDEN`; nothing changes.
- **E2 — Not suspended:** `STATE_CONFLICT` and no change.
- **E3 — Concurrent suspension:** Another admin re-suspends meanwhile → conflict returned; refetch before retry.
- **E4 — KYC lapsed during suspension:** `KYC_NOT_APPROVED` → the store stays suspended until the KYC decision is refreshed (UC-031).

## Postconditions
- The store is `ACTIVE` with BR-VND-04 holds lifted, or unchanged on refusal.
- One audit entry exists for the reversal (BR-PLT-06).

## Business Rules Applied
- BR-VND-04, BR-PLT-06

## Related Requirements
- FR-007 (Vendor Onboarding & KYC)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN` only; Moderator cannot re-activate stores.
- **Data involved:** Store status, listing/order/payout flags, audit entry.
- **External dependencies:** KYC validity check; audit writer (BR-PLT-06).

## Acceptance Criteria
- **AC-UC097-01:** Given a suspended store with valid KYC, when activate is posted, then status becomes `ACTIVE` and the BR-VND-04 holds lift.
- **AC-UC097-02:** Given no reason, when posted, then `REASON_REQUIRED` returns and no state changes.
- **AC-UC097-03:** Given invalid KYC, when posted, then `KYC_NOT_APPROVED` returns and the store stays suspended.
- **AC-UC097-04:** Given the reversal, when completed, then an `auditId` returns (BR-PLT-06).
