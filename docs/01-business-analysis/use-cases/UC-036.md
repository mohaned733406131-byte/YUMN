# UC-036 — View Audit Log

## Header Info
- **Use Case ID:** UC-036
- **Title:** View Audit Log
- **Actor:** Admin (ACT-04) — platform scope; Super Admin full (UC-037); vendors see own-store scope; nobody can edit (DOC-OVR-007)
- **Trigger:** Admin opens the audit trail console for investigation
- **Priority:** P2
- **Goal:** Query append-only audit entries (actor, action, entity, before/after, IP, timestamp) for privileged and money actions.
- **Preconditions:** Admin authenticated with audit-read permission; entries exist from privileged/money actions (BR-PLT-06).

## Main Scenario
1. Admin opens Audit → client `GET /admin/audit-log?actor=&action=&entity=&from=&to=&page=…` with server-side filtering and cursor pagination.
2. System returns append-only entries (SEC-REQ-010) scoped to platform visibility; sensitive PII fields are redacted per role (DATA-REQ-002).
3. Admin drills into an entry → sees before/after values, IP, timestamp, correlation ID linking to logs/traces (NFR-014).
4. Admin exports the filtered set (CSV) for compliance — export itself is audited (BR-PLT-06).
5. Entries can be cross-checked against money actions: KYC decisions (UC-031), top-up verification (UC-034), dispute resolutions (UC-033), role changes (UC-037).

## Alternative Scenarios
- **A1 — Vendor view:** Vendor reads own-store scoped entries only (BR-VND-07 / DOC-OVR-007); cross-store entries never returned.
- **A2 — Courier view:** Courier sees own delivery scope only; read-only.
- **A3 — Retention window:** Financial audit retention ≥5 years (NFR-019); older archived entries served from cold storage if within retention.

## Exception Scenarios
- **E1 — Tampering attempt:** Any UPDATE/DELETE on audit rows is impossible at the API level (append-only, DATA-REQ-007); attempt rejected and alerted (SEC-REQ-010).
- **E2 — Over-broad query:** Query exceeds rate limits → throttled (SEC-REQ-009); large exports queued as jobs (BR-PLT-01).
- **E3 — Missing correlation:** Entry lacks correlation ID (write failure) → flagged by integrity monitoring; no entry is silently dropped.

## Postconditions
- Read-only: no config, order, or money change; export creates an audited artifact.
- Audit chain integrity preserved (SEC-REQ-010).

## Business Rules Applied
- BR-PLT-01, BR-PLT-06, BR-VND-07, BR-PAY-10

## Related Requirements
- FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Read per role scope: Admin platform, Super Admin full, Vendor/Courier own scope, Moderator none, System write-only (DOC-OVR-007).
- **Data involved:** Audit entries (append-only), exports; PII redaction per DATA-REQ-002.
- **External dependencies:** Log/trace pipeline (NFR-014); export jobs (BullMQ, BR-PLT-01).

## Acceptance Criteria
- **AC-UC036-01:** Given an admin filter by action, when queried, then matching entries return with before/after values (BR-PLT-06).
- **AC-UC036-02:** Given any API call attempting to modify an audit row, when issued, then it is rejected (DATA-REQ-007).
- **AC-UC036-03:** Given a vendor, when querying audit logs, then only own-store entries are visible (BR-VND-07).
