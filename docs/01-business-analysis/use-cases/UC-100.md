# UC-100 — Monitor the Support Ticket Queue

## Header Info
- **Use Case ID:** UC-100
- **Title:** Monitor the Support Ticket Queue
- **Actor:** Admin (ACT-04) — support operations scope
- **Trigger:** Admin opens Support → Tickets in the console
- **Priority:** P1
- **Goal:** See every support ticket with ownership, source and overdue flags so nothing sits unanswered.
- **Preconditions:** Admin or Moderator authenticated with queue access (API-ADM-039); tickets exist (raised by UC-014 or auto-created by the lockout flow).

## Main Scenario
1. Admin opens the queue → `GET /admin/tickets?page=&pageSize=&status=&category=&source=AUTO|MANUAL&sort=updatedAt_asc` (API-ADM-039).
2. System returns rows: ticket number, category, source (`AUTO`/`MANUAL`), status, user, linked order, assignee and overdue flag.
3. Auto-created delivery-lockout tickets (`source=AUTO`) appear with their linked order timeline (rel UC-014 step3 — customer sees the ticket enter the queue).
4. Admin sorts by `overdue` or `updatedAt_asc` to triage, then opens a ticket to claim (UC-101) or reply (UC-102).
5. Staff actions taken from this console are privileged and recorded in the append-only audit trail (BR-PLT-06).

## Alternative Scenarios
- **A1 — Moderator view:** Moderator reads the same queue (API-ADM-039 roles) and replies or resolves within moderation scope.
- **A2 — AUTO filter:** Isolate system-generated lockout tickets for backlog and SLA review.

## Exception Scenarios
- **E1 — Permission denied:** Non-staff session → `403 FORBIDDEN`.
- **E2 — Empty queue:** No tickets → zero-state "all clear" with HTTP 200, not an error.
- **E3 — Concurrent claim:** Another admin claims a ticket while the list is open → the stale row fails with `TICKET_STATE_CONFLICT` on action; refresh updates the assignee.
- **E4 — Overdue backlog:** Rows past their response window keep the `overdue` flag until resolved, so the backlog stays visible on the console.

## Postconditions
- The queue reflects request-time state; viewing mutates nothing (FR-020).
- A target ticket is identified for claim, reply or resolve.

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN`/`MODERATOR` read; writes belong to UC-101, UC-102, UC-103.
- **Data involved:** Support tickets, linked orders, assignee and overdue flags.
- **External dependencies:** Notification channels (customer updates); audit writer (BR-PLT-06).

## Acceptance Criteria
- **AC-UC100-01:** Given tickets in all statuses, when the queue is loaded, then rows return with source, status, assignee and overdue flag.
- **AC-UC100-02:** Given zero tickets, when loaded, then an empty state returns with HTTP 200.
- **AC-UC100-03:** Given an auto-created lockout ticket, when listed, then `source=AUTO` shows with the linked order id (rel UC-014).
- **AC-UC100-04:** Given a non-staff session, when requested, then `403 FORBIDDEN` is returned.
