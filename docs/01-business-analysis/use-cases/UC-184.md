# UC-184 — Track the KYC Case Status and SLA Age

## Header Info
- **Use Case ID:** UC-184
- **Title:** Track the KYC Case Status and SLA Age
- **Actor:** Vendor (ACT-02)
- **Trigger:** The vendor wants to know where the KYC case stands and how much decision-SLA time remains
- **Priority:** P1
- **Goal:** Monitor the KYC case status, decision details, and SLA age without contacting support.
- **Preconditions:** Vendor authenticated; a KYC case exists (or the empty onboarding state is shown); view is read-only.

## Main Scenario
1. Vendor opens onboarding → client `GET /vendor/onboarding/status` (`API-VND-001`) returns step, `kycStatus`, `submittedAt`, `slaDueAt`, `resubmissionAllowed`.
2. Vendor opens the case → client `GET /vendor/kyc` (`API-VND-005`) returns status, the uploaded document list, and the decision block when present.
3. System computes SLA age = now − `submittedAt` and the time left against the 48-hour deadline (`slaDueAt`, BR-VND-03).
4. While the case is under review the screen is read-only; new document uploads are refused (`KYC_IN_REVIEW`).
5. When a decision lands the vendor sees outcome, reason, `decidedAt`, `decidedBy` and is notified; a rejection exposes the resubmission path (BR-VND-03).

## Alternative Scenarios
- **A1 — SLA breached:** `now > slaDueAt` with no decision → the case shows as overdue and sits in the admin escalation queue (BR-VND-03).
- **A2 — Decision received:** outcome and reason shown; `APPROVED` unlocks the next onboarding step, `REJECTED` offers resubmission (BR-VND-03).

## Exception Scenarios
- **E1 — No case yet:** `GET /vendor/kyc` → `NOT_FOUND`; the UI shows the empty onboarding state with a start action.
- **E2 — Decision lands concurrently:** the admin decides while the screen is open → refresh replaces the pending view with the outcome; no vendor action is lost.
- **E3 — Read failure:** network error on the status call → retry; both calls are idempotent reads, nothing changes.

## Postconditions
- No state change — status, decision data, and SLA age are accurately displayed (read-only).
- The vendor knows whether the 48-h decision SLA is running, breached, or decided (BR-VND-03).

## Business Rules Applied
- BR-VND-03

## Permissions / Data / External Dependencies
- **Permissions:** Vendor reads own case only; the decision belongs to Admin (ACT-04).
- **Data involved:** KYC case status, document list, decision block, SLA timestamps.
- **External dependencies:** notification channels for the decision message.

## Acceptance Criteria
- **AC-UC184-01:** Given a submitted case, when opened, then status, `submittedAt`, and `slaDueAt` are displayed (BR-VND-03).
- **AC-UC184-02:** Given 48 h elapsed without a decision, when viewed, then the case is marked overdue and sits in the admin escalation queue (BR-VND-03).
- **AC-UC184-03:** Given a decided case, when opened, then outcome, reason, `decidedAt`, and `decidedBy` are shown.
- **AC-UC184-04:** Given no case exists, when opened, then the empty onboarding state is shown without an error crash.
