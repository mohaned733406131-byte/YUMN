# UC-001 — Browse Marketplace as Guest

## Header Info
- **Use Case ID:** UC-001
- **Title:** Browse Marketplace as Guest
- **Actor:** Customer (ACT-01) — unauthenticated guest
- **Trigger:** Guest opens the storefront (web or mobile app home screen)
- **Priority:** P1
- **Goal:** Let a guest explore categories, stores, and ACTIVE products without creating an account.
- **Preconditions:** Platform is reachable; catalog data exists; guest cart is held client-side (BR-CRT-03).

## Main Scenario
1. Guest opens home → system `GET /home` returns banners, top categories, featured/deal merchandising, and locale default Arabic RTL (BR-PLT-05, C-24).
2. Guest opens a category → system `GET /categories/{slug}` returns sub-categories (tree depth ≤5, BR-CAT-03) and a paginated product list.
3. Guest scrolls the product list → system `GET /products` returns only ACTIVE products of non-suspended stores (BR-CAT-06, BR-VND-04), each showing Arabic name, YER price, stock badge, store name.
4. Guest opens a store page → system `GET /stores/{slug}` returns storefront profile, rating summary (BR-REV-05) and its products.
5. Guest taps "add to cart" → item is added to the client-side guest cart (no login yet, BR-CRT-03); a login gate appears only when proceeding to checkout (permission matrix, DOC-OVR-007).
6. Guest may switch locale (ar default ↔ en) at any time; all strings come from localized templates (BR-PLT-05, C-24).

## Alternative Scenarios
- **A1 — Deep link:** Guest arrives via shared product link → system serves the product detail view directly (same guards as step 3).
- **A2 — Guest search:** Guest types in the search box → flow continues as UC-006 (Search Products).
- **A3 — Empty category:** No ACTIVE products in category → system shows localized empty state with suggestions; no error.

## Exception Scenarios
- **E1 — Catalog service degraded:** Search/cache unavailable → system serves cached browse content and degrades gracefully (NFR-007); no blank pages.
- **E2 — Network failure on client:** Request times out → client keeps last rendered content and shows a retry affordance; no partial data corruption.
- **E3 — Suspended vendor mid-browse:** Store suspended after page load (BR-VND-04) → product detail fetch returns not-found; list refresh removes it.

## Postconditions
- No account, session, or OTP is created; guest remains unauthenticated.
- Guest cart (if used) persists client-side and merges on later login (BR-CRT-03).
- No order, reservation, or ledger entry exists.

## Business Rules Applied
- BR-CAT-03, BR-CAT-04, BR-CAT-06, BR-CRT-03, BR-PLT-05, BR-REV-05, BR-VND-04

## Related Requirements
- FR-004 (Product Catalog Management), FR-009 (Search & Discovery)

## Permissions / Data / External Dependencies
- **Permissions:** Public/read-only; no authentication required; no write endpoints reachable.
- **Data involved:** Products, categories, stores, banners, ratings (read-only).
- **External dependencies:** Redis cache for catalog reads (NFR-004); CDN for images.

## Acceptance Criteria
- **AC-UC001-01:** Given a guest, when home loads, then categories and products render with no login prompt.
- **AC-UC001-02:** Given a suspended vendor's product, when the guest browses or refreshes the list, then the product is not shown (BR-CAT-06, BR-VND-04).
- **AC-UC001-03:** Given default locale Arabic, when home renders, then UI is RTL Arabic with a working English toggle (C-24).
