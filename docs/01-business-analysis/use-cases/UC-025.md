# UC-025 — View Available Deliveries

## Header Info
- **Use Case ID:** UC-025
- **Title:** View Available Deliveries
- **Actor:** Delivery Provider / Courier (ACT-03)
- **Trigger:** Courier opens the deliveries screen or receives an assignment push
- **Priority:** P1
- **Goal:** Let a courier browse open delivery offers in their zone plus their active jobs, without any GPS/location exchange (C-16).
- **Preconditions:** Courier authenticated and enabled for a shipping zone; offers exist for `READY_FOR_PICKUP` sub-orders (BR-SHP-04).

## Main Scenario
1. Courier opens the app → client `GET /deliveries/available?zone=…` returns offers: package weight band, pickup point, drop-off district/address (no live customer position tracking, BR-SHP-05), offered fee, deadline.
2. System only shows offers for the courier's eligible zones (BR-SHP-04); first-accept wins — availability list refreshes optimistically (DOC-SA-010).
3. Courier switches to "My deliveries" → client `GET /deliveries/mine` returns assigned, picked-up, in-transit, out-for-delivery jobs with their states (BR-ORD-09 scope).
4. Courier opens a job → detail shows pickup contact, delivery contact, package notes, and — once `OUT_FOR_DELIVERY` — the code-entry screen entry point (UC-030).
5. All text localized ar/en (BR-PLT-05); courier identity on each state change is recorded (BR-SHP-07).

## Alternative Scenarios
- **A1 — No offers:** Empty state with next-refresh hint; courier keeps existing jobs.
- **A2 — Offer taken by someone else:** Refresh shows the job removed → "already assigned" notice on open (BR-SHP-04 optimistic lock).
- **A3 — Return pickup job:** Approved return pickups (UC-021) appear in the same offer list with a "return" marker.

## Exception Scenarios
- **E1 — List request fails:** Network error → cached last list shown with retry; no local state mutation.
- **E2 — Zone revoked:** Courier disabled by admin → available list returns empty; active jobs remain visible with guidance to contact dispatch.
- **E3 — Stale offer deep link:** Opening an expired job → `404/409` with "no longer available"; nothing changes.

## Postconditions
- Read-only: no assignment, state, or money change (accepting happens in UC-026).
- Courier sees only zone-eligible and own deliveries (scoping per DOC-OVR-007).

## Business Rules Applied
- BR-SHP-04, BR-SHP-05, BR-SHP-07, BR-ORD-09, BR-PLT-05

## Related Requirements
- FR-015 (Shipping & Delivery)

## Permissions / Data / External Dependencies
- **Permissions:** Courier reads own/eligible deliveries only; Admin dispatch view exists (DOC-OVR-007); no GPS data ever collected (BR-SHP-05, C-16).
- **Data involved:** Delivery offers, assignments, addresses (PII — DATA-REQ-002), fees.
- **External dependencies:** Assignment engine (INT-REQ-005); push notifications (B10).

## Acceptance Criteria
- **AC-UC025-01:** Given a courier in zone A, when listing offers, then only zone-A jobs appear (BR-SHP-04).
- **AC-UC025-02:** Given the platform contract, when the app runs, then no location permission/API is requested (C-16, BR-SHP-05).
- **AC-UC025-03:** Given another courier's active job, when the courier opens "My deliveries", then it is not listed (BR-ORD-09).
