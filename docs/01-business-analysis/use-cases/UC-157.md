# UC-157 — Browse Deals and the Promotion Gallery

## Header Info
- **Use Case ID:** UC-157
- **Title:** Browse Deals and the Promotion Gallery
- **Actor:** Customer (ACT-01)
- **Trigger:** Customer opens the deals route or the promotions entry point
- **Priority:** P1
- **Goal:** List every currently active platform and store promotion with its terms so the customer can pick a code.
- **Preconditions:** Deals route `/{locale}/deals` is public (routing.md §2); campaigns are admin/vendor-authored (FR-019).

## Main Scenario
1. Client calls `GET /promotions?scope=PLATFORM|STORE` (API-CNT-003).
2. System returns active coupons/promotions: `code`, `scope`, bilingual `label`, `discountPercent`, optional `maxDiscount`, `startsAt`, `endsAt`, `terms` (FR-019).
3. Only campaigns inside their validity window are listed; every window is ≤90 days (BR-PRM-01).
4. Customer copies a code; the discount itself is applied later at checkout, where the server validates the coupon — the gallery never applies discounts client-side.
5. Labels render in the current locale — Arabic default with English parity (BR-PLT-05, verified applicable for localized content reads).

## Alternative Scenarios
- **A1 — Scope filter:** customer switches between platform-wide deals and store-scoped deals (`scope` parameter).
- **A2 — Campaign just started or ended:** rows enter and leave the gallery automatically as `startsAt`/`endsAt` pass (BR-PRM-01).

## Exception Scenarios
- **E1 — Feed unavailable:** cached copy serves (this read is cacheable) with a retry affordance; no partial list is fabricated.
- **E2 — Invalid query parameters:** `VALIDATION_ERROR` → client falls back to default parameters (FR-019).

## Postconditions
- Success: current promotions displayed; no coupon state changed — creation and disablement are admin-owned.
- Failure: empty or cached gallery shown; customer may retry.

## Business Rules Applied
- BR-PRM-01

## Related Requirements
- FR-019 (Content & Promotions)

## Permissions / Data / External Dependencies
- **Permissions:** public read of active campaigns only; disabled or expired codes never appear.
- **Data involved:** coupon/promotion rows (code, window, discount, terms).
- **External dependencies:** page cache for the gallery read.

## Acceptance Criteria
- **AC-UC157-01:** Given an active platform coupon, when the gallery loads, then it is listed with code, label and end date (BR-PRM-01).
- **AC-UC157-02:** Given a campaign whose `endsAt` has passed, when the gallery loads, then it is absent (BR-PRM-01).
- **AC-UC157-03:** Given a copied code, when validated at checkout, then the server computes the discount — the client never does.
