# UC-094 — View Store Detail and Open Exposure

## Header Info
- **Use Case ID:** UC-094
- **Title:** View Store Detail and Open Exposure
- **Actor:** Admin (ACT-04) — vendor operations scope
- **Trigger:** Admin opens a store from the directory (UC-093)
- **Priority:** P1
- **Goal:** Assess one store's configuration and open exposure — products, open orders, open returns and disputes — before deciding its lifecycle.
- **Preconditions:** Admin or Moderator authenticated (API-ADM-010); the target store exists.

## Main Scenario
1. Admin opens a store → `GET /admin/stores/{id}` (API-ADM-010).
2. System returns status, KYC link, commission tier, product count, open orders, open returns and KYC status for that store only (BR-VND-07 — no cross-store figures).
3. Admin reviews exposure: heavy open caseload → route to dispute/return handling (UC-033, UC-125); light caseload → routine monitoring.
4. Admin picks the lifecycle action from this screen: approve (UC-095), suspend (UC-096) or re-activate (UC-097).
5. The view itself is read-only (FR-008).

## Alternative Scenarios
- **A1 — Suspended store:** Detail shows held payouts and blocked orders so Admin can evaluate re-activation (UC-097).
- **A2 — Moderator read:** Moderator opens the detail read-only (API-ADM-010 roles).

## Exception Scenarios
- **E1 — Permission denied:** Non-staff → `403 FORBIDDEN`; unknown id → `404 NOT_FOUND`.
- **E2 — No exposure:** Brand-new store → all counts zero, rendered as empty states.
- **E3 — Concurrent case movement:** Orders or returns advance while the page is open → counts are a point-in-time snapshot, refreshed on reload.
- **E4 — KYC decision pending:** `kycStatus` shows pending/overdue → Admin defers the lifecycle action to the KYC queue (UC-031).

## Postconditions
- Store detail and exposure are displayed; nothing changed (FR-008).
- A lifecycle decision is prepared or explicitly deferred.

## Business Rules Applied
- BR-VND-07

## Related Requirements
- FR-008 (Store Management & Storefront Configuration)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN`/`MODERATOR` read; writes belong to UC-095, UC-096, UC-097.
- **Data involved:** Store detail, commission tier, product and open-case counts (single-store scope).
- **External dependencies:** Store, order and returns services (count projections).

## Acceptance Criteria
- **AC-UC094-01:** Given a store id, when opened, then status, KYC link, commission tier and open-case counts return.
- **AC-UC094-02:** Given two stores, when compared, then counts never include rows from the other store (BR-VND-07).
- **AC-UC094-03:** Given a brand-new store, when opened, then all counts are zero with no error.
- **AC-UC094-04:** Given an unknown id, when requested, then `404 NOT_FOUND` is returned.
