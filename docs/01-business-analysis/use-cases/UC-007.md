# UC-007 — View Product Detail

## Header Info
- **Use Case ID:** UC-007
- **Title:** View Product Detail
- **Actor:** Customer (ACT-01) — guest or authenticated
- **Trigger:** User opens a product from browse/search results
- **Priority:** P1
- **Goal:** Show complete, trustworthy product information (media, price, variants, stock, policy, reviews) to support a purchase decision.
- **Preconditions:** Product is ACTIVE and its store is not suspended (BR-CAT-06, BR-VND-04).

## Main Scenario
1. User opens the product → client `GET /products/{slug}`.
2. System returns Arabic name (+ English if present), description, up to 10 images ≤5 MB jpg/png/webp with EXIF stripped (BR-CAT-08), category path, store card with follow button (UC-008).
3. System returns price in integer YER with optional sale price < original price (BR-CAT-04) and VAT-inclusive hint per breakdown rules (BR-FIN-01).
4. If variants exist, system returns ≤5 dimensions / ≤50 combinations with per-SKU stock and price (BR-CAT-02); user selects a combination.
5. System shows available stock (integer ≥0), `isReturnable` flag and `returnPeriodDays` (C-11), shipping fee estimate for the user's zone (BR-SHP-01).
6. System returns visible reviews (1–5 integer, ≤5 images, BR-REV-03) sorted by date with store rating summary (BR-REV-05).
7. User taps "Add to cart" → continues as UC-009.

## Alternative Scenarios
- **A1 — Out of stock:** Stock = 0 → "Out of stock" state; add-to-cart disabled; product remains visible.
- **A2 — Non-returnable product:** `isReturnable = false` → return policy shown as non-returnable; checkout still allowed.
- **A3 — Variant price spread:** Selected variant differs in price → displayed price updates to the variant's SKU price before add-to-cart.

## Exception Scenarios
- **E1 — Product deleted mid-session:** Soft-delete after load (BR-CAT-06) → next fetch returns not-found; client shows removed state.
- **E2 — Image CDN failure:** Image request fails → placeholder renders; other fields unaffected.
- **E3 — Stale price cached:** Price changed since page load → server recalculation at add-to-cart/checkout surfaces the new price for re-confirmation (BR-CRT-04).

## Postconditions
- Read-only: no cart, order, or wallet change until the user acts.
- Review list excludes hidden/moderated reviews (BR-REV-04).

## Business Rules Applied
- BR-CAT-02, BR-CAT-04, BR-CAT-06, BR-CAT-08, BR-FIN-01, BR-REV-03, BR-REV-04, BR-REV-05, BR-SHP-01, BR-VND-04

## Related Requirements
- FR-004 (Product Catalog Management), FR-006 (Reviews & Ratings)

## Permissions / Data / External Dependencies
- **Permissions:** Public read of publishable products; hidden reviews never returned.
- **Data involved:** Product, variants, images, stock, policy, reviews, rating aggregates.
- **External dependencies:** Image storage/CDN; shipping zone calculator (B08).

## Acceptance Criteria
- **AC-UC007-01:** Given a product with 5 variants, when opened, then each selectable combination shows its own price and stock (BR-CAT-02).
- **AC-UC007-02:** Given a moderated (hidden) review, when the page renders, then it is not displayed (BR-REV-04).
- **AC-UC007-03:** Given price changed after page load, when added to cart, then the new price is shown for re-confirmation (BR-CRT-04).
