# UC-031 — Approve / Reject Vendor KYC

## Header Info
- **Use Case ID:** UC-031
- **Title:** Approve / Reject Vendor KYC
- **Actor:** Admin (ACT-04)
- **Trigger:** A vendor KYC submission enters the admin review queue
- **Priority:** P0
- **Goal:** Decide a KYC case (APPROVED/REJECTED) within 48 hours, unlocking or blocking vendor capabilities.
- **Preconditions:** Admin authenticated with KYC-review permission (scoped RBAC, DOC-OVR-007); case status `SUBMITTED` (UC-015).

## Main Scenario
1. Admin opens the KYC queue → client `GET /admin/kyc` lists pending cases with age against the 48-hour SLA (BR-VND-03).
2. Admin opens a case → views applicant profile, store data, and uploaded documents (PII access is permission-gated and audited, DATA-REQ-002, BR-PLT-06).
3. Admin approves → client `POST /admin/kyc/{id}/approve`; system sets KYC = APPROVED, notifies the vendor (BR-NTF-01).
4. Vendor gains publishing rights (BR-VND-01) and payout eligibility (BR-ESC-06); storefront onboarding screen shows APPROVED.
5. Or Admin rejects with mandatory reason → KYC = REJECTED; vendor may resubmit (BR-VND-03); notification includes the reason.
6. System writes an append-only audit entry (actor, action, before/after, IP, timestamp — BR-PLT-06, SEC-REQ-010).

## Alternative Scenarios
- **A1 — Suspension instead:** For already-approved vendors, Admin suspends (BR-VND-04) → products hidden, orders frozen, payouts held.
- **A2 — Re-verification:** Admin requests additional documents → case returns to `SUBMITTED` with note; SLA clock noted (BR-VND-03).
- **A3 — Super Admin oversight:** Super Admin may override any KYC decision (UC-037 scope, DOC-OVR-007).

## Exception Scenarios
- **E1 — SLA breach risk:** Case ages toward 48 h → queue highlights and escalates; breach flagged (BR-VND-03).
- **E2 — Document unreadable/corrupt:** Reviewer rejects with "invalid documents" reason; vendor resubmits (BR-VND-03).
- **E3 — Concurrent decisions:** Two admins act on the same case → optimistic lock; one wins, other gets `409` (DOC-SA-010 §5 pattern).

## Postconditions
- KYC is APPROVED or REJECTED with audit trail; vendor notified.
- Publishing/payout gates reflect the new status immediately (BR-VND-01, BR-ESC-06).

## Business Rules Applied
- BR-VND-01, BR-VND-03, BR-VND-04, BR-ESC-06, BR-NTF-01, BR-PLT-06

## Related Requirements
- FR-007 (Vendor Onboarding & KYC), FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** Admin KYC scope (ACT-04); Super Admin full (ACT-05); vendors submit only (DOC-OVR-007).
- **Data involved:** KYC documents (highly classified PII), decision records, audit log.
- **External dependencies:** File storage/scanner (SEC-REQ-011); notification channels (B10).

## Acceptance Criteria
- **AC-UC031-01:** Given an approved KYC, when the vendor publishes, then publishing succeeds (BR-VND-01).
- **AC-UC031-02:** Given a rejection, when the vendor resubmits, then a new decision cycle starts within a fresh 48 h SLA (BR-VND-03).
- **AC-UC031-03:** Given a decision, when recorded, then an append-only audit row with before/after exists (BR-PLT-06).
