# UC-087 — Review the Daily Reconciliation Result

## Header Info
- **Use Case ID:** UC-087
- **Title:** Review the Daily Reconciliation Result
- **Actor:** Admin (ACT-04) — finance scope
- **Trigger:** Admin opens Finance → Reconciliation after the nightly run
- **Priority:** P0
- **Goal:** Review ledger, wallet, escrow and payable totals against provider statements and spot unresolved mismatches.
- **Preconditions:** Admin with finance read access (API-ANL-009 `ADMIN`); the daily job has produced a result for the requested date.

## Main Scenario
1. Admin opens `/[locale]/admin/finance/reconciliation` → `GET /admin/reconciliation?date=&status=` (API-ANL-009).
2. System returns one row per source (`MFLOOS`, `ONECASH`, `BANK`, `INTERNAL`) with ledger total, provider total, delta in integer YER and `MATCHED`/`MISMATCH`, plus totals: mismatch count and unresolved YER.
3. Rows are produced by the nightly job (queue `b07.ledger.daily-reconcile`) enforcing Σ ledger entries balance and wallet + escrow + payable = provider statements (BR-ESC-08, BR-FIN-03).
4. Admin filters `status=MISMATCH`, drills into the delta and ledger references, and records findings for finance follow-up.
5. The screen mutates no money state — figures are read straight from the append-only ledger (FR-013).

## Alternative Scenarios
- **A1 — All matched:** Every source returns `MATCHED` with zero delta; Admin confirms the day as balanced, no action needed.
- **A2 — Single-rail mismatch:** Admin narrows to one source (e.g. `BANK`) and compares against provider evidence before escalating to finance.

## Exception Scenarios
- **E1 — Permission denied:** Moderator or non-finance role → `403 FORBIDDEN`.
- **E2 — No result for date:** Job has not run yet (first day or outage) → empty/pending result, never fabricated totals.
- **E3 — Concurrent next run:** The following night's job appends a new date while Admin reads → each date's result is immutable; prior days are never rewritten.
- **E4 — Mismatch left unresolved:** Unresolved YER accumulates across days and re-alerts finance on every run (BR-ESC-08) until an owner resolves it.

## Postconditions
- A reconciliation view exists for the chosen date; money state unchanged (FR-013, FR-020).
- Unresolved mismatches stay visible and alerting until cleared (BR-ESC-08, BR-FIN-03).

## Business Rules Applied
- BR-ESC-08, BR-FIN-03

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN` finance read; Moderator excluded; resolution actions are owned by finance outside this use case.
- **Data involved:** Reconciliation rows (ledger vs provider totals, deltas, status); no balance mutation.
- **External dependencies:** Provider statements (m-Floos, OneCash, bank), nightly job queue `b07.ledger.daily-reconcile`.

## Acceptance Criteria
- **AC-UC087-01:** Given a balanced day, when queried, then every source row shows `MATCHED` with a zero delta.
- **AC-UC087-02:** Given a source whose provider total differs, when the job runs, then the row is `MISMATCH` with the delta in integer YER.
- **AC-UC087-03:** Given a date the job has not processed, when queried, then an empty/pending result returns without error.
- **AC-UC087-04:** Given a Moderator session, when the endpoint is called, then `403 FORBIDDEN` is returned.
