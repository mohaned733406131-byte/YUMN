# UC-093 — Browse the Store Directory

## Header Info
- **Use Case ID:** UC-093
- **Title:** Browse the Store Directory
- **Actor:** Admin (ACT-04) — vendor operations scope
- **Trigger:** Admin opens Vendors → Stores in the console
- **Priority:** P1
- **Goal:** Locate any store by name, status or governorate and see its ownership and KYC posture at a glance.
- **Preconditions:** Admin or Moderator authenticated with directory read access (API-ADM-009); at least one store exists.

## Main Scenario
1. Admin opens the store directory → `GET /admin/stores?page=&pageSize=&status=&q=&governorate=` (API-ADM-009).
2. System returns offset-paginated rows: id, name, ownerId, status, kycStatus, rating, createdAt.
3. Each row is a single-store projection — store data never merges across stores, and cross-store reads are denied at the service layer for non-platform callers (BR-VND-07).
4. Admin filters by status (`PENDING`, `SUSPENDED`) to triage approvals (UC-095) or suspensions (UC-096), then drills into a row (UC-094).
5. The listing is read-only (FR-008, FR-020).

## Alternative Scenarios
- **A1 — Moderator read:** Moderator browses the directory (API-ADM-009 roles) with no lifecycle actions.
- **A2 — Governorate filter:** Narrow by governorate to investigate regional fulfillment or demand issues.

## Exception Scenarios
- **E1 — Permission denied:** Non-staff session → `403 FORBIDDEN`.
- **E2 — Empty directory:** Fresh platform → zero rows with an empty state, not an error.
- **E3 — Concurrent lifecycle change:** A store is suspended while the page is open → status is stale until refresh; detail re-reads server state.
- **E4 — KYC backlog:** `PENDING` stores awaiting a decision appear in this filter and are triaged in UC-031 inside the decision window.

## Postconditions
- The directory shows request-time state; no store was mutated (FR-008).
- A target store is selected for detail or lifecycle action.

## Business Rules Applied
- BR-VND-07

## Related Requirements
- FR-008 (Store Management & Storefront Configuration)
- FR-020 (Platform Administration, Settings & Audit)

## Permissions / Data / External Dependencies
- **Permissions:** `ADMIN`/`MODERATOR` read; writes belong to UC-095, UC-096 and UC-097.
- **Data involved:** Store records (status, owner, KYC, rating) strictly as per-store projections.
- **External dependencies:** Store service (service-layer store scoping, BR-VND-07).

## Acceptance Criteria
- **AC-UC093-01:** Given stores across owners, when listed, then every row carries its own store scope with no fields merged across stores.
- **AC-UC093-02:** Given `status=SUSPENDED`, when filtered, then only suspended stores return.
- **AC-UC093-03:** Given an empty platform, when listed, then HTTP 200 returns with zero rows.
- **AC-UC093-04:** Given a non-staff session, when requested, then `403 FORBIDDEN` is returned.
