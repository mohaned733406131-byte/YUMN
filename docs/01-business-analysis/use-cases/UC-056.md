# UC-056 — Generate Monthly Vendor Statements

## Header Info
- **Use Case ID:** UC-056
- **Title:** Generate Monthly Vendor Statements
- **Actor:** System (ACT-07) — reporting job (no interactive login)
- **Trigger:** Month-end scheduler runs the reporting rollup (FR-018)
- **Priority:** P1
- **Goal:** Produce a complete monthly statement per store — sales, commission, refunds, payouts, adjustments — so vendors can reconcile their earnings.
- **Preconditions:** The month's transactions, ledger entries and payout records exist; the vendor's store is identifiable from scoping (FR-014).

## Main Scenario
1. The month-end scheduler enqueues statement generation for each active store (FR-018).
2. The job aggregates the store's period figures: sales, commission, refunds, payouts and adjustments (BR-FIN-04).
3. Figures are derived from ledger and order records — money views are exact, never estimated (FR-014, FR-018).
4. The statement is assembled per store and persisted for the reporting period (FR-018).
5. The statement becomes downloadable in the vendor Finance area (FR-014, FR-018).
6. The vendor receives a notification that the new statement is available (FR-018).

## Alternative Scenarios
- **A1 — Download only (relation):** the vendor simply downloads the ready statement — generation is this UC's job; retrieval mirrors UC-022 step 5 (BR-FIN-04).
- **A2 — Store with zero activity:** an empty statement with zeroed sections is still produced for completeness (BR-FIN-04).
- **A3 — Mid-month suspension:** statements still cover the actual activity window; suspended store figures reflect only pre-suspension data (FR-014).

## Exception Scenarios
- **E1 — Job fails mid-generation:** retried with backoff; a partial statement is never published — only complete runs surface for download (FR-018).
- **E2 — Data discrepancy during aggregation:** figures that fail the balance check block publication of that store's statement and are flagged for review (BR-FIN-04).
- **E3 — Month boundary race:** transactions posting exactly at cutoff are attributed to the window by timestamp; a rerun regenerates a consistent statement (FR-018).

## Postconditions
- Success: a complete, downloadable monthly statement exists per store covering sales, commission, refunds, payouts, adjustments.
- Failure: no statement published for the affected store; job retries; prior-month statement remains available.

## Business Rules Applied
- BR-FIN-04

## Related Requirements
- FR-018 (Analytics & Reporting), FR-014 (Escrow, Commission & Vendor Payouts)
- **Related:** extends UC-022 step 5 (download only) — statement retrieval mirrors the Finance download; generation is this UC's job.

## Permissions / Data / External Dependencies
- **Permissions:** service identity generates; each vendor accesses only own-store statements (store scoping in FR-014).
- **Data involved:** orders, ledger entries, commission records, refunds, payouts, adjustments, statement documents.
- **External dependencies:** reporting/analytics store (B11), notification pipeline for availability notice.

## Acceptance Criteria
- **AC-UC056-01:** Given a month with sales, refunds and payouts, when generation runs, then the statement contains all five sections (BR-FIN-04).
- **AC-UC056-02:** Given an active store, when the month closes, then a downloadable statement exists (FR-018).
- **AC-UC056-03:** Given a job failure mid-run, when retried, then no partial statement is ever published (FR-018).
- **AC-UC056-04:** Given two stores, when statements generate, then each store's figures cover only its own activity (FR-014).
