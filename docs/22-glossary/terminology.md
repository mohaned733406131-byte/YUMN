# Terminology — Canonical Term Register (DOC-GL-002)

**The single source of truth for what every yumn term means** (root README §4). One row per concept, sorted A–Z (case-insensitive). Rules of the register:

- Use the **Term** column verbatim in English documents and the **Arabic** column verbatim in Arabic UI/copy; `—` in the Arabic column means the term is a loanword used as-is (e.g. `OTP`, `SKU`).
- The **Definition** is normative. Where a definition goes beyond its cited canon it is tagged `INFERENCE`; silence of canon is never papered over.
- **Never redefine a term outside this file** — reference the term and cite the IDs in the *Domain/IDs* column.
- Categories: `Business` (marketplace/domain concept), `Technical` (implementation-facing concept), `Process` (documentation/methodology concept).
- Disallowed synonyms are registered as their own rows (e.g. *Seller*) so authors can find the rejection.

## Notes & Disambiguations

1. **Customer vs Vendor vs Courier:** ACT-01 / ACT-02 / ACT-03 respectively; never swap ("seller" for vendor, "user" for customer). See `DOC-OVR-007`.
2. **Master order vs sub-order:** one master per checkout, one sub-order per vendor; the 17-state machine runs **per sub-order**, master aggregates (BR-ORD-07).
3. **Escrow hold vs stock hold vs wallet freeze vs lockout:** four different "holding" concepts — funds protection (7 days), inventory reservation (15 minutes), admin money restriction, and login restriction. Never use "hold" alone without qualifying which.
4. **Delivery code vs OTP:** both are 6-digit, 3-attempt secrets, but the delivery code locks for 24 h (`BR-SHP-03`) and is not an authentication factor; OTP expires in 5 minutes (`BR-AUTH-03`).
5. **Surface count:** most canon says **four surfaces** (customer web, vendor panel, admin console, mobile apps as one) — `C-09`, `FR-001`, `AC-S-04`; `13-testing/` and `ADR-008` say **five** (counting the two mobile apps separately). `05-frontend/README.md` reconciles them: S4+S5 = one "mobile apps" surface in requirement texts. This register uses **"five binaries / four requirement-counted surfaces"** — see the *Surface* row.
6. **Time zone:** all business-hour logic renders in `Asia/Aden` (UTC+3); storage is UTC. Payout "business days exclude Fri–Sat" is `INFERENCE` pending finance confirmation (`../11-ui-ux/core/localization.md` §5).
7. **Evidence:** rows restate only cited canon; anything else carries `INFERENCE` inline (see *Asia/Aden*, *Surface*).
