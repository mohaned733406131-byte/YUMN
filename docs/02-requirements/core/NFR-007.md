# NFR-007 — Fault Tolerance

## Description

No single dependency failure may take down the core buying flow, and no accepted write may be silently lost. The system degrades in defined, tested ways: search and cache failures fall back to database-backed category browsing; queue failures retry durably and land in a dead-letter queue; provider failures fail over (SMS → WhatsApp). Degraded modes are explicit features with alerts, not accidents.

## Metric / Target

- **Elasticsearch down** → category browse, product pages and cart continue serving from PostgreSQL/Redis; search box shows a friendly fallback; recovery without restart ≤ 60 s after ES returns.
- **Redis down** → catalog reads fall back to PostgreSQL with stricter rate limits; users keep working on unexpired access tokens (≤ 15 min, `C-08`) while sessions/cache recover; zero 5xx storms (error rate < 1% during the drill).
- **BullMQ/queue down** → accepted jobs durably persisted; retries **3× with exponential backoff → DLQ** (`BR-PLT-02`); DLQ depth > 0 raises an alert within 1 minute.
- **Zero silent data loss**: every accepted payment, order and stock write is committed to PostgreSQL before the 2xx response; post-failure reconciliation shows 0 unaccounted entries (`BR-ESC-08`).
- **SMS provider failure** → automatic failover to WhatsApp per `INT-REQ-003`, OTP delivery success ≥ 99% across both channels.

## Rationale

`OBJ-05` (availability) and `AC-S-06` are unreachable without graceful degradation; `DEP-04` explicitly anticipates search degradation ("browse-by-category fallback only"). Wallet/escrow trust (`C-01`, `C-12`, `OBJ-02`) makes silent data loss the single worst failure mode.

## Measurement Method

- **Failure-injection drills in staging** (same compose stack): stop the ES container, kill Redis, stop BullMQ workers, block the primary SMS provider, then run the core-journey smoke suite and watch error rates in Grafana.
- Queue durability checked by injecting jobs, restarting the worker, and counting completions vs DLQ.
- Post-drill reconciliation job report proving ledger/wallet/stock totals balance.

## Verification / Acceptance

`AC-NFR-007-01` — ES and Redis kill drills: core journeys (browse, cart, checkout with wallet) complete successfully with error rate < 1% and no data inconsistency. `AC-NFR-007-02` — queue and SMS provider drills: retries → DLQ with alert, and zero lost or duplicated jobs/money entries after recovery. Both PASS required.

## Dependencies

- NFR-005, NFR-006 (last-resort availability/recovery), NFR-008 (integrity after failures), NFR-014 (detecting degradation).
- FR-009 (search fallback), FR-017 (notification failover), INT-REQ-003, INT-REQ-006, DEP-03, DEP-04.

## Failure Consequences

A routine dependency outage becomes a full platform outage (violating `C-26`/`AC-S-06`); retried money jobs are dropped or double-applied, breaking `BR-PAY-08`/`BR-ESC-08` invariants; customers lose trust in wallet balances and the marketplace stalls.
