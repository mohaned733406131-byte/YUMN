# NFR-006 — RTO / RPO

## Description

Recovery targets for total loss of the primary environment (host failure, corruption, region-level incident): service must be **restored within 1 hour (RTO ≤ 1 h)** and **no more than 15 minutes of committed data may be lost (RPO ≤ 15 min)**. Backups combine continuous PostgreSQL WAL archiving with daily snapshots of database and MinIO object storage; the targets are proven by scheduled restore drills, never assumed from backup job green status alone.

## Metric / Target

- **RTO ≤ 1 hour**: from disaster declaration to first healthy write-serving instance (measured end-to-end in the drill).
- **RPO ≤ 15 minutes**: at most 15 minutes of committed transactions lost; WAL segments shipped at least every **5 minutes** so the 15-minute ceiling holds with margin.
- Backup freshness: alert if no successful WAL segment or snapshot in **15 minutes** (WAL) / **24 hours** (snapshot).
- **Quarterly restore drills** (`DATA-REQ-004`) — drill succeeds only if both numbers are met on measured wall-clock time.
- Backup retention: 30 days of WAL, 35 daily snapshots, 12 monthly snapshots; object storage versioned.

## Rationale

`C-26` fixes RTO ≤ 1 h and RPO ≤ 15 min as non-negotiable; `OBJ-05` and `AC-S-17` require a verified drill. For a wallet-and-escrow platform, lost ledger rows are lost money: `DATA-REQ-007` (append-only ledger) makes recoverability a financial-integrity requirement, not just an ops one.

## Measurement Method

- **Restore drill**: provision a clean host from the compose stack, restore latest snapshot + WAL replay, run reconciliation job (`BR-ESC-08`) to prove data completeness; stopwatch the whole procedure.
- **Prometheus** backup-age metrics from the backup cron/agent with alert rules at the freshness thresholds above.
- RPO verified by comparing last committed transaction timestamps in source vs restored database.

## Verification / Acceptance

`AC-NFR-006-01` — drill report shows RTO ≤ 1 h and RPO ≤ 15 min (measured, evidenced). `AC-NFR-006-02` — backup freshness alerts fire in a staged failure test and quarterly drill cadence is scheduled. Both PASS; a failed drill blocks launch per `AC-S-17`.

## Dependencies

- NFR-005 (availability is the first line, DR the second), NFR-008 (post-restore integrity), NFR-020 (runbooks/drills).
- DATA-REQ-004 (backup & restore), DATA-REQ-007 (ledger immutability), DEP-02 (PostgreSQL 16 PITR), DEP-07 (MinIO object durability).

## Failure Consequences

Beyond `C-26`: committed wallet, escrow or order data is permanently lost (irreconcilable with vendors and customers), platform cannot meet `AC-S-17`, and any legal/regulatory claim of financial-record retention (`NFR-019`) collapses.
