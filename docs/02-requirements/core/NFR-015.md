# NFR-015 — Browsers/devices

## Description

The customer web and both admin-facing web surfaces must render and function correctly on the browsers and mobile operating systems actually used by the target market, in Arabic RTL and English LTR. The supported matrix is explicit; anything outside it degrades gracefully rather than breaking.

## Metric / Target

- **Desktop browsers**: last **2 major versions** of Chrome, Safari, Firefox and Edge (8 browser/version combinations minimum in the matrix).
- **Mobile**: Android **10+** (API 29+) and iOS **15+** — native apps and customer web; web views used by WhatsApp/SMS link opening must render the core read paths.
- **Matrix pass rate: 100%** of P1 flows (register, browse, cart, checkout, wallet, order tracking) with **0 blocking defects** in the supported matrix, in both locales.
- Responsive layout supported from **320 px** viewport width to ≥ 1440 px; no horizontal scrolling on core pages at 360 px (dominant phone width).
- Out-of-support browsers receive a graceful message on critical flows instead of a broken UI; **0 data-corrupting failures** on unsupported browsers.

## Rationale

Yemen's device mix skews toward older, budget Android phones and browsers — support must be broad where it matters. `NFR-002` targets (LCP/INP) are only meaningful on the same matrix; `AC-S-04` requires all four surfaces to deliver their UC set, which presupposes the client actually runs on user devices.

## Measurement Method

- **Playwright cross-browser runs** (Chromium, Firefox, WebKit) in CI on every PR for P1 flows.
- Real-device pass on the device lab (`DEP-12`): ≥ 6 physical devices covering Android 10/12/14 and iOS 15/17, manual smoke of P1 flows in `ar` and `en`.
- Weekly cloud-grid run (BrowserStack/SauceLabs or equivalent) on the full version matrix before each release.

## Verification / Acceptance

`AC-NFR-015-01` — automated cross-browser suite passes P1 flows on all 8 desktop combinations with 0 blocking defects. `AC-NFR-015-02` — device-lab pass on Android 10+ / iOS 15+ (including in-app webviews) in both locales at 320–1440 px. Both PASS before release.

## Dependencies

- NFR-002 (performance per browser), NFR-011 (accessibility per browser/AT), NFR-013 (RTL rendering per browser).
- FR-011 (checkout UI), DEP-11 (design system browser support), DEP-12 (device lab).

## Failure Consequences

A large share of Yemeni users hits broken layouts or failed checkouts on their actual devices; support tickets spike (`FR-020`); conversion and `AC-S-04` (all surfaces deliver their UC set) fail despite the code being "correct" on developer machines.
