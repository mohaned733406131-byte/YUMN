# NFR-016 — Deployment

## Description

The entire stack must run on **any Docker host using Docker Compose — no cloud-vendor lock-in in v1** (`C-22`). Infrastructure is described as code (compose files, env config), so the same images deploy to development, staging and production without modification, and the platform can be relocated (different host, different provider, on-premises) by moving the compose project.

## Metric / Target

- Clean-host bring-up: a fresh Docker Engine ≥ 24 host reaches a healthy stack (all services `healthy`, smoke suite green) in **≤ 30 minutes** from `git clone` + `docker compose up` using documented steps.
- **Identical image digests** across dev/staging/prod for the same release tag — 0 environment-specific rebuilds.
- **0 cloud-vendor proprietary services or SDKs** in the runtime dependency graph (no AWS RDS/Lambda, GCP, Azure managed equivalents); object storage accessed only through the S3-compatible MinIO abstraction (`DEP-07`).
- Environment configuration: **100% via environment variables/secrets files** — 0 host-specific configuration baked into images (`SEC-REQ-007`, `NFR-020`).
- Portability drill executed and recorded **at least once before launch** and repeated annually: bring the stack up on a second, differently-provisioned host with zero code changes.

## Rationale

`C-22` (Docker + Compose, no Kubernetes, `ADR-004`) and `C-19`/`C-20` (PostgreSQL 16, BullMQ only) deliberately minimize infrastructure surface; portability is the payoff of those constraints. `C-18` (100% custom build) keeps the platform free of platform-as-a-service dependencies that would undermine the control objective.

## Measurement Method

- Clean-host drill (documented in `15-deployment/`) with stopwatch and checklist; smoke tests after bring-up.
- CI job comparing image digests per release tag across environments.
- Dependency audit script flagging cloud SDKs (`@aws-sdk/*`, `@google-cloud/*`, `@azure/*`, etc.) and managed-service references in compose/infra files.

## Verification / Acceptance

`AC-NFR-016-01` — clean-host drill completes with healthy stack + green smoke suite in ≤ 30 minutes using identical image digests. `AC-NFR-016-02` — dependency/infra audit reports 0 cloud-vendor lock-in findings and 0 host-specific config in images. Both PASS.

## Dependencies

- NFR-009 (same builds behind module gates), NFR-020 (health checks, zero-downtime deploys), DATA-REQ-005 (migrations run identically everywhere).
- INT-REQ-008 (provider adapters keep integrations portable), DEP-01, DEP-02, DEP-03, DEP-07, `ADR-004`.

## Failure Consequences

`C-22` is violated; environments diverge ("works on my machine"); releases become environment-specific snowflakes; the platform is stranded on one hosting provider, raising cost and exit risk, and DR (NFR-006) cannot be exercised off-site.
