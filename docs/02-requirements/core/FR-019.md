# FR-019 — Content & Promotions (CMS + Coupons)

**Block:** B12 Content & CMS · **Priority:** High · **Status:** approved · **Registry:** `DOC-REQ-001` §1

FR-019 provides the CMS surface (admin-managed bilingual static pages, scheduled banners and featured/deal merchandising slots feeding discovery) and the coupon engine: platform- and store-scoped codes, unique codes with validity ≤ 90 days, percentage discounts ≤ 90% of order value, strictly non-stackable (one coupon per order), optional minimum order amount and per-user/global usage limits, four types (percentage, fixed, free shipping, buy-X-get-Y), and rejection of invalid coupons before any order row exists.

## Rationale

- Traces `OBJ-01` (block B12), `OBJ-11` (promotions drive marketplace liquidity) and `OBJ-03` (bilingual content quality under `C-24`).
- The coupon engine is where `BR-FIN-01` (VAT on subtotal − discount) and `C-14` (order bounds after discount) intersect — validation must happen before order creation (`BR-PRM-06`) to avoid money-row rollbacks.
- Admin oversight of vendor-created coupons (`BR-PRM-03`) prevents discount abuse of platform revenue.

## Requirements Detail

- Static pages (about, terms, privacy, help) authored by Admin, published/unpublished, fully bilingual with RTL rendering (`BR-PLT-05`, `C-24`).
- Banners: placement slots, scheduling window, target locale, linking to products/categories/stores; rendered on customer surfaces.
- Featured/deal merchandising slots consumed by search/storefront discovery (FR-009).
- Coupon scope: platform coupons (admin-created) and store coupons (vendor-created); admin can list and disable any store coupon (`BR-PRM-03`).
- Coupon constraints: unique code, validity window ≤ 90 days, percentage discount ≤ 90% of order value (`BR-PRM-01`).
- Coupons never stack — exactly one coupon per order (`BR-PRM-02`).
- Optional `min_order_amount`; usage limits per-user and global; expired or fully-used coupons rejected before order creation (`BR-PRM-04`).
- Types: percentage, fixed amount, free shipping, buy-X-get-Y (`BR-PRM-05`).
- Invalid coupon → localized validation error; no order row is created (`BR-PRM-06`).
- Free-shipping coupons zero the shipping fee (`BR-SHP-01`); discount reduces the VAT base (`BR-FIN-01`).
- Coupon application is idempotent via idempotency key (`BR-PLT-03`); discount is included in server-side total recalculation (`BR-CRT-04`).
- Discounted order totals remain inside 500–5,000,000 YER bounds (`C-14`, `BR-CAT-04`).
- CMS content changes by privileged roles write audit entries (`BR-PLT-06`); page/banner copy exists in ar and en (`BR-NTF-04` analog via `BR-PLT-05`).

## Preconditions

- Admin (and vendor for store coupons) authenticated with content/coupon permissions (FR-002).
- Products/categories/stores exist to target banners and coupons (FR-004/FR-008).
- Checkout is ready to validate coupons before order creation (FR-011).

## Expected Result

Operators publish bilingual content and merchandising that renders in discovery surfaces, and customers can apply exactly one valid coupon whose discount, VAT effect and order bounds are computed correctly — with every invalid case stopped before an order row exists.

## Acceptance Criteria

- **AC-FR019-01** — Given a coupon with a 91-day validity window, when saved, then it is rejected (≤ 90 days, `BR-PRM-01`).
- **AC-FR019-02** — Given a second coupon is applied to an order that already has one, when processed, then it is rejected/replaced so exactly one discount line exists (never stacked).
- **AC-FR019-03** — Given a percentage coupon of 95%, when saved, then it is rejected (≤ 90% of order value).
- **AC-FR019-04** — Given an expired or fully-used coupon at checkout, when validated, then a localized error is returned and no order row is created.

## Business Rules Applied

- `BR-PRM-01` code/validity/discount bounds; `BR-PRM-02` non-stacking; `BR-PRM-03` platform vs store scope with admin disable.
- `BR-PRM-04` min amount + usage limits; `BR-PRM-05` coupon types; `BR-PRM-06` invalid → no order row.
- `BR-SHP-01` free-shipping type; `BR-FIN-01` VAT base after discount; `BR-PLT-03` idempotent application; `BR-PLT-05` bilingual content.

## Constraints Honored

- `C-14` discounted order totals still bounded 500–5,000,000 YER.
- `C-24` Arabic-first bilingual CMS content with English parity.

## Dependencies

- **FR:** FR-004 (target products), FR-009 (merchandising slots), FR-011 (coupon validation at checkout), FR-015 (shipping fee zeroing), FR-017 (promotion notifications), FR-020 (content/coupon admin oversight).
- **NFR:** NFR-013 (bilingual rendering), NFR-001 (CMS read performance).

## Verification Method

- Coupon engine unit tests: bounds (90 days, 90%), stacking prevention, usage limits, expiry, each type's math.
- Integration tests: invalid coupon → error with no order row; free-shipping effect on total; admin disabling a store coupon.
- Content tests: bilingual publish/render (RTL/LTR), banner scheduling window, audit entries for CMS changes.

## Out of Scope Notes

- Loyalty points and rewards redemption (`GAP-04`), sponsored/paid advertising placements (FUTURE SCOPE).
- A/B testing, personalized promotions, referral programs and affiliate networks.
- Coupon stacking, auto-applied surprise discounts beyond configured types, and coupons in non-YER denominations (`C-04`).
