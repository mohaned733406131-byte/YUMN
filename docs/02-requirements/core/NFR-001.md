# NFR-001 — API Response Time

## Description

Every HTTP API response must be fast enough that interactive flows (browse, cart, checkout, wallet, order tracking) feel instant on Yemeni mobile networks. Server-side latency is a hard release gate. "Nominal load" means the reference k6 traffic profile run at the full **10,000 concurrent users** required by `C-25`; reduced-load runs during earlier phases are informative only — the 10,000-user run is the acceptance gate (`AC-S-05`). Latency is measured at the API gateway (time from request receipt to first response byte), excluding client rendering.

## Metric / Target

- p95 latency, **read** endpoints (GET catalog, search, orders, wallet balance): **< 200 ms**.
- p95 latency, **write** endpoints (POST/PUT/PATCH/DELETE — cart, checkout, payment, admin): **< 500 ms**.
- p99 latency: ≤ 400 ms read, ≤ 1,000 ms write (secondary budget, monitored).
- Error rate (5xx + timeout) during the reference run: **< 0.1%** of requests.
- Thresholds must hold for a **30-minute steady-state window**, not only during short bursts.

## Rationale

`OBJ-04` (Critical) sets p95 < 200 ms; `C-25` forces that objective to hold at 10,000 concurrent users; `AC-S-05` makes the k6 result a launch gate. Slow writes delay order confirmation and wallet debits, undermining the escrow trust model (`C-01`, `C-12`) and the 17-state order flow (`C-09`) that all four surfaces depend on.

## Measurement Method

- **k6** reference scenarios (read-heavy, write-heavy, mixed browse-and-buy) executed from a same-region runner against staging with production-like data volume.
- Server-side **Prometheus** RED histograms per endpoint (15 s scrape), p95 computed with `histogram_quantile` and reviewed in **Grafana**.
- Evidence: k6 JSON summary + Grafana snapshot attached to the release test report in `13-testing/`.

## Verification / Acceptance

`AC-NFR-001-01` (read p95 < 200 ms) and `AC-NFR-001-02` (write p95 < 500 ms) in `02-requirements/acceptance-criteria.md`. Both PASS only on the 10,000-concurrent-user, 30-minute run with error rate < 0.1%; failing either percentile point fails the NFR and blocks release (`AC-S-05`).

## Dependencies

- NFR-003 (concurrency target), NFR-004 (caching), NFR-014 (latency observability).
- FR-009, FR-010, FR-012, FR-013 — highest-volume read/write endpoint families.
- DEP-02 (PostgreSQL 16 indexing), DEP-03 (Redis 7 cache tier).

## Failure Consequences

Checkout and wallet flows feel broken on mobile data; cart abandonment rises; `AC-S-05` and `OBJ-04` fail at the quality gate; the platform cannot substantiate the `C-25` scale claim and release is blocked.
