# FR-009 — Search & Discovery

**Block:** B04 Search & Discovery · **Priority:** High · **Status:** approved · **Registry:** `DOC-REQ-001` §1

FR-009 provides Arabic-aware full-text product search over an Elasticsearch cluster (`DEP-04`) with filters (category, price, store, rating, availability), sorting (relevance, price, newest, rating), category-tree browsing up to 5 levels, and CMS-driven banner/merchandising placements. Only ACTIVE products with available stock are discoverable; index updates flow through background jobs; if search degrades, category browsing keeps working.

## Rationale

- Traces `OBJ-03` (Arabic-first quality — the rationale of `C-24` explicitly names the ES Arabic analyzer), `OBJ-01` (block B04) and `OBJ-04` (p95 latency targets under `C-25` load).
- Discovery is the marketplace's demand engine (`OBJ-11`); Arabic text quality directly determines whether Yemeni customers find products.
- `NFR-007` graceful degradation requires an explicit fallback (browse-by-category) when the search cluster is unavailable.

## Requirements Detail

- Full-text search with Arabic analysis: normalization (alef/ya/ta-marbuta variants), diacritics handling, bilingual ar/en content (`C-24`).
- Indexed fields: product name (ar/en), description, store name, category, attributes.
- Filters: category, price range (integer YER), store, minimum rating, in-stock only; combinable.
- Sorting: relevance, price ascending/descending, newest, rating.
- Category browse: tree depth ≤5 with unique slugs per level (`BR-CAT-03`).
- Only ACTIVE, non-deleted products appear in results (`BR-CAT-06`); results reflect available stock (FR-005).
- Banner and featured/deal placements sourced from CMS merchandising (FR-019) are injected into discovery surfaces.
- Index updates are asynchronous via BullMQ jobs with retries and DLQ; new/edited/deleted products converge without manual reindexing (`BR-PLT-01`, `BR-PLT-02`).
- Result aggregation/facets are cached to keep cache-hit ratio ≥ 80% on catalog reads (`NFR-004`).
- p95 latency within `NFR-001` at `C-25` (10,000 concurrent users); pagination remains stable under concurrent indexing.
- Degrade path: search cluster down → category browse and cached listings continue (`NFR-007`).
- Result snippets and UI localized ar (default) / en with RTL layout (`NFR-013`).

## Preconditions

- Products exist and are indexed (FR-004) with stock data available (FR-005).
- Elasticsearch cluster (`DEP-04`) is reachable; degraded mode is exercised when it is not.
- Category tree and CMS placements are configured (FR-004/FR-019).

## Expected Result

Customers find relevant products quickly in Arabic or English through text search, filtering, sorting or category browsing; unpublished/deleted items never appear; catalog changes propagate to results automatically; and a search outage degrades to working category browsing instead of an error page.

## Acceptance Criteria

- **AC-FR009-01** — Given an Arabic query using variant letter forms (e.g., alef variants), when searched, then matching products are returned thanks to Arabic normalization.
- **AC-FR009-02** — Given a soft-deleted or inactive product, when any search or sort query runs, then it never appears in results.
- **AC-FR009-03** — Given the search cluster is unavailable, when a customer browses by category, then browsing returns correct products (no hard failure, `NFR-007`).
- **AC-FR009-04** — Given a filter+sort combination, when applied, then results match all filters, ordering is deterministic, and facet counts equal returned totals.
- **AC-FR009-05** — Given admin-configured banners/merchandising in an active window, when a customer opens the home/category page, then configured banners and featured/deal placements render during the window and disappear after expiry (`FR-019`).

## Business Rules Applied

- `BR-CAT-03` category depth ≤5 and slug uniqueness for browse URLs; `BR-CAT-06` ACTIVE-only visibility.
- `BR-PLT-01`/`BR-PLT-02` background job queues, retries and DLQ for index synchronization.

## Constraints Honored

- `C-24` Arabic-first search with the ES Arabic analyzer and English parity.
- `C-25` discovery must hold p95 targets at 10,000 concurrent users (`NFR-001`, `NFR-003`).

## Dependencies

- **FR:** FR-004 (source content), FR-005 (availability), FR-008 (store filters), FR-019 (banners/featured slots).
- **NFR/DEP:** NFR-001, NFR-004, NFR-007, DEP-04 (Elasticsearch), DEP-03 (Redis cache).

## Verification Method

- Relevance test corpus in Arabic and English (including variant spellings and diacritics).
- Integration tests: index consistency after create/edit/soft-delete; facet/total correctness; failover to browse-only mode.
- Load test: p95 search latency at `C-25` concurrency; cache-hit ratio assertion (`NFR-004`).

## Out of Scope Notes

- Personalized/ML recommendations, "customers also bought" models, and sponsored/paid placements (advertising is FUTURE SCOPE).
- Voice search, image search, cross-language transliteration beyond ar/en (`C-24`).
- Fuzzy typo-tolerance SLAs and synonym management workflows — not specified in v1; refine via relevance testing.
