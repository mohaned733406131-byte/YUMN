# NFR-009 — Modularity & standards

## Description

The codebase must remain a **modular monolith with enforced module boundaries** (`C-21`, `ADR-002`): 13 block modules communicate only through their public APIs, never through each other's internals. Engineering standards — formatting, linting, strict typing, tests and documentation — are enforced mechanically in CI so quality does not depend on reviewer vigilance. The architecture stays evolvable without drifting toward uncontrolled coupling.

## Metric / Target

- **Module-boundary violations in CI: 0** — automated dependency rule check (e.g. dependency-cruiser / ESLint import rules) fails the build on cross-module internal imports.
- **CI gate pass rate: 100% of merged PRs** passed format check, lint, `tsc --noEmit` (strict mode), unit tests and coverage gates.
- **Coverage gates**: overall ≥ 80% lines; payment module ≥ 95%; auth ≥ 90% (`AC-S-08`) — breach fails CI, not a warning.
- **Documentation currency: 0 stale documents** flagged in the monthly doc audit; every module has a README stating its public API and owning FRs.
- **Onboarding/objective measure**: a new developer ships a validated change within **5 working days** using this knowledge base alone (`OBJ-10`).
- Regression suite completes in **< 30 minutes** (`AC-S-09`), keeping the gates fast enough to run on every PR.

## Rationale

`C-21` (modular monolith, no microservices) makes internal boundaries the only thing preventing a "big ball of mud"; `OBJ-09` (quality velocity) and `OBJ-10` (maintainability) require gates that keep quality measurable. `ADR-002` chose the monolith specifically for operability — that choice only pays off if modularity is enforced.

## Measurement Method

- **dependency-cruiser (or ESLint boundaries)** run in CI on every PR; violation report archived.
- CI metrics: pipeline results, coverage report (Istanbul/c8) published per PR.
- Timed onboarding exercise (`OBJ-10`) and monthly documentation-freshness audit recorded in `20-validation/`.

## Verification / Acceptance

`AC-NFR-009-01` — dependency analysis reports 0 boundary violations across the full module graph and all merged PRs in the release branch passed lint/type/test gates. `AC-NFR-009-02` — coverage thresholds enforced as failing gates, module READMEs present for all 13 blocks, and the onboarding change ships ≤ 5 working days. Both PASS.

## Dependencies

- NFR-010 (testability gates feed the same CI), NFR-016 (same build runs anywhere), FR-020 (audit/admin concerns stay inside their module), DATA-REQ-005 (expand-contract migrations).
- DEP-01 (Node 20 LTS + TypeScript 5), `C-21`, `ADR-002`.

## Failure Consequences

Modules start importing each other's internals; changes ripple across the codebase; the monolith becomes unmaintainable and any future extraction (or even routine refactoring) turns costly; velocity (`OBJ-09`) degrades and defect escape rate climbs.
