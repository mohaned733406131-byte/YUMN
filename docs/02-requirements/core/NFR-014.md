# NFR-014 — Logging/metrics/tracing

## Description

Operators must be able to see, correlate and alert on system behaviour in real time: **structured JSON logs with correlation IDs on every request, RED metrics (rate, errors, duration) for every endpoint, and alert routes to on-call.** Logging never leaks secrets or PII (passwords, OTPs, tokens are redacted — `BR-AUTH-02`, `SEC-REQ-007`). Detail plans live in `12-non-functional/observability.md`.

## Metric / Target

- **Correlation ID coverage: 100%** of inbound requests — ID generated at the edge, propagated through NestJS handlers and BullMQ jobs, present in every related log line.
- **Structured logs: 100%** of backend log output is JSON with a fixed field schema (`ts`, `level`, `service`, `module`, `requestId`, `userId?`, `msg`); 0 unstructured lines in a 1,000-line production sample.
- **RED metrics: 100% of HTTP endpoints** exposed as Prometheus histograms/counters (15 s scrape), with dashboards per block and an aggregation dashboard per surface.
- **Alerting**: paging alerts fired ≤ **1 minute** after condition is met; on-call acknowledgement ≤ **15 minutes**; alert inventory complete per `AC-S-18`; 0 critical signals without an alert rule.
- **Traceability of money events**: 100% of payment/escrow/payout operations log a before/after audit entry (`BR-PLT-06`, `SEC-REQ-010`).
- Log retention: hot/queryable **≥ 30 days**; audit-grade records retained **≥ 5 years** (`NFR-019`).

## Rationale

`AC-S-18` requires monitoring/alerting live for every signal in `12-non-functional/observability.md`; `OBJ-08` (operational control — 100% of privileged/money actions audited); `INT-REQ-007` defines the Prometheus/Grafana/on-call export. Without correlation IDs, debugging a failed order across 13 modules is guesswork.

## Measurement Method

- **Prometheus** scrape-target health check (0 missing targets) + Grafana dashboard inventory review.
- Log sample audit script validating JSON schema and secret redaction on a rolling 1,000-line extract.
- Alert fire drill (induce test condition in staging) measuring detection → page → ack times; coverage diff between endpoints and metric names.

## Verification / Acceptance

`AC-NFR-014-01` — log audit shows 100% structured output with correlation IDs flowing end-to-end (HTTP → queue → response) and zero secrets/PII in samples. `AC-NFR-014-02` — RED metrics cover every endpoint, and the alert drill pages on-call within 1 minute with ack ≤ 15 minutes (`AC-S-18`). Both PASS.

## Dependencies

- NFR-005 (MTTD/MTTR depend on detection), NFR-007 (degradation must be visible), NFR-019 (audit retention), NFR-020 (runbooks consume these signals).
- INT-REQ-007, SEC-REQ-010, FR-020, DEP-03 (Redis metrics), DEP-02 (database metrics).

## Failure Consequences

Outages are discovered by customers instead of monitoring (99.99% target unreachable); incidents cannot be reconstructed; money-audit evidence is missing (violating `SEC-REQ-010`/`OBJ-08`); `AC-S-18` fails and operational readiness sign-off is withheld.
