# NFR-012 — Core-task efficiency

## Description

Key tasks must be completable quickly by first-time users with no training: a new customer goes from registration to first paid order in under five minutes, and a new vendor lists a first product in under ten minutes. Efficiency is measured with real representative users, not assumed from design reviews; Arabic-first flows are the measured default (`C-24`).

## Metric / Target

- New customer: **registration → first completed order < 5 minutes** (median across usability participants, `ar` locale, mid-tier Android on 4G).
- New vendor: **account → first published product listing < 10 minutes** (median, including image upload and pricing).
- Task success rate **≥ 90%** across8 core tasks (register, verify OTP, top-up, search, add to cart, checkout, track order, request return) with **0 unrecoverable dead ends** (every error offers a next action).
- System Usability Scale (SUS) **≥ 78** per persona (customer, vendor, admin) in moderated sessions.
- Inline validation on all money and address forms: **100% of rejected inputs** explained in the user's locale before submission fails.

## Rationale

`C-24`'s constraint interaction map explicitly states "C-24 (Arabic) drives NFR-012"; `OBJ-03` (Arabic-first UX quality) and `OBJ-06` (vendor onboarding velocity — KYC to listing) set the business stakes. Time-to-first-order is the marketplace's core growth lever; time-to-first-listing drives supply liquidity (`OBJ-11`).

## Measurement Method

- **Moderated usability sessions** (≥ 5 participants per persona) on real devices before release; stopwatch/observer timing recorded per task in `13-testing/`.
- Post-launch funnel analytics (time between registration, first top-up, first order events) for continuous monitoring.
- Error-path audit: scripted failed inputs on every form, verifying recoverable messaging.

## Verification / Acceptance

`AC-NFR-012-01` — median new-customer time registration→first order < 5 min with ≥ 90% task success in the `ar` usability round. `AC-NFR-012-02` — median vendor time to first published listing < 10 min and SUS ≥ 78 for both personas. Both PASS before release.

## Dependencies

- NFR-011 (accessible flows are a precondition), NFR-013 (Arabic default quality), NFR-001 (perceived speed of each step).
- FR-001 (OTP registration), FR-004 (listing form), FR-007 (KYC path), FR-011 (checkout), DEP-11 (design assets/Arabic copy).

## Failure Consequences

Users abandon at OTP, top-up or checkout; vendors list nothing and the catalog stays empty (`OBJ-11` liquidity fails); support ticket volume rises (`FR-020`); the Arabic-first promise (`OBJ-03`) rings hollow in exactly the flows that generate revenue.
