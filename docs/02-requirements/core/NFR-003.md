# NFR-003 — Concurrency

## Description

yumn must sustain **10,000 concurrent authenticated users** (browsing, carting, ordering and paying simultaneously) while all latency and error targets hold. Concurrency is verified as a sustained load, not a spike: connection pools, row locks on wallets/stock, BullMQ workers and Elasticsearch all have to survive 30 minutes of steady pressure and drain cleanly afterwards. This is the quantitative expression of `C-25`.

## Metric / Target

- **10,000 concurrent users** held for **30 minutes** on the mixed browse-cart-pay profile (k6 `vus = 10000`).
- Within the run: p95 read < 200 ms, p95 write < 500 ms, error rate < 0.1% (all per NFR-001).
- Resource headroom during the run: API host CPU average < 70%, memory < 75%, PostgreSQL connections < 80% of pool, no connection-pool wait p95 > 50 ms.
- After the run: BullMQ backlog returns to baseline within 5 minutes; zero stuck jobs; zero deadlocks reported.

## Rationale

`C-25` (10,000 concurrent users within NFR targets) is a non-negotiable constraint verified by a load test on `NFR-003`; `OBJ-04` and `AC-S-05` bind performance to this scale. Marketplace launches concentrate traffic in flashes (promotions, Eid), so sustained headroom prevents oversell races on stock (`C-13`) and wallet row-lock contention (`BR-PAY-05`).

## Measurement Method

- **k6** load scenario ramping to 10,000 VUs over 5 minutes, holding 30 minutes, with a read/write mix derived from the browse-buy funnel.
- **Prometheus/Grafana**: host CPU/memory, PgBouncer pool stats, BullMQ queue depth, ES thread-pool metrics sampled every 15 s during the run.
- Concurrency correctness checked in parallel: stock never negative, no duplicate orders from the same idempotency key.

## Verification / Acceptance

`AC-NFR-003-01` — 10,000 VUs sustained 30 minutes with all NFR-001 thresholds met and error rate < 0.1%. `AC-NFR-003-02` — resource headroom limits above respected and queues drained to baseline within 5 minutes. Both must PASS; the k6 report is attached to `AC-S-05` evidence.

## Dependencies

- NFR-001 (latency under load), NFR-004 (cache absorbs read amplification), NFR-008 (locking correctness), NFR-018 (replica path).
- FR-010, FR-011, FR-013 (concurrent cart/checkout/wallet paths), DEP-02, DEP-03.

## Failure Consequences

`C-25` is violated and unverifiable; wallet debits or stock deductions could serialize or deadlock under load; flash-sale traffic causes timeouts and lost orders; release fails `AC-S-05` and the platform cannot go live with a defensible scale claim.
