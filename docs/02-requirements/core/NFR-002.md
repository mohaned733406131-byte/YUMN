# NFR-002 — Client Performance

## Description

The customer web app (Next.js 14) must load and respond quickly on mid-tier Android devices over 4G — the dominant Yemeni access profile — while carrying Arabic/RTL typography and font payloads. Performance is enforced continuously in CI (Lighthouse CI + bundle budget) and observed after launch through real-user monitoring. Vendor panel and admin console are secondary surfaces: same measurement pipeline, informational targets (LCP < 3.5 s) instead of binding gates.

## Metric / Target

- **LCP < 2.5 s** for the customer web on simulated 4G, mid-tier mobile (Lighthouse mobile preset), on home, category, product and checkout pages.
- **INP ≤ 200 ms**, **CLS ≤ 0.1** on the same pages (Core Web Vitals "good" range).
- Customer web initial JS bundle **< 200 KB gzipped**, enforced per-route by code splitting; no single vendor chunk > 100 KB gzipped.
- TTFB for cached pages < 500 ms from a regional edge.
- Font payload budget: Arabic + Latin webfonts ≤ 150 KB combined, `font-display: swap`.

## Rationale

`OBJ-04` (performance targets) and `OBJ-03` (Arabic-first UX quality): a slow storefront directly costs conversions on mobile data. `C-24` (Arabic-first RTL) makes font and RTL layout cost a first-class budget item, and `AC-S-05`/`AC-S-10` require measurable frontend evidence at release.

## Measurement Method

- **Lighthouse CI** (mobile, throttled 4G) run on every PR for the four customer pages; scores and metrics stored as CI artifacts.
- **bundlesize / size-limit** check on the gzipped entry bundle in CI (fails the build on breach).
- Post-launch **Web Vitals RUM** (p75 LCP/INP/CLS) exported to Prometheus/Grafana via `12-non-functional/performance.md` pipeline.

## Verification / Acceptance

`AC-NFR-002-01` — LCP < 2.5 s with INP ≤ 200 ms and CLS ≤ 0.1 on all four customer pages in Lighthouse CI. `AC-NFR-002-02` — gzipped initial bundle < 200 KB and font budget ≤ 150 KB. Either breach fails the NFR; release blocked until CI is green.

## Dependencies

- NFR-001 (server TTFB), NFR-013 (Arabic font/RTL payload), NFR-015 (browser matrix).
- FR-009, FR-010, FR-011 (heaviest client surfaces), DEP-11 (design assets), DEP-08 (CDN/edge).

## Failure Consequences

High bounce and cart abandonment on mobile networks; Lighthouse budgets start failing silently in CI; RTL pages become heavy and janky; `OBJ-04` and the customer-facing half of `AC-S-11` are undermined.
