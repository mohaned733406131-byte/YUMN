# NFR-010 — Testability

## Description

All business logic must be unit-testable **without network access, real SMS/WhatsApp calls, real payment providers or a shared database** — dependencies are injected behind interfaces (aligned with `INT-REQ-008` provider abstraction) so tests run in milliseconds, deterministically, in CI. Coverage thresholds and suite speed are hard gates, not aspirational numbers.

## Metric / Target

- **Coverage** (line, measured by c8/Istanbul in CI): overall **≥ 80%**; payment/wallet/escrow module **≥ 95%**; auth module **≥ 90%** (`AC-S-08`).
- **Network isolation**: 0 unit tests touch the real network or third-party providers — enforced by blocking outbound sockets in the unit-test runner; unit suite passes fully offline.
- **Determinism**: 0 flaky tests — the full unit suite passes **10 consecutive CI runs** with zero reruns.
- **Speed**: regression suite completes in **< 30 minutes** (`AC-S-09`); unit suite < 3 minutes so it runs on every PR.
- **Critical-path coverage**: every `BR-*` rule touching money, auth and order state has at least one automated test (`AC-S-03`), traceable in `19-traceability/`.

## Rationale

`OBJ-09` (automated suites gate every release, regression < 30 min) and `AC-S-08` quantified the thresholds; money-path correctness (`OBJ-02`, `AC-S-15`) is only provable if tests can simulate replays, concurrency and provider failures cheaply. `INT-REQ-008`'s adapter pattern exists precisely to make this possible.

## Measurement Method

- Coverage report generated per CI run; thresholds configured to fail the pipeline on breach.
- Outbound-socket block in unit-test setup (e.g. undici mock / `nock` allowlist / custom net guard); test categorized as unit/integration/e2e via project tags.
- Flakiness tracked by CI rerun counter over 10 consecutive runs; suite duration recorded as a CI metric.

## Verification / Acceptance

`AC-NFR-010-01` — coverage thresholds met in the CI report (80% / 95% payment / 90% auth) with the unit suite passing offline (network blocked). `AC-NFR-010-02` — regression suite < 30 minutes and 10 consecutive rerun-free runs. Both PASS required before release sign-off.

## Dependencies

- NFR-008 (integrity invariants proven by these tests), NFR-009 (same CI gates), NFR-017 (tests must run against large synthetic volumes for capacity checks).
- FR-011, FR-013, SEC-REQ-002, SEC-REQ-003, DEP-12 (device-lab tests remain manual/integration level).

## Failure Consequences

Regressions in wallet, escrow or auth ship undetected; releases become risky manual events; `AC-S-03`/`AC-S-08`/`AC-S-09` fail; defect escape rate rises against `OBJ-09` and every downstream integrity claim (`NFR-008`) loses its evidence base.
