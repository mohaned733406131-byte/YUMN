# NFR-011 — WCAG 2.1 AA

## Description

All customer-facing web surfaces (registration, catalog, cart, checkout, wallet, orders, support) must conform to **WCAG 2.1 Level AA**, in both Arabic RTL and English LTR rendering. Automation catches most issues on every PR; the remainder (keyboard flow, screen-reader semantics, focus behaviour) is verified manually on the core journeys with TalkBack and VoiceOver.

## Metric / Target

- **Automated pass rate ≥ 95%** on every customer page (axe-core rule set), with **0 critical and 0 serious violations** (`AC-S-10`).
- **Keyboard**: 100% of core-journey tasks completable with keyboard only; visible focus indicator on all interactive elements; no keyboard traps; logical focus order mirrored in RTL.
- **Screen reader**: registration → browse → cart → checkout → order tracking completable with TalkBack (Android) and VoiceOver (iOS/Safari) with correct labels, live regions and headings.
- Text contrast ≥ **4.5:1** (normal text), ≥ 3:1 for large text and UI components; form errors programmatically associated (`aria-describedby`).
- All images/icons conveying meaning have Arabic or English alternative text; decorative images hidden from AT.

## Rationale

`OBJ-03` (Critical: WCAG 2.1 AA pass ≥ 95%, Arabic-first UX quality) and `AC-S-10` make accessibility a launch gate. The Yemeni customer base includes low-literacy and older users on small screens; inaccessible checkout directly reduces conversion and exposes the platform to exclusion complaints.

## Measurement Method

- **axe-core** integrated into Playwright/E2E tests in CI — report per page, thresholds failing the pipeline.
- **Lighthouse accessibility** audits on the four core pages (secondary signal).
- Manual test passes with TalkBack/VoiceOver recorded as evidence with screen recordings; checklist from `11-ui-ux/accessibility.md`.

## Verification / Acceptance

`AC-NFR-011-01` — automated report shows ≥ 95% pass and 0 critical/serious violations on all customer pages, in both `ar` and `en` locales. `AC-NFR-011-02` — keyboard-only and screen-reader completion of all core journeys, evidenced by recordings. Both PASS (`AC-S-10`).

## Dependencies

- NFR-002 (performance of assistive-technology-heavy pages), NFR-012 (usability overlaps), NFR-013 (RTL/focus-order parity).
- FR-011 (checkout forms), FR-017 (non-intrusive notifications), DEP-11 (design tokens include contrast-compliant palette).

## Failure Consequences

Excluded users cannot complete purchases; `AC-S-10` and half of `OBJ-03` fail; RTL-specific accessibility defects surface late and are expensive to fix; reputational and potential regulatory exposure for an essential marketplace service.
