# FR-003 — User & Profile Management

**Block:** B01 Identity & Access · **Priority:** High · **Status:** approved · **Registry:** `DOC-REQ-001` §1

FR-003 lets customers and staff maintain their profile and privacy surface: display name, immutable phone identity, optional verified email, locale, a bounded address book (≤10 addresses), password change gated by OTP, account deletion, and per-device session management capped at 5 concurrent devices. Personal data is collected minimally, encrypted at rest, localized ar/en, and removable on demand while financial records are retained as required.

## Rationale

- Traces `OBJ-01` (all blocks production-ready) and `OBJ-03` (Arabic-first UX quality) — addresses and profile text are core Arabic-RTL form content.
- Supports `DATA-REQ-002` (data minimization) and `DATA-REQ-003` (retention/deletion), which only become real through an executable deletion workflow.
- The ≤10 address and ≤5 device bounds (registry §1, `BR-AUTH-06`) exist to keep checkout fast on low-end devices and sessions auditable — they must be enforced, not aspirational.

## Requirements Detail

- Profile view/edit: display name, phone (immutable primary identifier), optional email, preferred locale (Arabic default), profile summary.
- Email, if provided, must be verified and is never usable for login or OTP (`BR-AUTH-08`).
- Address book: create/edit/delete up to **10** saved addresses, each with recipient name, phone, zone/area and notes; one default address flag for checkout.
- Address fields fully support Arabic text and RTL input (`C-24`, `NFR-013`).
- Password change requires current password **plus** OTP verification (sensitive change, `SEC-REQ-001`).
- Successful password change/reset invalidates all existing sessions (`BR-AUTH-07`).
- Session management: list active devices/sessions, revoke one or all; hard cap of 5 concurrent sessions with oldest eviction (`BR-AUTH-06`, `C-08`).
- Account deletion workflow: explicit confirmation, then purge/anonymize personal data while retaining financial records ≥ 5 years (`DATA-REQ-003`, `NFR-019`).
- PII (phone, email, addresses) encrypted at rest; only necessary PII is collected (`SEC-REQ-006`, `DATA-REQ-002`).
- Phone uniqueness is enforced platform-wide (`BR-AUTH-01`).
- All profile labels, validation errors and confirmations localized ar (default) / en (`BR-PLT-05`).
- Profile reads/writes are scoped to the authenticated owner (`DATA-REQ-008`).

## Preconditions

- FR-001 authentication is available and the user holds an active session.
- The user record exists; at most 10 addresses exist before a new one is added.
- Data retention policy (`DATA-REQ-003`) and classification (`16-data/`) are defined for the fields involved.

## Expected Result

Users manage identity data, addresses and sessions within the stated bounds; sensitive changes are OTP-gated and terminate prior sessions; deletion removes personal data without touching financial history; no other actor can read or modify another user's profile or addresses.

## Acceptance Criteria

- **AC-FR003-01** — Given a customer who already has 10 saved addresses, when an 11th address is submitted, then the request is rejected with a limit error and no row is created.
- **AC-FR003-02** — Given a user who changes their password with a valid OTP, when the change commits, then all previously issued sessions are invalid and re-login is required.
- **AC-FR003-03** — Given a user with 3 active device sessions, when one device is revoked, then that device's refresh token fails on next use while the other two remain valid.
- **AC-FR003-04** — Given a confirmed account deletion, when the workflow completes, then PII is purged/anonymized while financial records remain retained ≥ 5 years.

## Business Rules Applied

- `BR-AUTH-01` unique phone identifier; `BR-AUTH-06` 5-session cap with oldest-session eviction.
- `BR-AUTH-07` password change/reset invalidates all sessions; `BR-AUTH-08` optional verified email, never used for login.

## Constraints Honored

- `C-06` phone remains the identity anchor — no email-primary or social identity flows.
- `C-08` session/token lifecycle (15-minute access, 7-day rotating refresh, ≤5 devices).
- `C-24` Arabic-first bilingual profile, address and error text.

## Dependencies

- **FR:** FR-001 (authentication/OTP), FR-002 (ownership checks), FR-011 (addresses consumed by checkout).
- **NFR/SEC/DATA:** SEC-REQ-001, SEC-REQ-006, DATA-REQ-002, DATA-REQ-003, DATA-REQ-008, NFR-013.

## Verification Method

- Unit tests: address-count bound, locale formatting, deletion data-selection logic.
- Integration tests: address CRUD limits, password-change session invalidation, device revocation, cross-user profile access denial.
- Privacy/compliance tests: deletion run leaves financial records intact (`DATA-REQ-003`); encryption-at-rest verified for PII columns (`SEC-REQ-006`).

## Out of Scope Notes

- Phone-number change, account merge/transfer and multiple accounts per person — not specified in v1; the phone is immutable.
- Social profile import, avatars beyond basic identity fields, and marketing preference centers (handled by FR-017 preferences).
- Geocoded/GPS address capture (`C-16`) and address validation against external services.
