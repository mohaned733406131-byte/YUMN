# FR-020 — Platform Administration, Settings & Audit

**Block:** B13 Platform Administration · **Priority:** Critical · **Status:** approved · **Registry:** `DOC-REQ-001` §1

FR-020 is the operator control plane: an Admin console covering users, vendors/KYC, catalog oversight, order operations and state overrides, finance (bank-transfer top-up verification, wallet freezes, escrow/dispute resolution), delivery escalations and code lockouts, platform settings (commission tiers, VAT rate, zones, required KYC documents), role management by Super Admin, human support tickets, and a tamper-evident append-only audit log — with health/readiness endpoints gating traffic.

## Rationale

- Traces `OBJ-08` (100% of state-changing admin actions audited; daily reconciliation available — surfaced here), `OBJ-01` (block B13) and `OBJ-12` (`C-09`, `C-12`, `C-16`, `C-26` enforcement surfaces).
- Automated escalations (`BR-ORD-10`, `BR-SHP-03`, `BR-SHP-06`) are only safe because this requirement guarantees a human queue with full timeline context.
- `C-16`'s 24-hour code lockout and `C-12`'s dispute freeze both require operator tooling; without FR-020 those constraints would have no runtime home.

## Requirements Detail

- Admin console modules: users, vendors/KYC, catalog oversight, orders, finance, delivery operations, content, settings, audit logs, support tickets, disputes.
- KYC review decisions (approve/reject/suspend) within the 48-hour SLA (`BR-VND-03`), with resubmission handling (`FR-007`).
- Bank-transfer top-up verification: match reference → credit wallet (`BR-PAY-04`, `INT-REQ-002`).
- Wallet freeze/unfreeze for legal/security reasons; frozen wallets cannot pay or top up but receive refunds (`BR-PAY-09`).
- Dispute handling: DISPUTED freezes escrow (`BR-ORD-05`); resolution moves to COMPLETED (vendor win) or REFUNDED (buyer win); admin is final arbiter where policy conflicts (`BR-RET-06`); every decision audited.
- Order state overrides follow RBAC and remain inside the 17-state transition table — overrides can never invent states (`C-09`, `BR-ORD-01`).
- Escalation queues: 24-hour CONFIRMED SLA breach (`BR-ORD-10`), 3rd failed delivery code attempt (`BR-SHP-03`), 3 failed delivery attempts (`BR-SHP-06`) — each auto-creates a ticket with the full timeline.
- Support tickets are handled by human agents only — no AI chatbot in v1 (project scope decision).
- Platform settings management: commission tiers (5–20%, default 10%), VAT rate (15%), shipping zone config, required KYC document set, notification templates — changes are audited (`BR-PLT-06`).
- Role management by Super Admin only (create/modify admin & moderator roles); vendor staff roles remain Owner-managed (`BR-VND-06`); vendor suspension with freeze effects (`BR-VND-04`).
- Append-only audit log: actor, action, entity, before/after, IP, timestamp — immutable, role-scoped reads, financial retention ≥ 5 years (`BR-PLT-06`, `SEC-REQ-010`, `NFR-019`).
- Liveness/readiness health endpoints gate traffic and support the availability target (`BR-PLT-07`, `C-26`).

## Preconditions

- FR-001/FR-002 provide authenticated Admin/Super Admin/Moderator principals with console permissions.
- Underlying domain data exists (orders, wallets, KYC cases, tickets) from FR-007/012/013/015/016.
- The canonical transition table and constraint register are the fixed boundaries of all override tools.

## Expected Result

Operators can safely run the platform day to day — verify payments, decide KYC, resolve disputes, unfreeze/escalate, tune settings, manage roles — with every privileged action immutably recorded, all escalations visible as tickets, and no tool able to violate the 17-state machine, escrow rules or constraint register.

## Acceptance Criteria

- **AC-FR020-01** — Given an admin changes a platform setting, when saved, then an append-only audit entry with actor, before/after values and timestamp exists.
- **AC-FR020-02** — Given a Moderator requests role-management access, when checked, then access is denied per the permission matrix (Super Admin only).
- **AC-FR020-03** — Given a dispute resolved for the buyer, when processed, then escrow unfreezes into the refund flow and an audit entry records the decision.
- **AC-FR020-04** — Given a third failed delivery-code attempt, when the system reacts, then a support ticket with the full order timeline is auto-created.

## Business Rules Applied

- `BR-PLT-06` append-only audit entries; `BR-PLT-07` health gating; `BR-ORD-05` dispute escrow freeze; `BR-ORD-10` SLA escalation.
- `BR-SHP-03` code-lockout ticket; `BR-SHP-06` delivery escalation; `BR-RET-06` admin final arbiter.
- `BR-PAY-04` bank-transfer verification; `BR-PAY-09` wallet freeze; `BR-VND-03` KYC SLA; `BR-VND-04` suspension effects; `BR-VND-06` role management.

## Constraints Honored

- `C-09` overrides and tools use only the canonical 17 states.
- `C-12` dispute-driven escrow freeze/resolution handled in console.
- `C-16` 6-digit code lockout (24 h) has operator tooling and ticket automation.
- `C-26` health endpoints and operations support 99.99% availability, RTO ≤ 1 h, RPO ≤ 15 min.

## Dependencies

- **FR:** FR-001/FR-002 (identity/RBAC), FR-007 (KYC queue), FR-012 (state overrides), FR-013/FR-014 (finance ops), FR-015/FR-016 (escalations, arbitration), FR-018 (dashboards).
- **NFR/SEC:** SEC-REQ-010, NFR-019, NFR-020 (operability), NFR-005/NFR-006 (availability, RTO/RPO), NFR-011 (accessible admin UI).

## Verification Method

- RBAC tests per console module and endpoint (denial matrix for Moderator/Customer/Vendor).
- Audit completeness tests: 100% of state-changing privileged actions produce an entry; tamper-evidence check (`SEC-REQ-010`).
- E2E: dispute resolution, bank-transfer verification, wallet freeze, escalation ticket creation; health endpoint gating tests (`C-26`).

## Out of Scope Notes

- AI chatbot support and automated dispute adjudication — human ticketing and admin decisions only (project scope decision).
- Customer-session impersonation tooling and bulk data-fix/SQL console (not specified; use controlled tooling outside v1 scope).
- Changing constraint-encoded values (state count, order bounds, escrow days) through the UI — these are code/test-enforced (`C-09`, `C-12`, `C-14`), not runtime settings.
